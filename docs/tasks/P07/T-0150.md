### T-0150 · Global error, permission and offline handling in the app
`P07` `[UI][QA]` · deps: T-0085, T-0137 · size: M · owner: ui
**Objective.** Make failures in the signed-in app clear and recoverable.
**Steps.**
1. Implement the HTMX error handler island: map response statuses to UI (inline ErrorState for fragments, toasts for background actions, full-page for navigation), include request IDs, and keep user input.
2. Implement the session-expiry flow: a 401 during an HTMX request opens the step-up/login modal (or redirects with return URL) without data loss when possible.
3. Implement permission-denied pages explaining the required role and who can grant it (org owners list for the user's org).
4. Implement offline detection (navigator online events plus failed request heuristics) showing an offline banner and disabling destructive actions until reconnected.
5. Implement retry with backoff for idempotent background polls and manual retry buttons for others.
6. Implement graceful degradation when SSE fails (polling).
7. Add tests injecting network failures via CDP network emulation.
8. Document UX behavior per failure type.
**Deliverables.**
- island updates, templates, tests
**Acceptance.**
- A1: forms keep user input on server errors and offline failures.
- A2: session expiry during a form submit preserves the form content in the retry flow.
- A3: destructive actions are disabled while offline (browser test).
- A4: error states show request IDs.
- A5: SSE failure falls back to polling with visible status text.
**Tests.**
- Browser tests with CDP network conditions (offline, slow, 5xx injection through a test-only fault route that exists only under `cfg(test)`).
**Notes.** No fault-injection routes exist in release builds.
