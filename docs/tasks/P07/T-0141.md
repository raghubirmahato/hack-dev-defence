### T-0141 · Notification center and bell (S-075)
`P07` `[UI][API]` · deps: T-0137, T-0105 · size: M · owner: ui
**Objective.** Provide durable in-app notifications with live updates.
**Steps.**
1. Implement `notifications` service functions: create (from event routing, T-0453 later), list with filters (severity, read state, kind), mark read/unread, bulk mark, delete old per retention (90 days), and unread count with a cached counter.
2. Implement the bell button with the accessible count, a popover list of the latest 8 items, "Mark all read" and a link to S-075.
3. Implement S-075 as a DataTable with severity pills, kind icons with text, timestamps and links to the related resource (permission-checked; stale links show a neutral message).
4. Implement live updates: an SSE channel for the current user (new notification fragment, count update) with polling fallback; announcements are polite and rate-limited.
5. Implement per-user preferences integration (T-0129) to suppress categories.
6. Implement notification templates with i18n keys and parameters (no pre-rendered text stored; render at read time for locale correctness).
7. Implement deduplication keys to collapse repeated notifications (e.g., repeated origin down).
8. Add tests for permissions (a notification about a resource the user lost access to is hidden).
**Deliverables.**
- service, handlers, templates, island hooks, tests
**Acceptance.**
- A1: new notifications appear in an open session within 3 s via SSE.
- A2: the unread count matches the database after concurrent updates.
- A3: users lose visibility of notifications for orgs they left.
- A4: bulk actions are keyboard accessible and announced.
- A5: notifications render in the user's locale.
**Tests.**
- Integration: SSE delivery; unit: dedupe logic; browser: bell popover keyboard behavior.
**Notes.** Email and webhook channels are handled in P24; this is the in-app channel.
