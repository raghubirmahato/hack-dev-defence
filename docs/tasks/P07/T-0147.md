### T-0147 · Audit log UI (S-084)
`P07` `[UI][API]` · deps: T-0131, T-0087 · size: M · owner: ui
**Objective.** Make the audit log searchable, exportable and verifiable.
**Steps.**
1. Implement the table with filters (actor, event type, target type/ID, time range, outcome), cursor pagination, column visibility, and saved views.
2. Implement the event detail drawer showing sanitized `detail` JSON (pretty, escaped, expandable), request ID, IP (truncated per org policy), and links to targets.
3. Implement verification indicator: last verification time/result, a "Verify now" action (rate-limited), and an explanation of the hash chain in plain language with a "what this proves and does not prove" note.
4. Implement export (CSV/NDJSON) with formula protection and size/time limits, as an async job for large ranges with email notification.
5. Implement the actor display for system, API key and impersonation events (clear labels).
6. Implement permission handling (`audit.read`, `audit.export`) and org scoping.
7. Add performance tests for 1M rows with filters.
8. Add accessibility and responsive checks.
**Deliverables.**
- handlers, templates, export job, tests
**Acceptance.**
- A1: filters combine correctly and survive pagination.
- A2: exports neutralize formula injection and respect permissions.
- A3: verification shows a clear result and failure location when a break is simulated in a test database.
- A4: the page loads under 300 ms for typical filters on 1M rows.
- A5: detail JSON never renders unescaped content.
**Tests.**
- Integration: large dataset query plans (EXPLAIN assertions for index use); unit: filter model; browser tests.
**Notes.** Platform admins have a separate global audit view (T-0430).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
