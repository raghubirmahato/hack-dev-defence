### T-0137 · App frame, sidebar, top bar and switchers
`P07` `[UI]` · deps: T-0125, T-0043, T-0048 · size: L · owner: ui
**Objective.** Implement the authenticated frame defined in B2.3 with real data.
**Steps.**
1. Implement the app layout using the frame primitives: skip link, top bar (org switcher, domain switcher, search button, notification bell, theme toggle, help menu, user menu), sidebar (permission-filtered items), main region, footer with build info and honest limits link.
2. Implement the org switcher with membership-based data and last-used memory; creating a new org links to a quota-checked flow.
3. Implement the domain switcher (type-ahead over the current org's domains) that appears only inside an org context; results are fetched via HTMX with debounce and server-side filtering.
4. Implement sidebar collapsed state persisted per user, with tooltips for icon-only mode and `aria-label`s.
5. Implement responsive behavior: below 1024 px the sidebar is a drawer; the top bar condenses switchers into a menu.
6. Implement the impersonation banner and maintenance banner slots (non-dismissible when applicable).
7. Implement active-state computation from route metadata and breadcrumbs.
8. Add keyboard tests (tab order, skip link, escape in drawers) and visual baselines.
**Deliverables.**
- `crates/hdd-web/src/app/frame.rs`, templates, tests
**Acceptance.**
- A1: a viewer role sees only permitted nav items (generated matrix test over roles).
- A2: switchers never include organizations or domains the user cannot access.
- A3: the sidebar state persists across sessions and does not cause layout shift on load.
- A4: the frame passes axe and keyboard traversal tests at 360 and 1280 px.
- A5: the impersonation banner is visible on every page during impersonation.
**Tests.**
- Browser: role-based navigation snapshots; integration: switcher endpoints with BOLA assertions.
- Visual: baselines for expanded, collapsed and mobile modes.
**Notes.** Items are hidden when the user lacks the permission; plan-limited items show an explanation (B2.3).
