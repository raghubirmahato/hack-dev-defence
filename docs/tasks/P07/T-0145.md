### T-0145 · Organization settings (S-086)
`P07` `[UI][API]` · deps: T-0126, T-0117 · size: M · owner: ui
**Objective.** Let owners manage organization-level policy and the danger zone safely.
**Steps.**
1. Implement settings sections: general (name, slug with redirect warning), security (require MFA with member impact list and grace period, session policy, IP truncation, default block page branding), data (events retention within the plan cap, audit retention information), defaults (default preset for new domains, notification email), and ownership transfer.
2. Implement the danger zone: delete organization with type-to-confirm, domain count and DNS-impact warnings, export prompt, step-up, and grace period.
3. Implement optimistic concurrency (`If-Match`) and audit events with before/after.
4. Implement plan-aware controls (retention caps) with explanations and no hiding of security controls.
5. Implement ownership transfer (target selection, acceptance email, step-up for both).
6. Implement validation for each setting and field-level errors.
7. Add accessibility and keyboard checks.
8. Add BOLA and permission tests (admin vs owner differences).
**Deliverables.**
- handlers, templates, tests
**Acceptance.**
- A1: enabling org-wide MFA lists members without MFA first and requires confirmation.
- A2: deletion requires the exact org name and step-up and starts the grace period.
- A3: retention cannot exceed the plan cap (server-validated).
- A4: changes are audited with before/after hashes.
- A5: only owners can transfer or delete.
**Tests.**
- Integration: transfer flow; browser: danger zone; unit: validators.
**Notes.** Slug changes redirect and are reflected in docs links.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
