### T-0148 · Help menu, shortcuts overlay, in-app docs links and feedback
`P07` `[UI]` · deps: T-0098, T-0137 · size: S · owner: ui
**Objective.** Provide consistent, privacy-preserving help.
**Steps.**
1. Implement the help menu (docs home, current-page docs link, shortcuts, status page, contact, report an issue) in the same position on every page (WCAG 3.2.6).
2. Implement contextual "Learn more" links using a registry mapping screen IDs to docs slugs, validated by `xtask docs check`.
3. Implement the shortcuts overlay listing active shortcuts with enable/disable toggle.
4. Implement the in-app feedback form (message, optional screenshot upload disabled) sending to the support email via the outbox with the page URL and request ID but no personal data beyond the account email; rate-limited.
5. Implement a "Copy diagnostics" button that copies non-sensitive context (build version, request ID, route, timestamp) for support.
6. Implement system status inclusion (banner if the platform has an active incident).
7. Add tests for link validity.
8. Document support flows.
**Deliverables.**
- menu, registry, forms, tests
**Acceptance.**
- A1: every screen maps to a docs link that exists.
- A2: diagnostics contain no secrets, tokens or emails.
- A3: feedback submissions are rate-limited and reach the sink.
- A4: the help control is in a consistent location across surfaces.
- A5: shortcuts overlay is keyboard accessible.
**Tests.**
- Link registry test; integration with sink; browser tests.
**Notes.** No third-party chat widgets.
