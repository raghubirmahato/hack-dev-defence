### T-0142 · Command palette and global search (S-091)
`P07` `[UI][API][SEC]` · deps: T-0137, T-0048 · size: L · owner: ui
**Objective.** Let users jump anywhere quickly without leaking data.
**Steps.**
1. Implement `GET /orgs/{org}/search?q=` with entity providers: pages (static registry filtered by permission), domains, DNS record names, rules, bans/IPs (exact IP or prefix), Ray IDs (exact), team members (by name/email prefix for admins), API keys (names), settings; each provider enforces its own permission and RLS.
2. Implement ranking: exact match, prefix, word match, recency boost, and a fixed cap per group (5) and total (25); query length limits (2 to 100 chars), debouncing, and rate limiting (`read` class).
3. Implement action results ("Add domain", "Create rule", "Ban an IP") that appear only when permitted and navigate to the corresponding forms (never execute actions directly).
4. Implement recent items per user (stored client-side minimal and server-side list of the last 10 route visits with titles), clearable.
5. Implement the HTML results fragment with `role="listbox"`/`option`, announcements of result counts, and highlighted matches via escaped markup.
6. Ensure the search never returns data from other orgs and that IP/Ray-ID lookups require `event.read`/`ban.read`.
7. Add input sanitization: queries are never concatenated into SQL (parameterized, trigram indexes for names), and logs record only query length.
8. Add accessibility and keyboard tests.
**Deliverables.**
- search service, providers, endpoint, palette wiring, tests
**Acceptance.**
- A1: a viewer cannot find actions or entities requiring higher permissions.
- A2: cross-tenant probes (searching IDs of another org) return nothing and are indistinguishable from no match.
- A3: SQL metacharacters in queries do not alter behavior or error (fuzz).
- A4: results appear within 150 ms p95 for 1,000 domains.
- A5: palette opens via Ctrl/Cmd+K and button, closes with Esc, and returns focus.
**Tests.**
- Integration: provider tests; BOLA suite additions; fuzz target on query parsing; browser keyboard test.
**Notes.** Query contents are not stored or logged beyond aggregate counters (privacy).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
