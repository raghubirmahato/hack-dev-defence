### T-0139 · Organization overview (S-040)
`P07` `[UI][API]` · deps: T-0137, T-0140 · size: L · owner: ui
**Objective.** Show the owner what matters now, honestly.
**Steps.**
1. Implement the KPI row (requests, blocked, active bans, healthy domains) from rollups, each with a definition tooltip, comparison to the previous period, and the Unknown state with reason when no source exists.
2. Implement the 24-hour chart (requests and blocked) with annotation markers (mode changes, rule changes) from `config_revisions` and a table alternative.
3. Implement the **attention list** with deterministic rules: certificate within one quarter lifetime, domain in monitor mode for more than 14 days with would-block activity, domain without traffic for 48 hours after activation, origin unhealthy, pending appeals, failed webhook deliveries, unverified domains, readiness below 60, MFA not enrolled for owners, platform announcement; each item has a primary action link.
4. Implement the onboarding checklist block (T-0143) and recent events list (last 10, escaped payload excerpts).
5. Implement empty states: new org (no domains), domains without traffic (explain what to expect, link to troubleshooting).
6. Implement partial failure handling per widget (HTMX lazy-loaded widgets with skeletons and ErrorState).
7. Implement caching of widget queries (30 s) with `Cache-Control: private` and invalidation on relevant events.
8. Add performance tests (render under 50 ms server time with 100 domains).
**Deliverables.**
- overview page, widget endpoints, attention rules module, tests
**Acceptance.**
- A1: with no traffic, KPI cards display `No traffic yet` or Unknown with a reason, not zeros presented as measurements.
- A2: each attention rule has a unit test with positive and negative cases.
- A3: widget failure isolates to that widget.
- A4: org A's overview never includes org B's data (BOLA suite).
- A5: the page passes axe and the performance budget.
**Tests.**
- Unit: attention rules table tests; integration: widgets with seeded rollups; browser: empty and populated states.
**Notes.** Attention items link to fixes, never to marketing upsells.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
