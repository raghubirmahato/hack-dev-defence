### T-0138 · Navigation state, breadcrumbs, titles and keyboard shortcuts
`P07` `[UI]` · deps: T-0137 · size: M · owner: ui
**Objective.** Make wayfinding consistent across every page.
**Steps.**
1. Implement breadcrumb generation from route metadata with dynamic labels (org name, domain name) truncated safely with accessible full names.
2. Implement the canonical `<title>` builder and the single-`h1` page header component with status pills and primary action slots.
3. Implement focus management after navigation: full page loads place focus on the `h1` (or skip-link target) via `autofocus` semantics and `tabindex="-1"`; HTMX boosted navigation moves focus to the swapped `h1` and announces the title in the polite live region.
4. Implement the keyboard shortcut layer (`g o`, `g d`, `g e`, `g b`, `/`, `?`) with the ability to disable single-key shortcuts (stored per user), no firing inside inputs, and a shortcuts overlay.
5. Implement scroll restoration rules for tabs and wizard steps.
6. Implement canonical redirects for org slug changes and trailing slashes.
7. Add tests for long names, RTL names, and 360 px behavior.
8. Document patterns for page authors.
**Deliverables.**
- navigation helpers, templates, shortcut island, docs, tests
**Acceptance.**
- A1: after any navigation focus lands on the page heading (browser test across 15 routes).
- A2: single-key shortcuts can be disabled and never trigger in text fields.
- A3: breadcrumbs handle 100-character names without overflow.
- A4: titles follow the canonical format for all routes (route-table test).
- A5: slug-change redirects work for 30 days (test clock).
**Tests.**
- Browser keyboard tests; unit tests for title/breadcrumb builders; proptest for truncation never splitting grapheme clusters.
**Notes.** Screen-reader announcements for HTMX navigations use a single dedicated live region.
