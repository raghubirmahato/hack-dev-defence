### T-0146 · Plans, quotas and usage metering (S-085)
`P07` `[UI][API][DB]` · deps: T-0126, T-0140 · size: M · owner: api
**Objective.** Enforce plan limits and show usage honestly.
**Steps.**
1. Implement plan definitions (`plans.limits`) and effective limit resolution (plan + org overrides by platform admin) with typed accessors; seed the `unlimited` plan for `owner_only` mode.
2. Implement `QuotaGuard` usage in all creation paths (domains, seats, API keys, rules per domain, webhooks, report schedules, custom certs) returning `ERR-RATE-002`/`ERR-DOM-006` with the limit, usage and a link to S-085.
3. Implement usage counters: gauges computed from tables (domains, members), and metered counters (requests, blocked, bandwidth, DNS queries) from rollups with monthly periods.
4. Implement S-085: plan card, limits with progress bars (text + bar), usage history, and an explanation of what happens at limits (soft limits warn at 80%, hard limits block creation, traffic limits never silently drop protection: documented behavior is "alert and notify; protection continues" unless the operator configures otherwise).
5. Implement platform-side editing hooks used by T-0429.
6. Implement notifications at 80% and 100% of limits.
7. Implement tests across all guards, including races (two concurrent creations at the limit).
8. Document quota semantics and defaults.
**Deliverables.**
- plan service, guards, S-085, tests, docs
**Acceptance.**
- A1: concurrent creations at the limit result in exactly the allowed number.
- A2: traffic quotas never disable protection by default (documented and tested).
- A3: S-085 progress bars have text equivalents.
- A4: limit changes by platform admins take effect within 2 s.
- A5: the `unlimited` plan shows no misleading limits.
**Tests.**
- Integration: race tests; unit: limit resolution; browser: S-085.
**Notes.** Billing integration is optional and deferred (T-0558).
