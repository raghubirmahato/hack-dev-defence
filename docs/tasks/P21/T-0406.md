### T-0406 · Origin lockdown wizard (S-098): stack snippets, verification probes and safe relaxation
`P21` `[UI][API][SEC]` · deps: T-0405, T-0210, T-0383 · size: L · owner: ui
**Objective.** Give owners copy-paste-correct instructions for their stack and check that they worked, without risking a lockout of their own site.
**Steps.**
1. Build the wizard route `/domains/{id}/origin/lockdown/*` with steps: (1) why this matters (plain language, bypass diagram), (2) choose a method (header, mTLS, firewall-only, combination) with trade-offs, (3) stack-specific instructions, (4) verify, (5) done/ongoing monitoring. All state is server-side; the wizard is resumable.
2. Generate **stack snippets** from templates tested in CI where possible: nginx (`allow`/`deny`, `if ($http_hdd_origin_auth != "…") { return 403; }` using a secret placeholder with copy-to-clipboard), Apache (`SetEnvIf`, `Require`), Caddy, HAProxy, Traefik, IIS (URL Rewrite), Cloudflare-style tunnels are not applicable; cloud firewalls (AWS security group CLI, GCP firewall rule, Azure NSG, DigitalOcean/Hetzner firewall, UFW, `iptables`/`nft` with sets), Kubernetes `NetworkPolicy`, WordPress/PHP `mu-plugin` example verifying the header (marked as defense in depth), and Node/Express middleware. Secrets are shown once per rotation with an eye-toggle and never embedded in downloadable files unless the owner clicks "include secret".
3. Implement **self-lockout protection** (C9.2): the wizard computes the HDD egress IP list and warns that the owner's own SSH and monitoring addresses must stay allowed; firewall snippets add rules for HDD IPs and never remove existing rules; every firewall snippet includes a timed-revert variant (`at now + 10 minutes` or `systemd-run --on-active`) that the owner can use for the first application.
4. Implement the **verification step**: run the off-platform probe (T-0405) and the header/mTLS probes with live status (queued, running, results table: direct IPv4, direct IPv6, with SNI, without SNI, with Host header, with secret header, with wrong secret, via HDD). Each row has a plain-language outcome and next action.
5. Implement the **safe relaxation** flow: "I need to access my origin directly for a moment" creates a time-boxed (max 2 h) relaxation instruction set (add owner IP to allowlist) with an auto-reminder to remove it; the wizard never contacts the origin to relax anything itself.
6. Implement the **post-cutover reminder** for the apex origin: after `full_ns` go-live, show the lockdown task prominently until verified; include a one-click "email me these instructions" (rendered into the mailer as a templated message with the same snippets).
7. Accessibility: tabs/code blocks keyboard operable, copy buttons with accessible names and live-region confirmation, snippet language labels, no color-only status; the wizard passes the axe oracle and screen-reader smoke script.
8. Add i18n keys and the claims-lint guard: the UI says "Applied and verified from outside HDD at <time>" only when `verified`; "Applied (not yet verified)" otherwise; never "your origin is secure".
9. Write end-to-end tests with a headless browser against local stacks (nginx and Apache containers in the lab) following the generated snippets and verifying the probe outcomes before and after.
**Deliverables.**
- wizard screens, snippet templates and tests, i18n, e2e tests
**Acceptance.**
- A1: following the nginx and Apache snippets in the lab results in `verified` and direct requests refused (e2e).
- A2: every snippet includes the timed-revert variant or a "keep your management access" warning (static test over templates).
- A3: the secret appears only in the reveal element and the one-time download (DOM and network log checks).
- A4: the wizard is fully keyboard operable and passes axe.
- A5: wording tests prove no absolute-security claims.
**Tests.**
- Browser e2e, template unit tests (snapshot), accessibility oracle.
**Notes.** The templates live in `design/snippets/` with their own CHANGELOG so updates are reviewable.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
