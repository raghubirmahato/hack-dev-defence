### T-0412 · Client-side supply-chain visibility: CSP report collector, SRI advisor and third-party script inventory
`P21` `[API][DP][SEC][UI]` · deps: T-0410, T-0302 · size: L · owner: api
**Objective.** Help owners notice injected or compromised third-party scripts (skimmers, malicious tags) without HDD modifying page content.
**Steps.**
1. Implement the **reserved report endpoint** `POST /__hdd/csp-report/{site-token}` on customer domains (path prefix `/__hdd/` is reserved, handled before the origin), accepting `application/csp-report` and `application/reports+json` (Reporting API) with a 64 KiB cap, strict parsing, per-IP and per-site rate limits (30/min/IP), no cookies, CORS closed, and authentication by the unguessable per-site token in the path (rotatable). Reports never reach the origin.
2. Normalize and store aggregated reports: `(violated-directive, blocked-uri host/scheme, document-uri path template, source-file host, disposition)` with counts per day; discard query strings and fragments; sample at most 50 distinct raw reports per site per day with redaction; cap storage (plan-based).
3. Implement the **third-party script inventory**: from CSP reports plus (opt-in) a periodic **passive crawl** of the owner's own public pages through the sandbox/posture scanner path (`hdd-scan`, built in P27, ≤ 5 req/s, only the owner's verified domain) that extracts `<script src>`, `<link rel=stylesheet>`, `<iframe src>`, `<form action>` hosts and notes missing `integrity` attributes, `crossorigin`, and `rel=noopener` on external links. The crawl respects `robots.txt` disallow for the scanner UA only as informational; consent is explicit per domain.
4. Implement **new-host alerts**: a script/connect host never seen before on a checkout or login page (path classes declared by the owner) raises `new_third_party_host` as an attention item with severity depending on page class (payment pages high), and a "mark as expected" action with reason.
5. Implement the **SRI advisor**: for static third-party scripts on a CDN with stable URLs, compute and display recommended `integrity` hashes (fetched via the egress client from the pinned host, size-limited, shown with the fetch time and a warning that dynamic scripts cannot use SRI); never write hashes into the owner's pages.
6. Implement the **CSP builder wizard** (S-097 sub-page): starts from observed reports, generates a report-only policy with explanations per directive, shows risky patterns (`'unsafe-inline'`, wildcards, `data:` for scripts), and offers "add as report-only response header" through T-0410 (never enforced by default).
7. Add **form-action tripwire** (optional): for login/payment forms, report if `<form action>` host differs from the declared set (observed by the crawler only; HDD does not rewrite HTML in v5).
8. Provide events, metrics, API (`GET D/client-side/*`), notifications, and docs; add everything to the readiness score as low-weight informational items.
9. Write tests: report parsing fuzz (malformed JSON, huge arrays, deep nesting), rate limits, token rotation, redaction, aggregation, crawler extraction fixtures (static HTML fixtures with inline events and obfuscated loaders), new-host alert flow, SRI computation correctness, claims-lint ("helps you notice changes", never "prevents skimming").
**Deliverables.**
- report endpoint, aggregation, inventory, SRI advisor, CSP builder, UI, tests
**Acceptance.**
- A1: the endpoint rejects oversize/malformed/unauthenticated reports with the documented statuses and never forwards them to the origin.
- A2: aggregation stores no query strings/fragments (property test).
- A3: crawl traffic stays within the posture-scan rate limit and only targets verified domains (audit log check).
- A4: a newly added third-party host on a declared checkout page raises an attention item in the fixture scenario.
- A5: SRI hashes match independently computed values (`openssl dgst`) for fixture scripts.
**Tests.**
- Unit/fuzz (parsers), integration (endpoint, crawler against fixture origin), browser e2e for the CSP builder.
**Notes.** The `/__hdd/` prefix is reserved platform-wide; origin applications using it receive a warning at onboarding.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
