### T-0413 · Tenant egress safety in the data plane: SSRF guard, DNS pinning and rebinding verification
`P21` `[DP][SEC][QA]` · deps: T-0365, T-0163, T-0378 · size: M · owner: sec
**Objective.** Prove that HDD cannot be turned into a request-forwarding weapon against private networks or other tenants through origin configuration.
**Steps.**
1. Review and unify every code path in which HDD opens an outbound connection on behalf of a tenant: origin client, health checks, connectivity test, origin TLS diagnostics, CSP-related fetches, webhooks (P24), feed fetchers (no tenant input), SRI advisor, posture scanner, external DNS target resolution (flattening). Document each in `docs/EGRESS.md` with the guard used.
2. Centralize the guard in `hdd-common::egress` (the single connector): resolve → validate → connect-to-IP with SNI/Host preserved; reject loopback, link-local (including 169.254.169.254), private (RFC 1918/ULA), CGNAT (100.64/10), multicast, reserved, documentation, IPv4-mapped/translated IPv6 forms, `0.0.0.0`, broadcast, and the platform's own addresses, with overrides only for `owner_only` mode via the explicit `egress.private_origin_allowlist` profile entry (never for `saas`), never for the metadata/link-local ranges, and with the single built-in exemption `origin_kind=platform_internal` for HDD's own surfaces (section 2.9). Add the egress class `dns_resolution` (section 2.1) to the inventory, the kill switch (`hddctl egress disable dns_resolution`) and `docs/EGRESS.md`.
3. Add **pinning and revalidation**: connections use the validated IP; revalidation on every new connection and when a DNS TTL expires; if a hostname's A set changes to include a blocked address, the entire host is blocked (not just the address) until an owner edit, with an event `origin_rebinding_detected`.
4. Enforce **port allowlists** and **protocol allowlists** (no `file:`, `gopher:`, `ftp:`; schemes `http`/`https` only), no redirects followed anywhere in the egress client (a single code path, tested).
5. Add a **kill switch for egress classes** (`hddctl egress disable webhooks|probes|scan`) for incident response.
6. Build the **SSRF test matrix** (≥ 150 vectors): decimal/octal/hex IP encodings, IPv6 forms, userinfo tricks (`http://good@evil`), URL parser differentials (backslashes, tab/newline), unicode dots, trailing dots, `localhost` variants, DNS names resolving to private IPs, DNS rebinding with short TTL flip, redirect to internal, SSRF through `Host` and SNI fields, and the cloud metadata endpoints; run against every egress user via a common harness.
7. Add a **static analysis gate** (`xtask egress-lint`) that fails the build if any crate other than `hdd-common::egress` constructs a `reqwest::Client`/`hyper` client/`TcpStream::connect` toward a non-loopback target, with an explicit allowlist file for the host-local services.
8. Run the matrix in the lab with a DNS rebinding server (controllable authoritative server) and record evidence for AC-17.
**Deliverables.**
- unified egress module, egress documentation, test matrix, lint gate
**Acceptance.**
- A1: all 150+ vectors are rejected on every egress path (matrix report by path).
- A2: the egress-lint gate passes and fails when a violation is injected.
- A3: rebinding flips are caught at connect time and block the host.
- A4: `saas` mode has no override path for private ranges (config validation test).
- A5: `docs/EGRESS.md` lists every outbound path with its guard.
**Tests.**
- Matrix harness, static gate tests, lab rebinding server.
**Notes.** This is AC-17's data-plane half; the save-time half is T-0163.

## Definition of done for this task's tags (section 0.7)
