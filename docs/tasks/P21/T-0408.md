### T-0408 · Outbound leak detection engine (pure library) and signature catalog
`P21` `[DP][SEC]` · deps: T-0311, T-0239, T-0253 · size: L · owner: dp
**Objective.** Detect, in response bodies, the content that helps attackers or reveals secrets, with a low false-positive rate.
**Steps.**
1. Implement `hdd-waf-core::leak` as a pure library: input `(content_type, status, decompressed_prefix_bytes, flags)`, output `LeakFindings` with category, confidence, pattern id, offset and a redacted 512-byte snippet (via T-0253). No allocation per byte; patterns compiled into automata at snapshot load.
2. Define **categories and patterns** (all documented in `docs/OUTBOUND.md`, each with a positive and negative fixture):
   - Database errors: MySQL (`You have an error in your SQL syntax`, `mysql_fetch_`, `Warning: mysqli_`), PostgreSQL (`PG::SyntaxError`, `ERROR:  syntax error at or near`, `pg_query()`), SQL Server (`Unclosed quotation mark after the character string`, `Microsoft OLE DB Provider for SQL Server`, `ODBC SQL Server Driver`), Oracle (`ORA-\d{5}`, `quoted string not properly terminated`), SQLite (`SQLiteException`, `sqlite3.OperationalError`, `near "…": syntax error`), MongoDB (`MongoError`, `E11000 duplicate key`), generic JDBC/Hibernate/Sequelize/GORM/Doctrine exceptions.
   - Stack traces: Java (`at com.…(File.java:123)` blocks, `java.lang.*Exception`), .NET (`at System.…` lines, `Server Error in '/' Application`), Python (`Traceback (most recent call last):`), PHP (`Fatal error:`, `Stack trace:`, `on line \d+`), Ruby/Rails, Node (`at Object.<anonymous> (/path`), Go panics (`goroutine 1 [running]`), Rust panics (`thread 'main' panicked at`).
   - Secrets: private-key PEM headers, AWS access key ids (`AKIA…`, `ASIA…`) with secret-shaped neighbors, GitHub/GitLab/Slack/Stripe token formats (prefix + length + charset), JWTs in HTML/JSON that look like admin tokens (only when `Set-Cookie`-less body leak patterns), `.env`-style lines (`DB_PASSWORD=`, `APP_KEY=base64:`), connection strings with credentials (`postgres://user:pass@`).
   - Source code markers: raw `<?php` / `<%@ ` / `<% ` in responses served as text/html where the origin should have executed them, `#!/usr/bin/env` heads, `__pycache__` paths.
   - Directory listings: `Index of /`, `<title>Index of`, Apache/nginx/IIS listing structures, S3-style `ListBucketResult` bodies.
   - Version banners and internal paths: `/var/www/`, `C:\inetpub\`, `/home/<user>/`, with a minimum-evidence rule (two or more path occurrences or a path adjacent to an error marker).
3. Apply **confidence scoring** (high: error + context, medium: single marker, low: weak path/version) and a **context filter**: documentation sites, security blogs and code hosting pages may legitimately contain these strings; the filter downgrades findings when the response is `text/html` with `<pre>`/`<code>` density over a threshold or the path is on the owner's `outbound_exclusions`. Findings from `application/json` and `text/plain` carry higher confidence.
4. Implement **streaming-friendly scanning** API (`LeakScanner::feed(chunk)` with a bounded rolling window so patterns spanning chunk boundaries are found) used by the proxy buffer in T-0409.
5. Implement **false-positive controls**: benign corpus of 500 pages (docs about SQL errors, StackOverflow-like pages, tutorials, changelogs) that must produce zero `high` findings in `block` eligibility; patterns that fail the corpus are downgraded or require context.
6. Provide pattern pack versioning (signed packs with rollout stages like WAF packs, rollback via config revisions) so false-positive fixes ship without a release.
7. Write unit tests (≥ 300 positive fixtures across languages, ≥ 300 negatives), property tests (chunk-boundary invariance: scanning in any chunking equals scanning whole), and fuzz targets for the scanner.
8. Benchmark: ≥ 400 MB/s scan throughput on cached patterns for 64 KiB windows on the builder; document.
**Deliverables.**
- `leak` module, pattern packs, fixtures, benches, `docs/OUTBOUND.md`
**Acceptance.**
- A1: all positive fixtures are detected with the documented category and confidence; no negative fixture yields a `high` finding.
- A2: chunk-boundary invariance holds for 100,000 random chunkings.
- A3: the canary `leak.txt` sentence is detected as `high` database error.
- A4: scanner memory is bounded (window ≤ 128 KiB + pattern state).
- A5: the throughput target is met or the deviation is documented.
**Tests.**
- Unit/property/fuzz/bench as above.
**Notes.** The scanner reports patterns; it never claims the response "contains no sensitive data".
