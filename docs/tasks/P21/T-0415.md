### T-0415 · Origin protection end-to-end tests (AC-10, AC-18, AC-05 headers, AC-17 connect-time) on the pilot and lab
`P21` `[QA][HUMAN]` · deps: T-0406, T-0407, T-0409, T-0410, T-0413, T-0218 · size: L · owner: qa
**Objective.** Prove the origin-protection and outbound behaviors on real infrastructure.
**Steps.**
1. Execute AC-10: with the canary `leak.txt`, verify detection in `monitor`, block in `block`, exclusions, partial-scan labeling with an oversized canary variant, binary negatives (`static.css`/`.js` byte-exact via hashes), compressed responses, and the S-097 test tool. UNVERIFIED(`capability_not_supplied`) if the operator cannot place `leak.txt`; the lab fixtures still run and are reported separately as lab evidence.
2. Execute AC-18 on the pilot: instruct the operator (STOP-style, T-0216) to apply the origin firewall allowlist and the secret header requirement; after the operator confirms, run the off-platform probe from the runner and the canary echo checks; verify `lockdown_state` transitions pending → instructed → applied_unverified → verified. Without operator action, record `UNVERIFIED(human_step_pending)`.
3. Verify the negative paths: wrong secret header gets the origin's refusal, mTLS option test with the lab origin, rotation with both-accepting origin, drift simulation by relaxing the firewall in the lab.
4. Execute the AC-05 header checks: `X-Forwarded-For`, `HDD-Connecting-IP`, the secret header, spoofed header stripping, response header policy results, cookie policy in `report` mode, HSTS gating.
5. Execute the AC-17 connect-time checks in the proxy with the rebinding lab server and all egress paths (T-0413 matrix).
6. Run the benign outbound corpus (500 pages) through the proxy in `block` mode and require zero blocks.
7. Verify the claims: UI strings, docs, and exports for lockdown and outbound pass claims-lint, and screenshots of the wizard and S-097 are captured in both themes for the evidence bundle.
8. Archive evidence with SHA-256 and update STATUS lines for AC-05, AC-10, AC-17, AC-18.
**Deliverables.**
- evidence bundle, updated STATUS/capability matrix, operator instruction pages
**Acceptance.**
- A1: AC-10 PASS (live canary and lab fixtures) with evidence.
- A2: AC-18 is PASS, or UNVERIFIED with exactly `human_step_pending`, and the instructions are precise and copy-pasteable.
- A3: AC-05 header checks PASS with the canary echo (or UNVERIFIED(`capability_not_supplied`)).
- A4: AC-17 connect-time matrix PASS on all egress paths.
- A5: zero false positives on the benign outbound corpus in `block` mode.
**Tests.**
- Live and lab runs from the runner under correct rate profiles.
**Notes.** Never fabricate a leaking endpoint: the leak tests use only the operator's canary file or the lab-only fixtures (section 2.8).
