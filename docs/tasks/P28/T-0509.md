### T-0509 · Regression orchestration: non-destructive subset, destructive subset, flake control and CI integration
`P28` `[QA][OPS]` · deps: T-0492, T-0497, T-0498, T-0499, T-0500, T-0501, T-0503, T-0505, T-0506, T-0507, T-0508 · size: M · owner: qa
**Objective.** Make the whole suite runnable regularly, safely and with controlled flakiness.
**Steps.**
1. Define the **suite tiers:** `smoke` (AC-00, AC-05, AC-22 — minutes, safe in production), `nondestructive` (adds AC-03, AC-20, AC-01 login checks, AC-35 login-only, sandbox-only checks — safe in production), `pilot-full` (adds AC-04, AC-06..AC-18 live subsets, ban tests with 60 s TTLs, resilience announced), `lab-full` (Vuln-Lab, oracles, floods in closed lab), and `release` (everything required for release gates); tiers are encoded in the catalog and enforced by stage rules.
2. Implement **scheduling and CI integration:** `xtask acceptance --tier smoke` on every deploy, `nondestructive` nightly against the pilot, `lab-full` nightly on the lab runner (UNVERIFIED if no lab runner), `release` before tagging; results are stored, compared with previous runs, and trend charts (table alternative) are rendered in the report; failures create issues in the task queue with evidence links.
3. Implement **flake control:** the failure budget (3 attempts) per check with automatic annotation; a flake registry tracks checks that pass only on retry and creates diagnosis tasks (retries never hide a real failure: a check that fails on attempt 1 and passes later is reported `Pass (flaky)` with the ratio and cannot be used as release evidence unless diagnosed); randomized order within tiers to find hidden dependencies; deterministic seeds for generators.
4. Implement **time budgets:** per-check timeouts and an overall suite budget; slow checks are flagged; parallelism where safe (read-only checks) and serialization for checks sharing ban state or rate budgets.
5. Implement **environment drift detection:** the suite records tool versions, kernel, config hashes and fixtures hashes with every run and flags drift between runs that could explain differences.
6. Implement **evidence retention and privacy:** evidence is stored with retention (default 180 days), contains no secrets (scan on write), and is excluded from the release artifacts but included in the operator handoff pack on request.
7. Re-run **AC-53** (readiness score correctness against scenario fixtures) and **AC-24 prep** (hooks for performance measurements) as part of the tiers.
8. Write meta-tests for the orchestrator: tier selection, stage refusals (production + destructive), flake detection logic, resume, trend computation.
**Deliverables.**
- tier definitions, schedulers, flake registry, retention policy, docs
**Acceptance.**
- A1: each tier runs end to end in its environment and respects stage rules (production refuses destructive tiers without approval).
- A2: a synthetic flaky check is detected, annotated and excluded from release evidence.
- A3: `smoke` completes in under 5 minutes on the pilot.
- A4: evidence scans find no secrets.
- A5: trend reports are generated and compared across runs.
**Tests.**
- Meta-tests, dry-run in CI.
**Notes.** The orchestrator's rules protect production traffic by construction.
