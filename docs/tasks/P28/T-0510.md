### T-0510 · Acceptance suite and Vuln-Lab gate G28 with acceptance report v1
`P28` `[QA][DOC]` · deps: T-0509, T-0497, T-0499, T-0502, T-0504 · size: M · owner: qa
**Objective.** Close phase P28 with the first complete acceptance report.
**Steps.**
1. Run the `release` tier end to end (pilot + lab) and render the acceptance report v1 (`acceptance-<ts>/report.md|html|json`).
2. Verify the report completeness: every AC-00..AC-54 has a status; every PASS has evidence with SHA-256; every UNVERIFIED has an enumerated reason and the operator action required; no FAIL remains.
3. Verify the packet-capture and audit proof that no acceptance traffic left its allowlist, and that oracles ran only against lab addresses.
4. Verify the release exclusion of the Vuln-Lab by building release artifacts and inspecting the SBOM.
5. Review the claims appendix: every product claim in docs/UI/marketing maps to an evidence id and a limit statement; claims-lint passes.
6. Compile the gate report with the headline figures (AC-38 table, AC-39 figures, FP baseline, coverage by group), the UNVERIFIED list and "what we need from you" operator actions.
7. Update the capability matrix (REQ-ACC) and STATUS; archive evidence.
8. Tag `gate-G28`.
**Deliverables.**
- acceptance report v1, `docs/gates/G28.md`

- A1: report completeness checks pass (status and evidence for all 55 criteria of AC-00 to AC-54; AC-55 to AC-58 are accepted at G33 and AC-59 to AC-62 at G34).
- A2: no FAIL; all UNVERIFIED have reasons.
- A3: traffic-containment proof is attached.

- A5: tag exists.
**Tests.**

**Notes.** Next: performance, chaos, fuzz and supply chain (P29).
