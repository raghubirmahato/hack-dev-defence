### T-0503 · Identity, tenant isolation, admin, appeals and audit acceptance: AC-01, AC-19, AC-35, AC-36, AC-42, AC-43, AC-47
`P28` `[QA][SEC]` · deps: T-0133, T-0128, T-0439, T-0324, T-0491 · size: XL · owner: qa
**Objective.** Execute the full product-security acceptance on HDD's own login, admin, isolation and data-handling flows.
**Steps.**
1. **AC-35 (identity e2e):** signup (including email verification, abuse controls and disposable-email policy), login (password, TOTP, recovery codes, passkeys using a virtual authenticator via CDP), session management (rotation on login/privilege change, idle/absolute timeouts, revoke), password reset (token single-use, expiry, no account enumeration, timing equalization), change email/password, MFA enforcement, API keys, account lock/unlock, login anomaly notifications; run on the live pilot with the operator account for login-only checks and on the lab stack for the full suite.
2. **AC-19 (dashboard and headers, frontend security):** login with MFA works in a real browser (driven by `chromiumoxide`), CSP with nonces and Trusted Types are enforced (violations reported and none in normal flows), CSRF is enforced on every mutation, a stored-XSS payload placed in an event or comment renders escaped everywhere it is displayed, and SSE delivers a new event to the live monitor; the frontend security suite (T-0093) is re-run against the release candidate.
3. **AC-01 (auth and admin isolation):** the privilege matrix from T-0439 re-run end to end across surfaces (www/app/admin/api/status), host-header confusion, cross-surface cookie replay, admin exposure mode checks (`tunnel_only` reachability tests from outside), session fixation, CSRF on every mutation, clickjacking, CORS, and rate limits on auth endpoints (HDD's own login protected by HDD's own SQLi shield: run the six mandated payloads against HDD's login and signup forms and confirm they are blocked and the source banned, with the runner's IP protected via the second-source mechanism).
4. **AC-36 (RLS + BOLA):** automated BOLA suite generated from the API catalog for every resource type (org, domain, DNS record, certificate, rule, ban, event, report, webhook, API key, integration, notification, appeal, export, scan, component) with cross-org identifiers and cross-role attempts; RLS verification by direct database access using the `hdd_api` role with a forged `app.org_id`, attempts to read other orgs' rows through views, functions and partitions, and ensuring `SECURITY DEFINER` functions are reviewed; both must show zero leakage.
5. **AC-42 (admin operations and tenant lifecycle):** suspend/unsuspend, delete with grace and purge, impersonation constraints, platform-wide emergency controls, plan changes, announcements, backups (smoke), audit export verification, with data-deletion scanner results (no org-scoped rows remain).
6. **AC-43 (appeals):** visitor sees block page with Ray ID, submits appeal with PoW, rate limiting and abuse resistance (floods of appeals), owner receives notification, resolves (unban, exception, decline), visitor outcome page, appeals never reveal rule names, and no appeal path allows ban evasion (attacker cannot unban via appeals without owner action).
7. **AC-47 (audit and data export):** audit event completeness for a catalog of 60 actions, chain verification under tamper, export manifests, user data export and account deletion flows (grace period, owner transfer prerequisite), consent records, retention enforcement.
8. Run **secret-leak scans** across logs, events, exports and API responses (planted canary secrets must never appear) and **timing-oracle tests** for login/reset/enumeration.
9. Record evidence, update statuses, and log any finding as a task under the failure budget.
**Deliverables.**
- evidence bundles for AC-01/19/35/36/42/43/47
**Acceptance.**
- A1: BOLA/RLS suites show zero cross-tenant access over all resource types.
- A2: HDD's own login/signup block and ban the six mandated payloads (with runner protection honored).
- A3: no account enumeration or timing oracle exceeds the documented tolerance.
- A4: deletion scanner finds no residual org data after purge.
- A5: audit completeness test passes for the 60-action catalog.
**Tests.**
- Browser e2e, API suites, DB-level tests.
**Notes.** HDD protecting its own login with its own shield is a deliberate dogfooding proof.
