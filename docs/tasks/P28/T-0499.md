### T-0499 · AC-39: SQL injection matrix, evasion catalog, held-out set and the sqlmap campaign
`P28` `[QA][LAB][SEC]` · deps: T-0496, T-0283, T-0280, T-0278 · size: XL · owner: qa
**Objective.** Measure and document SQLi detection and banning exhaustively, with exact figures and honest limits.
**Steps.**
1. **Matrix test (in-process and inspect API):** the cross product of M1–M6 and the ≥ 300 variant fixtures (case, whitespace, comments, encodings, quote folding, dialect-specific forms) against **every vector** in C4.2 (query, path, form urlencoded, multipart, JSON, XML, headers, cookies, fragments reflected via referer) and **each field kind** (password field exception documented): require 100% `would_block` with category `sqli` and the expected hardness; record the matrix as CSV evidence.
2. **Live enforcement subset on the sandbox** (inspect-first gate): Class A shapes in GET/HEAD via `test_hostname`/`sandbox_hostname`, with 60 s test bans for the runner; verify 403 and ban creation; verify cross-site context returns 403 without ban; verify password-field soft behavior in Balanced and hard in Paranoid.
3. **Evasion catalog:** run the C4.8 evasion catalog (double URL encoding, unicode normalization tricks, null bytes, inline comments `/**/`, case alternation, whitespace substitutes, scientific notation, `CONCAT`/`CHAR()` obfuscation, comment-split keywords, HPP, JSON unicode escapes, multipart charset tricks) through all vectors; record detections, misses and the miss classification.
4. **Held-out set:** execute `heldout/sqli/*` (never used for tuning) and report the detection rate separately; any miss opens a diagnosis, but the held-out set may not be added to training fixtures until the gate is closed (anti-overfitting rule).
5. **Benign suite:** run `benign-sql-prose.txt` (400+), `benign-general.txt` (500+) and apostrophe names through all vectors in `block` mode; require 0 false positives (any FP is a FAIL until fixed).
6. **Oracle campaign (lab):** sqlmap levels 1–3, risk 1–2, default tampers plus the published tamper list (`space2comment`, `between`, `randomcase`, `charencode`, `apostrophemask`, `equaltolike`, `base64encode`, `versionedkeywords`, `space2mysqlblank`, etc.) against the login, search, ID, JSON, header and cookie endpoints through HDD: in `block` mode no data extraction succeeds (canary token never appears), and the source is banned at the first hard hit; in `monitor` mode at least **95%** of injection-bearing requests are flagged `would_block`; report the exact figure and the classes of un-flagged requests (for example harmless boolean probes that contain no SQL syntax).
7. Run **ban-diversity and ladder checks** during the campaign: distinct sqlmap sessions from different sources, the campaign detector (V16), the global jail promotion thresholds (3 orgs/1 h) using multiple lab orgs.
8. Run **performance checks:** inspection p50 < 1 ms and p99 within budget for the matrix payload sizes; mutation testing score ≥ 80% on `hdd-waf-core` (from T-0258) re-verified.
9. Produce the AC-39 report: counts, rates, miss analysis, statement of limits, and proposed rule tasks for misses (not auto-added).
**Deliverables.**
- AC-39 evidence bundle, CSV matrices, campaign logs, miss analysis
**Acceptance.**
- A1: 100% detection of M1–M6 and variants in the matrix (exceptions only for documented password-field soft cases with their expected behavior).
- A2: 0 false positives on the benign suites in `block` mode.
- A3: sqlmap campaign: zero extraction in block mode; ≥ 95% flagged in monitor mode, with the exact figure reported.
- A4: live subset produces bans for outside-cross-site contexts and no bans for cross-site context.
- A5: held-out set results reported separately with miss diagnoses.
**Tests.**
- The matrix and campaigns themselves.
**Notes.** If any threshold is missed, the failure budget applies: diagnose, fix at root, re-run; never relax the threshold.
