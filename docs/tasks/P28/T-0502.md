### T-0502 · AC-40 and AC-41: WCAG 2.2 AA conformance and public-page quality gates
`P28` `[QA][UI]` · deps: T-0094, T-0151, T-0091, T-0104, T-0440 · size: L · owner: qa
**Objective.** Verify accessibility and public-page quality across the whole product, not screen by screen.
**Steps.**
1. Build the **screen inventory test** from the catalog (S-001..S-148 with the reserved ids S-131 to S-134 as defined and S-137 to S-139 added in P34, plus emails and PDFs): each entry has route, role, fixture state(s), themes and viewports; coverage test fails if a screen lacks an accessibility entry.
2. Run **automated checks** (axe-core oracle through CDP) on every screen × state × theme (dark, light) × viewport (320, 768, 1280) with zero serious/critical violations required; include contrast verification of all token pairs (`contrast.py` equivalent in `xtask`), focus visibility, target sizes (24×24 CSS px minimum), focus not obscured, consistent help, redundant entry avoidance, accessible authentication (no cognitive tests; passkeys/password managers supported), dragging alternatives, and reduced-motion behavior.
3. Run **keyboard traversal tests** (scripted Tab/Shift+Tab/arrow/Escape flows) across the main journeys J-01..J-34 (signup, login with MFA, add domain wizard, DNS edit, rule builder, ban/unban, appeals, report builder, admin flows), asserting no keyboard traps, logical focus order, visible focus, working skip links, and modal focus management.
4. Run **zoom and reflow** tests: 200% and 400% zoom, 320 CSS px width without horizontal scroll (except data tables with their own scroll region and keyboard access), text spacing overrides (WCAG 1.4.12), forced-colors mode, and prefers-contrast.
5. Run **screen-reader smoke scripts** (NVDA/JAWS/VoiceOver where available; recorded manual evidence with tester, version and date; UNVERIFIED(`human_step_pending`) for combinations not performed) on the critical journeys, verifying landmarks, headings, form labels/errors, live regions (toasts, monitor), chart table alternatives and data table semantics.
6. **AC-41 public pages:** performance (Lighthouse-style lab metrics with CI budgets: LCP ≤ 2.0 s on the lab profile, CLS ≤ 0.05, JS ≤ 60 KB on the landing page), no-JS rendering of all public pages and critical forms, SEO metadata/sitemap/robots/canonical checks, security headers/CSP (no violations in the console), cookie-less public pages, claims-lint (no forbidden claims), legal pages presence, and broken link checks.
7. Run the **i18n/pseudo-locale checks:** pseudo-localization expands strings 40% without truncation/overlap; RTL smoke (if RTL locale planned) or documented non-support; date/number formatting tests.
8. Record the AC-40/AC-41 reports; list known exceptions with justification and remediation task ids (no unexplained exceptions allowed); update the accessibility statement page (S-0xx) with the actual conformance level and test methods.
**Deliverables.**
- accessibility/public-page suites, reports, accessibility statement
**Acceptance.**
- A1: zero serious/critical axe violations across the full screen×state×theme×viewport matrix.
- A2: all journeys J-01..J-34 are keyboard-operable (scripted tests pass).
- A3: 320 px reflow and 200%/400% zoom pass for all screens.
- A4: public pages meet the performance budgets and render without JS.
- A5: the accessibility statement matches test results and lists manual-test coverage honestly.
**Tests.**
- Browser suites in CI; manual evidence recorded.
**Notes.** WCAG conformance claims require manual evidence; automated tools find only a subset.

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
