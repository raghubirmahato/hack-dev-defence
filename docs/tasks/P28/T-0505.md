### T-0505 · AC-12, AC-13 and AC-16: rule dry-run, modes, safe mode, auto-rollback and convergence
`P28` `[QA][SEC]` · deps: T-0371, T-0229, T-0234, T-0491 · size: L · owner: qa
**Objective.** Verify that policy changes are safe, observable, reversible and converge quickly across all components.
**Steps.**
1. **AC-12:** rule dry-run and baseline replay: create custom rules in the UI/API, run dry-run against stored baseline traffic, verify counts of affected requests and false-positive candidates, create revisions, rollback to previous versions with preview, and verify behavior change at the proxy ≤ 2 s.
2. **AC-13 (modes):** `off`, `monitor`, `log`, `block`, safe mode (global and per domain), pause protection: same attack under each mode yields the documented outcome (e.g., blocked in `block`, `would_block` in `monitor`, passes in safe mode and blocked after exit, TLS/routing intact in safe mode).
3. **Auto-rollback correctness:** change a rule to one that blocks benign known-good probes → automatic rollback occurs and alerts; change a rule that blocks real attack traffic and benign probes pass → no rollback; attacker-driven manipulation scenarios (generate block storms and origin 5xx storms) → no rollback (C14.8); rollback thresholds (`min_distinct_ips`) validated; rollbacks visible in revisions.
4. **AC-16 (convergence):** measure propagation time of: rule changes, mode changes, bans/unbans, allowlist changes, DNS record changes (snapshot apply), certificate updates, plan limit changes to every consuming component (proxy, DNS, fw-agent, XDP, web); target ≤ 2 s p95 for security-relevant changes; multi-node behavior (if >1 proxy process or lab nodes) including resync after partition and missed messages.
5. **Config safety:** invalid policies are rejected atomically (no partial application), concurrent edits detected via `If-Match`, snapshot signatures verified by consumers, downgrade protection (older revision cannot overwrite newer).
6. **Self-lockout prevention** in rule/access changes (preview + refusal).
7. **Chaos in distribution:** drop/duplicate/reorder config bus messages and verify convergence by periodic resync (≤ 30 s worst case documented).
8. Record results with measurements; update the capability matrix.
**Deliverables.**
- evidence bundle with timing tables
**Acceptance.**
- A1: security-relevant changes converge ≤ 2 s p95 on the pilot and lab.
- A2: auto-rollback behaves per spec in both directions, with no attacker-triggerable rollback.
- A3: invalid or older revisions are never applied.
- A4: modes produce the documented outcomes for the same attack.
- A5: self-lockout prevention blocks harmful changes.
**Tests.**
- Live (sandbox), lab, chaos.
**Notes.** Rollback uses `config_revisions` and is itself audited.
