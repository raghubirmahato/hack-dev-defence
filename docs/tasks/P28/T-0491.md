### T-0491 · Acceptance runner v1: full catalog, modes, profiles, evidence store and report
`P28` `[QA][OPS][SEC]` · deps: T-0215, T-0216, T-0217 · size: XL · owner: qa
**Objective.** Turn the runner skeleton into the production-grade engine that executes, records and renders every acceptance criterion.
**Steps.**
1. Finish the `hdd-acceptance` architecture: `Catalog` (all AC-00..AC-62 as typed `Check`s; AC-55 to AC-62 stay `UNVERIFIED(stage_not_reached)` until P33 and P34 with id, title, phase of first requirement, stage constraints, required capabilities, safety class, default profile, dependencies on other checks), `Executor` (plan → run → collect), `Evidence` store (content-addressed files + JSON records), `Report` renderer (Markdown, HTML and JSON), and a CLI/xtask front end (`xtask acceptance --only AC-39 --mode live|lab --stage pilot|production --profile functional|burst|protocol-abuse|load|lab`).
2. Implement the **status taxonomy** in the type system: `Pass`, `Fail { reason }`, `Unverified { reason: ReasonCode }` with the closed reason set (`capability_not_supplied`, `human_step_pending`, `environment_unsupported`, `oracle_unavailable`, `tool_unavailable`, `stage_forbids`, `skipped_by_operator`); there is no "skipped" and no "pending" outside this set; the renderer refuses to print a PASS without at least one evidence artifact reference.
3. Implement the **target and egress allowlists** read from `hdd.live.yaml` (live mode) or the lab profile (lab mode): every HTTP/DNS/TLS/raw-socket connection from the runner passes through one connector that enforces the allowlist, rate profile, per-target concurrency, global kill switch and payload class gating; a request outside the allowlist aborts the check, writes an audit record and marks the run invalid.
4. Implement **rate profiles**: functional (≤ 20 req/s sustained, ≤ 5 minutes continuous), burst (one capped burst of ≤ 100 HTTP requests and one capped DNS burst of ≤ 500 queries), protocol-abuse (sandbox only: ≤ 5 connections, ≤ 2,000 frames and ≤ 10 MiB on the wire per test), load (separate written operator approval per run, sandbox only, own hard caps, auto-abort when origin health degrades), lab (≤ 500 req/s per client process, 10 minutes, one client process per oracle tool); profile selection per check with hard ceilings that checks cannot raise.
5. Implement the **inspect-first gate**: before a live enforcement test with a payload, the runner calls `POST /api/v1/waf/inspect` for the same vector and requires the expected category/verdict (otherwise the enforcement test is skipped as `Fail("inspect_mismatch")` instead of sending traffic that would not be blocked); records both results.
6. Implement **payload classes**: A (inert, any live target in the allowlist), B (GET/HEAD attack shapes, `test_hostname` + `sandbox_hostname` only, sandbox preferred), C (body-bearing or higher-risk, `sandbox_hostname` or lab only); the class is part of the fixture metadata and enforced by the connector (fixtures without a class are rejected).
7. Implement **resume and idempotency**: each check has a deterministic run id; interrupted runs resume; evidence is append-only with SHA-256 manifests; reruns create new attempts linked to previous ones; flaky checks are annotated by the failure budget (3 attempts maximum, then FAIL).
8. Implement **report rendering** (`xtask report`): summary tables by phase/area/status, per-check detail with commands, outputs, hashes, environment facts, UNVERIFIED reasons with the remediation each needs from the operator ("what we need from you"), trend versus previous runs, and a claims appendix mapping product claims to evidence ids.
9. Write tests: allowlist violations (HTTP, DNS, raw sockets), rate ceilings, taxonomy enforcement (compile-fail tests for illegal statuses), inspect-first gate behavior, payload class enforcement, resume after crash, evidence manifest verification, and report golden tests with fixtures covering all statuses.
**Deliverables.**
- `hdd-acceptance` v1, catalog (AC-00..AC-54), report renderer, tests, docs `docs/ACCEPTANCE.md`
**Acceptance.**
- A1: every catalog entry exists with id, owner phase, required capabilities and safety class (static test against Appendix E3).
- A2: no network I/O in the crate bypasses the connector (static grep gate and runtime allowlist tests).
- A3: the renderer cannot output PASS without evidence references (test).
- A4: runs resume after being killed mid-check without duplicating destructive actions.
- A5: the report lists UNVERIFIED reasons with operator actions.
**Tests.**
- Unit, compile-fail, integration, golden.
**Notes.** The catalog is the executable form of Appendix E3; the two must stay identical (a CI test compares them).

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
