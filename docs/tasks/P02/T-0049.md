### T-0049 · Rule builder and condition-group components
`P02` `[UI]` · deps: T-0040, T-0044 · size: L · owner: ux
**Objective.** Build the interactive rule composition component used by custom rules, access lists and alert rules.
**Steps.**
1. Define the `Condition` row: field select, operator select (filtered by field type), value input (type-appropriate: text, list, CIDR tags, regex input, country select, number), negate toggle, remove button; each row labelled for screen readers ("Condition 2 of 3").
2. Define groups: AND within a group, OR between groups, explicit visible group labels and add/remove group controls; no hidden precedence.
3. Provide reorder via move up/down buttons (and optional drag with pointer, never required) to satisfy WCAG 2.5.7.
4. Implement server-driven validation: each change posts to a validation endpoint via HTMX and receives row-level diagnostics (position, message) and a human-readable sentence ("Block when the path starts with /admin and the country is not NL").
5. Implement the action selector with consequence text and the scope panel (path pattern, methods, expiry).
6. Implement the sample tester panel (paste a URL or raw request) using the inspect/test endpoint, showing match/no-match explanation.
7. Define serialization: the component posts a canonical JSON representation matching the `match jsonb` schema; versioned.
8. Document accessibility patterns for dynamic add/remove (focus moves to the new row's first field; removal moves focus to the previous row).
**Deliverables.**
- component, templates, CSS, island JS (optional pointer drag), docs, JSON schema for conditions
**Acceptance.**
- A1: every operation is possible by keyboard without drag.
- A2: focus moves predictably on add and remove (browser test).
- A3: the sentence preview matches the structured form for 20 sample rules.
- A4: diagnostics show positions and are associated with rows (`aria-describedby`).
- A5: the JSON schema round-trips with no loss.
**Tests.**
- Browser tests for flows; unit tests for sentence generation and schema round trip; proptest for random valid rules.
**Notes.** Backend validation and evaluation are implemented in T-0228 and T-0248.
