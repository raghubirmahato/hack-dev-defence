### T-0038 · Text inputs, textarea, labels, help and error summary
`P02` `[UI]` · deps: T-0037 · size: M · owner: ux
**Objective.** Build accessible form text controls and the form-level error pattern.
**Steps.**
1. Implement `FormField` (label, optional hint, control slot, error message, `aria-describedby` wiring, required text marker), `TextInput` (types text, email, url, search, tel, number with `inputmode`), `Textarea` with character counter (polite, debounced announcements), and read-only/disabled states.
2. Enforce `autocomplete` tokens in props (enum) to satisfy WCAG 1.3.5 and support password managers.
3. Implement `ErrorSummary` that lists errors with in-page links to fields, receives focus on submit failure, and uses `role="alert"` once.
4. Implement inline validation display (on blur and on submit) driven by server responses (field path to message), never client-only truth.
5. Implement input groups (prefix/suffix such as `https://`, `.example.com`), clear button, and copy-on-focus for read-only values.
6. Implement size variants and density rules.
7. Document patterns: never placeholder-as-label, optional vs required text, long-help disclosure.
8. Implement unit tests for ID generation (stable, unique) and association correctness.
**Deliverables.**
- `components/form_field.rs`, `text_input.rs`, `textarea.rs`, `error_summary.rs`, templates, CSS, docs
**Acceptance.**
- A1: label, hint and error are programmatically associated (axe label and aria rules pass).
- A2: the error summary receives focus and links work with keyboard.
- A3: every input type has the correct `inputmode` and `autocomplete`.
- A4: error text uses text plus icon, not color alone.
- A5: read-only inputs are focusable and copyable.
**Tests.**
- Snapshot tests; browser tests for focus movement; axe on a form gallery page; unit tests for ID uniqueness across fragments.
**Notes.** HTMX partial swaps must keep IDs stable to avoid breaking `aria-describedby` references.
