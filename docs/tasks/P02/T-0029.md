### T-0029 · Brand foundations: name, logo mark, wordmark, favicons
`P02` `[UI][DOC]` · deps: T-0011 · size: M · owner: ux
**Objective.** Establish a simple, ownable identity that works at 16 px and in forced-colors mode, without third-party fonts or raster-only assets.
**Steps.**
1. Write `design/brand/BRAND.md`: name usage ("Hack Dev Defence", short form "HDD"), tone, clear-space rules, minimum sizes, do/don't, and the operator-ownership note (the operator may replace the mark; nothing else depends on its shape).
2. Design the mark as a hand-authored SVG: a shield outline with a stylized request-path notch, using only `currentColor` and one accent via CSS variable so it adapts to themes and forced colors; provide 16, 24, 32, 64 px optical variants.
3. Create the wordmark lockups (horizontal, stacked, icon-only) as SVG with text converted to paths or using the self-hosted font with `font-display` fallback; record how to regenerate them.
4. Generate the favicon set from the SVG by an `xtask ui build` step: `favicon.svg` (with `prefers-color-scheme` handling), `favicon.ico` fallback (16/32/48), `apple-touch-icon.png` (180), maskable PWA icons (192/512) for P32, and a monochrome `safari-pinned-tab.svg`.
5. Create an Open Graph card template rendered at build time (1200x630) as a static asset with the tagline; no raster tools outside Rust (use the `image` crate or render SVG with `resvg` if vetted).
6. Define email header and footer branding that works without remote images (inline CID or text fallback).
7. Add `design/LICENSES.md` stating the mark is original and listing licenses of anything reused.
8. Add the brand name and logo path as profile fields (`branding.product_name`, `branding.logo_path`) consumed by templates, so the operator can rebrand without code changes.
**Deliverables.**
- `design/brand/*.svg`, `design/brand/BRAND.md`, `design/LICENSES.md`
- `xtask ui build` favicon and OG generation
- tests rendering the mark in light, dark and forced-colors mockups
**Acceptance.**
- A1: the mark is legible at 16 px (visual check recorded) and uses no raster data.
- A2: favicon set is generated reproducibly (hash stable across two builds).
- A3: replacing `branding.logo_path` changes the logo everywhere through the template layer without code edits.
- A4: the mark meets 3:1 contrast against both theme backgrounds.
- A5: no external fonts or remote assets are referenced.
**Tests.**
- Snapshot test of the SVG sprite output; build-reproducibility test; contrast test of the mark colors via the token checker.
**Notes.** The operator can supply a real logo later; nothing here blocks on it (UXD default recorded in T-0028).
