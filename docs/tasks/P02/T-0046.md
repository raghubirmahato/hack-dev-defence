### T-0046 · Chart and map visual specification (style, data tables, patterns)
`P02` `[UI]` · deps: T-0030, T-0044 · size: M · owner: ux
**Objective.** Specify the SVG chart family and world map so implementation in P04 is mechanical.
**Steps.**
1. Specify each chart type (line, area, bar, stacked bar, ranked horizontal bar, donut, sparkline, heatmap, choropleth) with anatomy, margins, axis rules, label placement, tick generation, and null/gap handling.
2. Specify pattern fills for color-independent series differentiation and line dash styles.
3. Specify the text summary generation rules (peak, trough, total, change) and the "View as table" alternative.
4. Specify tooltip/crosshair enhancement contract as optional JS reading `data-*` attributes.
5. Specify the map: projection (equirectangular or Robinson simplified), country geometry source (Natural Earth, public domain) simplified by an `xtask` step to a size budget, ISO code mapping, ranked-table alternative, legend with numbers.
6. Define responsive behavior (aspect ratio, label thinning, small-screen simplifications) and print styles.
7. Define performance limits (max points, downsampling algorithm such as largest-triangle-three-buckets with documented parameters).
8. Add a visual test plan (golden SVG snapshots with tolerance).
**Deliverables.**
- `docs/UX/CHARTS.md`, `design/charts/*.toml` parameters, map data build plan
**Acceptance.**
- A1: each chart type has anatomy, margin and label rules.
- A2: the text-summary algorithm is deterministic and specified with examples.
- A3: map data license and size budget are recorded.
- A4: downsampling rules are numeric.
- A5: color-independence is defined for every chart.
**Tests.**
- Spec examples become unit tests in T-0088.
**Notes.** No charting JavaScript library is used (rust-first, budgets).
