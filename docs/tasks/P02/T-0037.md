### T-0037 · Buttons, links and icon buttons
`P02` `[UI]` · deps: T-0034, T-0035 · size: M · owner: ux
**Objective.** Implement the foundational interactive controls with complete states.
**Steps.**
1. Define the `Button` props: label (i18n key), variant (primary, secondary, ghost, danger, link), size (compact 32, default 40, large 48), icon (optional, leading/trailing), loading, disabled (with reason), full-width, `type` (submit/button/reset), `form`, and `aria-*` passthrough limited to an allowlist.
2. Implement CSS states: hover, active, focus-visible ring (2 px, offset 2 px, 3:1), disabled (still readable), loading (spinner or static text, `aria-busy="true"`, width preserved).
3. Implement `IconButton` requiring a label; render tooltip text through the accessible name, not `title`.
4. Implement `LinkButton` semantics: a real `<a>` styled as a button for navigation; `<button>` only for actions.
5. Implement external link treatment (icon plus `rel="noopener noreferrer"`) and `aria-current` handling for nav links.
6. Implement the danger variant using `--danger-solid` with 4.5:1 white text, and the primary variant using `--brand`/`--on-brand`.
7. Implement the HTMX-aware loading state (`hx-indicator` hooks) without JavaScript dependence for the base state.
8. Write the keyboard map (Enter/Space activation) and ARIA contract docs; add disabled-reason pattern (`aria-describedby` + visible text).
**Deliverables.**
- `components/button.rs`, `icon_button.rs`, `link.rs`, templates, CSS, docs, snapshot tests
**Acceptance.**
- A1: every variant meets 4.5:1 text and 3:1 boundary contrast in both themes (checker).
- A2: icon-only button without a label cannot be constructed.
- A3: min target size 40 px default, never below 24 px.
- A4: the loading state preserves width and announces busy.
- A5: buttons remain operable and visible in forced colors.
**Tests.**
- Snapshot tests of all variants; browser focus ring visibility test; axe; forced-colors screenshot.
**Notes.** Disabled controls must explain themselves when the reason is a permission or plan limit.
