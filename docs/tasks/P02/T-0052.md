### T-0052 · Design system release, visual baselines and gate G02
`P02` `[UI][QA][DOC]` · deps: T-0047, T-0048, T-0049, T-0050, T-0051 · size: M · owner: ux
**Objective.** Freeze design system v1.0, record visual baselines and pass the phase gate.
**Steps.**
1. Run `cargo xtask ui build` and `cargo xtask ui verify` (tokens, contrast, lint, budgets, gallery, axe, screenshots).
2. Create visual-regression baselines for the gallery across the viewport matrix and themes; store baseline images in `design/baselines/` (compressed PNG, size budget) with a reviewer note.
3. Write `design/CHANGELOG.md` and tag design system `v1.0.0`; define the process for changes (spec update, token update, gallery update, baseline update with reviewer).
4. Run the complete accessibility checklist for components: keyboard maps documented, ARIA contracts, forced colors, reduced motion.
5. Produce the operator review pack: screenshots of the gallery (light/dark), token tables, and a short list of decisions needed (logo, fonts).
6. Paste real outputs (contrast report, axe summary, budgets, test counts) into `docs/gates/G02.md` using the Appendix E5 format.
7. Update the capability matrix for REQ-DSN rows and `STATUS.md`.
8. Tag `gate-G02`.
**Deliverables.**
- `design/baselines/*`, `design/CHANGELOG.md`, `docs/gates/G02.md`
**Acceptance.**
- A1: contrast report has zero failures; axe gallery report has zero serious or critical findings.
- A2: CSS and JS budgets are within limits (reported).
- A3: all components in B11.8 are implemented with documented keyboard maps.
- A4: visual baselines exist for dark, light, high-contrast and the viewport matrix.
- A5: the gate report is complete and the tag exists.
**Tests.**
- The full `xtask ui verify` run captured with SHA-256 of logs.
**Notes.** Later visual changes must update baselines intentionally with reviewer notes.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
