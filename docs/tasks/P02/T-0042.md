### T-0042 · Overlays: dialog, drawer, confirm dialog, popover, tooltip, dropdown menu
`P02` `[UI][SEC]` · deps: T-0041 · size: L · owner: ux
**Objective.** Implement overlays with correct focus management and safe confirmation patterns.
**Steps.**
1. `Dialog` built on native `<dialog>` with `showModal()`: labelled by heading, `aria-describedby` for body, focus moves to the first meaningful element or the safe action, `Escape` closes, focus returns to the invoker, background inert; no-JS fallback navigates to a full page route.
2. `Drawer` (side panel) with the same semantics, used by event detail (S-066) and navigation on small screens; deep-linkable by URL.
3. `ConfirmDialog` with consequences list, optional type-to-confirm (exact resource name, paste allowed), default focus on the safe action, destructive button disabled until confirmed, and optional "Run as dry-run first" link for self-lockout cases.
4. `Popover` (non-modal) with focus management and Esc, `aria-expanded` on the trigger.
5. `Tooltip` for supplemental description only (never required), shown on hover and focus, dismissible, hoverable, persistent (WCAG 1.4.13), referenced via `aria-describedby`.
6. `Menu` (button + menu) with roving tabindex, type-ahead, `aria-haspopup`, `Home/End`, and close on Tab.
7. Implement stacking rules (z-index tokens) and scroll locking without layout shift (scrollbar-gutter).
8. Document anti-patterns (modal inside modal, autoplay dialogs, hover-only tooltips).
**Deliverables.**
- components, CSS, small island JS modules for popover/menu positioning (CSS anchor positioning when available, JS fallback), docs
**Acceptance.**
- A1: focus is trapped inside modals and returns on close (browser test).
- A2: type-to-confirm requires the exact name and blocks the destructive action otherwise.
- A3: tooltips satisfy 1.4.13 (dismissible, hoverable, persistent).
- A4: menus support full keyboard navigation and Escape.
- A5: dialogs work without JavaScript through route fallbacks for critical flows.
**Tests.**
- Browser tests for focus management and keyboard; axe; unit tests for type-to-confirm logic server-side.
**Notes.** ConfirmDialog is the only component allowed to render destructive primary buttons.
