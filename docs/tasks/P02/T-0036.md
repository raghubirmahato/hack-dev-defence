### T-0036 · Layout primitives and the application frame
`P02` `[UI]` · deps: T-0035 · size: M · owner: ux
**Objective.** Provide composable layout primitives and the page frames used by all surfaces.
**Steps.**
1. Implement primitives as CSS classes with component wrappers: `Stack`, `Cluster`, `Grid` (auto-fit with min width), `Sidebar` layout, `Switcher`, `Cover`, `Container` (max widths 1280 and 1100), `Center`, `Frame` for aspect ratio.
2. Implement the app frame: skip link, header (56 px), sidebar (240/64 px) with collapsed state, main with `scroll-padding-top` for sticky headers (focus not obscured), complementary region, footer.
3. Implement the public frame (marketing header/footer) and the auth frame (centered card with brand).
4. Implement the admin frame variant with the persistent "Platform admin" band using the `admin-banner` copy and a distinct accent token.
5. Implement responsive behavior: below 1024 px the sidebar becomes an off-canvas drawer (using the Drawer component later); the frame supports `inert` on background when open.
6. Implement landmark roles and labels; ensure heading hierarchy rules (one `h1` per page, enforced by the page header component).
7. Provide print layout variants (hide navigation, expand content).
8. Document usage examples and anti-patterns.
**Deliverables.**
- `crates/hdd-ui/src/layout/*.rs`, templates, CSS, docs
**Acceptance.**
- A1: the three frames render with correct landmarks (axe landmark rules pass).
- A2: the skip link is the first focusable element and works.
- A3: no horizontal page scroll at 360 px for any frame.
- A4: sticky header does not obscure focused elements (scroll-padding test).
- A5: the admin frame is visually distinct and passes contrast.
**Tests.**
- Browser tests at 360/768/1280 for the frames; axe; keyboard traversal order test.
**Notes.** Frames take their navigation items as data so permission filtering happens before rendering.
