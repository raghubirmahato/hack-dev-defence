### T-0050 · Theming runtime, high-contrast and forced-colors support
`P02` `[UI]` · deps: T-0030, T-0048 · size: S · owner: ux
**Objective.** Make theme switching robust, instant and accessible.
**Steps.**
1. Define the `data-theme` attribute states (`system`, `dark`, `light`) and server-side first paint from the cookie and account setting.
2. Add a high-contrast preference (`data-contrast="more"`) honoring `prefers-contrast: more`: increase border contrast, remove translucency, strengthen focus rings; define the token overrides.
3. Add forced-colors tests: every component retains boundaries, focus and state indication using system colors and outlines.
4. Ensure images and SVGs adapt (`currentColor`, `forced-color-adjust` where appropriate).
5. Define color-scheme meta tags and `color-scheme` CSS for form controls and scrollbars.
6. Document how to test themes (harness helper that emulates `prefers-color-scheme`, `prefers-contrast`, `forced-colors`).
7. Add visual regression coverage plan for theme matrix.
8. Verify print uses light theme tokens regardless of the current theme.
**Deliverables.**
- token overrides, CSS layer additions, harness emulation helpers, docs
**Acceptance.**
- A1: gallery renders correctly in dark, light, high contrast and forced colors (screenshots stored).
- A2: no component loses state indication in forced colors (assertions on borders/outlines).
- A3: print output uses the light theme.
- A4: no flash of the wrong theme on load.
- A5: contrast checker covers the high-contrast overrides.
**Tests.**
- Browser emulation tests; contrast checker extension tests.
**Notes.** High-contrast overrides count toward the CSS budget.
