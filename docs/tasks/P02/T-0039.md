### T-0039 · Selection controls: checkbox, radio, switch, select, segmented control
`P02` `[UI]` · deps: T-0038 · size: M · owner: ux
**Objective.** Provide accessible selection controls built on native elements.
**Steps.**
1. Implement `Checkbox` and `CheckboxGroup` (fieldset/legend), indeterminate state via `aria-checked="mixed"` for parent selections, and large click areas.
2. Implement `Radio` and `RadioCards` (card-style options for integration mode and presets, each with title, description, badge, and disabled-reason) using real radio inputs and a visible focus ring around the card.
3. Implement `Switch` as `input[type=checkbox][role=switch]` with visible "On/Off" text and support for confirm-before-toggle for dangerous settings.
4. Implement `Select` using a native `select` styled consistently, with option groups and a disabled placeholder pattern.
5. Implement `SegmentedControl` (radio group semantics) for mode choices (monitor/log/block).
6. Provide consequence text slots (`aria-describedby`) for security-relevant options.
7. Ensure touch target sizing and spacing in groups.
8. Document keyboard maps (Space toggles, arrows within radio groups).
**Deliverables.**
- component code, templates, CSS, docs, snapshot tests
**Acceptance.**
- A1: groups expose legend and role relationships (axe).
- A2: RadioCards are fully keyboard-operable and announce description.
- A3: the switch exposes state text and is not color-dependent.
- A4: indeterminate checkboxes announce mixed state.
- A5: all controls pass the 24 px minimum target and the 40 px default.
**Tests.**
- Snapshot tests; keyboard traversal tests; forced-colors screenshot test.
**Notes.** The mode selector uses SegmentedControl plus a consequences panel, not a dropdown.
