### T-0041 · Feedback components: toast, banner, inline message, progress, spinner, skeleton, empty and error states
`P02` `[UI]` · deps: T-0037 · size: M · owner: ux
**Objective.** Make system feedback consistent, polite and non-blocking.
**Steps.**
1. `Toast` stack with polite/assertive regions, minimum 8 s display, pause on hover and focus, undo action slot, dismiss button, queue limit of 3 visible, and server-driven creation through the `HX-Trigger` contract (T-0084).
2. `Banner`/`Alert` variants (info, success, warning, danger), optional action, dismissible only for non-critical, `role` mapping.
3. `InlineMessage` for field/section feedback with icon+text.
4. `ProgressBar` (determinate/indeterminate), `Spinner` (with text), and `Skeleton` (text, card, table row) with reduced-motion variants and a delayed-appearance rule (show after 300 ms).
5. `EmptyState` (title, explanation, primary action, secondary link, decorative illustration slot) and `ErrorState` (message, request ID chip, retry action).
6. `OfflineBanner` pattern placeholder for connectivity loss.
7. Document usage rules: toasts never carry the only copy of an error; banners for persistent states; skeleton thresholds.
8. Provide server helpers to build these from `Problem` responses (RFC 9457) consistently.
**Deliverables.**
- components, CSS, docs, snapshot tests, `Problem`-to-UI helpers
**Acceptance.**
- A1: toasts do not steal focus and are announced once.
- A2: banners expose correct roles and meet contrast in both themes.
- A3: skeletons are static under reduced motion.
- A4: the error state shows the request ID and a retry control that works without JS via a link or form.
- A5: no component uses color alone to convey state.
**Tests.**
- Browser tests for announcement behavior (via accessibility tree snapshot), delayed skeleton test, axe.
**Notes.** The toast contract fields are documented for T-0084.
