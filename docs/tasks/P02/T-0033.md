### T-0033 · Motion tokens and reduced-motion behavior
`P02` `[UI]` · deps: T-0032 · size: S · owner: ux
**Objective.** Make motion purposeful and safe.
**Steps.**
1. Create `design/tokens/motion.toml` with durations and easings from B11.5 and generate CSS properties.
2. Write the global reduced-motion layer: `@media (prefers-reduced-motion: reduce)` sets transition and animation durations to 0 except opacity fades up to 80 ms, disables parallax and auto-scrolling, replaces spinners with static text.
3. Define which components animate and how: dialog open/close, drawer slide, toast enter/exit, accordion, readiness ring fill, skeleton shimmer (static under reduced motion), chart draw (none by default).
4. Ban flashing content: no element changes luminance more than three times per second (lint on keyframes and review).
5. Provide a user preference "Reduce motion" in the profile that overrides the system setting in both directions where permitted.
6. Add a motion test utility in the harness to emulate reduced motion and assert computed durations.
7. Document performance rules (animate only `opacity` and `transform`, avoid layout thrash).
8. Add motion usage to the component docs.
**Deliverables.**
- `design/tokens/motion.toml`, `motion.css`, harness helper
**Acceptance.**
- A1: with reduced motion emulated, no transition duration exceeds 80 ms in the gallery (assert on computed styles).
- A2: skeletons and spinners have static equivalents.
- A3: a keyframe lint rejects animations that animate layout properties.
- A4: the profile preference overrides correctly.
- A5: no animation starts on page load without user action except permitted progress indicators.
**Tests.**
- Browser tests emulating `prefers-reduced-motion`; CSS lint unit tests.
**Notes.** Reduced-motion users must lose nothing functionally.
