### T-0034 · Icon system and SVG sprite pipeline
`P02` `[UI]` · deps: T-0032 · size: M · owner: ux
**Objective.** Provide a consistent, accessible, license-clean icon set without runtime requests per icon.
**Steps.**
1. Choose a permissively licensed icon set (ISC or MIT; record the license text and version in `design/LICENSES.md` and an ADR) and vendor only the icons needed.
2. Draw the custom icons needed that do not exist: `cloud-orange` (proxied), `cloud-grey` (DNS only), `ray-id`, `ban-ip`, `shield-sql`, `nameserver`, with the same grid and stroke.
3. Implement `xtask ui build` sprite generation: one SVG with `<symbol>` entries, ids `i-<name>`, normalized viewBox 24, stroke `currentColor`, optimized with a Rust-based minifier.
4. Create the `Icon` component (name enum generated from the sprite so unknown icons fail to compile), size variants 16 and 20, `aria-hidden` default, with an optional accessible label that switches to `role="img"`.
5. Provide RTL mirroring flags for directional icons.
6. Generate an icon gallery for the design system with names and usage notes.
7. Add a lint that rejects inline `<svg>` in templates except via the component and chart kit.
8. Budget: the sprite must be at most 25 KB gzip; unused icons are tree-shaken by a usage scan.
**Deliverables.**
- `crates/hdd-ui/assets/icons/*.svg`, generated `sprite.svg`, `Icon` component
- ADR for the icon set
**Acceptance.**
- A1: an unknown icon name is a compile error.
- A2: every icon in the required list of B11.6 exists.
- A3: the sprite meets the size budget after tree shaking.
- A4: icon-only buttons require a label (type-level or runtime error).
- A5: custom cloud icons are distinguishable without color (shape/pattern).
**Tests.**
- Compile-fail test for unknown icon; snapshot test of sprite; unit test for RTL mirroring list.
**Notes.** The cloud icons also appear in documentation; keep the source SVGs.
