### T-0043 · Navigation components: sidebar, top bar, tabs, breadcrumbs, pagination, stepper, switchers
`P02` `[UI]` · deps: T-0036, T-0042 · size: L · owner: ux
**Objective.** Implement wayfinding components according to the navigation spec.
**Steps.**
1. `Sidebar` (items, groups, badges, collapsed icon mode with tooltips, `aria-current`, permission-filtered data), `TopBar` (slots for switchers, search, bell, theme, user menu).
2. `Tabs` with URL-backed state (links with `aria-current`) and optional ARIA tabs pattern for in-page panels (roving tabindex, automatic or manual activation by prop).
3. `Breadcrumbs` (`nav aria-label`, last item `aria-current`, truncation with menu).
4. `Pagination` (cursor-based previous/next, page size select, counts, URL state).
5. `Stepper`/`Wizard` (ordered list, step status, URL per step, back/next, resume, leave-guard text, "why we ask" slot).
6. `OrgSwitcher` and `DomainSwitcher` combobox patterns (type-ahead, recent, empty state).
7. Provide mobile variants (drawer navigation, bottom action bar for wizards).
8. Document keyboard maps and focus movement on navigation (focus the page `h1` after full navigations).
**Deliverables.**
- components, templates, CSS, docs
**Acceptance.**
- A1: tabs and stepper expose correct semantics and keyboard behavior.
- A2: sidebar collapsed mode remains operable with labels via tooltip and accessible names.
- A3: breadcrumbs pass axe and handle long names.
- A4: pagination preserves filters in links.
- A5: wizard steps are individually linkable and resumable.
**Tests.**
- Browser keyboard tests; axe; snapshot tests; unit tests for the combobox filtering and highlight logic (server-side).
**Notes.** Domain and org switchers must not leak other tenants' names (filtering happens server-side by membership).
