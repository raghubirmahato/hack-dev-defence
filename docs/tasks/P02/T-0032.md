### T-0032 · Spacing, size, radius, elevation, z-index tokens and the token build pipeline
`P02` `[UI]` · deps: T-0030 · size: S · owner: ux
**Objective.** Finish the token set and make `xtask ui build` the only producer of generated design assets.
**Steps.**
1. Create `design/tokens/space.toml`, `size.toml`, `radius.toml`, `elevation.toml`, `zindex.toml`, `breakpoint.toml` with the values of B11.4.
2. Implement the generator that emits custom properties, container-query-friendly breakpoint constants, and Rust constants for server-side layout calculations (chart sizes).
3. Provide logical-property utilities (`margin-inline`, `padding-block`) to support RTL.
4. Define elevation per theme (dark relies on surface tint plus border; light uses shadow) and test that popovers remain distinguishable in forced colors (outline).
5. Implement a token documentation page generator for the gallery (T-0047).
6. Create `xtask ui build` orchestration: tokens, fonts, sprite, CSS bundle, JS bundle, hash-named outputs, and the asset manifest (`assets.json`) with SRI hashes.
7. Make the build deterministic and cached (skip when inputs unchanged).
8. Add budget reporting (CSS and JS gzip sizes) with thresholds from Part A.
**Deliverables.**
- `design/tokens/*.toml`, generator code, `assets.json` manifest format
- documentation of token usage
**Acceptance.**
- A1: `cargo xtask ui build` twice produces byte-identical outputs.
- A2: the manifest contains SRI hashes and is consumed by the template layer.
- A3: a token removed from TOML but used in CSS fails the build (unknown token lint).
- A4: logical properties are used in the generated utilities.
- A5: budgets are reported even when passing.
**Tests.**
- Golden tests for generated CSS; unit tests for manifest hashing; determinism test.
**Notes.** The manifest is the only way templates reference assets (cache-busting and SRI).
