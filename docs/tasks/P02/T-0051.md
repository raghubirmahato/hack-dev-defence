### T-0051 · Print stylesheet and report/PDF styles
`P02` `[UI]` · deps: T-0044, T-0050 · size: S · owner: ux
**Objective.** Make reports and audit exports print and PDF cleanly.
**Steps.**
1. Create `print.css` (layer `utilities`): hide navigation and interactive controls, expand collapsed sections, force light tokens, set page margins and sizes (A4/Letter by locale), `break-inside: avoid` for cards and chart figures, repeat table headers across pages.
2. Define the report template skeleton: cover block (org, period, generated at, version), summary KPIs, sections with charts (SVG), tables, appendix, and the honest footnote on measurement limits.
3. Define page numbering and headers/footers (CSS paged media where supported, fallback via the PDF renderer options).
4. Define link handling in print (show URLs for external links in an appendix list).
5. Provide a test route that renders a sample report fixture used by the PDF pipeline (T-0448).
6. Ensure the charts print in grayscale-safe patterns.
7. Document accessibility of generated PDFs (tagged PDF considerations; if the PDF path cannot produce tagged PDFs, state the limitation and offer HTML export as the accessible alternative).
8. Add print tests to the harness (emulate print media and take PDF).
**Deliverables.**
- `print.css`, report skeleton template, docs
**Acceptance.**
- A1: navigation and controls are hidden in print emulation.
- A2: table headers repeat and charts do not split across pages in the sample report.
- A3: print uses light tokens.
- A4: the PDF accessibility limitation (if any) is documented and surfaced in the report UI.
- A5: external links are listed in an appendix.
**Tests.**
- Browser print/PDF generation test and a visual check of the PDF pages (image diff against baseline).
**Notes.** The PDF generation pipeline itself is built in T-0448.
