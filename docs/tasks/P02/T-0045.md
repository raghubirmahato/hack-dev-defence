### T-0045 · Security-domain components: Ray ID, IP chip, countdown, payload viewer, readiness ring, cloud toggle, nameserver card, verification poller
`P02` `[UI][SEC]` · deps: T-0044 · size: L · owner: ux
**Objective.** Build the product-specific components with strict safety properties.
**Steps.**
1. `RayIdChip`: validates the `16hex-HDD1` format, monospace, copy button, link to event; invalid values render as plain text.
2. `IpChip`: IP with textual country code and optional flag (decorative), ASN label, actions menu (ban, allow, lookup, copy), IPv6 /64 key note, and collateral-risk badge slot.
3. `CountdownBadge`: server-rendered remaining time with a small island updating every second only when visible; static text for reduced motion and screen readers (updates announced no more than every 30 s).
4. `PayloadViewer`: renders redacted evidence as escaped text in a `pre`, highlights the matched span using background plus underline, indicates the 512-byte cap, never interprets HTML, and offers copy of the escaped text.
5. `ReadinessRing`: SVG ring with textual score, status text and list; the aria label announces "Protection readiness N out of 100"; includes the footnote slot.
6. `CloudToggle`: two-state control labeled "Proxied" and "DNS only" with icons and a consequence popover; server confirms and shows the resulting answer set.
7. `NameserverCard` and `VerificationPoller`: copy fields, status text, last/next check times, polite live region, manual "Check now" respecting rate limits.
8. Write abuse-case tests: HTML/JS payloads in `PayloadViewer`, extremely long unbroken strings, bidirectional control characters (rendered visibly and neutralized), and homoglyph hostnames (punycode shown alongside).
**Deliverables.**
- components, CSS, small islands, docs, tests
**Acceptance.**
- A1: XSS payloads in `PayloadViewer` never execute and render as escaped text (browser test with CSP violation trap).
- A2: bidi control characters are visibly neutralized.
- A3: readiness ring's text alternative contains the score and footnote.
- A4: the cloud toggle has a non-color distinction and a consequence description.
- A5: poller announcements are polite and rate-limited.
**Tests.**
- Browser tests with hostile strings; snapshot tests; axe; fuzz target for the escaping function.
**Notes.** This component set is the main defense against stored XSS from attacker-controlled event data (ATK-297).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
