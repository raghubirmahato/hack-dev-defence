### T-0047 · Component gallery, documentation standard and the browser smoke harness v0
`P02` `[UI][QA]` · deps: T-0037, T-0045 · size: L · owner: ux
**Objective.** Make every component reviewable and testable in one place, and start browser-based checks early.
**Steps.**
1. Implement `xtask ui gallery` that renders every component with all states, in dark and light, to static HTML under `target/ui-gallery/` (never shipped), including usage text, ARIA contract, keyboard map and do/don't from component docs.
2. Add a component documentation standard (`docs/UX/components/<name>.md` generated from doc comments): anatomy, props table, states, a11y contract, keyboard map, security notes.
3. Implement browser smoke harness v0 using `chromiumoxide`: launch headless Chromium from the preinstalled path, load a static file or URL, capture console errors and failed requests, take screenshots, and run the vendored `axe-core` oracle (checksum recorded; test-only).
4. Run axe against every gallery page in both themes and write `acceptance-ui/axe-gallery.json` (violations by impact).
5. Add screenshot capture for the viewport matrix of T-0024 into `acceptance-ui/screens/` with stable naming; baselines are created in T-0052.
6. Implement a CSP-violation trap in the harness (listens for `securitypolicyviolation`) and a network trap listing all requests (fails on any off-origin request).
7. Make the gallery a served route `/admin/design-system` later (T-0094) by sharing the same renderer.
8. Document how to add a component to the gallery and how to run the harness.
**Deliverables.**
- `xtask ui gallery`, `crates/hdd-xtask/src/browser/*`, vendored `axe.min.js` with checksum and license note, docs
**Acceptance.**
- A1: every component in B11.8 appears in the gallery with all declared states.
- A2: axe runs on all gallery pages and the JSON report is generated.
- A3: the harness fails the run on console errors, CSP violations or off-origin requests.
- A4: screenshot files are produced for the full viewport matrix.
- A5: documentation pages are generated for each component.
**Tests.**
- Harness self-tests with deliberately broken pages (missing label, inline script) proving detection.
**Notes.** The harness is extended (not replaced) in T-0089 to T-0093.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.
