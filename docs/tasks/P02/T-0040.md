### T-0040 · Advanced inputs: password, OTP, tag input, copy field, file dropzone, restricted regex input
`P02` `[UI][SEC]` · deps: T-0038 · size: L · owner: ux
**Objective.** Implement the security-sensitive inputs with accessible, safe behavior.
**Steps.**
1. `PasswordInput`: show/hide button (`aria-pressed`), paste always allowed, `autocomplete` `current-password`/`new-password`, strength meter (`role="meter"` with text label), rule checklist (length, not breached, not common), and a note that no composition rules are required; the meter receives its verdict from the server estimator (T-0106) via HTMX with debounce, never from client heuristics alone.
2. `OtpInput`: single input, `inputmode="numeric"`, `autocomplete="one-time-code"`, `pattern`, auto-submit option off by default, accessible hint about the code source.
3. `TagInput` for IPs/CIDRs/hostnames: commit on Enter/comma/space/paste, per-tag validation messages, removal by keyboard (Backspace/Delete on focused tag), max count, accessible list semantics, and a textual summary ("3 values") for screen readers.
4. `CopyField` with copy button, success announcement via polite live region, fallback selection if Clipboard API unavailable.
5. `FileDropzone`: button-first, drag-and-drop optional, type/size hints, client-side checks for UX, progress, error states, and server authority; limit multiple files by prop.
6. `RegexInput`: monospace input with the server-validated restricted syntax (no lookaround/backreference), inline diagnostics list with positions, never executes the regex client-side.
7. Add secret-value handling: values never rendered into the DOM unless the user reveals them, `autocomplete="off"` where appropriate, and no logging in HTMX events.
8. Document threat considerations (shoulder surfing, clipboard, autofill) per input.
**Deliverables.**
- component code, templates, CSS, islands JS (copy, password toggle; each under budget), docs
**Acceptance.**
- A1: password paste is possible and password managers can fill (autocomplete tokens verified).
- A2: the strength meter's text and role are announced and not color-only.
- A3: tag input is fully keyboard-operable and announces additions/removals.
- A4: copy success is announced politely and the secret value is not duplicated in hidden DOM.
- A5: regex diagnostics come from the server and include positions.
**Tests.**
- Browser tests for each input (keyboard flows, paste, announcements); axe; unit tests for tag parsing of messy pasted lists.
**Notes.** Client JS for these inputs is progressive enhancement; core submission works without it.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
