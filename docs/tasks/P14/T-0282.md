### T-0282 · SQLi shield UI integration: subtype toggles, strictness, payload tester wiring
`P14` `[UI][API]` · deps: T-0224, T-0272, T-0273 · size: M · owner: ui
**Objective.** Complete the user-facing shield controls with live engine behavior.
**Steps.**
1. Wire the S-057 subtype toggles to the policy document and the engine (disabling a subtype removes its rules from the compiled set for that site with Paranoid constraints enforced).
2. Wire the strictness selector (Balanced/Paranoid) to the preset logic, showing the exact diff of what changes (including password-field H2 hardness, soft-score repeat bans, auth endpoint rate limits).
3. Wire the "Try a payload" tool to the inspect API (T-0260) with the six mandated quick-fills, field-kind selection and vector selection, rendering subtype explanations and ban preview.
4. Implement the code-friendly and shared-address options (explained, with warnings).
5. Implement import of the user's own payload lists for testing (up to 200 lines, dry-run only, results table) for owners who want to test their own cases; rate-limited and sanitized.
6. Implement links from events (S-066) to the tool with the payload shape prefilled when the evidence is shown.
7. Add e2e tests: toggle subtype → dry-run changes accordingly → revision created → rollback restores.
8. Review copy against claims policy.
**Deliverables.**
- UI wiring, tests
**Acceptance.**
- A1: disabling the tautology subtype makes dry-run of M1/M2/M6 pass unless another family matches (and Paranoid prevents disabling).
- A2: the six quick-fills each return blocked with correct subtype under Balanced.
- A3: strictness diffs are shown before applying.
- A4: bulk payload testing is capped and rate limited.
- A5: all copy passes claims-lint.
**Tests.**
- Browser e2e; integration; accessibility.
**Notes.** Disabling hard subtypes is discouraged by prominent warnings in Balanced.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
