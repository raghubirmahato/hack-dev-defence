### T-0263 · SQL tokenizer with dialect awareness
`P14` `[DP][SEC]` · deps: T-0242, T-0262 · size: XL · owner: waf
**Objective.** Tokenize attacker-controlled text as SQL would see it, in several starting contexts, without depending on a database.
**Steps.**
1. Define token classes: `Keyword`, `Function`, `Operator`, `Number`, `String` (single, double, backtick, `$$`, `N'...'`, `E'...'`, `X'...'`), `Identifier`, `Comment` (`--`, `#`, `/* */`, `/*! */` unwrapped by the canonical view), `Punct` (`;`, `,`, `(`, `)`), `Variable` (`@x`, `@@x`, `$1`, `:name`), `Whitespace`, `Unknown`, plus a synthetic `BreakoutQuote` token representing a quote that closes an assumed enclosing string.
2. Implement the tokenizer as a hand-written, allocation-light lexer over `&str`/bytes with bounded steps (maximum tokens 2,048 per field; beyond that flag `ParserLimit`), handling dialect differences: MySQL/MariaDB (backslash escapes, `#`, `--` requiring whitespace, `/*!`), PostgreSQL (`$$`, `E''`, `::`, `||`), MSSQL (`[ident]`, `--`, `;`, `+` concat, `@@`, `0x`), Oracle (`||`, `q'[...]'`, `dual`), SQLite (`[ident]`, double-quote identifiers, `||`), ANSI baseline.
3. Evaluate three **starting contexts** per input: `none` (as if in an unquoted numeric position), `single_quote` (as if the value is inside `'...'`), `double_quote` (inside `"..."`), plus `backtick` for MySQL identifiers; for the quote contexts, the first matching closing quote becomes a `BreakoutQuote` and tokenization continues in normal mode, which is how `' OR 1=1--` is understood.
4. Provide keyword/function tables per dialect with a compact perfect-hash lookup, categorized (boolean connectors, set operators, DML/DDL, time/delay functions, metadata names, string/hex functions).
5. Provide token stream helpers: reduced token codes (a short alphabet used by fingerprints), position mapping back to the `decoded` view for evidence spans, and a streaming iterator to avoid allocating vectors on hot paths.
6. Document the design with a table of sample inputs and resulting token sequences for each mandated payload in each context.
7. Write 400 table tests across dialect features and 200 adversarial inputs (unterminated strings/comments, nested quotes, huge numbers).
8. Fuzz the tokenizer for panics and quadratic behavior.
**Deliverables.**
- `hdd-waf-core::sql::tokenizer`, tables, docs, tests, fuzz target
**Acceptance.**
- A1: `' OR 1=1--` tokenizes in `single_quote` context as BreakoutQuote, OR, Number, Operator, Number, Comment.
- A2: `admin' --`, `admin' #`, `admin'/*` produce Identifier, BreakoutQuote-or-Quote, Comment tokens in the relevant contexts.
- A3: tokenization is linear time on adversarial inputs (property test with measured scaling).
- A4: token and step caps produce `ParserLimit` flags instead of panics or long loops.
- A5: tables cover all five dialects with at least 60 cases each.
**Tests.**
- Table (400) / adversarial (200) / proptest (scaling) / fuzz.
**Notes.** The tokenizer is an original implementation; no third-party SQLi library code is copied.
