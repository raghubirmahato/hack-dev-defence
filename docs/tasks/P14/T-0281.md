### T-0281 · SQLi metrics, events and analytics
`P14` `[API][UI]` · deps: T-0273, T-0140 · size: M · owner: api
**Objective.** Make the shield's activity visible in dashboards and APIs.
**Steps.**
1. Implement metrics `MET-hdd_sqli_hard_hits_total{subtype,vector,field_kind}`, `MET-hdd_sqli_bans_total{subtype}`, `MET-hdd_sqli_cross_site_nobans_total`, `MET-hdd_auth_endpoint_attacks_total{kind}`, plus soft-hit counters, with bounded label cardinality.
2. Extend rollups with SQLi dimensions (`category=sqli`, `subtype`) and path groups, and implement query services for the security overview and analytics screens.
3. Implement the event detail enrichments for SQLi: subtype explanation text (benign wording), field kind, vector, policy branch, "what happens next" ladder info, and links to docs.
4. Implement the SQLi panel in S-057 (counts per subtype, last 7 days, targeted endpoints) and S-054 widgets.
5. Implement alert triggers: spike of SQLi hard hits (z-score vs baseline), SQLi against auth endpoints from many IPs (campaign), possible auth bypass tripwire.
6. Implement export of SQLi events with evidence.
7. Add tests with seeded events through the ingestion path.
8. Document the metrics for operators.
**Deliverables.**
- metrics, rollup extensions, UI panels, alert triggers, tests
**Acceptance.**
- A1: counters match the number of generated hard hits in integration tests.
- A2: label cardinality stays bounded under adversarial parameter names (test).
- A3: alert triggers fire exactly once per spike (dedupe).
- A4: event details contain no unredacted payloads.
- A5: UI panels pass axe and show Unknown states with no data.
**Tests.**
- Integration; unit: spike detection (proptest); browser: panels.
**Notes.** The campaign alert uses the campaign detector from P16 when available.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
