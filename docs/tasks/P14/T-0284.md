### T-0284 · SQL injection shield gate G14
`P14` `[QA][DOC]` · deps: T-0275, T-0276, T-0277, T-0280, T-0281, T-0282, T-0283 · size: M · owner: qa
**Objective.** Certify the SQL injection shield at engine and proxy level.
**Steps.**
1. Run `xtask verify`, mutation tests for the SQLi modules, fuzz smoke, benign gate, matrix tests, held-out evaluation, fixture reports.
2. Run the sqlmap monitor-mode campaign if the lab is available; otherwise record `UNVERIFIED(capability_not_supplied)` and what the operator must supply.
3. Measure detection latency impact and overall inspection p50/p99 with the SQLi modules enabled.
4. Review all rules' examples/counter-examples and the near-miss report.
5. Compile the gate report (Appendix E5) with detection rates, false-positive counts, mutation score, benchmarks, campaign results.
6. Update the capability matrix (REQ-SQLI) and STATUS; update S-003 evidence data.
7. List open risks (bypass classes found, password H2 policy, second-order limits).
8. Tag `gate-G14`.
**Deliverables.**
- `docs/gates/G14.md`
**Acceptance.**
- A1: mandated set and core variants 100% hard; held-out ≥ 95% (or diagnosis with plan).
- A2: zero false positives on the benign corpora.
- A3: SQLi mutation score ≥ 80%; fuzz smoke clean.
- A4: inspection latency budgets still met.
- A5: gate report complete; tag exists.
**Tests.**
- Full outputs attached.
**Notes.** The end-to-end ban proof arrives after P16.
