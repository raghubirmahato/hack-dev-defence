### T-0276 · Write-path hardening and second-order injection mitigation
`P14` `[DP][SEC]` · deps: T-0272 · size: M · owner: waf
**Objective.** Reduce stored-payload risks (stored SQL, XSS, template payloads) at the point where data enters the origin.
**Steps.**
1. Define "write requests": POST/PUT/PATCH/DELETE bodies and query parameters on those methods; apply stricter policy on **storage-likely fields** (free text, names, titles, bios, comments, addresses) with lowered soft thresholds (-1) and hard-family strictness (no `code_friendly` relaxation for names/titles).
2. Implement the **no-prefix-skip** rule: write requests under the shield are always inspected fully up to the field cap (no early exit on benign-looking prefixes).
3. Implement second-order indicators: payloads that are harmless in the first request but contain SQL control sequences destined for later concatenation (quote + comment markers in stored fields like display names) are flagged soft 3 with subtype `second_order_write` and event tags for analysts.
4. Implement outbound cross-check (links to P21): responses that echo previously stored suspicious content (DB error strings or script payloads) raise `data_leak`/`xss_stored_response` signals.
5. Implement policy options: `reject_suspicious_writes` (block soft second-order indicators) default off in Balanced and on in Paranoid.
6. Add UI controls (S-057) and explanations of residual risk.
7. Write tests with write-path fixtures (profile updates, comments).
8. Link ATK-019, ATK-071, ATK-282/283 heuristics.
**Deliverables.**
- write-path logic, options, tests
**Acceptance.**
- A1: suspicious stored-field payloads in write requests are flagged with subtype `second_order_write`.
- A2: Paranoid rejects them; Balanced records them.
- A3: GET requests are unaffected by the stricter write rules.
- A4: the UI states the residual risk (second-order attacks may still pass).
- A5: legitimate names with apostrophes and hyphens are unaffected.
**Tests.**
- Table tests; benign gate; integration with the proxy harness for write flows.
**Notes.** This is mitigation, not a guarantee; documented as a known limitation.
