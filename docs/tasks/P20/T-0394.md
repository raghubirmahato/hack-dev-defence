### T-0394 · TSIG zone transfers (AXFR/IXFR) and NOTIFY for external secondaries
`P20` `[DP][SEC]` · deps: T-0388, T-0389, T-0191 · size: XL · owner: dns
**Objective.** Let an external provider serve as secondary so the customer's DNS survives loss of the VPS, with transfers authenticated and incremental.
**Steps.**
1. Implement TSIG (RFC 8945) verification and signing with HMAC-SHA256 (and SHA512), key names and secrets from the `secondary_dns` settings (secrets decrypted from the envelope store at service start only, zeroized after use, never logged), time-fudge window of 300 s, replay protection per (key, MAC, time), and the `BADKEY/BADSIG/BADTIME` error responses.
2. Implement **AXFR** over TCP only: allowed only for (a) a zone with a configured secondary, (b) a source address in that secondary's allowlist **and** a valid TSIG; every other attempt is refused (`REFUSED`) and counted as `axfr_denied` with a security event (rate limited). Stream the zone in multiple messages respecting the 64 KiB limit; include SOA first and last; honor global transfer concurrency (default 4) and per-zone rate limits.
3. Implement **IXFR** (RFC 1995) from the zone version history (T-0185): the server keeps the last N (default 20) deltas per zone in the snapshot service; if the requested serial is older or the delta chain is incomplete, fall back to full AXFR in the same message sequence; TCP preferred, UDP IXFR answered with the SOA only per RFC when the response would not fit.
4. Implement outbound **NOTIFY** (RFC 1996): on each published revision, send NOTIFY (opcode 4) with the new SOA to every configured secondary address over UDP, with retries (5 s, 15 s, 60 s, 5 min, then stop and alert), record success when the secondary answers; track `notify_sent_total`, `notify_acked_total`, latency histograms, and the **lag** (time between publish and secondary's first IXFR/AXFR request or SOA poll match).
5. Implement inbound NOTIFY handling: ignore (HDD is never a secondary for tenant zones) but answer `NOTAUTH`/`REFUSED` quickly and count it; no state change.
6. Implement secondary health verification: a worker task queries each secondary for the zone SOA every 5 minutes (UDP then TCP) and compares serials; a secondary behind by more than 2 serial values or older than 15 minutes raises `secondary_lag` and updates the UI hooks from T-0191 (status fields via a queue; the DNS service never writes to Postgres directly).
7. Implement TSIG key rotation: two active keys per secondary (current and next), a procedure documented for the operator, and an audit event on every key creation/rotation; support for a "test transfer" API action that performs an authenticated AXFR to a loopback test client and reports sizes and times without sending data externally.
8. Implement hidden-primary source restriction interplay with T-0395 (in `hidden_primary` topology only secondary addresses may query at all).
9. Make transfers bounded: zone size cap (plan-based), message size cap, total transfer time cap (60 s), and a refusal for zones in `quarantined` state.
10. Write the tests: TSIG test vectors from RFC 8945/4635, an AXFR client built on `hickory-client` (T-0401) verifying content equality with the snapshot, IXFR chain tests including serial wraparound (RFC 1982 arithmetic), NOTIFY retries with a fake secondary, wrong-key and wrong-time cases, and a security test that unsigned and wrongly signed attempts leak nothing (response bytes identical for non-existing and existing zones).
**Deliverables.**
- `xfr/` module, key rotation docs, API actions, tests, `docs/dns/SECONDARY.md`
**Acceptance.**
- A1: an AXFR/IXFR without a valid TSIG from any source is refused, including from the secondary's own address.
- A2: a test secondary (BIND or Knot from the oracle set, lab-only) receives the zone via NOTIFY plus IXFR and serves identical answers (compared with a zone-diff tool).
- A3: serial arithmetic handles wraparound.
- A4: a transfer of a zone with 100,000 records completes in ≤ 15 s and ≤ 256 MiB memory.
- A5: the lag alert fires when the secondary is stopped.
**Tests.**
- Unit vectors; integration with BIND/Knot containers in the lab (UNVERIFIED(`oracle_unavailable`) if absent); fuzz seeds for TSIG parsing.
**Notes.** This is the L4 survivability mechanism (C11.3); AC-21 depends on it.
