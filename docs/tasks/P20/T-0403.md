### T-0403 · DNSSEC readiness and automated DS check (cutover safety)
`P20` `[DP][OPS][SEC]` · deps: T-0189, T-0161, T-0395 · size: M · owner: dns
**Objective.** Prevent the classic outage where a domain with an existing DS record is moved to an unsigned zone, and make the DNSSEC status honest.
**Steps.**
1. Implement the **DS check** in the control-plane worker: query the parent for DS (`DS` at the apex via a validating public resolver and by walking to the parent's authoritative servers, comparing results), record `ds_present`, key tags, algorithms and digest types, and store the observation time and source resolvers in `domain_dns_observations`.
2. Implement the **cutover blocker**: if `ds_present` is true and HDD's zone is unsigned, activation of `full_ns` and `hidden_primary` is blocked with a clear explanation and two paths: (a) remove the DS at the registrar first (human step with instructions; wait for the DS TTL), or (b) use the signing option when the Tier 3 feature exists (not available in v5; the UI says so without teasing a date).
3. Implement the **post-cutover DNSSEC validation probe** (`delv` oracle or an in-process validating check using `hickory-resolver` in validation mode): after NS change, verify from validating resolvers that names resolve (not SERVFAIL/bogus); alert with high severity within 5 minutes if validation fails across two resolvers, and surface the rollback instruction.
4. Implement claims enforcement: no UI string, API field, report or doc may say a zone is DNSSEC signed unless `delv` validation passes (claims-lint rule `dnssec_claim`); the readiness page shows "DNSSEC: not enabled (HDD serves unsigned zones)" with a link to the DS explanation.
5. Implement the key-material design stubs for Tier 3 (T-0548) without enabling signing: reserved columns, a disabled feature flag, and an ADR describing online signing (ECDSA P-256, NSEC3 with opt-out disabled or NSEC with minimal enumeration risk, key storage in the envelope store, KSK/ZSK rollover plan, DS publication workflow), so the future task is a bounded extension.
6. Provide `hddctl dns ds-check <domain>` and `hddctl dns dnssec-probe <domain>` for break-glass use, with machine-readable output.
7. Add the DS check to the Protection Readiness Score (T-0172) for `full_ns` and `hidden_primary`, and to the go-live checklist (T-0168).
8. Write tests against synthetic delegations in a lab (signed parent zone with a DS for a test child, served by BIND), including: DS present → blocked, DS removed → allowed, DS algorithm unsupported by validators, parent unreachable (check state `unknown` blocks activation unless the operator overrides in `owner_only` mode with an explicit acknowledgment).
**Deliverables.**
- DS check job, blockers, probe, claims-lint rule, ADR for Tier 3 signing, `hddctl dns` subcommands, tests
**Acceptance.**
- A1: activation is blocked for every DS-present scenario in the lab matrix.
- A2: the post-cutover probe detects bogus answers within 5 minutes in a simulation where the DS and zone mismatch.
- A3: claims-lint fails any string claiming DNSSEC protection without a passing validation oracle.
- A4: `unknown` DS state never silently passes.
- A5: the readiness UI and docs describe the unsigned status honestly.
**Tests.**
- Lab matrix with BIND-signed parent; unit tests; claims-lint tests.
**Notes.** This is AC-23's DNSSEC component and a mandatory cutover gate item (C17.2 step 2).
