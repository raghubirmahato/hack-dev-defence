### T-0397 · Parser hardening and fuzzing for the DNS wire path
`P20` `[SEC][QA]` · deps: T-0392, T-0394 · size: M · owner: sec
**Objective.** Prove that no input byte sequence can crash, hang or inflate memory in the DNS service.
**Steps.**
1. Create `cargo fuzz` targets: `dns_decode` (full message decode and re-encode), `dns_query_path` (decode + answer against a fixed multi-zone snapshot + encode), `dns_tcp_frame` (stream framing state machine), `dns_tsig` (TSIG parse and verify with fixed keys), `dns_edns` (OPT parsing and cookie handling), `zone_text_import` (zone file parser used by T-0157), `svcb_params` (SVCB/HTTPS parameter parser).
2. Seed corpora from: the RFC examples, the protocol table (T-0389), captures from the conformance suite (T-0401), historical malformed-packet shapes (compression loops, pointer to self, label length 64, name length 256, huge RDLENGTH, OPT with 65,535 options, TSIG with truncated MAC, QDCOUNT=65,535, ANCOUNT mismatch, trailing garbage).
3. Add invariants asserted in the harness: no panic, bounded time (≤ 50 ms per input), bounded allocation (custom allocator counting, ≤ 1 MiB per decode), decode→encode→decode idempotence for valid messages, and that responses never exceed the negotiated size.
4. Add structure-aware generators (`arbitrary`) for DNS messages to reach deep states, and a "mutation around valid messages" strategy.
5. Run a CI smoke (60 s per target) and a nightly campaign (30 minutes per target) on the builder only, never on the production VPS; persist corpora and minimize crashes; any crash blocks the gate and opens a diagnosis.
6. Add a **live malformed-packet replay**: send the minimized corpus to a running `hdd-dns` on the pilot from the runner (private rate profile, load-lab rules) and verify the process stays healthy, responses are well-formed or absent, and memory returns to baseline.
7. Add sanitizer runs (`-Zsanitizer=address` for the fuzz build, `miri` on the pure parsing modules where feasible).
8. Document the corpus policy and triage steps in `docs/fuzz/DNS.md`.
**Deliverables.**
- fuzz targets, corpora, CI jobs, docs
**Acceptance.**
- A1: all targets complete the smoke run with no crash, timeout or OOM.
- A2: the live replay leaves memory within 5% of baseline and the process up.
- A3: decode→encode idempotence holds for ≥ 1,000,000 generated valid messages.
- A4: coverage report shows ≥ 90% line coverage of the wire modules from the corpora.
- A5: miri passes on the pure parsing modules (or UNVERIFIED(`tool_unavailable`) with justification).
**Tests.**
- The fuzz campaigns themselves; live replay in the acceptance runner.
**Notes.** Fuzz findings are fixed in the root cause (a bounded decoder) rather than by catching panics.
