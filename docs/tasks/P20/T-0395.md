### T-0395 · Topologies, automatic NS/SOA, serial policy and glue
`P20` `[DP][API]` · deps: T-0394, T-0188, T-0161 · size: L · owner: dns
**Objective.** Make `self_authoritative` and `hidden_primary` both correct, switchable and safe.
**Steps.**
1. Implement the topology in the snapshot: for `self_authoritative` zones the NS RRset at the apex is the pair assigned from `ns_pairs` (names under `platform.ns_hostnames`), with glue `A/AAAA` only for names inside the zone; for `hidden_primary` zones the NS RRset is `dns.public_ns` (the external secondary's names) and the zone is answered **only** to the secondary's addresses and `admin_cidrs`; all other sources get `REFUSED` (not silence) so scanners cannot enumerate.
2. Implement per-zone topology switching with a preview of effects (API `POST D/dns/topology:preview`), a safety check that blocks a switch to `hidden_primary` unless a secondary is configured, TSIG is verified (test transfer OK), and the secondary's SOA matches; a switch back requires the registrar NS change to be confirmed (it creates a human-step instruction via T-0216).
3. Implement automatic SOA management: MNAME = the first platform NS (self) or the hidden primary's name, RNAME from the platform contact (`hostmaster@`), `serial` auto-incremented by the control plane per change (never by the DNS service), refresh 3,600 s, retry 600 s, expire 1,209,600 s, minimum (negative TTL) 300 s by default; per-zone override within documented bounds; changes audited.
4. Implement `NS` and `SOA` tamper protection: tenants cannot edit apex NS/SOA; `source=system` rows are regenerated at every publish; attempts to import them are reported as informational in the parity report.
5. Implement glue handling for the platform's own domain (in-bailiwick NS names) and the operator's documented registrar host-object step (human step) with checks that glue at the parent matches expectations (via recursive lookups from the control plane, never from the DNS service).
6. Implement the preflight warnings: both NS names resolving to the same IP or provider, missing IPv6 for one NS, secondary addresses equal to HDD's own, topology mismatch between what the registrar delegates (observed) and what the zone says (reported in S-113).
7. Implement `SOA` serial verification across all served replicas (single node in v5; the multi-node case is a documented extension) and a consistency check job comparing the snapshot and the live answer for each zone every 5 minutes (the probe queries its own server through the network path).
8. Write the topology test matrix: both topologies × (apex, subdomain, wildcard, delegated child zone) × source classes (secondary, admin, public, spoofed), asserting answers, REFUSED behavior and glue.
**Deliverables.**
- topology logic, API endpoints, UI hooks, probes, docs
**Acceptance.**
- A1: in `hidden_primary`, a query from a public address is REFUSED while the secondary's query succeeds.
- A2: serials strictly increase across all mutation types including imports and rollbacks.
- A3: the preflight warnings fire for the shared-IP and same-provider cases.
- A4: the consistency job reports divergence within 5 minutes in a fault-injection test (snapshot swapped out of band).
- A5: tenants cannot create, modify or delete apex SOA/NS.
**Tests.**
- Integration matrix; fault injection; property test on serial monotonicity.
**Notes.** AC-03, AC-21 and AC-28 assert per topology (C13.2).
