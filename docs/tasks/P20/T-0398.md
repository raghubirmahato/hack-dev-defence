### T-0398 · Amplification and reflection measurement (closed lab)
`P20` `[QA][LAB][SEC]` · deps: T-0393, T-0389 · size: M · owner: qa
**Objective.** Quantify the response-to-query ratio for every query class and prove HDD is a poor reflector.
**Steps.**
1. Build `xtask dns-amp` in `hdd-acceptance` that sends a catalog of queries (A, AAAA, MX, TXT with long values, DNSKEY, ANY, SRV, HTTPS, CAA, NXDOMAIN, wildcard, DS, RRSIG, large TXT at 2 KB, TXT near the 1,232 limit, EDNS 4,096 request, no-EDNS, cookies present/absent) against the pilot or lab server and records query bytes, response bytes (UDP and TCP) and the ratio.
2. Define thresholds: for UDP without a valid cookie the ratio must not exceed 3.0 for any query class on a zone whose records were created by the standard fixtures; the maximum single UDP response is ≤ 1,232 bytes; `ANY` ratio ≤ 1.5; truncated responses ≤ query size + 64 bytes.
3. Run the test within a closed lab (network namespace with a source-address spoofing sandbox so spoofed-source behavior is observed without touching third parties) and for non-spoofed live checks from the runner at the **protocol-abuse profile** limits (section 2.4).
4. Test RRL under spoofed-source patterns in the lab: a victim address receives at most the configured responses/s regardless of attacker volume; measure the victim-side bandwidth and compare with the attacker-side bandwidth.
5. Test large-answer defenses: zones with many TXT/A records produce TC=1 and the TCP fallback works; ensure TCP responses cannot be abused from spoofed sources (the TCP handshake prevents spoofing; verify via SYN cookie behavior).
6. Add the ATK-221, ATK-222, ATK-223, ATK-224, ATK-229 checks to the attack-matrix coverage (T-0313 extension) with measured values stored as evidence.
7. Produce `docs/dns/AMPLIFICATION.md` with a table of measured ratios per query class and the lab methodology.
8. Add a regression gate: any code change that increases the maximum ratio by more than 10% fails `xtask verify` (stored baseline in `tests/baselines/dns_amp.json`).
**Deliverables.**
- `xtask dns-amp`, report doc, baseline file, lab scripts as xtask subcommands
**Acceptance.**
- A1: ratios meet the thresholds for every query class.
- A2: under a simulated spoofed-source flood, the victim receives no more than the RRL limit plus slip responses.
- A3: the report states how the measurements were taken and which numbers are lab-only.
- A4: regression gate runs in `xtask verify`.
**Tests.**
- The measurement run itself plus unit tests for the ratio math.
**Notes.** Lab traffic never leaves the operator-owned network (section 2.6); numbers are not extrapolated to the internet.
