### T-0388 · Snapshot ingestion, atomic swap and the DNS data-plane role
`P20` `[DP][DB][SEC]` · deps: T-0387, T-0211, T-0177 · size: L · owner: dns
**Objective.** Make zone changes visible within 2 s without any database access from the query path and without ever serving a half-applied zone.
**Steps.**
1. Implement the snapshot store as `ArcSwap<ZoneSet>` where `ZoneSet` holds immutable per-zone structures: sorted name tree (canonical DNS order), RRsets indexed by (name, type), wildcard index, delegation points, empty-non-terminal markers, precomputed SOA/NS answers, per-zone limits and flags (`state`, `proxied_defaults`, `topology`).
2. Implement ingestion from the config bus (T-0211): full snapshot on boot (from a signed local cache file, then verify against Postgres through the read-only role `hdd_dns_ro`), and incremental revision messages (zone id, version, content hash). Fetch the new zone version, build the new structure off the hot path, validate invariants (CNAME exclusivity, SOA present, NS present, no duplicate tuples, apex rules), then swap atomically.
3. Enforce monotonic versions: a revision lower than the current is ignored with a metric; a gap triggers a resync of that zone; a hash mismatch quarantines the zone revision (keep serving the previous version) and raises an alert (`MET-hdd_dns_snapshot_rejected_total`).
4. Create the database role `hdd_dns_ro` with `SELECT` only on the views `dns_zone_export_v` and `dns_record_export_v` (no access to org, user or audit tables), and ensure the service refuses to start if it detects write privileges (self-check query against `has_table_privilege`).
5. Persist the last good snapshot to `/var/lib/hdd/dns/snapshot.bin` (0600, owned by the service user), written atomically (`rename`), with a header containing schema version, content hash and Ed25519 signature from the control plane; on boot with the database unreachable, serve from that file and report `degraded=cache` in `/healthz` and metrics.
6. Implement apply latency measurement: control plane stamps `published_at`; the DNS service records `applied_at` and exports the histogram `MET-hdd_dns_apply_seconds`; alert above 2 s p95.
7. Implement memory accounting per zone and a global cap (default 512 MiB); zones that would exceed the cap are rejected at ingestion with an alert instead of crashing.
8. Implement graceful removal: a zone with `state in (deleted, suspended, decommissioned)` answers `REFUSED` (suspended: `REFUSED` with an EDE 18 "Prohibited" extended error where supported) after the swap.
9. Write the chaos tests: kill Postgres, kill Redis, corrupt the cache file, deliver revisions out of order and duplicated, deliver a poisoned revision (invalid CNAME coexistence) and verify the previous version keeps serving.
**Deliverables.**
- `snapshot/` module, migration for the read-only role and export views, cache file format doc, tests
**Acceptance.**
- A1: with Postgres and Redis stopped, queries for existing zones are answered from the cache without errors for 10 minutes.
- A2: a record change appears in answers within 2 s p95 (measured on the pilot with a probe).
- A3: a corrupted or unsigned cache file is rejected (service starts empty and degraded, never serves unsigned data).
- A4: the service fails to start when its database role has `INSERT/UPDATE/DELETE` privileges (test with a deliberately over-privileged role).
- A5: out-of-order or duplicate revisions never cause a rollback of served data.
**Tests.**
- Integration with real Postgres; chaos suite; property test for monotonic version handling.
**Notes.** The control plane never pushes record data through Redis; Redis carries only revision pointers (zone id, version, hash).

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
