### T-0401 · Independent conformance suite: hickory-client tests and external oracles
`P20` `[QA][LAB]` · deps: T-0389, T-0392, T-0394 · size: L · owner: qa
**Objective.** Test `hdd-dns` with software that did not share code with it, so shared-bug blind spots are exposed.
**Steps.**
1. Build `hdd-acceptance::dns` using `hickory-client` (as a test-only dependency) to issue queries over UDP, TCP and with EDNS options, verify rcodes/flags/sections, perform AXFR/IXFR with TSIG, and send NOTIFY; the suite reads the same protocol table (T-0389) and adds live-only behaviors (cookies, RRL slip, truncation, TCP keepalive).
2. Integrate external oracles pinned in `lab/oracles/` (versions + checksums): `dig` and `kdig` (query/response checks), `delv` (to assert unsigned zones are reported as insecure and that **no DNSSEC claim** is made), `named-checkzone` and `kzonecheck` (zone export validity), `dnsviz probe` (offline analysis of captures where available), `ldns-verify-zone` (only relevant when T-0548 lands), `zonemaster-cli` (delegation and best-practice tests against the pilot subzone; UNVERIFIED(`oracle_unavailable`) if absent).
3. Implement differential testing: for the same zone fixture, load it into a reference authoritative implementation (BIND `named` or Knot DNS inside the lab) and compare answers for 20,000 generated queries; expected differences (minimal responses, ANY policy, RRL) are listed in an allowlist with justifications.
4. Run the IDN and long-name conformance cases, 0x20 case-randomization from a recursive resolver (Unbound with `use-caps-for-id: yes` in the lab) to verify case preservation.
5. Run a recursive-resolver compatibility test: Unbound, BIND recursive and Knot Resolver resolve names in the pilot subzone with DNSSEC validation disabled/enabled (expected: insecure/unsigned for the pilot subzone) and report any SERVFAIL.
6. Run public-resolver checks from the runner (rate-limited to the functional profile): 1.1.1.1, 8.8.8.8, 9.9.9.9 resolve pilot names, record propagation times, and verify EDNS/cookie behavior does not cause failures. Do this only for the operator's own pilot names.
7. Store the evidence (queries, responses hex dumps, tool versions, SHA-256) for AC-03.
8. Document known divergences from reference implementations in `docs/dns/DIVERGENCES.md`.
**Deliverables.**
- conformance suite, oracle manifests, differential harness, divergence doc
**Acceptance.**
- A1: the hickory-client suite passes on all protocol rows over UDP and TCP.
- A2: differential testing shows no unexplained divergence in 20,000 queries.
- A3: recursive resolvers with 0x20 and strict validation resolve pilot names without SERVFAIL.
- A4: zonemaster reports no errors for the pilot subzone (warnings documented) or UNVERIFIED with reason.
- A5: no DNSSEC claim: `delv` reports the pilot zone as insecure (unsigned) and the docs say so.
**Tests.**
- The suite itself; CI runs the offline portion; live portion in the acceptance runner.
**Notes.** The differential harness is the most effective detector of subtle wildcard/empty-non-terminal bugs.
