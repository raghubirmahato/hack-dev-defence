### T-0086 · SSE plumbing and the live-feed island
`P04` `[UI][API][DP]` · deps: T-0078, T-0085 · size: L · owner: ui
**Objective.** Deliver reliable, bounded, accessible live updates.
**Steps.**
1. Implement the server-side SSE helper in `hdd-web`/`hdd-api`: event IDs (monotonic per stream), `Last-Event-ID` resume from a bounded ring buffer, heartbeat comments every 15 s, per-connection bounded queue with drop-and-disconnect for slow consumers, authorization re-check at connect and periodically, graceful shutdown.
2. Implement per-user and per-org connection caps and a global cap; exceeding returns `429` with `Retry-After`.
3. Implement the client island `live-feed`: connect with `EventSource`, show connection state text (Live, Reconnecting in N s, Paused), exponential backoff with jitter, pause/resume button, "N new events" counter, insertion rules that never scroll while focus is inside the list or the user scrolled, batch announcements via polite live region at most every 10 s, DOM node cap (default 500) with oldest removal.
4. Implement fallback polling (`hx-trigger="every 10s"`) when SSE is unavailable, with the same visible state text.
5. Implement filter propagation: stream filters are server-validated and the stream is re-established on filter change.
6. Define event payload formats as HTML fragments rendered by the server with escaped content (no client templating) plus a small JSON control channel.
7. Add metrics: active streams, dropped slow consumers, resumes, bytes.
8. Document the protocol.
**Deliverables.**
- SSE helper crate module, `live-feed.js` island, docs, tests, metrics
**Acceptance.**
- A1: a slow consumer is disconnected and the server's memory stays bounded (test with a stalled client).
- A2: resume with `Last-Event-ID` delivers missed events within the buffer, otherwise signals a full refresh.
- A3: authorization revocation closes the stream within the re-check interval.
- A4: announcements are rate-limited and non-intrusive (accessibility tree test).
- A5: the DOM never exceeds the node cap during a 10,000-event burst.
**Tests.**
- Integration: SSE with real sockets, stalled and reconnecting clients; browser: live-feed behaviors with injected events.
- Load: 1,000 concurrent streams on the builder within memory bound (functional profile only).
- Fuzz: `Last-Event-ID` parser.
**Notes.** The event source for the live monitor is wired in T-0446; here the helper is exercised with a test publisher on the gallery.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
