### T-0076 · Static asset serving: caching, compression, ranges and path safety
`P04` `[UI][DP]` · deps: T-0072, T-0073 · size: M · owner: ui
**Objective.** Serve assets fast and safely.
**Steps.**
1. Serve hash-named assets from the embedded or on-disk asset directory with `Cache-Control: public, max-age=31536000, immutable`; HTML pages `no-cache` or `no-store` according to authentication.
2. Serve precompressed `.br`/`.gz` according to `Accept-Encoding` with correct `Vary`, `Content-Encoding`, `Content-Length` and `ETag` (strong, from the manifest hash).
3. Support conditional requests (`If-None-Match`) and byte ranges for large assets (fonts are small, but docs images and PDFs may be large).
4. Enforce path safety: no directory traversal, no symlink following outside the asset root, no dotfiles, canonical path checks, and fixed `Content-Type` from an allowlist with `nosniff`.
5. Embed assets in the binary for release builds (rust-embed style, vetted) and serve from disk in test builds using the same code path.
6. Add font preload `Link` headers for the critical font and `103 Early Hints` evaluation (documented, optional).
7. Add request metrics and per-route cache hit information.
8. Document the cache invalidation story (new build means new hashes).
**Deliverables.**
- `crates/hdd-web/src/assets.rs`, tests, docs
**Acceptance.**
- A1: requests with `..`, encoded traversal, absolute paths and null bytes never read outside the asset root.
- A2: `If-None-Match` returns 304 and `Accept-Encoding: br` returns Brotli.
- A3: unknown extensions are rejected with 404.
- A4: HTML responses are never served with `immutable`.
- A5: the asset server has no directory listing and returns identical errors for missing and forbidden files.
**Tests.**
- Unit: path canonicalization table; integration: range and conditional tests.
- Fuzz: path normalization never panics or escapes.
- Property: any generated path either resolves inside the root or is rejected.
**Notes.** Asset serving is on the public path, so it is also a target of ATK-079 to ATK-090.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
