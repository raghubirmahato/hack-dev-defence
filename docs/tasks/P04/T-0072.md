### T-0072 · Asset pipeline: CSS and JS bundling, SRI manifest, precompression
`P04` `[UI][OPS]` · deps: T-0032, T-0035, T-0071 · size: M · owner: ui
**Objective.** Produce the shipped assets deterministically, with integrity data and precompressed variants, without Node.
**Steps.**
1. Implement the JS bundling step in `xtask ui build`: islands are authored as ES modules under `crates/hdd-ui/js/`; the step resolves imports, concatenates per surface, and minifies with a vetted Rust minifier (ADR) or ships unminified modules if the budget allows (record the decision).
2. Verify there is no use of `eval`, `new Function`, `document.write`, or `innerHTML` with non-constant data; implement a JS lint (token-level) in `xtask ui lint` to enforce this.
3. Produce hash-named outputs (`core.<hash>.css`, `app.<hash>.js`), and the manifest `assets.json` with SRI (`sha384`) values consumed by templates for `<link>` and `<script>` tags with `integrity` and `crossorigin`.
4. Precompress assets with Brotli (level 11) and gzip (level 9) at build time, storing `.br` and `.gz` siblings; verify decompressed equality.
5. Vendor HTMX and axe-core as static files with recorded version, license and SHA-256 in `design/vendor.lock`; add a verification step that fails if a vendored file's checksum drifts.
6. Add the budgets: first-party JS at most 45 KB gzip total and 20 KB per route bundle; HTMX counted separately and reported; CSS limits from T-0035.
7. Generate the service-worker-free offline fallback page asset (S-018) as a static file.
8. Document the pipeline and the reproducibility guarantee.
**Deliverables.**
- extended `xtask ui build`, `design/vendor.lock`, `assets.json` format docs, JS lint
**Acceptance.**
- A1: building twice yields identical hashes.
- A2: templates reference assets only through the manifest (lint rejects hard-coded asset URLs).
- A3: modifying a vendored file without updating `vendor.lock` fails `xtask verify`.
- A4: budgets are reported and enforced; a synthetic oversized bundle fails.
- A5: the JS lint rejects `eval`, `new Function`, and unsafe DOM sinks in fixtures.
**Tests.**
- Unit tests for manifest generation and SRI correctness; JS lint fixture tests; determinism test.
- Integration: serve assets and verify SRI in a headless browser load (no integrity errors).
**Notes.** Node is never required in any build or test step.

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.
