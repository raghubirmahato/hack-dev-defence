### T-0094 · Serve the gallery at `/admin/design-system` and pass gate G04
`P04` `[UI][QA][DOC]` · deps: T-0078, T-0082, T-0083, T-0084, T-0086, T-0087, T-0088, T-0090, T-0091, T-0092, T-0093 · size: M · owner: ui
**Objective.** Expose the component gallery as a real route and certify the frontend foundation.
**Steps.**
1. Mount the gallery renderer (shared with `xtask ui gallery`) under `/admin/design-system` with the loopback-only dev gallery hook (replaced by real authorization in T-0125) and component documentation pages.
2. Add live demos using real server behavior: form validation, toast triggers, SSE test stream (publisher present only when `HDD_GALLERY_DEMOS=true`, default false and rejected in production profile validation), table pagination over a synthetic in-memory list clearly labeled Example data.
3. Run the whole frontend suite: contrast, lint, budgets, axe, keyboard, reflow, spacing, forced colors, visual regression, security tests, i18n checks.
4. Record real outputs and hashes under `acceptance-ui/`.
5. Update baselines (with reasons) for the served gallery and error pages.
6. Complete `docs/gates/G04.md` per Appendix E5 with metrics (JS/CSS sizes, test counts, coverage, axe summary, perf numbers).
7. Update the capability matrix for REQ-FEF rows; update STATUS.
8. Tag `gate-G04`.
**Deliverables.**
- served gallery, `docs/gates/G04.md`, updated baselines
**Acceptance.**
- A1: gallery served on loopback only; remote requests receive 503 until T-0125.
- A2: zero serious/critical axe findings across gallery and error pages in both themes.
- A3: budgets pass; visual baselines are in place.
- A4: frontend security suite is green; CSP has zero violations.
- A5: the gate report is complete and the tag exists.
**Tests.**
- Full `cargo xtask verify` and `cargo xtask ui verify` outputs pasted with SHA-256.
**Notes.** Demo publishers are disabled in any profile marked `production`.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
