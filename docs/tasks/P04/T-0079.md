### T-0079 · Form handling library: extraction, validation, errors, idempotency and PRG
`P04` `[UI][API][SEC]` · deps: T-0074, T-0038 · size: L · owner: ui
**Objective.** Make every form behave consistently, safely and accessibly.
**Steps.**
1. Implement a `Form<T>` extractor with strict content-type handling (`application/x-www-form-urlencoded` and `multipart/form-data` with limits), unknown-field rejection, size limits, and canonicalization (trim, NFKC where specified, empty to None).
2. Implement a validation framework (`garde`/`validator`-like, vetted) producing field-path errors with i18n message keys and parameters; business-rule errors from the domain layer map to the same structure.
3. Render errors with `ErrorSummary` and inline messages, preserving user input except secrets; password fields are never re-populated.
4. Implement the Post/Redirect/Get flow for non-HTMX submissions, flash messages for success, and in-place fragment swap for HTMX.
5. Implement idempotency keys: hidden input with a server-issued token bound to session and form; replays within 24 hours return the original result; stored in Redis with fallback.
6. Implement leave-guard metadata (forms declare dirty-state warning text) consumed by an island.
7. Implement optimistic concurrency fields (`version` hidden input and `If-Match` mapping) for edit forms.
8. Provide a test helper to submit forms with hostile values and assert error rendering.
**Deliverables.**
- `crates/hdd-web/src/forms/*`, tests, docs, example forms in the gallery
**Acceptance.**
- A1: unknown fields are rejected with `ERR-VAL-001` and a field path.
- A2: replaying the same idempotency token returns the first response and does not repeat side effects.
- A3: a stale `version` yields `ERR-CONC-001` with a recoverable UI.
- A4: password values are never echoed into HTML (assertion over rendered output).
- A5: the same form works with and without HTMX.
**Tests.**
- Unit: canonicalization table tests; proptest on field-path generation; fuzz target for multipart parsing limits.
- Integration: idempotency with real Redis (testcontainers); browser: error summary focus.
**Notes.** Large file uploads use a separate streaming path (certificates, zone files) with explicit size limits per route.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
