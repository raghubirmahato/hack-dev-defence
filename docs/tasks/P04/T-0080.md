### T-0080 · CSRF protection and request-origin verification
`P04` `[SEC]` · deps: T-0075, T-0079 · size: M · owner: sec
**Objective.** Defend every state-changing request against cross-site attacks with layered checks.
**Steps.**
1. Implement signed double-submit tokens: random value stored in a `__Host-hdd_csrf` cookie (`Secure; SameSite=Strict`) and an HMAC-bound token embedded in forms/meta; the HMAC binds the session (or an anonymous pre-session identifier for pre-auth forms) to defeat token fixation.
2. Verify, for every non-safe method: token validity, `Origin` header equals the expected origin (or, if absent, `Referer` origin), and `Sec-Fetch-Site` is `same-origin` (or `none` for top-level user-initiated navigations to GET only).
3. Reject cross-site requests with `ERR-AUTH-016` without revealing which check failed; log the failing check internally with request ID.
4. Rotate the token on authentication changes and periodically; support multiple tabs.
5. Provide the HTMX integration (token meta tag read by the loader) and for API-key authenticated JSON clients skip CSRF (bearer tokens are not ambient credentials) while forbidding cookie auth on API-key routes.
6. Define the pre-auth forms (login, signup, reset) token source (anonymous pre-session cookie with short TTL).
7. Add negative tests for JSON content-type CSRF, form-encoded forgery from other origins, missing/forged `Origin`, subdomain attacker (`evil.example.com` on the same site), and method override tricks.
8. Document the design and the exceptions list (none for browser-session routes).
**Deliverables.**
- `crates/hdd-web/src/security/csrf.rs`, tests, docs
**Acceptance.**
- A1: a cross-origin form post with a valid cookie but no token is rejected.
- A2: a request with a stolen token for another session is rejected.
- A3: the subdomain-attacker test (cookie tossing) fails to bypass `__Host-` cookies.
- A4: GET routes never mutate state (route table check).
- A5: API-key routes ignore cookies entirely.
**Tests.**
- Unit: token generation/verification tables; browser test with a hostile origin page posting to the app.
- Fuzz: header parsing of Origin/Referer.
- Security regression suite named `csrf_*` listed in the capability matrix.
**Notes.** Pairs with SameSite cookies as defense in depth, not as the only control.
