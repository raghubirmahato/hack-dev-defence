### T-0093 · Frontend security test suite
`P04` `[SEC][QA]` · deps: T-0075, T-0080, T-0085, T-0089 · size: L · owner: sec
**Objective.** Prove the UI layer resists the web attacks it will face.
**Steps.**
1. Build an XSS fuzz suite: render every component and error page with the hostile string corpus (HTML/JS/URL/CSS contexts, polyglots, bidi, null bytes, overlong strings) and assert no markup is injected (DOM inspection) and CSP is not violated.
2. Run a template audit: grep/AST-scan for `|safe`, raw string concatenation in templates, `innerHTML` assignments in JS, and unknown `href`/`src` schemes.
3. Test clickjacking protections (`frame-ancestors`, `X-Frame-Options` absence reasoning) with hostile framing pages.
4. Test open redirect handling for return URLs (login `next` parameters): only same-origin relative paths from an allowlist pattern are accepted; encoded and protocol-relative variants rejected.
5. Test cookie attributes and prefix enforcement, cookie tossing from sibling subdomains, and session cookie scope on the admin host.
6. Test CORS: no CORS headers on HTML routes; API CORS policy defined (deny by default).
7. Test HTTP method handling (TRACE disabled, HEAD parity, OPTIONS behavior) and cache headers on authenticated pages (`no-store`).
8. Test content sniffing and download behaviors (exports have `Content-Disposition: attachment` and `nosniff`).
**Deliverables.**
- `tests/frontend_security/*`, hostile corpora, scripts to run in CI
**Acceptance.**
- A1: zero XSS findings in the fuzz run; any finding blocks the gate.
- A2: open-redirect variants (at least 40 forms) are all rejected.
- A3: framing attempts are blocked.
- A4: authenticated routes are never cacheable by shared caches.
- A5: exports cannot be rendered inline by the browser.
**Tests.**
- The suite itself, run in browser and HTTP-level modes; results stored with SHA-256.
- Regression: each past finding gets a named test.
**Notes.** Findings feed STRIDE updates for the UI layer (ATK-296, ATK-297).
