### T-0091 · Accessibility test harness: axe, keyboard traversal, reflow, spacing, zoom, forced colors
`P04` `[QA][UI]` · deps: T-0089 · size: L · owner: qa
**Objective.** Automate everything that can be automated for WCAG 2.2 AA and record the rest.
**Steps.**
1. Integrate the vendored axe-core oracle: run per page/state with WCAG 2.2 A/AA and best-practice tags; store JSON with impact, node selectors and help URLs (local text only); fail on serious/critical.
2. Implement the keyboard traversal recorder: press Tab repeatedly and record the focus order with accessible names; assert logical order (DOM order match), no traps, visible focus (computed outline/box-shadow contrast check), skip link behavior, and Escape handling in overlays.
3. Implement reflow test at 320 CSS px width (no horizontal scroll except allowed regions) and 400% zoom emulation.
4. Implement text-spacing override test (inject the WCAG 1.4.12 CSS and assert no clipped text via scroll/client size checks).
5. Implement forced-colors and `prefers-contrast` emulation checks (borders/outlines present on controls).
6. Implement reduced-motion checks (computed transition durations).
7. Implement target-size check (all interactive elements at least 24x24 CSS px, with allowed inline-text exceptions list).
8. Implement heading-structure, landmark and label-in-name checks beyond axe defaults, and a report aggregator for gates (`acceptance-ui/a11y-summary.json`).
**Deliverables.**
- harness modules, report aggregator, docs
**Acceptance.**
- A1: seeded defects (missing label, low contrast, tiny target, focus trap) are each detected by at least one automated check.
- A2: the gallery passes all automated checks.
- A3: reports include per-screen results suitable for the G03/G04/P28 gates.
- A4: runtime of the full a11y suite on the gallery is under 5 minutes.
- A5: checks run in dark and light themes.
**Tests.**
- Meta-tests with deliberately broken fixtures; unit tests for focus-order assertion logic.
**Notes.** Screen-reader testing remains a human step (T-0022 checklists).

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
