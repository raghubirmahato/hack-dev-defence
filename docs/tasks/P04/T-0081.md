### T-0081 · Cookie utilities and preference cookies
`P04` `[SEC][UI]` · deps: T-0075 · size: S · owner: sec
**Objective.** Centralize cookie creation so attributes are always correct.
**Steps.**
1. Implement a cookie builder enforcing `__Host-` prefix rules (Secure, Path=/, no Domain) for security-relevant cookies and `Secure; HttpOnly; SameSite` defaults; a fixed registry of allowed cookie names with owners and lifetimes.
2. Implement signed preference cookies for pre-auth settings: theme, locale, density, reduced motion (HMAC with `HDD_SESSION_KEY`), size-capped, with graceful ignore on tampering.
3. Implement the anonymous pre-session cookie for forms (random ID, short TTL, not an identity).
4. Implement cookie deletion helpers (matching attributes) and a middleware that rejects unknown cookies in logs (not behavior).
5. Document the cookie inventory (name, purpose, lifetime, attributes, personal data: none) for the privacy page.
6. Add a test that scans all responses in the harness for `Set-Cookie` attribute compliance.
7. Implement cookie size and count limits to avoid request-header bloat.
8. Provide helper functions for tests to read and decode cookies.
**Deliverables.**
- `crates/hdd-web/src/cookies.rs`, cookie inventory page content, tests
**Acceptance.**
- A1: every `Set-Cookie` in the harness run has `Secure` and appropriate `SameSite`.
- A2: tampering with a preference cookie is ignored and does not error.
- A3: security cookies use the `__Host-` prefix.
- A4: the inventory lists every cookie the product can set.
- A5: no cookie contains personal data.
**Tests.**
- Unit: builder attribute tables; browser: cookie attribute scan across the gallery and error pages.
- Property: signed cookie verification rejects any single-bit modification.
**Notes.** The session cookie itself is created in T-0113.
