### T-0084 · Flash and toast contract: `HX-Trigger`, flash cookies and no-JS fallbacks
`P04` `[UI]` · deps: T-0041, T-0079 · size: S · owner: ui
**Objective.** Deliver success and error feedback consistently across HTMX and full-page flows.
**Steps.**
1. Define the toast event schema: `{kind, title_key, params, severity, undo?: {url, method, label_key, ttl}, id}` and the `HX-Trigger` header encoding with size caps.
2. Implement server helpers `toast_success`, `toast_error`, `toast_with_undo` that add the trigger header for HTMX responses and store a one-shot flash (signed cookie or server-side flash keyed by pre-session) for redirect flows.
3. Render flash messages in the layout on the next full page load as `Banner`/`Toast` equivalents with the same i18n keys.
4. Implement undo flows: undo links are POST forms with CSRF and idempotency, valid for a TTL, and audited.
5. Ensure messages never contain secrets or raw user input (parameters are escaped and length-capped).
6. Implement de-duplication and rate limiting for toasts to avoid flooding.
7. Provide tests for header size limits and fallback.
8. Document the contract for contributors.
**Deliverables.**
- `crates/hdd-web/src/flash.rs`, island integration, docs, tests
**Acceptance.**
- A1: the same action produces equivalent feedback with and without JavaScript.
- A2: undo expires after its TTL and is audited.
- A3: oversized toast payloads are truncated safely.
- A4: toasts announce once through the polite region.
- A5: no raw user input appears unescaped in toasts.
**Tests.**
- Unit: encoding tables; browser: toast announcement via accessibility tree; JS-off flash test.
**Notes.** Undo is only offered where the operation is genuinely reversible.
