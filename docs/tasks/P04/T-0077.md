### T-0077 · HTMX integration policy and configuration
`P04` `[UI][SEC]` · deps: T-0072, T-0075 · size: M · owner: ui
**Objective.** Use HTMX safely and consistently.
**Steps.**
1. Vendor the HTMX file and set the configuration in a nonce-allowed bootstrap or `meta` tag: `allowEval=false`, `allowScriptTags=false`, `selfRequestsOnly=true`, `includeIndicatorStyles=false`, `historyCacheSize=0` (no cached snapshots of authenticated pages), `refreshOnHistoryMiss=true`, `defaultSwapStyle=outerHTML` or `innerHTML` per documented rule, `scrollIntoViewOnBoost=false`.
2. Define the attribute conventions: `hx-target` always explicit and ID-based, `hx-swap` explicit, `hx-indicator` linking to text indicators, `hx-push-url` only for navigations, `hx-disabled-elt` on submit, `hx-confirm` forbidden (use ConfirmDialog), `hx-on` forbidden (CSP).
3. Define response handling: 2xx swaps; 4xx with `application/problem+json` or HTML fragments swap into an error region; 5xx shows ErrorState with request ID; network failure shows an OfflineBanner and keeps form input; use `htmx:responseError` and `htmx:sendError` handlers in an island.
4. Define CSRF header injection (`X-CSRF-Token` from a meta tag) for every non-GET request and verify `HX-Request` header presence server-side as a defense-in-depth signal (not as authentication).
5. Define focus and announcement handling after swaps: focus the swapped region's heading or the first error, announce via a polite live region; scroll positions preserved only for same-page swaps.
6. Define progressive enhancement rules: every HTMX interaction has a non-HTMX fallback (full-page form post or link) for critical flows (auth, add-domain, destructive confirms).
7. Create a lint that scans templates for forbidden attributes and missing targets.
8. Write the developer documentation with patterns for tables, filters, inline edit, polling, SSE.
**Deliverables.**
- vendored HTMX with lock entry, config bootstrap, error-handling island, template lint, docs
**Acceptance.**
- A1: injected `<script>` in an HTMX response is not executed (`allowScriptTags=false`).
- A2: cross-origin `hx-get` is refused (`selfRequestsOnly`).
- A3: after a swap, focus lands on the documented target (browser test).
- A4: critical flows work with HTMX removed (JS-disabled tests).
- A5: template lint flags `hx-on` and `hx-confirm`.
**Tests.**
- Browser tests for swap/error/network failure; JS-disabled fallback tests; lint unit tests.
**Notes.** The CSRF design is in T-0080; history cache is disabled to avoid exposing authenticated pages through back/forward cache on shared machines.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
