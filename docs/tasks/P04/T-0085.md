### T-0085 · Error pages and `Problem` rendering with content negotiation
`P04` `[UI][API][SEC]` · deps: T-0041, T-0074 · size: M · owner: ui
**Objective.** Render all errors consistently as HTML or `application/problem+json`, without leakage.
**Steps.**
1. Implement the `Problem` type (RFC 9457) with fields from B6.1 and mapping from internal error enums (`thiserror`) to `ERR-*` codes, HTTP statuses and i18n keys; unknown errors map to `ERR-SYS-002` with only the request ID exposed.
2. Implement content negotiation: HTML for browsers (via `Accept` and `Sec-Fetch-Dest: document`), JSON problem for API clients and HTMX fragments (ErrorState), with `Vary: Accept`.
3. Implement pages S-015 (not found), S-016 (server error), S-017 (maintenance with expected end), S-018 (offline fallback asset), and the 403 permission page with explanation of the role needed.
4. Ensure cross-tenant resource requests return the same not-found response as nonexistent ones (no existence oracle).
5. Implement the error-ID correlation: request ID in responses (`HDD-Request-ID` header) and display.
6. Implement redaction in error logs and a test that errors never include SQL fragments, file paths or hostnames.
7. Implement maintenance-mode behavior: file flag and platform setting produce `503` with `Retry-After` for non-admin surfaces and allow break-glass paths.
8. Document the catalog usage and how to add new errors (single enum, generated docs).
**Deliverables.**
- `crates/hdd-web/src/errors/*`, templates, docs, generated error documentation page for the docs site
**Acceptance.**
- A1: every `ERR-*` in B7 is represented by a variant and has an i18n key (checked by a test).
- A2: sample internal errors (DB failure, panic) never leak internals in HTML or JSON.
- A3: cross-tenant and nonexistent resources are indistinguishable (response bytes except request ID identical in test).
- A4: maintenance mode returns `503` with `Retry-After` and allows `/healthz`.
- A5: error pages meet accessibility checks (axe) and reflow at 320 px.
**Tests.**
- Unit: mapping tables; integration: forced failure injection (DB down, panic) with response assertions.
- Browser: axe on error pages; JS-off rendering.
**Notes.** Error documentation pages are generated from the same enum to prevent drift.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
