### T-0090 · Visual regression pipeline
`P04` `[QA][UI]` · deps: T-0089 · size: M · owner: qa
**Objective.** Detect unintended visual changes with a reviewable workflow.
**Steps.**
1. Implement screenshot capture with deterministic conditions: fixed viewport, disabled animations, fixed clock, hidden dynamic regions via test selectors, font loading wait, device scale factor 1.
2. Implement image comparison using the `image` crate: per-pixel threshold with anti-aliasing tolerance and region masks, producing diff images and a numeric score.
3. Implement baseline storage under `design/baselines/<surface>/<screen>/<state>-<theme>-<viewport>.png` with size budget enforcement and lossless compression.
4. Implement `xtask ui baseline update --screen S-xxx --reason "..."` that requires a reason, records it in a changelog, and shows diffs for review.
5. Implement a review report (HTML in `acceptance-ui/`) with side-by-side/diff views (a local artifact, not shipped).
6. Implement CI integration: any diff above threshold fails; baseline updates require the reason field and a reviewer entry.
7. Cover the matrix: dark/light, 360/768/1280, high contrast for gallery, LTR and pseudo-RTL for key pages.
8. Document flakiness policies (no retries masking diffs; investigate font/AA differences by pinning the browser build).
**Deliverables.**
- visual diff tool in xtask, baseline store, review report generator, docs
**Acceptance.**
- A1: unchanged UI yields a zero-diff run twice in a row.
- A2: a one-pixel color change in a token produces a failing diff.
- A3: updating a baseline without `--reason` is refused.
- A4: baseline repository size stays within the configured budget.
- A5: the report lists all changed screens with scores.
**Tests.**
- Unit: image diff on synthetic images (known regions); integration: end-to-end diff on the gallery.
**Notes.** Browser build pinning is recorded in `docs/ENV.md` so baselines remain stable.

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
