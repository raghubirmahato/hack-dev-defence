### T-0075 · Security headers, CSP with nonces, Trusted Types and violation reporting
`P04` `[UI][SEC]` · deps: T-0074 · size: M · owner: sec
**Objective.** Ship a strict, tested header policy for every surface.
**Steps.**
1. Implement per-response nonce generation (128 random bits, base64) passed to templates for any permitted inline script (theme bootstrap only) and verified absent elsewhere.
2. Compose CSP per surface: `default-src 'none'; script-src 'self' 'nonce-…'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none'; manifest-src 'self'; upgrade-insecure-requests; require-trusted-types-for 'script'; trusted-types hdd-islands; report-to hdd-csp` with the exact directives documented and tested; allow `wasm-unsafe-eval` only if the ADR chose WASM islands.
3. Set the companion headers: `Strict-Transport-Security` (2 years, includeSubDomains; preload only after operator approval), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` (no-referrer on token pages), `Permissions-Policy` denying camera, microphone, geolocation, payment, USB and others, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Embedder-Policy` evaluated but not enabled unless needed, `Cache-Control: no-store` for authenticated pages and token pages.
4. Implement the CSP report endpoint `POST /__csp-report` on the app/admin hosts accepting `application/csp-report` and `application/reports+json`, size-capped, rate-limited, parsed defensively, aggregated into `MET-hdd_csp_reports_total` and a rolling table; no raw URLs stored beyond origin + directive + short sample.
5. Implement Trusted Types policy `hdd-islands` in the island loader (the only sink users) and ensure no other script uses DOM sinks.
6. Add an `xtask` check that fetches every route from a running instance and validates headers against the expected policy.
7. Document each directive and why; document how to relax in a development override that is rejected in production configuration (there is no dev mode: tests use the same policy).
8. Add the clickjacking protections test (frame-ancestors) and a CSP bypass checklist (JSONP, `base`, dangling markup).
**Deliverables.**
- `crates/hdd-web/src/security/{csp,headers,report}.rs`, route-level header test harness, docs
**Acceptance.**
- A1: every route returns the full header set; missing headers fail the header check.
- A2: loading the gallery in the harness produces zero CSP violations.
- A3: an injected inline script (test) is blocked and reported through the report endpoint.
- A4: token pages carry `Referrer-Policy: no-referrer` and `Cache-Control: no-store`.
- A5: the CSP contains no `unsafe-inline` or `unsafe-eval`.
**Tests.**
- Unit: header builder snapshot tests per surface; parser tests for report payload formats incl. malformed and oversized.
- Browser: violation trap proves enforcement; clickjacking test via an iframe page.
- Fuzz: report body parser.
**Notes.** The data plane's own CSP for visitor pages is separate (T-0366).
