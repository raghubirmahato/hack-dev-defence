### T-0074 · Template layer: page contexts, layouts, partial rendering and `SafeHtml`
`P04` `[UI][SEC]` · deps: T-0073, T-0036 · size: L · owner: ui
**Objective.** Make server-side rendering safe by construction and efficient for full and partial responses.
**Steps.**
1. Define the `PageContext` struct (surface, locale, theme, density, nonce, csrf token, user summary, org summary, flash messages, breadcrumbs, page title key, active nav item, feature flags, build info) built by one extractor.
2. Define the `Page` trait for askama templates with `render_full` and `render_partial`; implement `HX-Request` detection so HTMX requests receive only the fragment (and `HX-Title`, `HX-Push-Url` when needed), with `Vary: HX-Request` set to keep caches correct.
3. Implement layouts for the three frames (public, app, admin) using the primitives of T-0036, with the skip link, landmarks, canonical `<title>` format `Screen · Domain · Org · Hack Dev Defence`, `<html lang dir data-theme>` attributes.
4. Implement the `SafeHtml` newtype: only constructible from (a) compile-time template output, (b) the sanitizer (ammonia policy in P05), or (c) escaping helpers; a grep-based lint forbids askama's `|safe` filter outside the `hdd-ui` crate's audited modules.
5. Implement helpers for escaping contexts beyond HTML text: attribute, URL (scheme allowlist), CSS identifier, JSON-in-HTML script data (`<script type="application/json">` with nonce, using safe JSON escaping of `<`, `>`, `&`, U+2028/9).
6. Implement the page-title and breadcrumb builders from route metadata.
7. Provide a testing helper that renders any page with a hostile-string fixture set (HTML, quotes, scripts, bidi controls, very long tokens) and asserts escaping.
8. Document the rules for authors (no string concatenation of HTML, no `|safe`, escaping contexts table).
**Deliverables.**
- `crates/hdd-web/src/render/*`, `SafeHtml` type, lint, hostile fixture set, docs
**Acceptance.**
- A1: a template using `|safe` outside the allowed module fails `xtask verify`.
- A2: every component rendered with the hostile fixture set produces no unescaped markup (automated assertion).
- A3: HTMX requests receive fragments and responses carry `Vary: HX-Request`.
- A4: JSON-in-HTML helper neutralizes `</script>` and U+2028/9 in tests.
- A5: titles follow the canonical format on all gallery pages.
**Tests.**
- Unit: escaping contexts table-driven tests; proptest that arbitrary strings never produce an unescaped `<` in text positions.
- Fuzz target: renderer inputs (strings, long tokens) never panic.
- Browser: gallery pages produce no CSP violations.
**Notes.** This is the first line of defense against stored XSS from attacker-controlled data (ATK-297).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
