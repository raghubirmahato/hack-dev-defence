### T-0092 · Performance budgets and lab Web Vitals checks
`P04` `[QA][UI]` · deps: T-0089 · size: M · owner: qa
**Objective.** Make speed a tested property.
**Steps.**
1. Implement CDP-based performance capture with a mobile profile (4x CPU slowdown, Fast 4G network emulation, 390x844 viewport): navigation timing, Largest Contentful Paint, Cumulative Layout Shift, Interaction to Next Paint (via event timing for scripted interactions), total transfer size, request counts.
2. Define budgets from Part A: LCP at most 2.5 s, INP at most 200 ms, CLS at most 0.1, JS at most 45 KB gzip, CSS at most 60 KB gzip, fonts at most 100 KB total, requests at most 25 on first load of any surface.
3. Run on the representative pages: S-001, S-020, S-023, S-040 (empty state), S-045 (large table), S-065 (live monitor), S-100, S-140 (data plane page size).
4. Add server-side render time histograms (`MET-hdd_web_render_duration_seconds`) and budgets (p95 under 50 ms for typical pages on the builder).
5. Implement trend storage in `acceptance-ui/perf/*.json` and regression detection against the previous gate.
6. Add the HTTP caching correctness checks (immutable assets, no-store pages) and compression checks.
7. Provide a developer command `xtask ui perf <route>`.
8. Document interpreting results and what to do on regressions.
**Deliverables.**
- perf harness, budgets file `design/perf-budgets.toml`, reports
**Acceptance.**
- A1: gallery and error pages meet all budgets.
- A2: an artificially heavy page fails the budget check (meta-test).
- A3: reports record the exact emulation parameters.
- A4: regression detection compares against the last passing gate.
- A5: server render time budgets are enforced.
**Tests.**
- Meta-tests; integration: perf runs under the harness; unit: budget parser.
**Notes.** Lab metrics approximate field behavior; real-user monitoring is not collected (privacy).

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
