### T-0083 · Date, time, number and unit formatting; time zones
`P04` `[UI]` · deps: T-0082 · size: S · owner: ui
**Objective.** Format values correctly and consistently, with user time zones.
**Steps.**
1. Choose the time-zone database approach (`jiff`/`chrono-tz`, ADR) and keep all stored timestamps in UTC.
2. Implement formatting helpers: absolute date-time in user zone with offset, date only, relative time ("2 minutes ago") with `<time datetime>` and a `title` containing the absolute value, durations, byte sizes (SI and IEC rules defined), request rates, percentages with locale separators, large-number abbreviations (cards only).
3. Implement the `time-local` island fallback: the server already renders the user's zone so the island is optional.
4. Define the user-zone resolution (account setting, browser hint stored once, default UTC) and DST-safe rendering tests.
5. Implement locale-aware sorting helpers for names (collation basics).
6. Implement ban countdown formatting rules (static text updated by server on poll; island enhances).
7. Add unit tests with DST transitions, leap days, extreme values, and negative durations.
8. Document formatting rules per data type.
**Deliverables.**
- `crates/hdd-web/src/format.rs`, docs, tests
**Acceptance.**
- A1: DST transition tests pass for at least five zones including half-hour offsets.
- A2: relative times always carry an absolute fallback.
- A3: numbers use the user's locale separators.
- A4: unknown/absent values render `Unknown (reason)` per T-0021.
- A5: no formatting function panics on extreme inputs (proptest).
**Tests.**
- Unit tests; proptest with arbitrary timestamps and durations.
- Browser: gallery rendering in two zones.
**Notes.** Reports (PDF) use the org's configured zone, stated in the report header.
