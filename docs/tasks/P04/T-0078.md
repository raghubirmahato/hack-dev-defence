### T-0078 · Islands framework and the first-party interactive modules
`P04` `[UI]` · deps: T-0072, T-0077 · size: L · owner: ui
**Objective.** Provide the small, budgeted set of JavaScript islands that enhance accessible server-rendered HTML.
**Steps.**
1. Implement a minimal loader: elements with `data-island="name"` lazily import `/assets/islands/name.<hash>.js` on idle/visible/interaction as declared, passing a typed configuration read from `data-*` attributes or a JSON script tag; no globals except the loader.
2. Implement islands: `theme` (apply/persist), `toast` (queue, timers, pause on hover/focus), `clipboard` (copy with fallback and announcement), `disclosure`, `dialog-helper` (native dialog enhancements), `popover` (positioning), `menu` (roving focus), `tooltip`, `combobox` (for switchers and palette), `tabs` (manual activation), `countdown`, `confirm-guard` (type-to-confirm enabling), `tag-input`, `file-drop`, `password-toggle`, `time-local` (render `<time>` in the user's zone).
3. Enforce Trusted Types: all DOM writes go through a single `hdd-islands` policy that accepts only static strings and sanitized fragments created by `textContent`/`DOMParser` of server-rendered, already-escaped HTML.
4. Add error isolation: an exception in one island logs to the console and shows the unenhanced baseline; no island may break core submission.
5. Add budgets per island and total (45 KB gzip across any route, 3,000 source lines total); the build reports sizes per island and fails on excess.
6. Implement a test mode for islands in the harness (events, state) without exposing test hooks in production builds.
7. Write unit tests for pure logic using a minimal Rust-driven JS runner? No: use the browser harness; keep logic small and covered by browser tests.
8. Document each island's data attributes, events, accessibility behavior and failure baseline.
**Deliverables.**
- `crates/hdd-ui/js/*.js`, loader, island docs, size report
**Acceptance.**
- A1: each island degrades to a working baseline when it fails to load (tested by blocking the script).
- A2: no island performs network requests other than same-origin fetches declared in docs.
- A3: total first-party JS is within budget and reported.
- A4: Trusted Types enforcement produces zero violations in the gallery.
- A5: islands have keyboard maps matching the component docs.
**Tests.**
- Browser tests per island including failure injection; budget test; lint (no `eval`, no unsafe sinks).
- Accessibility: axe plus keyboard traversal for island-enhanced components.
**Notes.** If T-0071 chose Leptos islands, this task is replaced by the equivalent WASM island set with the same behavioral tests.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
