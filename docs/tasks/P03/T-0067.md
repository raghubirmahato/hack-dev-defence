### T-0067 · Team, API keys, audit, plan, settings and account screens (S-080 to S-094)
`P03` `[UI][SEC]` · deps: T-0057 · size: L · owner: ux
**Objective.** Design administration screens for orgs and accounts.
**Steps.**
1. Design API keys (S-080): create form with scope selection grouped by area, expiry, IP restriction, secret reveal once, usage graph, revoke.
2. Design Team (S-081), Invitations (S-082), Roles (S-083): role cards, permission matrix view, last-owner protection messages.
3. Design Audit log (S-084): filters, event detail, export, hash-chain verification indicator and explanation.
4. Design Plan and usage (S-085) and Org settings (S-086) including danger zone with type-to-confirm.
5. Design Profile (S-087), Account security (S-088: password, MFA, passkeys, recovery codes, security timeline), Sessions (S-089), Data and privacy (S-090).
6. Design Config revisions (S-092), Emergency controls (S-093) with time-box UI, and Decommission (S-094).
7. Design the Command palette (S-091) results layout.
8. Provide states and small-screen variants.
**Deliverables.**
- prototype pages and states
**Acceptance.**
- A1: permission matrix view is generated from the B4 table in the design (no hand-copy drift).
- A2: emergency controls show auto-revert timers and plain effects.
- A3: decommission flow shows revert instructions before confirmation.
- A4: sessions page shows current session distinctly and offers revoke others.
- A5: data and privacy page states timelines for export and deletion.
**Tests.**
- Axe; heuristic review; security-UX checklist from T-0025.
**Notes.** The audit screen must remain readable with 100,000 entries via filters and cursor paging.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
