### T-0070 · Usability walkthrough, design sign-off request and gate G03
`P03` `[UI][HUMAN][DOC]` · deps: T-0069 · size: M · owner: ux
**Objective.** Obtain the operator's decision on the design and pass the gate.
**Steps.**
1. Prepare the review bundle: screenshot sets (dark/light, desktop/mobile) per surface, the flow diagrams, the component gallery, a list of the scripted scenarios with expected outcomes, and the summary of reviews.
2. Run scripted walkthroughs of scenarios (Maya adds a domain; Sara investigates an SQLi ban; Omar suspends a tenant; Vi files an appeal) using the prototypes and record friction points.
3. Present the open product decisions (brand, languages, plans, signup mode, status page hosting) with defaults.
4. Ask the operator for sign-off or change requests; record each change as a spec patch or a new task note.
5. Apply approved changes to tokens, components and prototypes; re-run reviews for affected screens.
6. Update `docs/UX/decisions/` with UXD entries and the final answers.
7. Fill `docs/gates/G03.md` with real output tails (contrast, axe, budgets, prototype counts), commit hash, REQ matrix updates, UNVERIFIED items, risks.
8. Tag `gate-G03` only after the sign-off is recorded or marked `UNVERIFIED(human_step_pending)` with the agent proceeding on stated defaults for non-blocking screens.
**Deliverables.**
- review bundle, decisions log, `docs/gates/G03.md`
**Acceptance.**
- A1: the operator's sign-off or change list is recorded.
- A2: all approved changes are applied and re-reviewed.
- A3: the gate report meets the Appendix E5 format.
- A4: all 143 screens have prototypes in required states (index shows 100% coverage).
- A5: the tag exists, and STATUS lists remaining human steps.
**Tests.**
- `xtask ui prototype build` coverage report equals the screen registry; `xtask verify` green.
**Notes.** Build of product screens in P05 onward may start for screens whose design is approved even if others await changes.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[HUMAN]`: Needs an operator action

Real probe detects the state; exact instructions printed; wait for confirmation.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
