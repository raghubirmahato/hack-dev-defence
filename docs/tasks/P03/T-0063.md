### T-0063 · Rate limiting, bots, access, honeypots, outbound, block page, access gate, API discovery, business flows, coverage (S-061 to S-063, S-095 to S-097, S-131 to S-134)
`P03` `[UI]` · deps: T-0061 · size: L · owner: ux
**Objective.** Design the remaining security configuration screens.
**Steps.**
1. Design Rate limiting (S-061): presets, rule table, per-path rules, burst allowance, action settings, test helper, explanation of consequences and shared-IP risk.
2. Design Bots and challenge (S-062): class-based policy table, verified bots, challenge difficulty and clearance duration, under-attack settings, reputation list policies.
3. Design Access lists (S-063): entries by kind, import CSV with validation preview, expiry, self-lockout preview, country selector with search and keyboard support.
4. Design Honeypots and decoys (S-095): default paths per platform, custom paths, ban toggle, WordPress note.
5. Design Outbound protection (S-097): mode, exclusions, patterns list, partial-scan note, events.
6. Design Block page customization (S-096) with live preview in both themes and appeals toggle.
7. Design Access gate (S-131): rule list and editor, template picker, credential reveal-once, signed-link generator, self-lockout preview (B12.2).
8. Design API discovery (S-132) with inventory table, state chips, schema drawer and the seven-day would-have-blocked preview; Business flows (S-133) with flow cards, signal explanations and Simulate; Coverage map (S-134, public and domain variants) with status chips that use text and icon as well as color, and the always-open "What HDD does not cover" section.
9. Provide states and validation messages; shared consequence components.
10. Provide small-screen variants.
**Deliverables.**
- prototype pages and states
**Acceptance.**
- A1: every list-changing screen has a self-lockout preview in the design.
- A2: the country selector is keyboard-operable and searchable.
- A3: the block page preview matches the actual visitor page layout (reuse of the same component).
- A4: CSV import shows row-level errors before commit.
- A5: outbound screen states the 64 KiB scan window limitation.
- A6: S-131 shows the self-lockout preview before saving, S-132 requires acknowledging the preview before `block`, and S-134 never renders a status by color alone.
**Tests.**
- Axe; heuristic review; copy review.
**Notes.** The block page preview uses the data-plane template to avoid drift.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
