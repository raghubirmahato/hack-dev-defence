### T-0054 · Public pages (S-001 to S-018)
`P03` `[UI][DOC]` · deps: T-0053 · size: L · owner: ux
**Objective.** Design the public site with honest, concise content and strong accessibility.
**Steps.**
1. Design the landing page (S-001): hero statement, three-step how it works, honest limits teaser, CTA variants for open and invite-only signup, trust section listing tested claims with test IDs (rendered from a static results file at release).
2. Design Features (S-002), How protection works and its limits (S-003) with an SVG request-path diagram (accessible: long description, ordered list alternative), Plans (S-004) driven by plan data with the rule that security controls are never gated behind opaque tiers.
3. Design Docs home/article/API reference (S-005 to S-007) including TOC, search results, code blocks, callouts, prev/next.
4. Design Status (S-008), Contact (S-009), legal pages (S-010 to S-013), security disclosure (S-014), and error/maintenance/offline (S-015 to S-018).
5. Write the real copy for these pages using the copy deck, glossary and the claims dictionary; mark operator-owned text (legal entity, addresses) as placeholders that the product refuses to publish until supplied.
6. Design the cookie notice: because only essential cookies are used, show an informational line, not a consent banner, and document why.
7. Provide variants for signup closed, invite-only, open and maintenance modes.
8. Prepare responsive and print variants.
**Deliverables.**
- prototype pages for all public screens in all required states; copy in `i18n/en/public.ftl` drafts
**Acceptance.**
- A1: page copy passes claims-lint and contains no forbidden phrases.
- A2: S-003 states the known limitations listed in C3.2 and cites test IDs for claims.
- A3: every page has a single `h1` and valid landmarks.
- A4: the diagram has a text alternative.
- A5: placeholders for operator-owned legal text are flagged.
**Tests.**
- Axe on prototypes; link check; claims-lint.
**Notes.** The public site must work with JavaScript disabled.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
