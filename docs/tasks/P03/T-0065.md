### T-0065 · IP jail, appeals and visitor-facing pages (S-067 to S-069, S-140 to S-148)
`P03` `[UI][SEC]` · deps: T-0064 · size: L · owner: ux
**Objective.** Design bans, appeals and the pages visitors see.
**Steps.**
1. Design the IP jail (S-067): columns, countdown badges, reasons, scope, filters, manual ban form with self-lockout and collateral hint, bulk unban, export.
2. Design Ban detail (S-068): offence history, TTL ladder step, evidence, propagation status per layer (L7, Redis, kernel, XDP), unban.
3. Design Appeals inbox (S-069) with evidence and four resolution actions.
4. Design visitor pages: Block page (S-140), Challenge (S-141), Rate limit (S-142), Origin error (S-143), Unknown host (S-144), Appeal form and confirmation (S-145, S-146), Under attack (S-147), Domain suspended (S-148); each uses inline critical CSS with a nonce, no external requests, dark/light via `prefers-color-scheme`, and the tenant brand slots.
5. Write visitor copy that never blames and never reveals rules; include JSON variants for API clients.
6. Design the challenge page accessibility (live region progress, noscript fallback, reduced motion).
7. Design how block pages look at 320 px and with large text.
8. Document the Ray ID presentation and copy behavior.
**Deliverables.**
- prototype pages and states; visitor-page template specs
**Acceptance.**
- A1: visitor pages reveal no rule names or internal hostnames (copy review checklist).
- A2: appeal form includes abuse resistance states (rate limit, proof-of-work).
- A3: jail table countdowns have static textual equivalents.
- A4: each visitor page is under 20 KB including inline CSS.
- A5: JSON variants documented for each status code.
**Tests.**
- Axe; page-weight check on prototypes; copy review.
**Notes.** These templates are shared with the data plane (T-0366).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
