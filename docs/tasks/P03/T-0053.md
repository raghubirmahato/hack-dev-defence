### T-0053 · Prototype tooling and policy
`P03` `[UI][QA]` · deps: T-0052 · size: M · owner: ux
**Objective.** Build a safe way to produce clickable prototypes from real components, with guards that prevent shipping them.
**Steps.**
1. Implement `xtask ui prototype build` that renders prototype pages from Rust fixtures (`design/prototypes/src/*.rs`) into static HTML under `target/prototypes/` using `hdd-ui` components and the same CSS bundles.
2. Mark every prototype page with a fixed banner "Design artifact. Example data. Not the product." styled with a dedicated token, and add `<meta name="robots" content="noindex">`.
3. Define the synthetic data policy: reserved names only (`example.org`, `.invalid`, RFC 5737 addresses), obviously fake brand names, no real personal data.
4. Implement link wiring between prototype pages so flows are clickable (static links plus minimal state through URL fragments); no JavaScript beyond the shipped islands.
5. Add a guard in `xtask release` and in CI: the shipped crates and asset manifests must not include prototype content (path and content scans), and `hdd-web` has no dependency on the prototype crate.
6. Add a guard in claims-lint to scan prototypes too (copy must still be honest).
7. Implement an index page listing all prototypes by surface/screen ID/state with links and statuses (draft, reviewed, approved).
8. Document the workflow and the review process.
**Deliverables.**
- `xtask ui prototype`, `design/prototypes/` skeleton, index generator, release guard
**Acceptance.**
- A1: prototype build fails if a fixture contains a non-reserved domain or a routable IP.
- A2: `cargo xtask release --dry-run` fails if prototype files are present in shipped inputs (demonstrated by a test).
- A3: every page shows the design-artifact banner and `noindex`.
- A4: the index lists screens with state variants.
- A5: prototype CSS/JS equals shipped bundles (hash equality), proving fidelity.
**Tests.**
- Unit tests for reserved-name validation; release-guard test; link checker over the prototype set.
**Notes.** Interaction fidelity is deliberately low (no real backend), but visual and semantic fidelity is high.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.
