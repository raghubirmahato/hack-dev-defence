### T-0056 · Onboarding wizard and MFA enrollment flows (S-035, S-030, S-031)
`P03` `[UI]` · deps: T-0055 · size: M · owner: ux
**Objective.** Design the first-run flow that gets a user to a domain with minimal friction.
**Steps.**
1. Design the onboarding wizard steps: profile, organization name and slug availability check, security recommendation (MFA, passkey), notification email, first-domain call to action; each step is resumable and skippable where safe.
2. Design the persistent onboarding checklist component for the overview screen (progress, next best action, dismiss).
3. Design the MFA enrollment page with QR (SVG), manual key reveal, code confirm, and the passkey alternative.
4. Design empty-state content that explains what happens next.
5. Design the slug availability feedback (debounced, accessible) and slug editing warnings.
6. Design the "invite teammates" optional step.
7. Include variants for invite-accepted users (skip org creation).
8. Document analytics (local counters) for each step.
**Deliverables.**
- prototype pages; copy drafts
**Acceptance.**
- A1: every step can be skipped or resumed without data loss.
- A2: next-best-action rules match T-0026.
- A3: slug validation messages are specific and accessible.
- A4: the QR has a text alternative (manual key) and is not the only path.
- A5: onboarding works at 360 px width.
**Tests.**
- Axe; keyboard walkthrough; review against T-0026 spec.
**Notes.** Do not block product use on MFA enrollment except where policy forces it.
