### T-0057 · App shell, organization overview and domains list (S-040, S-041)
`P03` `[UI]` · deps: T-0053 · size: L · owner: ux
**Objective.** Design the daily entry points of the customer app.
**Steps.**
1. Design the app frame with sidebar, top bar, switchers, notification bell and user menu in expanded/collapsed/mobile modes.
2. Design the Org overview: KPI cards (requests, blocked, active bans, healthy domains), 24-hour chart with annotation markers, attention list (certificates expiring, domains in monitor too long, appeals pending, origin unhealthy), onboarding checklist, recent events.
3. Design the Domains list: table with status pills, WAF mode pill, readiness ring/score, requests, blocked, last event; filters; bulk actions (pause, change mode with confirmation); add button; draft resume rows.
4. Design all empty states: new org with no domains (primary CTA), domains without traffic ("waiting for traffic" status with troubleshooting link).
5. Design the plan-limit state (quota reached) without hiding security controls.
6. Design the loading and error states, including partial widget failure.
7. Design keyboard shortcuts overlay and the command palette view for this context.
8. Provide dark/light, 360/768/1280 variants.
**Deliverables.**
- prototype pages with states; copy drafts
**Acceptance.**
- A1: KPI cards support an `Unknown (reason)` variant.
- A2: attention list items have actions and link targets.
- A3: bulk mode change requires confirmation listing affected domains.
- A4: empty states show the next action; no fake numbers anywhere in non-example contexts.
- A5: layout works from 360 to 1536 px.
**Tests.**
- Axe; screenshot matrix; heuristic review.
**Notes.** The attention list drives engagement without dark patterns (R-28).
