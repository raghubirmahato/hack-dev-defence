### T-0068 · Platform admin screens (S-100 to S-130, S-135, S-136)
`P03` `[UI][SEC]` · deps: T-0057 · size: XL · owner: ux
**Objective.** Design the platform admin panel as a distinct, safe operational console.
**Steps.**
1. Design the admin frame and overview (S-100) with real-metric cards, attention list, and attack summary.
2. Design Tenants (S-101/S-102), Users (S-103/S-104), Domains (S-105), Impersonation (S-118) with the persistent banner and read-only enforcement visuals.
3. Design Global jail (S-106), Never-ban (S-109), Global rules and packs (S-107) with staged rollout UI, Threat intel (S-108).
4. Design Infra nodes (S-110), Services and queues (S-111), Certificates inventory (S-112), DNS zones (S-113).
5. Design Abuse (S-114), Signup policy (S-115), Plans (S-116), Platform audit (S-117).
6. Design System settings (S-119), Email templates (S-120), Feature flags (S-121), Emergency (S-122), Releases (S-123), Backups (S-124).
7. Design Exposure board (S-125), Virtual patches (S-126), DDoS readiness (S-127) with the three capacity numbers, Firewall/XDP (S-128), Announcements (S-129), Support lookup (S-130).
8. Design Runtime and uptime (S-135) with the persistent local-mode notice, the honest-values rule and the outbox viewer, and Hosting check and setup guide (S-136) with the per-check list, remediation links and the four-step local first-run flow (B12.2).
9. Define step-up prompts, reason-required dialogs and audit previews for sensitive actions.
**Deliverables.**
- prototype pages and states; admin interaction spec
**Acceptance.**
- A1: each mutation screen lists the permission ID and the audit event it will write.
- A2: the admin frame is visually distinct and meets contrast.
- A3: DDoS readiness screen shows lab-proven, provider-advertised and verified-live numbers separately with UNVERIFIED states.
- A4: impersonation visuals make read-only state unmistakable.
- A5: emergency controls require typed confirmation and show expiry.
- A6: S-135 renders only real metrics with empty states for missing sources, and S-136 never shows an availability figure without its method and window.
**Tests.**
- Axe; heuristic review; security-UX checklist.
**Notes.** Admin pages are denser; they still follow all accessibility rules.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
