### T-0069 · Accessibility, content and heuristic review of all prototypes
`P03` `[UI][QA]` · deps: T-0054, T-0055, T-0056, T-0057, T-0058, T-0059, T-0060, T-0061, T-0062, T-0063, T-0064, T-0065, T-0066, T-0067, T-0068 · size: L · owner: ux
**Objective.** Find and fix design defects before any product code depends on them.
**Steps.**
1. Run axe over every prototype state in dark and light and the viewport matrix; list violations by impact and screen.
2. Run claims-lint, glossary consistency checks, and i18n key coverage checks over prototype copy.
3. Perform the keyboard walkthrough scripts for the 12 critical flows; record results (pass, issue) with screenshots of focus order.
4. Perform a Nielsen-style heuristic evaluation on the 12 critical flows and the admin flows; log issues with severity and owner.
5. Perform the security-UX review per T-0025: every dangerous action has preview, confirmation, undo, and audit.
6. Perform the honesty review per the charter (five questions) for every screen and fix violations.
7. Fix all serious/critical issues and re-run; list accepted minor issues with justification.
8. Mark flows requiring human screen-reader checks as `human_step_pending` with instructions.
**Deliverables.**
- `docs/UX/reviews/prototype-review.md`, fix commits, updated prototypes, `acceptance-ui/axe-prototypes.json`
**Acceptance.**
- A1: zero serious or critical axe findings across prototypes.
- A2: all 12 critical flows have recorded keyboard walkthrough results.
- A3: heuristic issues of severity high are fixed.
- A4: every dangerous action in the T-0025 catalog is verified present in the designs.
- A5: honesty review recorded with zero open violations.
**Tests.**
- The review scripts and tools are repeatable via `xtask ui review`.
**Notes.** The accepted-minor list is revisited at the P28 accessibility acceptance.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.
