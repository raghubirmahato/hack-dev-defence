### T-0061 · Security center screens (S-054 to S-057)
`P03` `[UI][SEC]` · deps: T-0057 · size: L · owner: ux
**Objective.** Design the heart of the product: the per-domain security overview, WAF settings, categories and the Vulnerable-Origin Shield.
**Steps.**
1. Design Security overview (S-054): mode banner, attack timeline, top categories, "would have blocked" panel in monitor mode with examples, shield status, quick links.
2. Design WAF settings (S-055): mode selector with consequences panel, paranoia level and threshold with plain explanations, over-limit policy with warnings, scheduled monitor-to-block switch.
3. Design Attack categories (S-056): matrix of categories by action with coverage counts, per-category notes, and risk labels; show which ATK groups each category covers.
4. Design the Vulnerable-Origin Shield (S-057) exactly per B12.2: explainer, strictness, ban behavior panel, auth endpoint table, SQL injection subtype panel, learned shapes, "Try a payload" box with the six canonical payload quick-fills, limits statement.
5. Design the block-mode confirmation dialog with collateral warnings.
6. Design the self-lockout warning presentation for policy changes.
7. Design empty, loading, error and permission states.
8. Provide preset comparison view (table from C3.4).
**Deliverables.**
- prototype pages and states
**Acceptance.**
- A1: S-057 includes all nine regions of B12.2.
- A2: the payload test box shows verdict, subtype and "would ban" without implying the request was sent.
- A3: monitor-mode panel never displays fabricated example events outside example context.
- A4: block confirmation lists consequences and an undo path.
- A5: limits and honesty statements are present and pass claims-lint.
**Tests.**
- Axe; heuristic review; scripted scenario "Maya enables the shield".
**Notes.** The payload test box calls only the dry-run inspect API.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
