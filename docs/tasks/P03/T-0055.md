### T-0055 · Authentication screens (S-020 to S-034)
`P03` `[UI][SEC]` · deps: T-0053 · size: L · owner: ux
**Objective.** Design the identity screens so they are clear, accessible and enumeration-safe.
**Steps.**
1. Design Sign up (S-020) with the password component, strength and breach feedback, terms consent, optional proof-of-work state, and the closed/invite variants.
2. Design Check your email (S-021) and Verification result (S-022) with the confirm-button pattern, resend with cooldown, expired state.
3. Design Log in (S-023), MFA (S-024), recovery (S-025), passkey (S-026), forgot/reset (S-027, S-028), invitation (S-029), enrollment (S-030), recovery codes (S-031), step-up (S-032), session expired (S-033), locked (S-034).
4. Define exact error copy that never discloses account existence and wait-time messaging that does not reveal lock cause.
5. Define focus management for each page (first field or error summary) and the autocomplete attributes.
6. Define the layout on small screens and the behavior of password managers (field order, labels).
7. Design the email previews for verification, reset, invite and security notice (HTML and text) and ensure they render without remote images.
8. Include state variants: loading, rate limited, network error, success.
**Deliverables.**
- prototype pages and email previews; copy drafts in `i18n/en/auth.ftl`
**Acceptance.**
- A1: no page reveals whether an email is registered.
- A2: all forms use correct `autocomplete` and labels; axe passes.
- A3: recovery codes page forces acknowledgment before continuing.
- A4: the step-up modal and page variants are both designed.
- A5: emails have plain-text alternatives and no remote assets.
**Tests.**
- Axe; copy review against enumeration rules; keyboard walkthrough scripts recorded for sign up and login.
**Notes.** WCAG 3.3.8 requires no cognitive function tests: only password/passkey/TOTP entry from managers or devices.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
