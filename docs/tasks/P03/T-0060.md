### T-0060 · TLS and origin screens (S-050 to S-053, S-098)
`P03` `[UI][SEC]` · deps: T-0057 · size: M · owner: ux
**Objective.** Design certificate and origin management with clear risk signaling.
**Steps.**
1. Design TLS overview (S-050): mode, minimum version, redirect, HSTS ramp with preload caution, status badges.
2. Design Certificates (S-051): list, details drawer, renewal timeline, ACME error explanations with next steps, custom upload.
3. Design Origin settings (S-052): fields, verification mode explanation, secret header status, test connection results.
4. Design Origin health (S-053): probe history chart, error classification, alert settings.
5. Design the Origin lockdown wizard (S-098): stack picker, generated allowlist/snippets with copy, verification probes with status, rollback instructions.
6. Design the lockdown warning that bypassing HDD becomes impossible and what to do if HDD is down (break-glass explanation).
7. Provide states for pending issuance, rate limited by CA, CAA conflicts, expired certificate.
8. Provide small-screen variants.
**Deliverables.**
- prototype pages and states
**Acceptance.**
- A1: HSTS controls show the staged ramp and preload warning.
- A2: ACME errors map to plain-language causes and remedies.
- A3: lockdown wizard explicitly lists how to roll back.
- A4: plaintext origin mode is visually flagged.
- A5: all snippet blocks have copy buttons and warnings to review before applying.
**Tests.**
- Axe; copy review; heuristic review.
**Notes.** Snippets are templates; the design shows them as examples only.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
