### T-0064 · Live monitor, event detail and analytics (S-065, S-066, S-070 to S-072)
`P03` `[UI]` · deps: T-0057 · size: L · owner: ux
**Objective.** Design the investigation experience for analysts.
**Steps.**
1. Design the Live threat monitor (S-065) per B12.2: columns, controls, filters, pause, new-event counter, connection status text, density, saved views, bulk actions.
2. Design the Event detail drawer/page (S-066): decision timeline, rule and policy branch, redacted evidence in `PayloadViewer`, request metadata, IP history, related events, actions (ban, allow, exception).
3. Design Analytics overview (S-070): KPI row, charts with annotation markers, status classes, latency percentiles, time range picker.
4. Design Geo and ASN (S-071): map plus ranked table alternative; Top attackers and paths (S-072).
5. Design compare-to-previous-period views and the empty/insufficient-data states.
6. Design export dialogs.
7. Design small-screen simplifications (details in drawer).
8. Design print views.
**Deliverables.**
- prototype pages and states
**Acceptance.**
- A1: live monitor behaves without auto-scroll while focus is inside and announces batches politely.
- A2: the map has a complete ranked-table alternative.
- A3: charts have text summaries and table toggles.
- A4: event detail never shows unredacted secrets and caps evidence at 512 bytes in the design.
- A5: annotation markers for mode/rule changes are designed.
**Tests.**
- Axe; keyboard walkthrough; heuristic review.
**Notes.** The monitor design must work for 10,000 events per hour without layout instability.
