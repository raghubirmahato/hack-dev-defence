### T-0154 · Domain input validation, normalization and claim rules
`P08` `[API][SEC]` · deps: T-0153 · size: M · owner: api
**Objective.** Accept only valid, safe, non-conflicting domain names.
**Steps.**
1. Implement parsing: trim, strip scheme/path/port if pasted as URL (with a notice), lowercase, IDNA2008 conversion to ASCII (punycode) with display of the Unicode form, reject mixed-script confusables per policy, reject labels over 63 or names over 253 characters, reject trailing dots normalization issues.
2. Implement registrable-domain detection with the public suffix list (vendored with update job and checksum), distinguishing apex (registrable domain) from subdomains; offer to add the apex when `www.example.org` is entered.
3. Reject reserved and dangerous names: the platform domain and its subdomains, `localhost`, `.local`, `.internal`, `.invalid`, `.test`, `.example` outside test mode, single-label names, IP literals, public suffixes themselves, and names matching the reserved hostnames list (ns1/ns2, HDD edge/acme zones).
4. Implement claim rules: if the hostname is already `active` in another org return `ERR-DOM-002` with the dispute flow link; if `draft` or `pending` elsewhere, allow concurrent drafts but only one can verify first; periodic cleanup of abandoned drafts after 14 days.
5. Implement bulk parsing (up to 20 per submission) with per-line errors.
6. Implement quota checks and rate limits (10 additions per hour per org, 30 per day).
7. Implement an abuse deny list (operator-managed hostnames or suffixes that cannot be proxied) editable by platform admins.
8. Add tests with a corpus of 300 valid and invalid names including homoglyph attacks.
**Deliverables.**
- `hdd-common::domain` module, tests, deny list
**Acceptance.**
- A1: confusable and mixed-script names are rejected or flagged per policy.
- A2: platform and reserved names cannot be added (tests).
- A3: `www.example.org` suggests the apex and still allows the subdomain-only mode.
- A4: bulk errors are reported per line.
- A5: parsing never panics (fuzz).
**Tests.**
- Table tests (300 names); fuzz target on the parser; proptest for idempotent normalization.
**Notes.** The public suffix list is data; updates are verified by checksum and recorded.
