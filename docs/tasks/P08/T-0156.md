### T-0156 · Existing-DNS scan job (step 2)
`P08` `[API][OPS][SEC]` · deps: T-0155, T-0009 · size: L · owner: dns
**Objective.** Discover a domain's current DNS using only lawful, rate-limited lookups through allowlisted resolvers.
**Steps.**
1. Implement the scan job in `hdd-worker` using `hickory-client` through the egress client policy (resolvers from `egress_allowlist`; at least two named public resolvers plus iterative queries to the domain's authoritative servers discovered via NS lookups, all under the egress class `dns_resolution` of section 2.1: public-unicast targets only, port 53 only), with global and per-domain rate limits (at most 10 qps per scan, 3 concurrent scans).
2. Query the parent NS delegation, apex NS, SOA, A, AAAA, CNAME, MX, TXT, SRV, CAA, HTTPS/SVCB at the apex and on a candidate name list (`www`, `mail`, `smtp`, `imap`, `pop`, `webmail`, `ftp`, `ssh`, `vpn`, `api`, `app`, `dev`, `staging`, `autodiscover`, `autoconfig`, `_dmarc`, `_domainkey` selectors discovered from TXT, `_acme-challenge`, `selector1/2._domainkey`, SRV standards), wildcard detection by querying random labels, and optional AXFR attempt only if the owner opts in (against their own NS, with TSIG options).
3. Detect provider by NS suffix and common record patterns (informational only).
4. Detect DNSSEC (DS at parent, DNSKEY at apex) and flag the DS risk early.
5. Classify results into groups (web, mail, other, unknown) and mark records proxiable vs non-proxiable with reasons.
6. Store results in `dns_scans.findings` with timestamps and resolver evidence; handle partial failures with explicit gaps.
7. Provide progress via polling or SSE to the wizard; respect cancellation.
8. Add tests using a real local authoritative server (hickory-server on loopback) serving varied zones including weird cases (wildcards, CNAME chains, large TXT).
**Deliverables.**
- scan job, findings schema, tests
**Acceptance.**
- A1: scanning never queries non-allowlisted resolvers (egress denial test).
- A2: wildcard zones are detected and flagged.
- A3: scanning a zone with 500 candidate-name misses stays within the rate limit.
- A4: DS presence is reported with the parent evidence.
- A5: results are deterministic for a fixed zone (ordering and formatting).
**Tests.**
- Integration against loopback authoritative servers with crafted zones; unit: classification tables.
- Fuzz: DNS response handling via the library boundary.
**Notes.** The scan does not send HTTP requests to the domain.
