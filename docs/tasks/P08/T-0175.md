### T-0175 · Onboarding end-to-end tests for all integration modes (AC-37)
`P08` `[QA]` · deps: T-0169, T-0172, T-0173, T-0174 · size: XL · owner: qa
**Objective.** Prove the wizard works end to end for every mode against real DNS and HTTP behavior.
**Steps.**
1. Build e2e tests using a local simulated DNS hierarchy and an authoritative server (loopback) for `full_ns`, `cname_partial`, `a_record_partial`, `subdomain_only`, and (when hidden primary exists) `hidden_primary`; include the operator's pilot subzones for the live variant later.
2. Script the owner's DNS changes in the tests by updating the simulated provider zones, exercising pollers and state transitions with the test clock.
3. Cover negative paths: wrong TXT, stale CNAME, DS present, origin unreachable, SSRF attempts, quota exceeded, dispute, abandoned draft.
4. Cover accessibility: keyboard-only completion of the wizard and screen-reader tree snapshots at each step.
5. Cover responsive variants (360 px) and dark/light baselines for every step.
6. Cover rollback: pause, DNS-only bypass, decommission.
7. Measure wizard timing and the number of user actions per mode (reported).
8. Integrate with `cargo xtask acceptance --only AC-37` including the live pilot variant (P11).
**Deliverables.**
- `tests/e2e/onboarding/*`, simulated DNS hierarchy fixtures, reports
**Acceptance.**
- A1: all modes reach `active` in the simulated environment with correct records and certificate plan.
- A2: negative paths show specific, actionable messages.
- A3: keyboard-only completion succeeds for each mode.
- A4: visual baselines exist for every step.
- A5: the suite runs under 15 minutes.
**Tests.**
- The suite; plus a meta-test confirming the simulated hierarchy behaves like a real resolver chain (cross-checked with `dig` as an oracle where available).
**Notes.** The live variant requires STOP #1 completion (pilot delegation).
