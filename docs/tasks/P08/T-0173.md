### T-0173 · Domain settings and decommission wizard (S-094)
`P08` `[UI][API][SEC]` · deps: T-0170, T-0171 · size: L · owner: api
**Objective.** Remove a domain safely without leaving it broken or dangling.
**Steps.**
1. Implement the decommission wizard: choose the end state (return DNS to the previous provider with exact records to restore, keep DNS-only on HDD, or remove entirely), show a diff of what changes, export the zone (BIND), and list certificates and their revocation option.
2. Require type-to-confirm with the domain name and step-up; enforce a cooling-off option (schedule removal for later).
3. Implement execution: set state `removing`, stop proxying (switch answers to grey or remove records according to the end state), release the hostname claim after the cooling period (default 7 days) to prevent immediate takeover, revoke or delete certificates (optional revocation through ACME), clear bans and caches, delete configuration after retention (events retained per retention policy, anonymization option).
4. Provide dangling-record warnings (CNAMEs pointing to HDD edge names after removal) and a periodic check that sends reminders to remove them.
5. Implement notifications and audit events.
6. Implement the API and idempotency.
7. Test all end states in `full_ns` and partial modes.
8. Add accessibility and the instruction clarity review.
**Deliverables.**
- wizard, jobs, tests
**Acceptance.**
- A1: the exported zone re-imports to an identical zone (round trip).
- A2: hostname claims are held for the cooling period.
- A3: dangling CNAME warnings are produced for partial modes.
- A4: certificates are revoked or retained according to the choice, with audit.
- A5: decommission can be canceled before execution.
**Tests.**
- Integration scenarios; unit: end-state planner; browser: wizard.
**Notes.** Events and rollups follow the org retention policy after removal.
