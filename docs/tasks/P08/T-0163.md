### T-0163 · Origin configuration (step 6) and SSRF guard at save time
`P08` `[UI][API][SEC]` · deps: T-0009, T-0153 · size: L · owner: api
**Objective.** Let owners define their origin safely, with the SSRF policy enforced and explained.
**Steps.**
1. Implement the form: scheme (https default, http requires acknowledgment), host (hostname or IP), port (allowlist 80/443/8080/8443 plus plan extras), Host header (default the domain), SNI name, TLS verification mode (`webpki`, `pinned_ca`, `pinned_spki`, `http_origin_ack`), pin value upload/paste, health path (default `/`), and origin weight for pools (single in Tier 1).
2. Validate the address with the SSRF guard: resolve hostnames, reject disallowed ranges, pin the validated addresses in the record (with TTL-based refresh), reject HDD's own platform addresses (loop prevention, `ERR-ORIGIN-005`), and reject hostnames that resolve into the disallowed ranges at any time.
3. Store the origin with secrets encrypted (secret header, pinned material if sensitive).
4. Implement the plaintext-origin acknowledgment: a clear explanation of the risk, a typed confirmation, and a persistent readiness penalty and banner.
5. Implement edit with `If-Match`, audit events, and snapshot revision publication.
6. Implement the pinned CA/SPKI input parsing with validation and error messages, and a "fetch current certificate details" helper that shows what the connection test sees (not auto-trusting).
7. Implement rate limits and quotas.
8. Test SSRF vectors: IP encodings, DNS names resolving to private addresses, IPv4-mapped IPv6, redirects (not followed), rebinding sequences.
**Deliverables.**
- origin service, form, tests
**Acceptance.**
- A1: the 60 SSRF vector fixtures (ATK-091 to ATK-097 forms plus platform-loop cases) are all rejected with `ERR-ORIGIN-001`.
- A2: a hostname that changes DNS to a private address after save is rejected at connect time (rebinding test).
- A3: the plaintext option requires typed confirmation and is flagged in readiness.
- A4: platform addresses are never accepted as origins.
- A5: secrets are encrypted and not rendered back.
**Tests.**
- Unit: range classifier (shared with T-0009); integration: DNS rebinding simulation with loopback authoritative server; browser: form flows.
**Notes.** The same guard runs at connect time in the proxy (T-0365).

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
