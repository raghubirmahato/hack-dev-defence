### T-0160 · Ownership verification engine
`P08` `[API][SEC]` · deps: T-0154, T-0156 · size: L · owner: dns
**Objective.** Prove control of a hostname before any traffic is proxied, and keep proving it.
**Steps.**
1. Implement challenge creation: per-site random token (192 bits), TXT name `_hdd-verify.<hostname>` with value `hdd-verification=<token>`, and HTTP proof path `/.well-known/hdd-verification/<token>` expecting the token as the body; tokens are unique per (site, hostname) and rotated on mode change.
2. Implement the DNS checker (queries via at least two resolvers and the authoritative servers directly, requiring consistency per policy) and the HTTP checker (single GET with strict limits: HTTPS or HTTP, no redirects across hostnames, 5 s timeout, 4 KB body cap, SSRF guard against private addresses, one attempt per check, user agent `HDD-Verifier`).
3. Implement the polling schedule (every 30 s for 10 minutes after the user clicks "Check now", then every 5 minutes for 24 hours, then hourly up to 7 days) with `next_check_at` shown in the UI and a rate-limited manual trigger.
4. Implement re-verification: active domains re-check at least every 24 hours; failure for 7 days moves the domain to `pending_verification` with notifications and a 14-day traffic grace period before pause.
5. Implement dispute handling support (verified control wins; see T-0174).
6. Implement metrics and audit events for success/failure with reasons.
7. Implement wildcard/CNAME edge cases (TXT at the label with CNAME conflicts: advise `_hdd-verify` is a separate label so no conflict).
8. Test with real local DNS and HTTP servers, including CDN-style caching delays and attacker-controlled content (token reflected by attacker's site must not count unless it matches expected content exactly).
**Deliverables.**
- verification module, jobs, tests
**Acceptance.**
- A1: verification succeeds only with exact token content and fails for partial matches.
- A2: the HTTP checker refuses to connect to private/loopback targets (SSRF guard).
- A3: a hostname resolving to HDD's own addresses does not verify via HTTP unless the DNS proof exists (loop prevention).
- A4: re-verification failure timeline matches the specification (test clock).
- A5: manual checks are rate-limited.
**Tests.**
- Integration with loopback servers; unit: schedule computation; security tests for SSRF and token reflection.
**Notes.** Verification is required in `saas` mode; in `owner_only` mode listed domains may be waived explicitly.
