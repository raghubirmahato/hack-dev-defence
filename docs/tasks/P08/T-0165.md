### T-0165 · Origin IP exposure analysis
`P08` `[API][SEC]` · deps: T-0158, T-0163 · size: M · owner: sec
**Objective.** Tell owners how likely it is that attackers already know the origin IP, and what to do.
**Steps.**
1. Implement analysis inputs: scan results (records pointing at the origin IP or its network), MX/SPF/TXT leaks, certificate transparency names (via an allowlisted CT search service if configured), headers in responses from the origin (`Via`, `X-Served-By`, `Server`), and user-provided history (checkbox: "Our origin IP was previously public").
2. Compute an exposure level (likely exposed, possibly exposed, no evidence found) with reasons; never claim "not exposed".
3. Generate remediation steps: apply origin lockdown (firewall allowlist of HDD IPs, secret header), rotate the origin IP if exposure is likely, remove leaking records, separate mail infrastructure.
4. Present results in step 4/6 and on the origin pages with links to the lockdown wizard.
5. Re-run on schedule (weekly) and on DNS changes; raise attention items when new exposure appears.
6. Provide API access and include in readiness.
7. Respect egress policy: CT lookups only if the operator allowlisted a CT search service; otherwise mark `UNVERIFIED(capability_not_supplied)` for that signal.
8. Test with fixtures.
**Deliverables.**
- analysis module, UI panels, tests
**Acceptance.**
- A1: records sharing the origin IP produce "likely exposed" with the record list.
- A2: without a CT service configured the CT signal shows the capability requirement (not zero).
- A3: the analysis never contacts the origin beyond the approved probe.
- A4: regressions trigger an attention item.
- A5: wording avoids absolute claims (claims-lint).
**Tests.**
- Scenario tests (20); unit: scoring; integration: scheduled re-run.
**Notes.** Passive-DNS history lookups are `UNVERIFIED` unless an allowlisted service is configured (AC-18).
