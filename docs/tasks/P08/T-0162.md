### T-0162 · CNAME and A-record verification for partial modes
`P08` `[API][OPS]` · deps: T-0160 · size: M · owner: dns
**Objective.** Detect when partial-mode records point at HDD correctly.
**Steps.**
1. Implement the CNAME checker: resolve the target name chain for each required hostname through allowlisted resolvers, verify the final target is `<site-id>.edge.{{PLATFORM_DOMAIN}}` and that the edge name resolves to HDD edge addresses; detect CNAME flattening artifacts.
2. Implement the A/AAAA checker for apex mode: compare returned addresses with `platform.public_ipv4/6`; warn about partial matches and stale addresses.
3. Implement the optional `_acme-challenge` CNAME check for pre-issuance.
4. Implement coexisting-record conflicts detection (a CNAME at a name with other data), and wildcard shadowing.
5. Provide a per-hostname status table with next check time and remediation hints (TTL waits, provider-specific caveats at generic level).
6. Handle IPv6 (AAAA) correctness: if HDD has no IPv6, warn that existing AAAA records pointing at the origin will bypass HDD and must be removed.
7. Notify on completion and on regressions after activation (CNAME removed or pointed elsewhere).
8. Test with local zones.
**Deliverables.**
- checkers, UI, tests
**Acceptance.**
- A1: stale AAAA pointing at the origin is flagged as a bypass risk.
- A2: apex A-record mode requires matching all HDD addresses (or reports partial).
- A3: regressions after activation produce an attention item and notification.
- A4: results are consistent across resolvers or flagged as propagating.
- A5: no HTTP requests are made to the tenant host by this checker.
**Tests.**
- Integration with loopback zones; unit: conflict detection; browser: status table.
**Notes.** TLS pre-issuance uses these results to decide readiness (T-0166).
