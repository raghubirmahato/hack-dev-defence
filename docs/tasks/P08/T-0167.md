### T-0167 · Protection preset selection (step 7)
`P08` `[UI][API][SEC]` · deps: T-0159 · size: M · owner: api
**Objective.** Start every domain in a safe, understandable protection posture.
**Steps.**
1. Implement preset definitions as data (C3.4): `monitor_first` (default), `balanced`, `strict`, `vuln_shield_balanced`, `vuln_shield_paranoid`, each producing a full `waf_policies` document with explicit values.
2. Implement the preset cards with plain-language summaries, a side-by-side comparison, and links to details; default `monitor_first` always for new domains, with a warning if the user selects block-mode presets before any traffic observation (they can, with an acknowledgment).
3. Implement the "start in monitor, auto-suggest block after N days of clean data" scheduler (user opt-in) that creates a reminder and shows the would-block summary.
4. Persist the preset and create the first `config_revision`.
5. Implement preset switching later (S-055) producing a diff view before applying.
6. Implement per-preset readiness implications.
7. Add tests verifying that preset documents match C3.4 values.
8. Document the presets in the docs site.
**Deliverables.**
- preset definitions, UI, tests, docs
**Acceptance.**
- A1: preset documents equal the C3.4 table values (golden test).
- A2: choosing a block-mode preset pre-traffic requires acknowledgment.
- A3: switching presets shows a diff and writes a revision.
- A4: the default is always `monitor_first`.
- A5: the comparison view is accessible (table semantics).
**Tests.**
- Golden tests; browser flows; unit: diff generator.
**Notes.** Presets are data, so tests can validate them without running the data plane.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
