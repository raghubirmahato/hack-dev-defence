### T-0161 · NS delegation checker and DS detection
`P08` `[API][OPS]` · deps: T-0160 · size: M · owner: dns
**Objective.** Detect when nameserver delegation to HDD is complete and flag DNSSEC risks.
**Steps.**
1. Implement the delegation checker: query the TLD/parent servers (iteratively from the root hints through allowlisted resolvers or by following referrals, under the egress class `dns_resolution` of section 2.1) for the domain's NS set and compare with the assigned HDD pair, also query via at least two public recursive resolvers to model propagation.
2. Record observations in `delegation_checks` (resolver, observed NS, match, DS present, timestamp) and compute the state (not delegated, partially delegated, delegated, delegated with stale parent TTL).
3. Implement DS detection and DNSSEC warnings: if DS exists at the parent and HDD serves unsigned data the zone will fail validation; block activation until the user acknowledges removal steps or provides signing keys (future), with exact instructions and TTL timing (remove DS one full DS TTL before NS change).
4. Implement the post-delegation sanity checks: HDD answers authoritatively for the apex SOA and NS and for the verification TXT.
5. Implement status UI (poller component) with last/next check, per-resolver matrix, and remediation hints (typical registrar mistakes: adding NS without removing old, glue missing for in-bailiwick, uppercase/trailing dot issues).
6. Implement notifications when delegation completes or has not completed after 48 hours.
7. Implement tests with local simulated hierarchies (loopback authoritative servers acting as root/TLD/zone).
8. Document timing expectations and TTLs.
**Deliverables.**
- checker, UI poller, tests, docs
**Acceptance.**
- A1: partial delegation (old and new NS mixed) is reported accurately.
- A2: DS presence blocks activation until acknowledged with explicit text.
- A3: the checker uses only allowlisted resolvers or iterative queries to servers returned by referrals with the public-address policy.
- A4: status changes trigger notifications exactly once.
- A5: the poller UI announces state changes politely.
**Tests.**
- Integration with a simulated DNS hierarchy; unit: state computation; browser: poller updates.
**Notes.** Registrar API automation is optional and deferred; manual instructions are the default (R-04).
