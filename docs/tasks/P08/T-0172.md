### T-0172 · Protection Readiness Score engine and page (S-044)
`P08` `[API][UI]` · deps: T-0171, T-0026 · size: L · owner: api
**Objective.** Compute and present an honest measure of configuration completeness.
**Steps.**
1. Implement the check catalog from the readiness model (T-0026) as typed checks with id, group, weight, data sources, evaluation function returning `Pass | Partial(ratio) | Fail | Unknown(reason)`, remediation link, and "why it matters" text keys.
2. Implement the weights summing to 100 per the model in B12.2 and per-mode adjustments (checks not applicable to a mode are removed and weights renormalized with documented rules).
3. Implement scoring rules: unknown scores 0 and is displayed distinctly; partial credit rules are explicit (for example HSTS by max-age tier); the total is rounded down.
4. Implement caching with invalidation on relevant events (certificate change, origin test, setting change) and a periodic refresh job; store history snapshots for trend display.
5. Implement the page: ring component, grouped checklist, remediation actions, history sparkline, the footnote, and a "What is this score?" explanation.
6. Implement the API and the attention-list integration (score below 60, newly failed critical checks).
7. Add exhaustive unit tests (property tests for monotonicity: fixing a failed check never decreases the score).
8. Document each check in the docs site (generated from the catalog).
**Deliverables.**
- readiness engine, page, docs, tests
**Acceptance.**
- A1: weights sum to 100 for each mode after renormalization (tests).
- A2: unknown never counts as pass (property test).
- A3: score monotonicity holds across random configurations.
- A4: each check has a docs entry and remediation link.
- A5: the footnote is present and linked.
**Tests.**
- Unit/proptest; integration: cache invalidation; browser: page accessibility and ring text.
**Notes.** AC-53 verifies score correctness against scenario fixtures.
