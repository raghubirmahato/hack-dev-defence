### T-0174 · Domain transfer between organizations and dispute resolution
`P08` `[API][UI][SEC]` · deps: T-0160, T-0153 · size: M · owner: api
**Objective.** Resolve conflicting claims and move domains between orgs safely.
**Steps.**
1. Implement the dispute flow: when an org tries to add a hostname active in another org, they can start a dispute by proving control through the verification methods; if proof succeeds while the incumbent fails re-verification, the claim moves per policy after a notice period (7 days) to the incumbent with a chance to respond.
2. Implement notifications to the incumbent org's owners with evidence summary (no sensitive data), a response deadline, and the option to release.
3. Implement admin-assisted transfer (platform support with reason) and org-to-org voluntary transfer (source owner initiates, target owner accepts, step-up for both), transferring configuration, DNS, certificates (re-encrypted under new org context), bans and history references as configured.
4. Implement locks to prevent transfer loops and abuse (rate limits, cooling period).
5. Implement audit events and platform review queue entries for disputes.
6. Implement UI for dispute status and transfer wizard.
7. Define abuse scenarios (griefing disputes, attacker claiming dangling domains) and mitigations; test them.
8. Document the policy.
**Deliverables.**
- dispute and transfer services, UI, docs, tests
**Acceptance.**
- A1: a dispute cannot succeed without valid proof of control.
- A2: the incumbent is notified and has the notice period.
- A3: voluntary transfers require both owners' step-up.
- A4: transferred certificates are re-encrypted under the new context and old context loses access.
- A5: griefing disputes are rate-limited and flagged to the platform queue.
**Tests.**
- Integration scenarios with the test clock; security tests for abuse cases.
**Notes.** Disputes are rare but must exist to prevent permanent squatting.
