### T-0153 · Domain data model and lifecycle state machine
`P08` `[DB][API]` · deps: T-0126 · size: L · owner: api
**Objective.** Define the domain/site schema and the legal state transitions.
**Steps.**
1. Write migration 0006: `sites`, `site_hostnames`, `domain_verifications`, `domain_claims`, `dns_scans`, `delegation_checks`, `origins`, `origin_pools`, `origin_health`, `config_revisions` (initial), with RLS, indexes, uniqueness (global unique hostname constraint for active claims), and check constraints for enumerations.
2. Define the state machine: `draft → pending_verification → pending_delegation → active → paused → suspended → removing → removed`, with permitted transitions, actors (user, system, platform) and side effects; encode as a typed `DomainState` with a transition table and a single `transition()` function that writes audit events and publishes snapshot revisions.
3. Define derived flags (`serving`, `proxied_names`, `needs_attention`) computed from state and checks.
4. Define invariants: a hostname can be active in at most one org; `active` requires verified ownership; `paused` keeps DNS but passes traffic through without inspection (pass-through) or stops proxying per user choice (documented); `suspended` is a platform action serving the neutral suspended page.
5. Implement repository functions with `OrgTx` and optimistic concurrency.
6. Implement the snapshot revision hook: any transition affecting serving increments the site's `config_revision` and notifies the config bus (built in P11/P18; here it writes to an outbox table consumed later).
7. Generate state-machine documentation and a diagram from the table.
8. Add tests for illegal transitions.
**Deliverables.**
- migration, state machine module, docs
**Acceptance.**
- A1: illegal transitions are rejected by type or runtime with `ERR-DOM-005`.
- A2: two orgs cannot both activate the same hostname (unique constraint test).
- A3: every transition writes an audit event.
- A4: state documentation is generated from code and matches.
- A5: RLS isolation tests pass for all new tables.
**Tests.**
- Unit: exhaustive transition table test; integration: constraints and concurrency; proptest on random transition sequences keeping invariants.
**Notes.** The `config_revisions` outbox is read by the data plane in P11.

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
