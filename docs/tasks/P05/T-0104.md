### T-0104 · Public site gate G05
`P05` `[UI][QA][DOC]` · deps: T-0096, T-0098, T-0099, T-0100, T-0101, T-0102, T-0103 · size: M · owner: qa
**Objective.** Certify the public surface.
**Steps.**
1. Run the full UI verification on public pages: axe, keyboard traversal, reflow, spacing, forced colors, reduced motion, visual regression, performance budgets, JS-disabled tests.
2. Run claims-lint, docs check, link check, i18n check, and the network trap (no third-party requests) across all public routes.
3. Verify cookies set (only essential), headers (CSP, HSTS), and robots/sitemap behavior.
4. Verify the evidence-driven claims display with and without evidence.
5. Verify legal-guard behavior and signup gating on unresolved legal text.
6. Record real outputs, hashes and metrics in `docs/gates/G05.md` (Appendix E5).
7. Update the capability matrix (REQ-PUB rows) and STATUS; list UNVERIFIED items (screen-reader checks, operator legal text, status external hosting).
8. Tag `gate-G05`.
**Deliverables.**
- `docs/gates/G05.md`, updated baselines
**Acceptance.**
- A1: zero serious/critical axe findings; budgets pass; no third-party requests.
- A2: all public pages work with JavaScript disabled.
- A3: claims-lint, docs check and i18n check pass.
- A4: the gate report is complete with pasted output tails.
- A5: the tag exists and UNVERIFIED items are listed with what the operator must supply.
**Tests.**
- Full `cargo xtask verify` and `cargo xtask ui verify` run captured.
**Notes.** Public launch of the site waits for the operator to supply legal and brand text.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
