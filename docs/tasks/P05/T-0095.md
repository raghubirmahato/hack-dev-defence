### T-0095 · Public surface scaffolding and the landing page (S-001)
`P05` `[UI]` · deps: T-0094, T-0054 · size: M · owner: ui
**Objective.** Implement the public frame and the landing page from the approved design.
**Steps.**
1. Implement the public router (`/`, `/features`, `/how-it-works`, `/pricing`, `/contact`, `/security`, `/status`, `/docs`, `/api-reference`, `/legal/*`) with route metadata from `routes.toml` and caching headers (public pages cacheable for 5 minutes with `stale-while-revalidate`).
2. Implement header/footer navigation, language and theme controls, and signup-state-aware calls to action (`disabled`, `invite_only`, `open`) read from platform settings.
3. Implement the landing page content: value statement, three-step explanation, honest-limits teaser, evidence strip fed by the claims-evidence file (T-0096), and a footer with legal links.
4. Add structured, minimal metadata (title, description, canonical, Open Graph with the generated card) and no analytics.
5. Add the `noscript` friendly rendering test and ensure all content is present without JavaScript.
6. Add copy to `i18n/en/public.ftl` from the approved design and verify with claims-lint.
7. Add the maintenance and error variants.
8. Write browser tests for navigation, keyboard, and responsive behavior.
**Deliverables.**
- public router and templates, i18n copy, tests
**Acceptance.**
- A1: landing meets the performance budgets (LCP, size) on the mobile profile.
- A2: CTA variants render correctly for all three signup modes.
- A3: page passes axe and has one `h1` and correct landmarks.
- A4: no third-party requests (network trap).
- A5: copy passes claims-lint.
**Tests.**
- Browser: three signup-mode variants; JS-off; axe; perf.
- Visual baselines for light/dark and 360/1280.
**Notes.** Signup routes (`/signup`) exist from T-0107.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
