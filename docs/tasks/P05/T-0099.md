### T-0099 · API reference page (S-007) from OpenAPI
`P05` `[UI][API][DOC]` · deps: T-0097 · size: M · owner: docs
**Objective.** Publish an accurate, readable API reference generated from the OpenAPI document.
**Steps.**
1. Implement the renderer that consumes `/openapi.json` (from `utoipa`, populated progressively as endpoints land) and renders resource groups, operations, parameters, request/response schemas, error codes and example requests (curl) server-side as accessible HTML.
2. Include authentication sections (API keys, scopes), pagination, idempotency, rate limit headers, errors (RFC 9457), versioning policy and webhooks verification.
3. Generate curl examples from schemas deterministically; mark destructive operations visibly.
4. Provide a search box (reusing the docs index) and anchors per operation.
5. Provide a downloadable `openapi.json` and a changelog page generated from OpenAPI diffs between releases.
6. Add contract tests ensuring the reference lists every route in the route table that is marked API.
7. Make the page work with JavaScript disabled; copy buttons are enhancements.
8. Add print styles.
**Deliverables.**
- renderer, page templates, changelog generator, tests
**Acceptance.**
- A1: every API route in the route table appears in the reference (test).
- A2: curl examples are syntactically valid (parsed by a shell-free checker) and use placeholders for secrets.
- A3: schemas render recursively without infinite loops (cycle handling test).
- A4: page passes axe and is usable at 360 px.
- A5: changelog marks breaking vs additive changes.
**Tests.**
- Unit: schema rendering cycles; golden tests of rendered operations.
- Integration: contract test against the live OpenAPI output.
**Notes.** The reference grows as phases add endpoints; the contract test prevents omissions.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
