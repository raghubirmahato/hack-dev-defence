### T-0102 · Contact, abuse report and security disclosure (S-009, S-014)
`P05` `[UI][SEC]` · deps: T-0095, T-0109 · size: M · owner: ui
**Objective.** Let people reach the operator and report problems without creating abuse vectors.
**Steps.**
1. Implement the contact form with fields (name optional, email, message), proof-of-work (`hdd-challenge` component when available, else a rate-limit-only baseline), honeypot field, and strict limits (message 4,000 chars, one per minute per IP, 5 per day per email-HMAC).
2. Deliver contact messages by email to `branding.support_email` through the outbox (T-0109) with headers preventing injection; store a minimal record (no raw message retention beyond 30 days).
3. Implement the abuse report form (`POST /public/abuse-report`): hostname, category (phishing, malware, copyright, other), evidence URL (validated, not fetched), reporter contact optional; stored in `abuse_reports`; acknowledgment email only if an address was provided and verified by a link.
4. Implement the security disclosure page (S-014) with scope, safe-harbor draft text flagged for operator/counsel review, contact addresses, encryption key placeholder, and response targets (acknowledge 3 business days).
5. Serve `/.well-known/security.txt` generated from the profile (contact, expires within one year, preferred languages, policy URL, canonical), with a reminder task when expiry approaches.
6. Add anti-enumeration and anti-email-bombing measures (never echo the entered email back as confirmed delivery to third parties).
7. Add admin notifications for new reports.
8. Add tests for header injection payloads in names and subjects.
**Deliverables.**
- forms, handlers, security.txt generator, templates, tests
**Acceptance.**
- A1: CRLF and header injection attempts do not alter email headers (tested with the SMTP sink).
- A2: rate limits trigger and return generic messages.
- A3: `security.txt` validates and is regenerated before expiry (job).
- A4: abuse reports never trigger server-side fetches of the evidence URL.
- A5: disclosure page contains the draft/review flag until the operator approves.
**Tests.**
- Integration with the SMTP sink; unit: security.txt format; browser: form flows.
**Notes.** Abuse report handling workflow for admins is T-0428.
