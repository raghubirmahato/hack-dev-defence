### T-0098 · Documentation content v1
`P05` `[DOC]` · deps: T-0097, T-0019 · size: XL · owner: docs
**Objective.** Write the documentation users need to succeed and trust the product.
**Steps.**
1. Write Get started: create an account, add a domain, choose a connection method, verify, set origin, go live; each page uses the exact UI copy and includes screenshots generated from the visual-regression harness (no hand-made images).
2. Write Concepts: orange vs grey cloud, WAF modes, paranoia levels, hard vs soft detections, ban policy and TTL ladder, challenge, shield, readiness score, revisions and safe mode.
3. Write DNS guides: full nameserver delegation, CNAME/partial setup, apex options, importing records, email records safety, DNSSEC and DS warnings; generic provider-agnostic steps with clearly labeled provider-specific notes only where verified.
4. Write TLS guides: certificate issuance, pre-issuance via CNAME delegation, HSTS ramp, custom certificates, CAA.
5. Write Security guides: "Protecting a login form" (including the SQL injection shield walkthrough and what is blocked), "Protecting a vulnerable site", rule writing, exceptions, false-positive handling, rate limiting, bots, access lists, origin lockdown per stack, outbound protection, appeals.
6. Write Operations guides: alerts, webhooks (with signature verification samples), API keys, audit log, team and roles, reports, data export.
7. Write Reference: configuration, error codes (generated), permissions (generated), metrics, API changelog, limitations and known issues.
8. Run claims-lint, link check, and a "docs-versus-UI" check that every UI string quoted in docs exists in `i18n/en`.
**Deliverables.**
- `docs/site/**/*.md` (at least 60 pages), generated includes, screenshots from harness
**Acceptance.**
- A1: every journey J-01 to J-34 is covered by at least one guide.
- A2: each guide ends with troubleshooting and "what to do if this goes wrong".
- A3: claims-lint passes; all commands in guides are runnable or marked illustrative.
- A4: UI strings quoted in docs exist in the catalog (checked).
- A5: the "Limits" page lists every `limit` row of the attack matrix.
**Tests.**
- `xtask docs check`; a doc-test harness executes the `curl` examples against a local instance where marked.
**Notes.** Docs must be updated by the task that changes behavior (R-30).
