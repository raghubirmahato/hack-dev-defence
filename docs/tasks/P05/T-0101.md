### T-0101 · Legal pages, cookie information and subprocessors (S-010 to S-013)
`P05` `[UI][DOC]` · deps: T-0095 · size: M · owner: docs
**Objective.** Provide legal pages that the operator can complete without code changes, and refuse to publish incomplete ones.
**Steps.**
1. Create templates in `legal/` for Terms, Privacy Notice, Acceptable Use Policy and DPA/subprocessors, written in plain language, with clearly marked operator fields (legal entity, address, contact, governing law) and an "operator must review with counsel" header comment that is not shown to visitors.
2. Implement the publication guard: a legal page whose required placeholders are unresolved is not served; the route returns a neutral maintenance-style page and the admin panel shows a blocking task "Complete legal pages"; signup is disabled until terms and privacy are published (configurable override recorded as a deviation).
3. Implement versioning: each published version has an effective date, a changelog entry, and consent records link to the version accepted.
4. Implement the cookie information section generated from the cookie inventory (T-0081), stating that only essential cookies are used.
5. Implement the subprocessor list generated from the live profile (SMTP relay, CA, DNS secondary, GeoIP provider, status hosting) with purpose and data categories.
6. Implement data-processing facts pages (retention table from C8) rendered from the same source as the product settings.
7. Add print and download (HTML) forms.
8. Add tests for placeholder detection and version history.
**Deliverables.**
- `legal/*.md` templates, guard, version tables (migration), pages, tests
**Acceptance.**
- A1: unresolved placeholders prevent publication (tested).
- A2: the subprocessor list reflects the profile and updates with it.
- A3: consent records capture the version accepted at signup.
- A4: retention tables match C8 and the actual settings (generated).
- A5: pages pass axe and claims-lint.
**Tests.**
- Unit: placeholder scanner; integration: version history; browser: legal pages render and print.
**Notes.** The agent does not provide legal advice; the operator is responsible for the content.

## Definition of done for this task's tags (section 0.7)

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
