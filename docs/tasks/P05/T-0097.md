### T-0097 · Documentation engine: Markdown rendering, sanitization, TOC and search
`P05` `[UI][SEC]` · deps: T-0074 · size: L · owner: docs
**Objective.** Render the documentation from Markdown safely, with navigation and search.
**Steps.**
1. Vet and select `pulldown-cmark` (or equivalent) and `ammonia` (sanitizer) with an ADR; define the allowed element/attribute/URL-scheme policy (no scripts, no iframes, no raw HTML pass-through except an allowlist of `details`, `kbd`, callout classes; images only from the docs asset directory).
2. Implement front-matter parsing (title key, summary, order, audience, last reviewed date, related), heading anchors with stable slugs, automatic TOC, callouts (`note`, `warning`, `limit`), tabs for per-provider instructions implemented as accessible sections (no JS requirement), and code blocks with copy buttons and language labels.
3. Implement the docs router with prev/next, breadcrumbs, "Edit on" link only if configured, and last reviewed badge with stale warning after 180 days.
4. Implement the search index at build time (inverted index with stemming rules for English, ADR on custom vs `tantivy`), served by a bounded in-memory structure and a `GET /docs/search?q=` endpoint with result highlighting by escaped markup; rate-limited; no logging of queries beyond aggregate counters.
5. Implement link checking (internal anchors and relative links) in `xtask docs check`; external links are listed but not fetched.
6. Implement the glossary tooltips linked to glossary entries (progressive).
7. Add the `include` mechanism to reuse generated snippets (error catalog, permission matrix, config table, metrics) so docs never drift.
8. Fuzz the Markdown pipeline with hostile inputs.
**Deliverables.**
- `crates/hdd-web/src/docs/*`, `docs/site/` structure, search index builder, ADR
**Acceptance.**
- A1: raw `<script>`, `javascript:` links, `onerror`, SVG scripts and iframes in Markdown are neutralized (fixture suite).
- A2: broken internal links fail `xtask docs check`.
- A3: search returns relevant results for 20 reference queries and never executes injected markup in result snippets.
- A4: the generated error catalog and permission matrix pages match their sources (tests).
- A5: stale pages display the warning after 180 days.
**Tests.**
- Unit: sanitizer policy tables; proptest on slug generation (unique, stable); fuzz target on Markdown rendering.
- Browser: docs navigation, search keyboard flow, copy buttons.
**Notes.** The same sanitizer policy is reused for any user-supplied Markdown later (none in Tier 1).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
