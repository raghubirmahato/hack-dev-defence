### T-0221 · Security overview screen (S-054)
`P12` `[UI]` · deps: T-0237, T-0171, T-0088 · size: L · owner: ui
**Objective.** Give owners a calm, accurate picture of what the security layer is doing.
**Steps.**
1. Implement the mode banner (current mode with plain-language meaning, since when, next scheduled change, link to S-055), using the exact copy for monitor/log/block/off.
2. Implement the attack timeline chart (blocked vs would-block vs allowed-suspicious) with annotation markers for mode changes, rule changes and bans; include a table alternative.
3. Implement the top categories panel (count, trend, subtype breakdown for SQLi) and top attacked paths, with links to filtered events.
4. Implement the **monitor-mode "would have blocked" panel**: number and examples of the most frequent would-block categories, each with the escaped redacted evidence and the false-positive review action (create exception / mark as expected) and a "Switch to block" call to action that opens the guided dialog (T-0222); empty state when no traffic.
5. Implement the shield status card (enabled, strictness, bans created by the shield in the last 24 h, last hard hit time) linking to S-057.
6. Implement the quick links (events, bans, rules, rate limits) and the attention items specific to security (rules about to expire, exceptions expiring, rate limit triggers).
7. Implement Unknown states for data not yet available (no traffic, data plane disconnected) and per-widget error isolation.
8. Add performance and accessibility tests.
**Deliverables.**
- screen, widget endpoints, tests
**Acceptance.**
- A1: in monitor mode the would-block panel shows real counts only; with no traffic it shows the empty state.
- A2: annotations come from `config_revisions` and bans (no fabricated markers).
- A3: every chart has a table alternative and a text summary.
- A4: widgets fail independently.
- A5: the page meets axe, keyboard and budget checks.
**Tests.**
- Integration with seeded events generated through the real ingestion path (test publisher into the event queue); browser tests; unit: panel aggregation.
**Notes.** The panel never displays raw payloads; only redacted evidence with the 512-byte cap.
