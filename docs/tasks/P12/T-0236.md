### T-0236 · Block page customization (S-096) with shared visitor templates
`P12` `[UI][API]` · deps: T-0237, T-0065 · size: M · owner: ui
**Objective.** Let owners brand the page visitors see without compromising safety.
**Steps.**
1. Implement the settings: brand name, logo upload (SVG sanitized or PNG/WebP up to 100 KB, stored as asset with content hash), accent color (validated for contrast on both themes using the contrast checker), message variant selection (from approved strings; no free HTML), contact email for appeals (encrypted at rest, optional), show Ray ID (always on; cannot be disabled), appeals toggle, footer attribution toggle (plan-dependent).
2. Implement a free-text "additional message" field (200 chars, plain text only, escaped) with abuse checks (links stripped).
3. Implement live preview in dark/light and mobile using the **same template renderer as the data plane** (shared crate), including the JSON variant.
4. Implement logo sanitization: SVG through a strict allowlist sanitizer (no scripts, no external references, no `foreignObject`), raster re-encoding to strip metadata, and size limits.
5. Implement distribution: the compiled page assets are embedded into the snapshot (inline CSS with nonce at render time, logo as data URI or served from `/__hdd/assets/` with immutable caching).
6. Implement accessibility checks on the generated page for arbitrary accent colors (contrast enforcement rejects failing colors).
7. Publish through the policy service and audit.
8. Add tests for sanitizer hostile inputs and contrast.
**Deliverables.**
- settings UI, shared renderer integration, sanitizer, tests
**Acceptance.**
- A1: SVG logos containing scripts or external references are rejected or stripped (fixtures).
- A2: accent colors failing contrast are rejected with suggestions.
- A3: the preview is byte-identical to the data plane output for the same inputs.
- A4: the page stays under 20 KB without a logo and under 120 KB with one.
- A5: the Ray ID cannot be hidden.
**Tests.**
- Unit: sanitizer corpus; integration: preview vs data plane; browser: preview in themes.
**Notes.** Block pages never include tenant-supplied HTML.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
