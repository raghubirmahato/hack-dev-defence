### T-0223 · Attack categories screen (S-056) and category policy model
`P12` `[UI][API]` · deps: T-0237, T-0222 · size: M · owner: ui
**Objective.** Let owners decide, per category, what happens on detection.
**Steps.**
1. Define the category registry (ID, label key, group, ATK ranges covered, supported actions, whether hard-ban-capable, paranoia notes, default per preset) generated from Part C and the event category enum.
2. Implement the matrix UI grouped by families (Injection, Cross-site scripting, Files and paths, Server-side requests, Protocol, Automation, Components and CVEs, Data leaks, API, Reputation): each row shows enabled state, action select (Off, Log, Challenge, Block, Block and ban), counts in the last 7 days, and the number of ATK classes covered with a drawer listing them.
3. Enforce constraints: some categories cannot be turned off when the shield is `paranoid` (SQLi, command injection, deserialization, SSTI); hard-ban-capable categories only allow Block and ban when the shield requires it; inconsistent combinations produce explanations.
4. Implement bulk presets ("Log everything for a week", "Block high-confidence categories") that produce diffs and require confirmation.
5. Implement per-category notes (why this category matters) and links to docs and to related fixtures counts (traceability).
6. Persist to the policy document via the policy service with validation and revisions.
7. Implement tests for constraint enforcement.
8. Add accessibility for the matrix (table with row headers, radio-group semantics).
**Deliverables.**
- registry, UI, API, tests
**Acceptance.**
- A1: the registry is generated from the spec's category list and covers every ATK ID (drift test).
- A2: constraint violations are rejected server-side with `ERR-WAF-004`-class errors and explained.
- A3: bulk presets show diffs before applying.
- A4: the matrix is operable by keyboard.
- A5: the number of ATK classes shown per category matches the attack-matrix source.
**Tests.**
- Unit: registry coverage; integration: constraints; browser: matrix interactions.
**Notes.** Category names are stable identifiers used in events, metrics and APIs.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
