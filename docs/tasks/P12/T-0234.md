### T-0234 · Configuration revisions screen (S-092): timeline, diff, rollback
`P12` `[UI][API]` · deps: T-0237, T-0044 · size: L · owner: api
**Objective.** Make every security change visible and reversible.
**Steps.**
1. Implement the revision timeline (revision number, time, author/system, summary, status: applied, rolled back, auto-rolled back, failed compile) with filters and annotations.
2. Implement the structured diff of policy documents (JSON path based, human-readable labels, category/rule/exception/access/rate-limit sections) using DiffViewer with text prefixes.
3. Implement rollback: select a revision, preview the resulting differences from current, run safety checks (self-lockout, known-good probes via dry-run), require confirmation, create a new revision that restores the target document, and publish.
4. Implement revision notes and labels.
5. Implement automatic revision creation guarantees: every mutation endpoint in P12 goes through the policy service (single choke point) so no change bypasses revisions (test).
6. Implement retention (all revisions for 90 days, then every Nth plus labeled ones) and export.
7. Implement the auto-rollback record display (reason, rule, distinct IPs, probes) once T-0371 lands.
8. Add tests for diff correctness (property tests of apply(diff(a,b),a)==b).
**Deliverables.**
- screen, diff library, rollback service, tests
**Acceptance.**
- A1: rollback within 2 s takes effect in the data plane (measured from commit to snapshot applied).
- A2: diff round-trip property holds on random policy documents.
- A3: no mutation endpoint can bypass revision creation (route audit test).
- A4: rollback runs safety checks and refuses unsafe targets (self-lockout).
- A5: the timeline marks auto-rollbacks distinctly with reasons.
**Tests.**
- Property tests; integration: rollback and data-plane convergence; browser: diff and rollback flows.
**Notes.** AC-16 covers revisions and convergence.

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
