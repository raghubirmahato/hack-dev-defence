### T-0235 · Domain emergency controls (S-093): under attack, safe mode, pause
`P12` `[UI][API][SEC]` · deps: T-0170, T-0237 · size: M · owner: ui
**Objective.** Give owners fast, understandable emergency levers with time boxes.
**Steps.**
1. Implement the three controls with plain-language effects: **Under attack** (challenge all new clients for N hours), **Pause protection** (pass-through for N minutes, from T-0170), and **Domain safe mode** (pass-through plus disable bans and rate limits; same as pause but also freezes automatic changes).
2. Implement time boxes (15 min to 24 h), a visible countdown banner across the domain pages, auto-revert jobs, and early end buttons.
3. Implement guard rails: enabling pause/safe mode requires step-up and a reason; under attack requires none but shows the effect on real visitors.
4. Implement shield integration (the shield can enable under attack automatically; the UI shows the trigger and lets the owner end it, subject to shield hold rules).
5. Implement notifications to owners/admins when controls are enabled or expire.
6. Implement API endpoints with idempotency and audit events.
7. Implement the break-glass instructions panel (CLI/SSH for platform operators in `owner_only` mode).
8. Add tests for expiry and concurrent toggles.
**Deliverables.**
- screen, API, jobs, tests
**Acceptance.**
- A1: time-boxed controls revert automatically even if the owner closes the browser.
- A2: pause/safe mode require step-up and reason.
- A3: the banner is visible on all domain pages while active.
- A4: shield-triggered under attack is distinguishable and can be ended by the owner unless held by a platform admin.
- A5: concurrent toggles resolve deterministically.
**Tests.**
- Integration with the test clock; browser: banner and flows; unit: state machine.
**Notes.** Platform-level emergency controls (global) are T-0434.
