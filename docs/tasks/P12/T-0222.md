### T-0222 · WAF settings screen (S-055) and the switch-to-block dialog
`P12` `[UI][API][SEC]` · deps: T-0237, T-0221 · size: L · owner: ui
**Objective.** Make mode changes explicit, consequential and reversible.
**Steps.**
1. Implement the mode selector (SegmentedControl: Off, Monitor, Log, Block) with a consequences panel per mode: what is inspected, what is blocked, what is banned, what is recorded, who is affected; use the approved copy (`monitor-explainer`, `block-confirm-*`).
2. Implement the paranoia level selector (1 to 4) with a table of what each level adds (rule counts, false-positive risk) generated from the rule registry, and the block threshold control with an explanation of soft vs hard signatures.
3. Implement the over-limit policy control (`inspect_prefix`, `block`, `pass`) with size input (1 KiB to 1 MiB) and a warning when `pass` is selected (bodies beyond the limit are not inspected).
4. Implement the **switch-to-block dialog**: lists consequences, shows the last 7 days of would-block counts by category, flags categories with unreviewed would-blocks, shows the self-lockout check (does any would-block event come from the user's own IP in the last 7 days?), the shared-IP collateral warning, and offers: switch now, schedule for a time (T-0222 scheduler), or switch with auto-revert in N hours.
5. Implement the scheduled switch (cron-free job with `mode_schedule`), cancel action, and notifications before and after.
6. Implement the safe fallback: if the data plane reports errors after switching (known-good probe failure), the auto-rollback engine (T-0371) reverts and the UI shows the revision timeline.
7. Implement permissions (`waf.mode.update` for mode, `waf.policy.update` for thresholds), step-up not required for mode changes except `off`, which requires step-up.
8. Add audit events and revision creation for every change.
**Deliverables.**
- screen, dialog, scheduler job, tests
**Acceptance.**
- A1: switching to `off` requires step-up and a typed confirmation.
- A2: the dialog's self-lockout check uses the actual events for the user's current IP and blocks switching without acknowledgment when matches exist.
- A3: scheduled switches execute at the scheduled time (test clock) and can be canceled.
- A4: paranoia and threshold descriptions are generated from the registry (no drift).
- A5: all controls have consequence text associated with `aria-describedby`.
**Tests.**
- Browser flows; unit: dialog data assembly; integration: scheduler with the test clock; security: permission matrix.
**Notes.** Mode changes publish a new revision; the data plane applies within 2 s.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
