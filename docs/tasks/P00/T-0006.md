### T-0006 · Live profile v5: schema, example file and validator
`P00` `[SEC][API]` · deps: T-0004 · size: M · owner: infra
**Objective.** Make the operator's inputs machine-validated, with errors that say exactly what to fix.
**Steps.**
1. Vet YAML parsers (`serde_yaml_ng`, `saphyr`, others) for maintenance, safety (no anchors-based bombs, depth limits) and licenses; if none qualifies switch the profile to TOML and record `DEV-V5-004` plus an ADR.
2. Define the profile types in `hdd-common::profile` mirroring section 8 exactly, with `serde` and `schemars`, using secrecy-typed env var *names* only (never values).
3. Generate the JSON Schema to `docs/profile.schema.json` and the commented `hdd.live.example.yaml` (every field documented, with the allowed enum values and the consequence of leaving it empty).
4. Implement `validate(profile) -> Report`: required-field presence; hostname syntax; `test_hostname` and `sandbox_hostname` must be distinct subdomains of `domain`; `platform_domain` registrable; CIDR parsing; `admin_cidrs` must not contain the runner IP when known; `ssh_allow_cidrs` allowed to; `egress_allowlist` must cover every configured feed, CA, resolver and SMTP host; `acme.directory` default `staging`; `lifecycle_stage` / `deployment_mode` enums; `signup.mode=open` flagged "needs operator approval".
5. Implement the unreachable-field probes as separate, explicit checks (DNS resolution of NS hostnames, TCP connect to SMTP) executed only by `hddctl preflight`, not by `validate`.
6. Implement `hddctl preflight --profile-only` printing a table with PASS/FAIL/UNVERIFIED per rule and the exact remediation text.
7. Add a "missing required fields" renderer for the first response (section 9, item 2).
8. Add a redaction layer so printing a profile never prints token values or paths of secret files beyond their names.
**Deliverables.**
- `crates/hdd-common/src/profile/*.rs`, `docs/profile.schema.json`, `hdd.live.example.yaml`
- `crates/hddctl` `preflight` subcommand (profile-only mode)
- ADR for the YAML parser
**Acceptance.**
- A1: the example file validates with only the expected "required fields empty" failures, each with remediation text.
- A2: a profile with the runner IP inside `admin_cidrs` fails with the documented message.
- A3: unknown keys are rejected (strict deserialization) with the key path.
- A4: no secret value can be parsed from the file (only env var names); a test proves a token-looking value in a name field is rejected.
- A5: the generated schema is stable (golden test).
**Tests.**
- Table-driven unit tests with 30+ valid and invalid profiles; proptest for CIDR and hostname parsing never panicking.
- `cargo xtask verify` includes a check that the example file and schema are up to date.
**Notes.** The validator is pure; network probes live in `hddctl` (R-22: they use the egress client).

## Definition of done for this task's tags (section 0.7)

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
