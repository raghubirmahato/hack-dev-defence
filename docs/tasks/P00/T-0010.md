### T-0010 · Capability matrix, requirement tooling and gate G00
`P00` `[DOC][QA]` · deps: T-0005, T-0008, T-0009 · size: M · owner: docs
**Objective.** Make traceability and the gate report mechanical, then pass gate G00.
**Steps.**
1. Implement `xtask matrix generate`: parse all task blocks, derive `REQ-<PREFIX>-<nn>` IDs from phase prefixes and task order, and write `docs/CAPABILITY-MATRIX.md` with columns REQ, task, description, tests (links to files or test names), evidence (path or hash), status.
2. Implement `xtask matrix check`: every REQ must map to at least one test or an explicit `deferred(reason)`; a row marked `done` must link to a passing test run record.
3. Implement `xtask gate-report <Gnn>`: assemble the gate report in the Appendix E5 format from `acceptance-*` logs, `STATUS.md`, metrics (`rust-share`, `tokei`, test count, coverage, mutation score, clippy/audit/deny/vet/geiger status).
4. Add the requirement-prefix table (phase to prefix) as a machine-readable file `docs/requirements.toml`.
5. Run the full G00 checklist: spec checksum, AGENTS.md size, workspace builds, `xtask verify`, profile validation, egress tests, matrix generation.
6. Paste real command output tails into the G00 gate report and store logs with SHA-256.
7. Update `STATUS.md`, mark P00 tasks `done`, and set the next task to T-0011.
8. Tag the commit `gate-G00`.
**Deliverables.**
- `docs/CAPABILITY-MATRIX.md`, `docs/requirements.toml`, `xtask matrix|gate-report`
- `docs/gates/G00.md` (the gate report)
**Acceptance.**
- A1: the matrix contains one REQ row per task (599 rows) with status `todo` except P00 `done`.
- A2: `xtask matrix check` fails when a `done` row lacks evidence.
- A3: `docs/gates/G00.md` follows the Appendix E5 template and includes pasted output tails.
- A4: all gate G00 conditions hold with evidence.
- A5: the git tag `gate-G00` exists and points at the commit with the gate report.
**Tests.**
- Unit tests for REQ derivation (golden test on a small spec fixture).
- The gate report is regenerated and compared with the committed copy.
**Notes.** Never mark a row `done` without a linked passing test run; UNVERIFIED rows list exactly what the operator must supply.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.
