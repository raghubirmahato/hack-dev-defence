### T-0005 · `hdd-xtask`: verify pipeline, spec tools and claims-lint
`P00` `[OPS][QA][DOC]` · deps: T-0004 · size: L · owner: infra
**Objective.** One command (`cargo xtask verify`) that enforces the rules mechanically, plus the spec and task tools that replace the bootstrap script.
**Steps.**
1. Implement the xtask binary with `clap` subcommands: `verify`, `spec split|check|show <T-id>`, `tasks index|order`, `gen-secrets`, `claims-lint`, `rust-share`, `matrix check`, `attack-matrix check`, `contrast-check`, `i18n check`, `routes check` (stubs return success with a note until their tasks land, each tracked in STATUS as `stub`).
2. Implement `spec split`/`check`/`show`: deterministic split at the markers; `check` compares with `docs/spec/`; `show T-0123` prints the task block and its referenced registry rows.
3. Implement `claims-lint` reading `docs/claims-lint.toml`; seed it with the forbidden phrases from section 4.2; scan `docs/`, `README.md`, `i18n/`, `crates/**/templates/`, OpenAPI descriptions, report templates; support allowlisted quotations in a clearly marked block (`<!-- claims-lint:allow-start -->`).
4. Implement `rust-share` per DEV-V5-002: run `tokei`, apply exclusions (generated, vendored, migrations, YAML/TOML, Markdown), print the table and fail below 90% Rust among programming-language lines; report CSS, HTML template and JS line counts against their caps.
5. Implement the `verify` pipeline order: `fmt --check`, `clippy -D warnings`, `nextest`, doc-tests, `deny`, `audit`, `vet`, geiger-or-substitute, `machete`, secret scan, claims-lint, rust-share, matrix checks; each step prints a tail and writes a log with SHA-256 under `acceptance-verify/`.
6. Implement the secret scanner as a Rust module (high-entropy tokens, private-key headers, `AKIA`-style patterns, `.env` content) wired into a git pre-commit hook installed by `cargo xtask hooks install`.
7. Remove the awk bootstrap from the repo history of tools (keep the DEV-V5-000 record) and update `docs/DEVIATIONS.md` with the removal date.
8. Document each subcommand in `OPERATIONS.md` (developer section).
**Deliverables.**
- `crates/hdd-xtask/` with the subcommands above and unit tests
- `docs/claims-lint.toml`, `.githooks/pre-commit` installer
- `OPERATIONS.md` developer section
**Acceptance.**
- A1: `cargo xtask verify` exits 0 on a clean tree and non-zero when any step fails (demonstrated per step).
- A2: `cargo xtask spec check` passes and fails after editing a split file.
- A3: `claims-lint` fails on a seeded forbidden phrase in a template and passes on the approved patterns of section 4.3.
- A4: the secret scanner blocks a commit containing a fake private-key block (test fixture generated at runtime, not committed).
- A5: `rust-share` prints the exclusion list and the three markup caps.
**Tests.**
- Unit tests for each lint (positive and negative cases); golden test for `spec split` using a small sample document.
- `cargo xtask verify` is itself run in CI as the gate.
**Notes.** Stubs are allowed only for checks whose subject does not exist yet; each stub is a named STATUS item and must be replaced by the task listed in its message.

## Definition of done for this task's tags (section 0.7)

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
