### T-0201 · CAA and Certificate Transparency monitoring
`P10` `[API][OPS][SEC]` · deps: T-0183, T-0198 · size: M · owner: sec
**Objective.** Detect unexpected certificate issuance for managed names.
**Steps.**
1. Implement the CT monitor job: query the configured CT search service (egress allowlist; if none configured, mark `UNVERIFIED(capability_not_supplied)`) for managed hostnames on a schedule (daily, plus after issuance), parse results into `ct_observations`.
2. Compare observations to expected issuance (known orders, uploaded certificates) and flag unexpected issuers/serials as `expected=false`.
3. Implement alerts: critical notification to owners with details and recommended actions (check CAA, revoke, investigate DNS control), plus attention items.
4. Implement the CAA enforcement suggestion linking to the CAA wizard and a periodic check that CAA remains as expected.
5. Implement rate limits and caching for CT queries; bounded response sizes; defensive parsing.
6. Implement UI in S-051 (CT tab) with observation list and expected/unexpected labels.
7. Add tests with a local CT-search-like HTTP service returning crafted data.
8. Document limitations (CT logs show issuance after the fact).
**Deliverables.**
- monitor job, UI, tests
**Acceptance.**
- A1: an unexpected issuance produces a critical notification once (deduplicated).
- A2: absence of a configured CT service shows the capability requirement.
- A3: parsing is robust against malformed responses (fuzz).
- A4: queries respect rate limits and caching.
- A5: observations link to the relevant certificate when expected.
**Tests.**
- Integration with a crafted local service; fuzz on the response parser; unit: expected matching.
**Notes.** This supports ATK-243 and AC-04's CT check.
