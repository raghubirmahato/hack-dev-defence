### T-0202 · Origin TLS verification diagnostics and pin management
`P10` `[UI][API][SEC]` · deps: T-0163, T-0164 · size: M · owner: sec
**Objective.** Make strict origin verification workable without disabling it.
**Steps.**
1. Implement the diagnostics view: for the last origin test, show the presented chain, the verification path result for the selected mode, hostname match against SNI/verify name, expiry, key type, and SPKI hash.
2. Implement pin management for `pinned_ca` (upload PEM CA/bundle or accept from the last-seen chain after explicit confirmation) and `pinned_spki` (hash value) with dual pins for rotation and expiry reminders.
3. Implement mismatch diagnostics (wrong hostname, expired, untrusted issuer, self-signed, name constraint, weak signature) with remedies.
4. Implement the "trust on first use" helper carefully: showing fingerprints and requiring confirmation; never auto-pinning.
5. Implement rotation workflow: add new pin, test, remove old pin.
6. Implement alerts when the origin certificate changes unexpectedly or nears expiry (via periodic probes).
7. Persist pins encrypted when sensitive and audited.
8. Test with local TLS servers using various certificates.
**Deliverables.**
- diagnostics UI, pin management, tests
**Acceptance.**
- A1: mismatches never result in silent downgrade (verification failure remains failure).
- A2: pin rotation with dual pins works without downtime in tests.
- A3: confirmation is required to pin from observed chain.
- A4: expiring origin certificates raise alerts.
- A5: UI shows SPKI hashes in a copyable format.
**Tests.**
- Integration with local TLS servers; unit: pin matching; browser: workflow.
**Notes.** `webpki` mode remains the default and simplest.
