### T-0197 · Certificates screen (S-051) and ACME error explanations
`P10` `[UI]` · deps: T-0196 · size: M · owner: ui
**Objective.** Make certificate state and failures understandable.
**Steps.**
1. Implement the list: names, issuer, kind (ACME/custom), validity dates, days remaining, status pill, renewal date, and actions (renew now, view details, delete for custom).
2. Implement the details drawer: SANs, serial, key type and size, SPKI hash (for pinning use), chain (collapsed), issuance history timeline, CT observations.
3. Implement the ACME order panel: current order state (pending DNS, validating, issued, failed), last error, next attempt time, and a plain-language mapping of ACME error types to causes and remedies (DNS not propagated, CAA forbids, rate limited, validation failed, unauthorized, connection refused on HTTP-01, timeout).
4. Implement actions with permission checks (`tls.write`) and rate limits ("Renew now" limited per day).
5. Implement empty states (no certificate yet, with the next step) and the pending state with polling.
6. Implement notifications links for expiry and failures.
7. Add visual baselines and accessibility checks.
8. Add tests with seeded certificates generated by a real test CA (`rcgen` in tests only).
**Deliverables.**
- screen and drawer, error mapping, tests
**Acceptance.**
- A1: each ACME error class has a human-readable cause and fix.
- A2: "Renew now" respects rate limits and shows the next allowed time.
- A3: the drawer shows the SPKI hash with a copy field.
- A4: expiry status text and color follow the lifetime-relative thresholds.
- A5: the screen works with 100 certificates in the performance budget.
**Tests.**
- Browser tests; unit: error mapping table; integration: rate limits.
**Notes.** Test CA material is generated at runtime and never committed.
