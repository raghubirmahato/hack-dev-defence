### T-0196 · TLS settings model, policy validator and UI (S-050)
`P10` `[UI][API][SEC]` · deps: T-0195, T-0171 · size: L · owner: api
**Objective.** Let owners set TLS policy with guardrails.
**Steps.**
1. Define settings: `ssl_mode` (`full_strict`, `pinned`, `http_origin_ack`), minimum TLS version (1.2 default, 1.3 option), HTTPS redirect (on by default), HSTS (off/on with max-age, includeSubDomains, preload), ALPN (h2, http/1.1), TLS session ticket policy (platform-level), and `Alt-Svc` placeholder for HTTP/3 (disabled until Tier 3).
2. Implement the policy validator: `http_origin_ack` requires the explicit acknowledgment flag; minimum TLS 1.3 shows compatibility warnings (older clients); HSTS rules in T-0200.
3. Implement the S-050 screen: current status badges (certificate valid, expiry, redirect on), settings forms with consequences panels, and the "What your visitors will see" summary.
4. Implement snapshot publication on change, audit events with before/after, and `If-Match` concurrency.
5. Implement previews: for HSTS and redirect changes, a short explanation and a test link to open the domain over HTTP and HTTPS.
6. Implement plan-aware controls where relevant (none restrict security).
7. Add API endpoints and OpenAPI.
8. Add tests for each rule and UI.
**Deliverables.**
- settings service, S-050, tests
**Acceptance.**
- A1: plaintext origin mode is impossible without the acknowledgment and shows a persistent warning.
- A2: changes publish a new revision visible to the data plane outbox.
- A3: TLS 1.3-only shows the compatibility warning with plain language.
- A4: every setting has help text and a docs link.
- A5: the page passes axe and keyboard checks.
**Tests.**
- Unit: validators; integration: revisions; browser: forms.
**Notes.** TLS 1.0/1.1 are not offered (ATK-240).

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
