### T-0381 · TLS policy verification: protocol, ciphers, HSTS and redirect behavior
`P19` `[QA][SEC]` · deps: T-0354, T-0200 · size: M · owner: qa
**Objective.** Verify TLS posture with external oracles and Rust checks.
**Steps.**
1. Implement Rust checks (using `rustls` clients with restricted configs) for: TLS 1.0/1.1 refusal, TLS 1.2/1.3 acceptance, ALPN h2/http1.1, session resumption behavior, renegotiation refusal, 0-RTT disabled, certificate chain delivery (leaf + intermediates), OCSP absence (documented), HSTS header values, HTTP→HTTPS redirect (status, location, exclusions).
2. Run oracles on the builder/lab: `openssl s_client` (version/cipher), `testssl.sh` (full report; output archived; not run against third-party hosts), and `curl` for HTTP/2 negotiation.
3. Generate a TLS posture report (`acceptance-tls/*`) with grades for categories and list intentional deviations.
4. Verify staging behavior against the real pilot host (AC-04) using only the runner and the profile's hosts.
5. Verify the HSTS ramp enforcement outputs actual headers per setting.
6. Verify ACME and redirect path exclusions.
7. Record the results in the gate report.
8. Fix issues at root cause.
**Deliverables.**
- checks, reports
**Acceptance.**
- A1: no weak protocol or cipher is accepted (oracle evidence).
- A2: HSTS and redirect behavior match settings for 10 configurations.
- A3: certificate chain delivery is complete.
- A4: OCSP stapling absence is documented (decision in T-0382).
- A5: reports archived with SHA-256.
**Tests.**
- The checks; oracle runs.
**Notes.** AC-04 evidence.
