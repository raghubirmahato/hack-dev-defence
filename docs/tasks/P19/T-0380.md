### T-0380 · Default certificate policy and `unrecognized_name` behavior
`P19` `[DP][SEC]` · deps: T-0375 · size: S · owner: dp
**Objective.** Make unknown-name handling explicit and safe.
**Steps.**
1. Implement the default behavior: unknown or absent SNI → TLS `unrecognized_name` alert (level fatal) or handshake failure, never serving a tenant certificate.
2. Implement the optional default certificate (flag `HDD_TLS_DEFAULT_CERT=true`) generated by the internal PKI (`rcgen`) with a neutral subject, serving only the neutral 404 page; document that this can help diagnostics but reveals the platform exists.
3. Implement IP-literal access handling (no SNI): refuse by default; if default cert enabled, serve the neutral page.
4. Implement metrics and rate limiting for unknown-SNI handshakes (cheap rejection under floods).
5. Test with `openssl s_client` (no SNI, wrong SNI, IP literal) and scanners.
6. Add the check to AC-04.
7. Document security tradeoffs (information disclosure vs diagnosability).
8. Ensure the default cert is never used for tenant names.
**Deliverables.**
- policy implementation, tests, docs
**Acceptance.**
- A1: unknown SNI is refused with the expected alert in default mode.
- A2: with the flag, only the neutral page is served and never tenant data.
- A3: flood of unknown-SNI handshakes is cheaply rejected and counted.
- A4: IP-literal requests behave per policy.
- A5: oracle outputs are recorded.
**Tests.**
- Oracle integration tests; unit: policy.
**Notes.** ATK-242.
