### T-0517 · Unsafe-code policy, `cargo-geiger` viability ADR and static analysis suite
`P29` `[SEC][DOC]` · deps: T-0466, T-0516 · size: M · owner: sec
**Objective.** Keep `unsafe` confined and justified, and add independent static analysis layers.
**Steps.**
1. Write the **ADR** on `cargo-geiger` viability: test the tool against the workspace and dependency graph (known limitations with workspace/build scripts and recent compiler versions), evaluate substitutes (`cargo-careful`, custom `syn`-based scanner `xtask unsafe-scan`, `cargo-udeps` for dependency pruning, Miri for selected crates), and choose the enforced mechanism; record the outcome and the fallback.
2. Implement `xtask unsafe-scan`: parses all workspace crates, reports `unsafe` blocks/functions/impls/extern blocks by crate, enforces: zero `unsafe` outside `hdd-xdp-ebpf/ctx` and the narrow FFI shims explicitly listed in `unsafe-allowlist.toml` (each entry with justification, owner, review date), and `#![forbid(unsafe_code)]` at every other crate root (verified by the scanner).
3. Add dependency unsafe accounting: list dependencies containing unsafe (via geiger or substitute), classify (well-known foundational crates vs niche), and require `cargo vet` audit entries for niche unsafe-containing crates.
4. Add **Miri** runs for pure crates that can run under Miri (`hdd-xdp-logic`, parsers in `hdd-common`, normalizer pieces) in CI nightly; document the crates that cannot.
5. Add **clippy extended lint set** (`clippy::pedantic` selections, `unwrap_used`/`expect_used`/`panic`/`indexing_slicing` denied in non-test code of the data plane crates, `unreachable` reviewed, `todo!`/`unimplemented!` denied, `dbg!` denied, `print_stdout` denied), with allowlists requiring comments.
6. Add optional **semgrep** (external oracle, pinned ruleset) and **CodeQL** (if hosted CI exists) scans with triage guidelines; findings recorded as UNVERIFIED if tools are unavailable.
7. Add **panic-safety checks** for the data plane: every request task runs under `catch_unwind` boundaries or equivalent isolation with `MET-hdd_panics_total`; a test injects panics at each pipeline stage and verifies isolation (no process crash, other requests unaffected, the request fails closed with 500 and Ray ID).
8. Document the **secure coding standard** (`docs/SECURE-CODING.md`): parsing at boundaries, no stringly-typed SQL, parameterized queries only (sqlx compile-time checked), no shell invocations, constant-time comparisons for secrets, zeroization, error hygiene, logging rules, integer arithmetic checks (`checked_*` in size computations), time handling; lints and tests mapped to each rule.
**Deliverables.**
- ADR, `xtask unsafe-scan`, allowlist, lint configs, standard doc, Miri CI
**Acceptance.**
- A1: `unsafe` exists only in allowlisted locations with justifications (scanner).
- A2: panic injection at every stage is isolated and fails closed.
- A3: clippy extended lints pass with no unexplained allows.
- A4: Miri passes on listed crates (or the gap list is documented).
- A5: the secure coding standard maps each rule to enforcement.
**Tests.**
- Scanner tests with seeded violations; panic-injection tests; CI jobs.
**Notes.** The ADR slot referenced from P00 (`cargo-geiger` viability) is settled here.
