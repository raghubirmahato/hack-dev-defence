### T-0516 · Supply-chain controls: dependencies, SBOM, reproducible builds and provenance (AC-33, part 1)
`P29` `[SEC][OPS]` · deps: T-0214, T-0481 · size: L · owner: sec
**Objective.** Know exactly what is in every artifact, keep it patched, and be able to rebuild it identically.
**Steps.**
1. Enforce dependency policy with `cargo deny` (licenses allowlist with reviewed exceptions, bans on duplicate major versions where feasible, banned crates list, source restrictions to crates.io and explicit git sources pinned by commit), `cargo audit` (RustSec, using the offline snapshot ingested by `hdd-vuln` plus network when allowed), `cargo vet` (audits for new crates with imports from trusted organizations; exemptions tracked with expiry), `cargo machete` (unused deps), and `cargo outdated` weekly reports.
2. Define **advisory SLAs for HDD itself**: exploited or critical RUSTSEC within 72 h, others within 14 days; every exception documented with an expiry and reviewer; `xtask deps` generates the weekly report and opens tasks automatically; the exposure board (S-125) shows HDD's own dependencies as an inventory source.
3. Generate **SBOMs** (CycloneDX JSON via `cargo cyclonedx` and `cargo auditable` embedded metadata) per release artifact, include container image SBOMs (`syft`), and publish them with checksums; verify the `hdd-vulnlab` and lab crates are absent from shipped SBOMs.
4. Implement **reproducible builds:** pinned toolchain (`rust-toolchain.toml`), `SOURCE_DATE_EPOCH`, `--remap-path-prefix`, locked dependencies (`--locked`), deterministic linking flags, containerized build environment pinned by digest; a verification job rebuilds on a second machine/container and compares SHA-256 of artifacts (bit-for-bit for static binaries; documented exceptions for embedded timestamps if any).
5. Implement **build provenance:** SLSA-style provenance statement (in-toto format) recording source commit, builder identity, inputs and digests, signed with the release key; `xtask provenance verify` validates it.
6. Implement **vendoring option** (`cargo vendor`) for offline builds with checksum verification, and the lockfile policy (Cargo.lock committed; changes reviewed).
7. Protect the **CI and build environment** (documented): least-privilege tokens, no secrets in build logs, pinned GitHub Actions (or equivalent) by digest if hosted CI is used, branch protection recommendations, signed commits/tags recommended, and a "no network during build except crates registry via lock" check.
8. Write tests: policy fixtures (a banned license/crate/source is rejected), SBOM completeness (every crate in `Cargo.lock` appears), reproducibility test in CI (two builds, equal hashes), provenance verification (tamper detection), lab-crate exclusion.
**Deliverables.**
- policy files (`deny.toml`, `supply-chain/`), `xtask deps|sbom|provenance|repro`, reports
**Acceptance.**
- A1: policy violations in seeded fixtures fail `xtask verify`.
- A2: SBOMs list all dependencies and exclude lab crates.
- A3: two independent builds produce identical artifact hashes.
- A4: tampering with an artifact or provenance statement is detected.
- A5: advisory SLA tracking shows no overdue item at the gate (or documented exceptions with expiry).
**Tests.**
- Policy fixtures, reproducibility job, provenance tests.
**Notes.** AC-33 completes with T-0518 (signing and self-update).
