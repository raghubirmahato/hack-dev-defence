### T-0515 · Mutation testing, coverage thresholds and test-quality gates
`P29` `[QA]` · deps: T-0258, T-0511 · size: M · owner: qa
**Objective.** Make sure the tests would actually catch regressions, especially in the security-critical crates.
**Steps.**
1. Configure `cargo-mutants` for the security-critical crates (`hdd-waf-core`, `hdd-common::{ip,egress,dns,webhook_sig}`, `hdd-auth`, `hdd-challenge`, `hdd-firewall` logic, `hdd-xdp-logic`, `hdd-dns` engine, `hdd-vuln` matching, `hdd-api` authorization) with per-crate timeouts and test selection; thresholds: `hdd-waf-core` ≥ 80%, `hdd-auth` ≥ 85%, `hdd-xdp-logic` ≥ 90%, DNS engine ≥ 80%, others ≥ 70%, with an exclusion file requiring justification for each excluded mutant.
2. Configure **coverage** with `cargo llvm-cov`: line and branch coverage thresholds (workspace ≥ 80% lines; security-critical crates ≥ 90% lines), HTML and lcov outputs, coverage diffs on PRs, and exclusion annotations only with comments.
3. Implement **property-test inventory** (`xtask tests inventory`): lists proptest/quickcheck suites per crate, seeds, and ensures regression seeds are committed (`proptest-regressions`).
4. Implement a **test-quality linter**: flags tests without assertions, `#[ignore]` without a tracked task id and expiry, `sleep`-based tests (require injected clocks), network-dependent tests without a feature flag, and use of real clocks in unit tests of time-dependent logic.
5. Implement **flaky test policy**: automatic rerun detection records flakes; a flaky test must be fixed or quarantined with a task id within 7 days (quarantine never applies to security-critical suites, which block until fixed); the quarantine list is visible in STATUS.
6. Add **golden test governance:** golden files require a reviewer approval note (`GOLDEN-UPDATES.md` entries) for security-relevant goldens (rule packs, claims, verdict tables).
7. Run the mutation analysis on the current codebase, triage surviving mutants (kill by adding tests, or justify exclusions), and publish `docs/TEST-QUALITY.md` with the results.
8. Wire the thresholds into `xtask verify` (mutation runs on a nightly schedule and at gates because of runtime; coverage on every PR).
**Deliverables.**
- mutation configs, coverage gates, inventory tool, linter, docs
**Acceptance.**
- A1: all thresholds are met at the gate with evidence reports.
- A2: every `#[ignore]` has a task id and expiry (linter).
- A3: no real-clock dependence in time-logic unit tests.
- A4: surviving-mutant triage list is complete with decisions.
- A5: the flake registry is empty for security-critical suites.
**Tests.**
- Tooling tests; the analysis runs.
**Notes.** Mutation testing runs are expensive; they execute in CI nightly and at gates.
