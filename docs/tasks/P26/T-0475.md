### T-0475 · Escalation actions: tighten, challenge, shed, DNS attack mode, and `skipped(feature_absent)` semantics
`P26` `[DP][OPS][SEC]` · deps: T-0474, T-0339, T-0393, T-0467 · size: L · owner: infra
**Objective.** Wire each shield state to concrete, reversible actions across the stack.
**Steps.**
1. Define the **action registry**: each action has an id, preconditions (feature present?), apply/undo functions, idempotency, a maximum duration, and an audit template. Actions: `xdp.tighten` (lower per-source rate thresholds by factor), `xdp.strict` (drop all non-essential UDP except DNS from known peers and DNS to port 53 subject to RRL), `proxy.under_attack_new_clients` (enable the under-attack challenge for new clients platform-wide using the mechanism of T-0339), `proxy.shed_nonessential` (return 503 with `Retry-After` for configured non-essential routes such as the public docs search or the app's analytics endpoints), `dns.attack_mode` (cookie-required responses with TC=1 for non-exempt sources, T-0393), `notify.page_operator`, `provider.activate` (T-0476), `dns.failover_standby` (T-0478), `cache.serve_static` (if a cache exists; otherwise skipped), `ban.escalate_ladder` (raise ban TTL ladder one rung for L7 offenders during ATTACK).
2. Map states to actions as a **configurable table** (default per C11.6): ELEVATED → `xdp.tighten`, `proxy.under_attack_new_clients`, `notify.alert`; ATTACK → `xdp.strict`, `provider.activate` (if configured), `notify.page_operator`, `proxy.shed_nonessential`, `cache.serve_static`, `dns.attack_mode`, `ban.escalate_ladder`; SATURATED → incident bundle, `dns.failover_standby` (if `standby_edge_ips` exist), keep secondary authoritative.
3. Implement the **feature-absent semantics**: before executing, check preconditions; absent features record `skipped(feature_absent: <what>)` in the audit event, metrics (`MET-hdd_shield_actions_total{action,result}`) and the incident timeline; the S-127 table shows each action's last result; unit tests assert nothing is silently dropped.
4. Implement **safety rules**: actions never target `admin_cidrs`, provider ranges or the origin; `xdp.strict` always keeps the dead-man timer armed; `proxy.under_attack_new_clients` exempts verified bots and operator CIDRs as configured; shedding lists must be explicitly configured (default empty) and cannot include the block page, challenge endpoints, appeal endpoints, ACME challenge paths or health endpoints.
5. Implement **undo on de-escalation** in reverse order with confirmation of effect (each undo verifies the previous state is restored, e.g., XDP thresholds equal the baseline), and a `shield undo-all` break-glass command.
6. Implement the integration contracts: the shield publishes its state in Redis (`hdd:shield:state`) so the proxy and DNS react within 2 s without direct coupling; a heartbeat key ensures components revert to normal if the shield is dead for more than 10 minutes (fail-safe to avoid permanent strict modes).
7. Add action budget limits: an action that fails 3 times is disabled for the incident with an alert; total actions per hour capped to avoid runaway loops.
8. Write tests: action registry unit tests, state→action table validation, trace replay with a fake effector registry that records calls plus a live integration test in the lab applying real XDP threshold changes and verifying restoration, feature-absent recording, fail-safe revert when the shield stops, and exempt-list guarantees.
**Deliverables.**
- action registry, effectors, state-action table, tests, docs
**Acceptance.**
- A1: every state transition in the trace suite produces the expected action list with results.
- A2: removing the shield process leads proxy and DNS to revert to normal behavior within 10 minutes.
- A3: absent features are recorded as `skipped(feature_absent)` and never as success.
- A4: undo restores the exact baseline values in the lab test.
- A5: safety rules prevent targeting exempt ranges (unit tests with hostile configs).
**Tests.**
- Unit, trace replay with effector recorder, lab integration.
**Notes.** The shield-driven triggers referenced from P17 (T-0339) connect here.

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
