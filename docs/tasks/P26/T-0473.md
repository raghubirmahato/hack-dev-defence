### T-0473 · `hdd-shield` telemetry: collectors, signals and the recorded-trace input mode
`P26` `[DP][OPS]` · deps: T-0214, T-0467, T-0400 · size: L · owner: infra
**Objective.** Measure the right signals cheaply and make them replayable for testing.
**Steps.**
1. Create the `hdd-shield` host service with collectors reading `/proc` and `/sys` (no external agents): NIC rx/tx bytes and packets (`/sys/class/net/*/statistics`), SYN rate and half-open counts (`/proc/net/netstat`, `/proc/net/tcp*` counters), UDP receive errors (`/proc/net/snmp`), conntrack usage (`/proc/sys/net/netfilter/nf_conntrack_count`, `max`, drops), accept-queue overflows (`ListenOverflows`, `ListenDrops`), softirq CPU (`/proc/stat`, `/proc/softirqs`), memory pressure (PSI), DNS qps and drops (from `hdd-dns` metrics), proxy in-flight and shed counts, origin health and proxy-added latency p99 (from proxy metrics), and XDP drop counters by reason.
2. Normalize signals into a `SignalFrame` every second: raw values, rates over 1/10/60 s windows, and thresholds relative to the configured `platform.uplink_mbps` (if unknown, relative thresholds only with `capacity_known=false`).
3. Define the **threshold configuration** (profile `shield.thresholds`): per signal, `elevated_pct` (50%), `attack_pct` (80%), `saturated_pct` (90%), absolute guards (for example SYN/s above N), and weights; thresholds are validated, versioned and shown in S-127.
4. Implement the **recorded-trace input mode**: the same collector interface can read from a trace file (`--trace file.jsonl` with timestamped `SignalFrame`s), a replay mode with time acceleration, and the live mode; the real binary runs in all modes through its normal telemetry interface (not a mock) and writes its decisions to the same outputs.
5. Implement **trace recording**: `hdd-shield record --out trace.jsonl` captures live frames for later replay and for incident bundles (T-0477), with size caps and compression.
6. Implement sanity guards: missing or stale collectors produce `unknown` signals and the state machine treats unknowns conservatively (never de-escalates on unknown); counter wrap/reset handling; negative rates clamped with a warning; clock jump detection.
7. Export metrics for every signal and its state, plus collector health.
8. Write tests: collector parsers against captured `/proc` fixtures from several kernels, counter-wrap tests, trace record/replay equality (replaying a recording yields identical frames), time acceleration determinism, unknown-signal handling, and performance (≤ 1% CPU of one core at 1 Hz).
**Deliverables.**
- `hdd-shield` telemetry module, trace tooling, fixtures, tests
**Acceptance.**
- A1: parsers handle the fixture corpus from at least three kernel versions without error.
- A2: replaying a trace through the real binary reproduces the same frames and decisions on every run.
- A3: collector failures yield `unknown` and are visible in S-127.
- A4: counter wraps and resets never produce spikes in the rates.
- A5: collection overhead is under 1% CPU.
**Tests.**
- Parser fixtures, replay determinism, performance.
**Notes.** The recorded-trace mode is a test input to the real service, not a separate test double.
