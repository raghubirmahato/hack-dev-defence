### T-0024 · Responsive and device strategy
`P01` `[DOC][QA]` · deps: T-0014 · size: S · owner: ux
**Objective.** Define how every screen behaves across devices without special cases.
**Steps.**
1. Define breakpoints and fluid behaviors from B11.4 and the layout rules (sidebar to drawer, tables to cards below 640 px when needed, wizards as single column).
2. Define the device test matrix for screenshots: 360x740, 390x844, 768x1024, 1024x768, 1280x800, 1536x864, 1920x1080; light and dark; LTR and pseudo-RTL.
3. Define input modalities (touch targets, hover alternatives, keyboard) and orientation.
4. Define printing and PDF behavior (report pages, audit exports).
5. Define performance budgets per device class (mobile mid-range profile for Core Web Vitals).
6. Define content priority per breakpoint (what moves into overflow menus).
7. Define the behavior of data-dense screens (live monitor) on small devices (simplified columns, details in drawer).
8. Define testing hooks (viewport helper in the harness).
**Deliverables.**
- `docs/UX/RESPONSIVE.md`
**Acceptance.**
- A1: the device matrix is explicit and used by T-0090.
- A2: each screen category has a defined small-screen behavior.
- A3: print requirements exist for reports and audit.
- A4: performance budgets are numeric.
- A5: tablets and landscape phones are covered.
**Tests.**
- Implemented by screenshot tests in P04 onward.
**Notes.** Do not hide security-critical controls on small screens.
