### T-0021 · State patterns: empty, loading, offline, permission-denied, partial data
`P01` `[DOC]` · deps: T-0020 · size: S · owner: ux
**Objective.** Make the non-happy states first-class.
**Steps.**
1. For each data region type (table, chart, stat card, feed, form, wizard) define the five states and their copy keys.
2. Define skeleton thresholds (show after 300 ms), timeouts (give up after 10 s with retry), and stale data labeling ("Updated 2 minutes ago").
3. Define the "Unknown (reason)" pattern for unavailable metrics and forbid zero as a placeholder.
4. Define the permission-denied pattern (explain role needed, who to ask, never show data).
5. Define the partial-failure pattern (one widget fails, page still usable).
6. Define the new-account empty-state journeys (what the first screen offers, honest next step).
7. Define the loading of live feeds (connecting, live, reconnecting with backoff, paused).
8. Provide examples for ten screens.
**Deliverables.**
- `docs/UX/STATES.md`
**Acceptance.**
- A1: every region type has five defined states.
- A2: the unknown-value pattern is specified with an example.
- A3: ten screens include concrete state examples.
- A4: timeouts and thresholds are numeric.
- A5: no state uses fabricated sample data.
**Tests.**
- Implemented by component tests in P02 and screen tests in P07 onwards.
**Notes.** R-16 (UI honesty) is enforced here.
