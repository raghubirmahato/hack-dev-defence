### T-0022 · Accessibility strategy and test plan
`P01` `[DOC][QA]` · deps: T-0011 · size: M · owner: ux
**Objective.** Make WCAG 2.2 AA achievable and testable.
**Steps.**
1. Write `docs/UX/ACCESSIBILITY.md` mapping each WCAG 2.2 A/AA criterion to the component or pattern that satisfies it (extend B11.11).
2. Define the assistive technology and browser matrix (Chromium-based, Firefox, Safari; NVDA, JAWS if available, VoiceOver, TalkBack; keyboard only; 200% and 400% zoom; high contrast and forced colors; reduced motion).
3. Define automated checks: axe-core oracle in CDP tests (zero serious/critical), color contrast token check, heading-structure check, landmark check, form-label check, focus-order recording.
4. Define manual checks: keyboard walkthrough scripts per critical flow, screen-reader checklists for 12 flows, zoom/reflow checks.
5. Define the severity scheme and the rule that serious issues block a gate.
6. Define the accessibility statement page content (honest conformance statement; known gaps).
7. Define how operator or volunteers run screen-reader checks if the agent cannot (record as `human_step_pending`).
8. Define the regression strategy (axe results stored per screen in `acceptance-ui/`).
**Deliverables.**
- `docs/UX/ACCESSIBILITY.md`, `docs/UX/a11y-checklists/*.md` (12 flows)
**Acceptance.**
- A1: every WCAG 2.2 A and AA criterion appears in the mapping with an owner component or "not applicable" reason.
- A2: the 12 critical flows are named and each has a checklist.
- A3: severity thresholds and gate rules are explicit.
- A4: manual checks that need human execution are marked `human_step_pending` with instructions.
- A5: the accessibility statement draft avoids claiming conformance beyond what is tested.
**Tests.**
- `xtask ux check` validates the criterion mapping completeness against a list of criteria stored in the repo.
**Notes.** AC-40 implements these checks (T-0502).
