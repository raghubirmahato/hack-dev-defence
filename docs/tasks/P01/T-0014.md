### T-0014 · Information architecture and URL scheme
`P01` `[DOC]` · deps: T-0012 · size: M · owner: ux
**Objective.** Turn B2 into the authoritative sitemap, URL scheme and permissions-aware navigation spec.
**Steps.**
1. Produce `docs/UX/IA.md` with the surfaces, hosts, and the full route table of B2.2 as a machine-readable `docs/UX/routes.toml` (route pattern, screen ID, surface, minimum permission ID, method set, rate-limit class).
2. Define URL rules: lowercase, hyphenated, no trailing slash, stable IDs, no PII or tokens in URLs, query parameters for filters only, canonical redirects.
3. Define the prefixed-ID format and its validation rules (type prefix, base32 over UUIDv7).
4. Specify the deep-linking behavior of tabs, wizard steps, filters and drawers (all state in the URL where meaningful).
5. Specify redirect rules (post-login return URL allowlist, org slug changes with permanent redirects for 30 days).
6. Specify 404 versus 403 behavior (cross-tenant resources are 404) and the not-found content.
7. Specify canonical titles and `<h1>` conventions.
8. Make `xtask routes check` compare `routes.toml` with the router at build time (stub until P04, enforced from T-0073).
**Deliverables.**
- `docs/UX/IA.md`, `docs/UX/routes.toml`
**Acceptance.**
- A1: every S-nnn screen of B12 appears in `routes.toml` exactly once (or is marked data-plane).
- A2: every route names a minimum permission ID from B4.2 or `public`.
- A3: URL rules include tests described for later implementation.
- A4: the ID format has a regex and a worked example.
- A5: no route contains a token or email.
**Tests.**
- `xtask ux check` verifies A1 and A2 against the spec registries.
**Notes.** This file is the contract for T-0073 and T-0125 (route permission check).
