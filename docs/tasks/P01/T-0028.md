### T-0028 · UX review pack and operator decision list
`P01` `[DOC][HUMAN]` · deps: T-0014, T-0015, T-0018, T-0019, T-0020, T-0021, T-0022, T-0023, T-0024, T-0025, T-0026, T-0027 · size: M · owner: ux
**Objective.** Package the UX foundations for review and capture decisions before design begins.
**Steps.**
1. Assemble `docs/UX/REVIEW-PACK.md`: summary of principles, personas, IA, journeys, states, accessibility plan, i18n plan, security UX, onboarding, dataviz, with links.
2. Run a Nielsen-style heuristic checklist against the journeys on paper and list the issues found and fixes made.
3. Run a security-UX review: for each dangerous action confirm the safeguard exists.
4. List open decisions for the operator: primary persona, languages at launch, plan model (unlimited vs tiered), signup mode, brand name/logo ownership, legal text ownership, status page hosting, data retention defaults.
5. Record the answers in `docs/UX/decisions/` as UXD entries or mark them open with defaults the agent will use.
6. Verify the traceability: every journey has screens; every screen has a journey or data-plane role.
7. Update `STATUS.md` and the capability matrix.
8. Request operator review; if unanswered, proceed with the stated defaults (recorded as assumptions).
**Deliverables.**
- `docs/UX/REVIEW-PACK.md`, UXD decision entries, updated register
- `docs/gates/G01.md` (the G01 gate report, E5.1 format)
**Acceptance.**
- A1: the pack links every UX document and states what changed since T-0011.
- A2: each open decision has a default and an owner.
- A3: heuristic review found issues and the fixes are recorded.
- A4: traceability script reports zero orphan screens or journeys.
- A5: nothing in the pack contradicts the claims policy.
- A6: `docs/gates/G01.md` records the G01 pass conditions with real output.
**Tests.**
- `xtask ux check` (traceability), `xtask verify`.
**Notes.** The pack is reviewed again at T-0070 with prototypes.
