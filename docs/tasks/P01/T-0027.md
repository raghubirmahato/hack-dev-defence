### T-0027 · Data visualization and dashboard information design
`P01` `[DOC]` · deps: T-0011 · size: S · owner: ux
**Objective.** Specify which numbers, charts and tables each screen shows and why.
**Steps.**
1. For each analytics screen (S-040, S-043, S-054, S-065, S-070 to S-072, S-100, S-127) list the questions the user is trying to answer and the metric that answers each.
2. Choose chart types per question using B11.10 and justify each.
3. Specify each metric's definition, unit, aggregation, time window, data source (rollup table or live), refresh cadence and the "Unknown" behavior.
4. Specify table columns, default sort, filters and density per table.
5. Specify the time range picker presets (last 15 minutes, 1 hour, 24 hours, 7 days, 30 days, custom) and limits per plan.
6. Specify comparison features (previous period) and annotations (rule changes, mode changes, deployments).
7. Specify color use and accessibility alternatives (table view, text summary).
8. Specify performance constraints (max points per chart, downsampling rule) and print layouts.
**Deliverables.**
- `docs/UX/DATAVIZ.md`, `docs/UX/metrics-dictionary.md`
**Acceptance.**
- A1: every KPI has a definition with source and window.
- A2: every chart has a text alternative defined.
- A3: annotations list includes mode changes, rule changes and bans.
- A4: downsampling rules are numeric.
- A5: unknown-data behavior defined per widget.
**Tests.**
- Implemented in T-0088 and the analytics phases; the metrics dictionary is cross-checked with B9 by `xtask ux check`.
**Notes.** Never chart interpolated or fabricated data.
