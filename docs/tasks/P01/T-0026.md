### T-0026 · Onboarding and activation design (checklist, readiness semantics)
`P01` `[DOC]` · deps: T-0018 · size: M · owner: ux
**Objective.** Design the first 15 minutes so users reach a protected domain safely.
**Steps.**
1. Define the onboarding stages (account, org, MFA nudge, first domain, DNS connect, verify, origin, monitor mode, first events, block-mode decision, alerts, team) and the checklist structure.
2. Define the readiness score model: categories, checks, weights, partial credit, unknown handling, and the exact honest footnote; list all checks with data sources and refresh intervals.
3. Define "next best action" selection rules (a deterministic priority list).
4. Define nudges and reminders (in-app, email) with frequency caps and opt-out.
5. Define the empty-state content of each major screen for new accounts.
6. Define how monitor mode results are summarized to support the block decision.
7. Define success and drop-off measures using local counters only.
8. Define the activation emails (welcome, verify, first domain, weekly summary) content outlines.
**Deliverables.**
- `docs/UX/ONBOARDING.md`, `docs/UX/READINESS-MODEL.md`
**Acceptance.**
- A1: the readiness model lists all checks with weight, data source, refresh interval and remediation link.
- A2: weights sum to 100 and unknown never counts as pass.
- A3: next-best-action rules are deterministic (a decision list).
- A4: nudges have frequency caps and an opt-out.
- A5: the footnote text matches B13 `readiness-footnote`.
**Tests.**
- A pure function spec with example inputs and expected outputs (implemented as tests in T-0172).
**Notes.** The model is scored for configuration completeness only.
