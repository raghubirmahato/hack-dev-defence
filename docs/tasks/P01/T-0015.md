### T-0015 · Navigation model and wayfinding
`P01` `[DOC]` · deps: T-0014 · size: S · owner: ux
**Objective.** Specify the navigation so users always know where they are, what they can do, and how to get back.
**Steps.**
1. Specify the org sidebar, top bar, domain context header and tabs of B2.3 including collapsed and mobile states.
2. Specify the org switcher and domain switcher behaviors (type-ahead, recent items, keyboard, empty states).
3. Specify breadcrumbs rules (maximum depth, truncation, current page).
4. Specify the command palette scope and ranking (recent, permitted actions, entities) and the keyboard shortcut map.
5. Specify how permission-restricted items are shown (hidden when no concept of the feature, explained when the feature exists but the plan lacks it).
6. Specify the admin surface visual distinction and its navigation.
7. Specify the focus management when navigating between pages and when HTMX swaps content (focus the new `h1` or the changed region and announce).
8. Specify the mobile navigation (drawer, bottom actions) and the minimal-width behavior at 360 px.
**Deliverables.**
- `docs/UX/NAVIGATION.md` with wireframe-level ASCII diagrams
**Acceptance.**
- A1: every navigation element has a keyboard behavior and an ARIA role.
- A2: focus management is specified for full page loads and partial swaps.
- A3: permission-hidden versus plan-limited states are distinguished.
- A4: mobile behavior is specified at 360, 480, 768 px.
- A5: the shortcut map has no conflicts with browser or screen-reader defaults (checked against a list in the doc).
**Tests.**
- Review checklist; later implemented and verified by T-0138 and T-0151.
**Notes.** Do not rely on hover for any navigation function.
