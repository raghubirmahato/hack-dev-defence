### T-0018 · Journey maps J-25 to J-34 (readiness, teams, API, admin, privacy, incident)
`P01` `[DOC]` · deps: T-0017 · size: M · owner: ux
**Objective.** Finish the journey set with team, developer, platform-admin, privacy and incident flows.
**Steps.**
1. Create maps for J-25 to J-34 in the same table format.
2. For J-25 define the readiness score semantics, the weights, the remediation links and the honesty footnote placement.
3. For J-27 define the API key lifecycle (create, secret reveal once, rotation, expiry, restrict by IP).
4. For J-29 to J-31 define the admin flows with reasons, step-up and audit visibility.
5. For J-33 define data export and deletion with timelines and legal-neutral wording.
6. For J-34 define the incident timeline: detection, under-attack mode, analyst actions, de-escalation, retrospective report.
7. Add the "stress case" for each (low bandwidth, small screen, keyboard only).
8. Consolidate cross-journey dependencies into a graph `docs/UX/journey-dependencies.md`.
**Deliverables.**
- `docs/UX/journeys/J-25.md` to `J-34.md`, `docs/UX/journey-dependencies.md`
**Acceptance.**
- A1: all journeys J-01 to J-34 now exist.
- A2: dependencies form an acyclic graph and match task dependencies where applicable.
- A3: each admin journey lists the permission ID and audit event.
- A4: J-34 includes a retrospective report outline.
- A5: all documents pass claims-lint.
**Tests.**
- `xtask ux check` (existence of all 34 files; graph acyclicity).
**Notes.** The incident journey is reused by AC-27 and AC-44 designs.
