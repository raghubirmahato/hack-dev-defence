### T-0013 · Pattern review of comparable products (documented first principles)
`P01` `[DOC]` · deps: T-0011 · size: M · owner: ux
**Objective.** Learn from established patterns for WAF, CDN and DNS consoles without copying and without out-of-scope browsing.
**Steps.**
1. Define the review questions: how do comparable consoles present onboarding, DNS import, proxy toggles, WAF modes, event logs, rule builders, bans, analytics, API keys, team management.
2. Establish sources: operator-supplied screenshots or exports, public documentation fetched via the egress client only if its hosts are allowlisted, and first-principles reasoning. If none is available, mark the review `UNVERIFIED(capability_not_supplied)` and proceed from first principles.
3. For each topic write the *pattern* (problem, common solutions, pitfalls) in our own words; never copy text or assets.
4. Record accessibility and clarity pitfalls commonly seen (color-only status, jargon, destructive actions without preview, hidden self-lockout risks).
5. Derive 20 design requirements (DR-01 to DR-20) with rationale, each traceable to a screen or component.
6. Capture explicit non-goals (features we will not copy and why).
7. Have the findings reviewed against the honesty tests of the charter.
8. Commit.
**Deliverables.**
- `docs/UX/PATTERNS.md`, `docs/UX/design-requirements.md`
**Acceptance.**
- A1: at least 12 topics have a pattern entry.
- A2: the source of each entry is stated (first principles, operator-supplied, allowlisted public doc).
- A3: no verbatim text from third-party sources.
- A4: DR-01 to DR-20 each link to a component or screen.
- A5: the status line states PASS or UNVERIFIED(reason).
**Tests.**
- Plagiarism-style check: no sentence longer than 12 words shared with fetched sources (simple xtask check when sources were fetched).
**Notes.** Network access for this task is optional; its absence must not block the phase.
