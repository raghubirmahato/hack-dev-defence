### T-0586 · Sentinel analyst (optional language model): triage, explanations and rule drafts for humans
`P34` `[SEC][API][DP]` · deps: T-0584, T-0229, T-0009, T-0368 · size: L · owner: sec
**Objective.** Give owners a helpful assistant that can never act on its own and cannot be steered by attackers.
**Steps.**
1. Implement the analyst service in `hdd-worker`, off by default (`HDD_ANALYST_MODE=off|local|remote`), reached only through the egress client to an allowlisted endpoint or a loopback model; cost and rate caps per organization; no cross-tenant context ever.
2. Define the input contract: redacted evidence (at most 512 bytes), features, event metadata, all placed in structured fields labeled untrusted; secrets, cookies and personal data are removed before the call (redaction library T-0253).
3. Implement the tasks: campaign summary, plain-language explanation of a block, triage ranking, and a draft rule or exception returned as a typed diff; the model has no tools and no write access.
4. Validate outputs against a schema; reject anything that is not valid; never render model text as HTML without escaping; label it "assistant suggestion".
5. Route every draft through the dry-run and replay harness (T-0229) automatically, attach the false-positive candidates, and require explicit human approval with step-up before it exists as a rule.
6. Log prompts and outputs redacted with a 30-day retention; add an owner switch and a platform switch; show the data-handling statement before first enable.
7. Add tests and the reusable prompt-injection harness consumed by T-0585: payloads in evidence, oversized inputs, malformed outputs, endpoint failures, cross-tenant leakage attempts.
8. Document the privacy and cost model.
**Deliverables.**
- analyst service, input and output contracts, approval flow, tests, docs
**Acceptance.**
- A1: with the analyst enabled and a malicious evidence field, no rule is created or changed without a human approval event.
- A2: a drafted rule always shows its replay results before the approve button is enabled.
- A3: no secret, cookie or other-tenant datum appears in any prompt (privacy test with canary values).
- A4: disabling the analyst changes nothing else in the product (differential test).
- A5: the egress allowlist rejects a non-configured endpoint (egress test).
**Tests.**
- Injection suite; privacy test; integration with the dry-run harness.
**Notes.** The analyst is a convenience. Everything it can do can also be done by a human without it.

## Definition of done for this task's tags (section 0.7)

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
