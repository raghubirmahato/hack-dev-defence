### T-0596 · Attack-matrix expansion: ATK-301 to ATK-390 fixtures, detectors and tests
`P34` `[DP][SEC][QA]` · deps: T-0595, T-0597, T-0598, T-0496, T-0497, T-0313, T-0289, T-0290, T-0296, T-0308, T-0310, T-0495 · size: XL · owner: waf
**Objective.** Implement and test every new row of AG-18 to AG-21; T-0597 and T-0598 build the shared parsers and detectors, and this task integrates, extends and verifies them in the matrix.
**Steps.**
1. For each of ATK-301 to ATK-340 create the fixture (shape only, inert, Class A or B per section 2.2) and the rule or detector entry in the VKB, with the CVE reference in the rule metadata and the "verify at build time" flag cleared only after the current KEV check.
2. For ATK-341 to ATK-360 integrate the framing and parser checks (provided by T-0597), the cache rules (T-0598) and the Sentinel row (ATK-360, shadow-evaluated); rows whose action is `P`, `L` or `Q` are mitigations or posture items and are tested for that behavior, not for detection.
3. For ATK-361 to ATK-370 integrate the AI-endpoint and exposure detectors (T-0598) with declared-endpoint configuration, and implement ATK-371 to ATK-390 (AG-21) with fixtures and detectors.
4. Add each row to `cargo xtask attack-matrix check` (fixture, test referencing the ID, mapped task).
5. Run each family in the lab against vulnerable containers where available (Struts, Spring, Jenkins, Tomcat, Laravel, Grafana and others pinned by digest) for the three-part test of T-0497.
6. Measure false positives for every new rule against the benign corpora and per-product benign sets.
7. Extend the coverage map (E15) with the new rows and statuses; downgrade any row without evidence.
8. Document limits per row (shape-only coverage; variants not seen).
**Deliverables.**
- 90 fixtures with tests, rules and detectors, lab proofs, matrix check, coverage-map rows
**Acceptance.**
- A1: `attack-matrix check` passes with 390 rows.
- A2: every row has a fixture and a test that references its ID.
- A3: no new false positive on the replay corpora at the stated size and confidence bound (T-0595), or the rule is narrowed to a product and path scope with the narrowing recorded.
- A4: for rows with a lab container, the three-part test passes (exploit works directly, blocked through HDD, legitimate use works).
- A5: rows without lab proof are marked `shape-only` in the coverage map.
**Tests.**
- Matrix check; lab runs; false-positive replays.
**Notes.** Named-vulnerability rows are shapes; they reduce exposure to those exploit paths and never mark a vulnerability resolved (R-11).

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.
