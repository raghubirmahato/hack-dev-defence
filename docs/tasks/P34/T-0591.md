### T-0591 · Continuous bypass verification, origin tripwire and the Bypass Guard screen (S-138)
`P34` `[SEC][OPS][UI][API]` · deps: T-0588, T-0590, T-0165, T-0192, T-0201, T-0063 · size: XL · owner: sec
**Objective.** Prove, repeatedly and from outside, that no direct path exists, and say so only with evidence.
**Steps.**
1. Implement the verification engine in `hdd-scan` (read-only, own addresses only): from at least two vantage points outside HDD's network (operator runner, operator-configured probes, bring-your-own-probe token page) attempt direct connections to the origin address, after proving ownership of each probed address and name (DNS or HTTP challenge), resolving once and pinning, and refusing private, loopback, link-local and cloud-metadata ranges, on the common web ports, configured ports and the top-100 web ports (rate-limited), over IPv4, IPv6 and UDP 443, with and without SNI and with varied `Host` values, plus every historic and certificate-transparency name and every sibling hostname found.
2. Classify results: `blocked`, `site_content` (matched by the echo canary token or content hash: bypass), `exposed_service` (any non-HDD service that answers: also fails verification), `inconclusive`, `unverified` (vantage unavailable); first run the origin-address check (a unique token must be seen on both the proxied and the direct path), record evidence hashes in `bypass_probes`, and write every probe target to the audit log. At least one vantage is HDD-operated with rotating unpublished addresses; owner probes sign results with a per-probe key and nonce.
3. Implement the origin tripwire ingestion: verifier heartbeats (T-0588) and the canary echo (T-0210) create `bypass_events` only for confirmed bypasses (served without a valid signature); rejected attempts are aggregated as informational counters and never change the state (health checkers are allowlisted by the owner).
4. Implement the state machine of C21.4 (`unprotected` to `bypass_detected`), transitions with evidence, two clean runs to leave `bypass_detected`, and the effects: critical alert, one-click key rotation, readiness penalty, block-mode promotion hold; a site already in `block` keeps blocking; `degraded` starts only after 24 hours without a valid verification.
5. Implement DNS and exposure checks: unproxied records sharing the origin address, wildcard policy, dangling names (T-0192), certificate-transparency names that resolve to the origin (T-0201), mail-header leaks.
6. Build S-138: state, evidence timeline, per-vantage results, open bypass paths with remediation links, probe schedule, and the exact wording rule ("no direct path found from N vantage points on <date>").
7. Implement the API of B6.7 (`/origin/bypass-guard*`), `PERM-bypass.read`, `PERM-bypass.verify`, `PERM-bypass.key_view` and `PERM-bypass.accept_risk`, the audit events `AUD-bypass.state_changed`, `AUD-bypass.risk_accepted`, `AUD-bypass.probe_run` and `AUD-bypass.event`, the metrics of B9 and notifications.
8. Test with lab origins in four configurations: open, header-only, signed, tunnel with closed inbound; plus injected faults (an open alternate port, an IPv6 side door, a leaked sibling hostname).
**Deliverables.**
- verification engine, tripwire ingestion, state machine, S-138, API, tests
**Acceptance.**
- A1: each injected bypass (open alternate port, IPv6 side door, leaked sibling hostname, direct IP with Host header) is detected within one probe interval.
- A2: a site whose origin is open is never shown as `verified`; the surfaces show "bypassable".
- A3: a probe from HDD's own network is never accepted as evidence, a probe target without ownership proof or in a private or metadata range is refused, and an owner probe that always reports `blocked` is flagged (tests).
- A6: a lab origin that answers on an alternate port with a non-site service is classified `exposed_service` and fails verification, and a header-only origin never exceeds `applied_unverified`.
- A4: a request served without a valid signature creates a `bypass_events` row within 60 s and an alert, while a rejected unsigned request only increments the attempt counter.
- A5: zero serious or critical axe findings on S-138, and no copy says bypass is impossible.
**Tests.**
- Lab matrix of origin configurations; injected-fault tests; browser tests; claims-lint.
**Notes.** The probe set is deliberately limited to the owner's own address and rate-limited; it never scans third parties (section 2.1).

## Definition of done for this task's tags (section 0.7)

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
