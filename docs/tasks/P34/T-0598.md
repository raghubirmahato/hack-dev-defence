### T-0598 · Deception, cache guard, origin integrity, script integrity and AI-endpoint protections
`P34` `[DP][SEC][API]` · deps: T-0309, T-0409, T-0412, T-0311, T-0302 · size: XL · owner: sec
**Objective.** Address further gaps that are not injection or bypass: stolen data, cache abuse, post-exploitation, client-side tampering and AI-backed endpoints.
**Steps.**
1. **Honeytokens:** generate decoy credentials, API keys, tokens and records, place them in responses to known-bad probes, decoy files and optional page comments; tokens are issued per session or per client and never placed in globally public comments; a token seen in a request raises a critical event and a high score, and it causes a ban only when the request is same-site or first-party and the token was issued to a different client (never in cross-site context, never behind a shared address without other signals; crawlers and archivers do not trigger bans) (`honeytokens` table, hashed values, rotation).
2. **Cache guard** (ATK-155, 156, 345, 346): applies to HDD-owned caching and to a declared cache topology (it warns when a CDN fronts HDD, where HDD sees neither key nor cache): strip a configured set of unkeyed headers only, enforce `Vary`, normalize path delimiters for cache eligibility only (never in the forwarded path, so matrix parameters and encoded slashes keep working), refuse caching of responses with credentials or with dynamic markers (a documented list: `Set-Cookie`, `Authorization`, `Cache-Control: private`, per-user content types), and detect cache-poisoned-DoS shapes.
3. **Webshell interaction detection** (ATK-127): request-side parameter and command shapes of common web shells, response-side output signatures (directory listings, command output), and file-hash watch of static public files.
4. **Origin integrity watch:** the verifier or canary reports hashes of an owner-chosen set of public files (scripts, templates, entry points); a changed hash raises an alert and, if the file is a served script, feeds the script-integrity monitor.
5. **Script-integrity monitor and generated CSP / Trusted Types:** inventory of scripts served to visitors (from the crawler and reports), change alerts, SRI suggestions, and a generated CSP in report-only mode first (extends T-0412); skimmer-shape detection (ATK-267).
6. **AI-endpoint protections** (ATK-361 to ATK-369): declared AI endpoints get prompt-size caps, per-identity token budgets, invisible-Unicode and instruction-marker signals (signal only), model-artifact upload checks, access-gate templates for model-serving and MCP paths, and outbound checks for secrets in model responses.
7. **Response hardening:** response-splitting and header-injection re-checks on origin responses, and `Content-Type` sniffing protection defaults.
8. Add tests for each measure with fixtures and a benign replay, and add S-132 and S-131 template entries for the new endpoint families.
**Deliverables.**
- honeytokens, cache guard, webshell and integrity detectors, script monitor and CSP generator, AI-endpoint protections, tests
**Acceptance.**
- A1: use of a honeytoken in the first-party case results in a critical event and a ban within 2 s, use in a cross-site or crawler context results in a critical event without a ban, and a benign replay never trips one.
- A2: the cache-deception and cache-poisoning fixtures (ATK-155, 156, 345, 346) do not poison or leak through the cache in the lab (differential test against named lab caches: Varnish, nginx proxy cache and a CDN emulator, with stated TTLs and cases).
- A3: a changed watched file raises an alert within one check interval.
- A4: a declared AI endpoint rejects an over-budget prompt and a per-identity token overrun with the right status and no origin traffic.
- A5: the generated report-only CSP runs on the canary site with zero violations of first-party assets.
**Tests.**
- Lab integration; cache differential tests; integrity tests; browser CSP test.
**Notes.** Prompt-injection signals on AI endpoints are advisory; HDD cannot make an LLM-backed application immune to prompt injection and says so.

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
