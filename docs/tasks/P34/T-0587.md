### T-0587 · Sentinel screen (S-137), API and operations
`P34` `[UI][API]` · deps: T-0584, T-0586, T-0137, T-0063 · size: L · owner: web
**Objective.** Let owners see, tune and trust (or distrust) Sentinel.
**Steps.**
1. Build S-137: mode selector with consequences and promotion checklist, findings table (score, features in plain language, action taken, label controls), baseline maturity per template, model versions and age, and the replay tool.
2. Implement the API of B6.7 (`/security/sentinel*`) with `PERM-sentinel.read`, `PERM-sentinel.write` (mode changes, step-up for `block`), `PERM-sentinel.label` and `PERM-sentinel.platform` (models), OpenAPI entries, the audit events of T-0581 and the metrics of B9.
3. Implement the platform views for models (`P/sentinel/models`): metrics, model cards, staged rollout and rollback, with step-up.
4. Implement notifications (appeal spike, drift, model age) and the readiness inputs (Sentinel mode is shown as information, never as a score gain).
5. Implement the honest copy: every label says "advisory"; the page shows the unseen-family detection number from the model card with its confidence interval and the limits statement.
6. Add i18n keys, empty and error states, accessibility checks and keyboard operation.
7. Add browser tests for mode changes, labeling and the promotion checklist.
8. Add the docs page "What Sentinel can and cannot do".
**Deliverables.**
- S-137, endpoints, platform views, notifications, docs, tests
**Acceptance.**
- A1: switching to `block` mode requires step-up and shows the false-positive budget and the held-out numbers.
- A2: the page never shows a score without its explanation and the word advisory.
- A3: zero serious or critical axe findings on S-137.
- A4: claims-lint passes on all Sentinel copy.
- A5: labels from analysts are tenant-scoped (BOLA test).
**Tests.**
- Browser, API contract, permission matrix, claims-lint.
**Notes.** Sentinel never appears in marketing copy except with its limits statement.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
