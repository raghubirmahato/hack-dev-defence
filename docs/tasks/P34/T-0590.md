### T-0590 · Origin firewall and cloud allowlist generators
`P34` `[OPS][SEC]` · deps: T-0405, T-0406, T-0407 · size: M · owner: ops
**Objective.** Make the network half of lockdown a copy-paste, verifiable, reversible step.
**Steps.**
1. Generate rule sets from the published HDD egress addresses (T-0405) for nftables, iptables, ufw, firewalld, Windows Defender Firewall, and the main cloud firewalls (AWS security groups, GCP, Azure NSG, DigitalOcean, Hetzner, OVH) as copy-ready text and as provider API call templates (never executed by HDD).
2. Include IPv4 and IPv6, TCP and UDP 443, and rules that also close other published ports (databases, admin ports) when the owner confirms the list from the port probe.
3. Add safety: SSH-lockout warnings, timed-revert command suggestions, and a dry-run diff against the owner's pasted current rules.
4. Handle changes of the HDD egress set: announce 30 days ahead, publish both sets during overlap, notify owners, show drift on S-138, expire removed addresses automatically after the overlap and have the probe confirm the old set is closed.
5. Add provider-specific caveats (shared hosting cannot close ports; managed load balancers; container platforms) and the co-tenant caveat: if the egress range is shared, other tenants of it can reach the origin, so a firewall-only setup is not eligible for `verified`.
6. Add tests that validate generated syntax with each tool's checker in the lab (nft `-c`, iptables-restore `--test`, ufw dry run).
7. Integrate with the verification probe (T-0591) so each step shows its verified effect.
8. Document the undo for each generator.
**Deliverables.**
- generators, wizard integration, syntax tests, docs
**Acceptance.**
- A1: every generated rule set passes its tool's syntax check in the lab.
- A2: applying the nftables output on a lab origin blocks a direct probe and allows HDD's addresses (integration test).
- A3: the egress-set overlap period publishes both sets and the generators produce the union.
- A4: the SSH-lockout warning appears on every output that could affect port 22.
- A5: the shared-hosting profile shows the `weak` classification with reasons.
**Tests.**
- Syntax checks; lab integration; snapshot tests of outputs.
**Notes.** HDD never applies origin firewall changes itself (R-04).
