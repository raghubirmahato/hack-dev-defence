### T-0589 · `hdd-tunnel`: outbound-only connector so the origin has no inbound exposure
`P34` `[SEC][DP][OPS]` · deps: T-0384, T-0365, T-0405, T-0355 · size: XL · owner: dp
**Objective.** Offer the strongest lockdown available: no inbound listener on the origin once the closure is verified.
**Steps.**
1. Specify the tunnel protocol: the connector on the origin host opens an outbound mutually authenticated TLS connection (HTTP/2 or QUIC-free multiplexing over TCP) to the HDD tunnel endpoint; HDD sends origin requests down existing streams; the connector forwards to a local address.
2. Implement the HDD side (`hdd-proxy::tunnel`): connector registration with single-use enrollment tokens (15-minute lifetime, bound to the site, fingerprint confirmed on both sides), client certificates from the internal PKI (T-0384), stream limits, health, backpressure and per-site isolation (a connector can serve only its own site).
3. Implement the connector binary `hdd-tunnel` (Rust, static, small): reconnect with jittered backoff, the target pinned to one configured `host:port` (no ranges), preferably a Unix socket or a dedicated address so that origin apps that trust loopback peers do not see tunnel traffic as local, no listening ports, resource limits, signed self-update through the release process (T-0518).
4. Integrate with the origin client: a site in tunnel mode routes through its connector, with failover to a second connector, and with signed authentication (T-0588) still applied inside the tunnel.
5. Extend the lockdown wizard: enrollment command, systemd/launchd/Windows service templates, and the firewall guidance to close all inbound web ports; verification probe confirms that direct connections fail.
6. Implement connector revocation, rotation and the `tunnels` table, with metrics (`MET-hdd_tunnel_connected`) and alerts for disconnects.
7. Test with a real origin in the lab: restart storms, network partitions, slow connectors, many connectors, hostile connector (tries other sites), enrollment-token race and replay, and a loopback-only admin path on the origin.
8. Document limits (latency added, single connector as a failure point without a second).
**Deliverables.**
- tunnel endpoint, `hdd-tunnel` connector, enrollment and revocation, wizard flow, tests, docs
**Acceptance.**
- A1: with the origin's inbound web ports closed, the site works end to end through the tunnel and every direct probe in the lab matrix fails.
- A2: a connector cannot receive or send traffic for any other site (isolation test).
- A3: a revoked connector is disconnected within 5 s.
- A4: killing the network for 60 s and restoring it resumes service without manual action.
- A5: the connector exposes no listening socket in the port-scan test.
**Tests.**
- Lab integration; chaos tests; isolation and revocation tests; port scan.
**Notes.** Tunnel mode removes the direct network path only if the origin host's inbound ports are closed; the probe checks it.
