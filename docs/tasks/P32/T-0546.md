### T-0546 · Tier 2: alternate ACME CAs and external account binding (EAB)
`P32` `[DP][API][SEC]` · deps: T-0376, T-0377 · size: M · owner: dp
**Objective.** Reduce dependence on a single CA and allow operators to use CAs requiring EAB.
**Steps.**
1. ADR on supported directories (Let's Encrypt, ZeroSSL, Google Trust Services, Buypass if available, and private ACME CAs such as step-ca for internal use), differences in rate limits and validation methods, ARI support, and EAB requirements; verify current CA policies at build time (limits, supported challenge types, lifetimes).
2. Extend the ACME client wrapper with EAB (HMAC key id/key stored encrypted), per-account/per-CA settings, CA selection per site/org (`acme.ca_profile`), and automatic fallback order with budgets per CA (failure of the primary CA after N attempts triggers the fallback only if the operator enabled it).
3. Implement budget tracking per CA with provenance of limit values (configurable, verified against CA documentation at build time), CT and CAA interplay (CAA records must allow each CA the operator uses; the CAA wizard lists CA identifiers).
4. Implement private CA mode for internal/lab (`step-ca`), isolated from public CA settings, and clear UI labels ("Private CA: not trusted by browsers").
5. Update the certificate screens (S-050/S-051) to show CA, account and rate-limit state, and the admin certificate inventory (S-112) to show per-CA budgets.
6. Write tests with Pebble (and `step-ca` for private mode), covering EAB success/failure, CA fallback, CAA mismatch, budget exhaustion, ARI-driven renewals on supporting CAs, and key/account rotation.
7. Document operational guidance on choosing CAs and managing accounts.
8. Update claims and capability matrix.
**Deliverables.**
- ADR, EAB support, CA profiles, UI changes, tests
**Acceptance.**
- A1: issuance works through at least two CA profiles in the test environment (Pebble variants) including one with EAB.
- A2: fallback occurs only when enabled and budgets allow.
- A3: CAA wizard lists correct identifiers per CA.
- A4: EAB secrets are encrypted and never logged.
- A5: private CA certificates are clearly labeled.
**Tests.**
- Integration with Pebble/step-ca, unit tests.
**Notes.** Live issuance on alternate CAs requires operator accounts: UNVERIFIED otherwise.
