### T-0558 · Tier 6: billing and subscription integration (optional)
`P32` `[API][UI][DB][SEC]` · deps: T-0429, T-0146 · size: XL · owner: api
**Objective.** If the operator runs HDD as a paid service, integrate with a payment provider without storing card data.
**Steps.**
1. ADR on provider (Stripe-class) with PCI scope minimization: hosted checkout/portal only, no card data ever touching HDD servers, webhook-driven state, idempotent handlers, signature verification, and replay protection; choose the provider based on the operator's jurisdiction; support for "invoice/manual billing" mode for B2B.
2. Data model: customers, subscriptions, invoices (references only), plan mappings (`external_price_id`), proration policies, dunning states, trial periods, coupons; usage-based add-ons (extra domains, retention) via metered usage reporting from analytics (idempotent usage records).
3. Flows: upgrade/downgrade, trial, cancellation, payment failure (grace period with banners, no abrupt protection removal: protection continues during the grace period; policy documented), invoice history, receipts, tax handling delegated to the provider (tax ID collection fields), billing role permissions (`billing` role has plan/usage only).
4. Webhook receiver for provider events with HMAC verification, replay window, idempotency table, and strict state machine transitions; reconciliation job comparing provider state with local state daily.
5. Safety: billing failures never disable the data plane abruptly; downgrade enforcement uses the quota semantics of T-0429 (no data deletion); fraud/abuse signals feed the abuse queue.
6. UI: S-085 plan & usage screens with upgrade flows, invoices list, payment method link to hosted portal; admin tools for refunds/credits delegated to provider dashboard (links), manual overrides for support (audited).
7. Tests with the provider's test mode and fake servers: lifecycle scenarios, webhook replay/forgery, race conditions, currency/rounding, proration, dunning, reconciliation, plus security tests (signature bypass, parameter tampering of price ids, IDOR on invoices).
8. Legal/compliance notes (terms, refund policy templates) as operator-reviewed documents; claims-lint for pricing statements.
**Deliverables.**
- ADR, billing module, UI, webhook receiver, tests
**Acceptance.**
- A1: no card data reaches HDD servers (network capture test against hosted flows).
- A2: webhook forgery and replay are rejected.
- A3: payment failure never drops protection abruptly (grace period tests).
- A4: reconciliation detects and reports divergences in the lab scenarios.
- A5: billing role cannot access security data (permission tests).
**Tests.**
- Provider test mode, fakes, security tests.
**Notes.** Disabled in `owner_only` mode; billing integration is explicitly optional.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
