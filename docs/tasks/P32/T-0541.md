### T-0541 · Tier 2: DNS provider import adapters (read-only) for common providers
`P32` `[API][UI][SEC]` · deps: T-0157, T-0184, T-0413 · size: L · owner: dns
**Objective.** Let owners import their existing zone by connecting a provider API token with read-only scope, reducing onboarding friction and errors.
**Steps.**
1. Write a short **ADR** selecting the first adapters by user demand and API stability (candidates: Cloudflare, AWS Route 53, DigitalOcean, Google Cloud DNS, Azure DNS, Namecheap, GoDaddy, Hetzner DNS, deSEC); record scopes needed (read-only), rate limits, record-type coverage and proprietary features per provider.
2. Extend the `ImportAdapter` trait (T-0157) with `authenticate`, `list_zones`, `export_zone` (normalized records plus provider-specific metadata such as proxied/orange-cloud flags and ALIAS/ANAME/redirect rules mapped to the HDD unsupported-type report); tokens are held encrypted for the import session only (default) and deleted after the import completes unless the owner opts into "re-sync later".
3. Implement each adapter against the provider API through the egress client with pinned hosts; pagination, rate-limit backoff, error mapping to owner-readable messages; no write operations exist in the adapter code (a static check forbids non-GET methods in the adapter modules).
4. Map provider semantics: Cloudflare proxied → HDD proxied with explicit confirmation, page rules/redirects reported as unsupported, Route 53 alias records → flatten/ALIAS handling or unsupported report, health-check-based routing → unsupported with explanation, geo/weighted routing → unsupported with explanation.
5. Present the import results in the existing parity UI (S-047) with a provider-specific section and the instructions for the NS change at the provider (human step) — HDD never changes anything at the provider.
6. Add **scoped token guidance**: step-by-step creation of minimal read-only tokens per provider (documented and screenshot-tested in docs tests where possible), token validation that rejects tokens with write scopes when the provider API exposes scopes (warn strongly otherwise).
7. Write tests against recorded provider API fixtures (VCR-style, sanitized) and against local fake servers for error conditions; no live provider calls in CI (live smoke tests optional with operator-provided read-only tokens).
8. Update docs and the capability matrix.
**Deliverables.**
- ADR, adapters, UI sections, docs, fixture-based tests
**Acceptance.**
- A1: for each adapter the fixture zones import with the documented mapping and unsupported-type report.
- A2: adapters cannot perform non-GET calls (static gate).
- A3: tokens are deleted after import by default (test).
- A4: provider hosts are pinned in the egress allowlist and nothing else is contacted.
- A5: tokens with write scopes trigger the documented warning/rejection where detectable.
**Tests.**
- Fixture replay, fake-server error tests, static gates.
**Notes.** Live smoke tests need operator tokens: UNVERIFIED(`capability_not_supplied`) otherwise.
