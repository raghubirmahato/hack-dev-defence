### T-0550 · Tier 3: HTTP/2 SETTINGS and advanced TLS fingerprinting (JA4 family) for bot scoring
`P32` `[DP][SEC]` · deps: T-0342, T-0340, T-0357 · size: M · owner: dp
**Objective.** Improve bot classification using protocol-level client fingerprints while handling their limits honestly.
**Steps.**
1. Extend the JA4 implementation (T-0342) to the JA4 family (JA4, JA4S optionally, JA4H for HTTP headers order/cookies presence, JA4X not required), with canonical computation tested against published vectors; compute HTTP/2 fingerprints from SETTINGS frame values and order, WINDOW_UPDATE initial values, PRIORITY frames and pseudo-header order (Akamai-style fingerprint concept).
2. Build and sign a **fingerprint reference database** of known clients (current browsers, popular HTTP libraries, curl, Go, Python requests/httpx, Java, scanners/headless tools) versioned and updated through packs; entries state confidence and date; unknown fingerprints are neutral, never penalized by default.
3. Integrate into **bot scoring:** consistency checks between claimed `User-Agent` and fingerprints (a Chrome UA with a Go TLS fingerprint scores high; a curl UA with curl fingerprint is consistent), rare-fingerprint tracking per site (new fingerprints seen from many IPs), and use as one signal among several with bounded weight (cannot ban alone; only influences challenge decisions and soft scores).
4. Handle **fingerprint randomization** (Chrome extension permutation, GREASE) with normalized forms; document the arms race and false-negative nature.
5. Privacy: fingerprints are stored as hashes with limited retention (30 days) in aggregated form; settings allow opting out per org.
6. Add S-062 views for fingerprint classes (counts, top unknown fingerprints) without raw identifiers beyond hash prefixes.
7. Write tests: vector tests, consistency scoring tables, randomization handling, FP controls with real browser captures (recorded from major browsers on common OSes, including mobile), performance (≤ 20 µs per connection).
8. Update docs and claims ("fingerprints are heuristics").
**Deliverables.**
- JA4 family, H2 fingerprinting, reference DB tooling, scoring integration, tests
**Acceptance.**
- A1: published JA4 test vectors reproduce exactly.
- A2: no ban is issued from fingerprint signals alone (test).
- A3: real browser captures are classified as consistent with their UAs (≥ 99% on the capture set).
- A4: retention and opt-out controls work.
- A5: overhead target met.
**Tests.**
- Vector tests, capture replay, performance.
**Notes.** Fingerprint evasion is easy for determined attackers; this improves cheap-bot detection only.
