### T-0559 · Tier 6: explainable ML-assisted anomaly scoring (offline-trained, bounded influence)
`P32` `[DP][SEC][QA]` · deps: T-0349, T-0340, T-0451 · size: XL · owner: sec
**Objective.** Add an optional statistical layer that surfaces novel anomalies without becoming an opaque blocker.
**Steps.**
1. ADR defining the philosophy: ML never makes a ban decision alone; it produces an **advisory anomaly score** feeding soft scores and owner-facing insights, with caps on influence, full explainability (top contributing features), per-site baselines, and an off switch; training is **offline** on synthetic and opt-in anonymized aggregated features (no raw payloads), models are small (gradient-boosted trees or isolation forests/logistic regression), exported to a deterministic Rust inference implementation (no runtime dependency on Python).
2. Define the **feature set** (privacy-safe): request rate patterns, path-template entropy and novelty, parameter count/length distributions per template, character class ratios, header order/set deviations, method/content-type combos, response status patterns, session-level sequences (bounded), time-of-day features, error ratios; no raw strings are stored in features beyond hashed tokens.
3. Build the **training pipeline** (`xtask ml train`): data from the Vuln-Lab runs, benign corpora, and synthetic traffic generators; cross-validation, calibration, evaluation on held-out sets, false-positive analysis at fixed operating points, drift detection, model cards (`docs/ml/MODEL-CARD.md`) with intended use, limits and bias considerations, and reproducible builds of model artifacts (hash-pinned, signed with pack signing).
4. Implement **inference** in `hdd-waf-core` as an optional detector with strict budgets (≤ 50 µs per request, no allocation in the hot path), deterministic outputs, per-site calibration of thresholds using local baselines (EWMA), and shadow mode by default (records scores without influence) for at least 14 days before enabling influence.
5. UI: anomaly insights panel (S-072 extension) showing flagged requests/path templates with explanations ("unusually long parameter for this endpoint; rare character mix"), an owner feedback loop (mark as normal) feeding local baselines (not global training without opt-in), and clear labeling "advisory".
6. Safety: model files are signed; invalid models are rejected; a model fault falls back to disabled with an alert; adversarial robustness tests (evasion by mimicry, poisoning attempts via crafted benign-looking requests to shift baselines): baseline updates are rate limited and bounded.
7. Evaluate on AC-06 (no increase in false positives with influence enabled) and AC-39 (no reduction in detection); document that ML does not replace signatures.
8. Governance: opt-in data sharing policy for model improvement (off by default), privacy impact notes, and claims-lint for ML statements ("advisory anomaly detection", never "AI-powered protection" without evidence).
**Deliverables.**
- ADR, feature extractor, training pipeline, inference, UI insights, model card, tests
**Acceptance.**
- A1: inference meets the latency and allocation budgets.
- A2: enabling influence causes zero additional false positives on the benign corpora and no reduction in AC-39 detections.
- A3: poisoning attempts cannot shift baselines beyond the configured bound (adversarial tests).
- A4: models are signed and invalid models are rejected.
- A5: the UI shows explanations for every flagged item.
**Tests.**
- Evaluation harness, adversarial tests, performance benchmarks.
**Notes.** If evaluation does not show a clear benefit at acceptable risk, the task closes with the ADR documenting "not adopted".
