### T-0553 · Tier 4: health-probed automatic edge failover (DNS-level, multi-edge)
`P32` `[DP][OPS]` · deps: T-0478, T-0554, T-0525 · size: L · owner: dns
**Objective.** Automate the manual standby failover of Tier 1 using external health probing and safe decision logic.
**Steps.**
1. ADR on the decision architecture: probes from at least three independent vantage points (self-hosted `hdd-probe` agents on different providers or operator-chosen services), quorum-based decisions (e.g., 2 of 3 vantage points report failure for 3 consecutive intervals), flap protection, minimum dwell, maximum failover frequency, and operator override.
2. Implement probe agents (`hdd-probe`): lightweight Rust binary performing TLS+HTTP checks of canary hostnames through each edge IP, DNS checks, and reporting signed results to the control plane (HMAC/mTLS) with bounded rates; agents are not trusted for security decisions beyond health.
3. Implement the **failover controller** in `hdd-shield`/control plane: evaluates quorum, verifies standby readiness (snapshot parity, certificates, lockdown allowlists), applies the edge address set revision (T-0478), records audit events, and notifies; includes automatic failback with cool-down and verification; honors per-site and platform-level enable switches (default off).
4. Integrate with TTL strategy: dynamic lowering of proxied TTLs when the system detects instability (bounded), and awareness of resolver caching (documented expected delay).
5. Add failure scenarios: partial failures (one edge degraded), network partition between probes and control plane, probe agent compromise (a single malicious agent cannot trigger failover), split-brain avoidance (control plane is the single decision point).
6. UI: S-127 failover panel gains probe status, quorum view, decision history and simulation mode ("what would happen") without acting.
7. Test with the lab (multiple edges, controlled failures), chaos suite additions, time-accelerated decision tests, and security tests on agent authentication.
8. Document risks (false failovers) and recommended settings.
**Deliverables.**
- ADR, `hdd-probe`, controller, UI, tests
**Acceptance.**
- A1: a single failed or malicious probe agent cannot trigger failover (quorum tests).
- A2: real edge failure triggers failover within the configured decision time and answers change within 2 s of decision.
- A3: flapping conditions do not cause oscillation (hysteresis tests).
- A4: simulation mode never changes DNS.
- A5: failback requires verification and respects cool-down.
**Tests.**
- Lab multi-edge, chaos, security.
**Notes.** Requires the multi-node data plane (T-0554) or an operator-run replica edge.
