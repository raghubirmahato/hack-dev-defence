### T-0549 · Tier 3: HTTP/3 (QUIC) support with `quinn`/`h3` — ADR and implementation
`P32` `[DP][SEC]` · deps: T-0354, T-0357, T-0463 · size: XL · owner: dp
**Objective.** Serve HTTP/3 to clients while preserving all inspection, banning and hardening guarantees.
**Steps.**
1. ADR on the library (`quinn` + `h3`, or alternatives such as `quiche`/`s2n-quic`), maturity and security posture, amplification protections (address validation tokens, retry), 0-RTT policy (disabled by default due to replay risk; if enabled, only for idempotent requests with documented risk), connection migration policy, and interaction with the TLS crypto provider decision (T-0354).
2. Implement UDP/443 listeners (`SO_REUSEPORT`, GRO/GSO where safe), QUIC handshake with certificates from the shared store (SNI-based), ALPN `h3`, `Alt-Svc` advertisement on h1/h2 responses per-site opt-in with `ma` set conservatively, and `HTTPS`/SVCB DNS records with `alpn=h3` generated by the DNS engine when enabled.
3. Map HTTP/3 requests into the same pipeline (stage 0–19) with a shared request model; implement protocol-specific hardening: stream and header limits (QPACK table size caps, max field section size), rapid-reset-style abuse mitigation (stream reset rate limits per connection), concurrent stream caps, flow-control and memory budgets per connection, idle timeouts, connection ID handling and amplification factor limits before address validation (3x rule), and version negotiation handling.
4. Integrate client IP resolution and bans: QUIC source addresses are subject to the L7 jail on handshake (drop initial packets from banned IPs via the XDP/nft UDP/443 rules if available); migration events re-check bans.
5. Extend metrics, events and the visitor pages (HTTP/3 clients receive the same block/challenge pages).
6. Extend the XDP logic and nftables baseline for UDP/443 (already allowed for HTTP/3) with QUIC-aware limits (per-source initial packet rate caps).
7. Testing: interop with `curl --http3`, `quiche` client, browsers via Chrome/Firefox headless in the lab, `h3spec` (if available) conformance, fuzzing of QPACK and frame parsing, flood tests in the closed lab (QUIC initial floods), and performance comparison with h2.
8. Add documentation and the claims evidence ("HTTP/3 supported" only after tests).
**Deliverables.**
- ADR, QUIC listener, pipeline integration, hardening, tests
**Acceptance.**
- A1: the same WAF fixtures produce identical verdicts over h1, h2 and h3 (differential test).
- A2: QUIC initial floods in the lab do not exhaust resources and legitimate h3 clients succeed.
- A3: 0-RTT is disabled by default and replay tests pass when enabled for idempotent requests.
- A4: banned IPs cannot complete QUIC handshakes (L7 jail and kernel).
- A5: interop tests pass with at least two independent clients.
**Tests.**
- Interop, conformance, fuzz, lab floods.
**Notes.** The `quinn`/`h3` ADR slot referenced in P00 is settled here.
