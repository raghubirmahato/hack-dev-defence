### T-0556 · Tier 6: organization SSO (OIDC and SAML) and SCIM provisioning
`P32` `[API][UI][SEC]` · deps: T-0117, T-0127, T-0128 · size: XL · owner: auth
**Objective.** Let enterprise orgs authenticate their members via their identity provider while keeping HDD's security properties.
**Steps.**
1. ADR on protocols and libraries: OIDC (authorization code + PKCE, discovery, JWKS caching, `nonce`/`state`, `iss`/`aud`/`exp` validation, clock skew), SAML 2.0 (SP-initiated and IdP-initiated policy, signed assertions, encryption optional, XML signature wrapping defenses, strict schema validation, no external entity resolution); library choice (`openidconnect`, `samael` or a minimal in-house SAML validator reviewed and fuzzed); decision to support SAML via a vetted component only.
2. Data model: per-org IdP configuration (issuer, endpoints/metadata, certificates, attribute mapping, allowed domains, default role, group-to-role mapping), enforced SSO modes (optional, required for all members except break-glass owner), JIT provisioning, domain verification for the org's email domains (DNS TXT) to prevent hijack, and login routing by email domain.
3. Implement flows with security properties: session creation equals password login (MFA policy interplay: IdP MFA trusted only if the org enables "trust IdP MFA" with `amr` claim checks), session fixation protections, logout (RP-initiated for OIDC; SLO optional), account linking rules (no automatic linking by unverified email), prevention of tenant confusion (issuer/audience bound to org), replay protection (assertion ID cache), and rate limits.
4. Implement **SCIM 2.0** (users, groups) with bearer tokens, filter/pagination support within spec subset, deprovisioning (disable and revoke sessions/API keys), group-role mapping, audit events, and conformance tests with the SCIM compliance suite.
5. UI: SSO setup wizard with metadata exchange, test login, attribute mapping preview, enforcement toggle with safeguards (cannot lock out all owners; break-glass owner path with MFA), and S-081/S-083 integration.
6. Security tests: SAML XSW attack corpus, XXE, signature stripping, algorithm confusion (`alg=none`), JWKS rotation, audience confusion across orgs, open redirect in `RelayState`, CSRF on callbacks, token substitution, IdP impersonation by another org, email domain claims, replay.
7. Fuzz the SAML/XML and JWT parsers; test with Keycloak and a SAML IdP container (SimpleSAMLphp or Keycloak SAML) in the lab.
8. Update the permission matrix, plans (enterprise feature), docs and claims.
**Deliverables.**
- ADR, SSO/SCIM implementation, UI, security corpus, tests
**Acceptance.**
- A1: all SAML and OIDC attack corpus cases are rejected.
- A2: enforced SSO cannot be bypassed by password login except the documented break-glass path.
- A3: deprovisioning via SCIM revokes sessions within 60 s.
- A4: cross-org issuer/audience confusion fails.
- A5: conformance and interoperability tests pass with Keycloak (OIDC and SAML).
**Tests.**
- Lab IdP integration, security corpus, fuzz.
**Notes.** SAML is high-risk; if a vetted validator is not available, ship OIDC only and record the decision.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
