### T-0548 · Tier 3: online DNSSEC signing (ECDSA P-256) with DS workflow and validation oracles
`P32` `[DP][API][UI][SEC]` · deps: T-0403, T-0388, T-0394 · size: XL · owner: dns
**Objective.** Offer optional per-zone DNSSEC with safe key management and verified correctness, without unsupported claims.
**Steps.**
1. ADR (building on the stub from T-0403): algorithm ECDSAP256SHA256 (13) default, optional Ed25519; NSEC vs NSEC3 (NSEC3 with opt-out disabled, minimal iterations, salt rotation) vs "NSEC with minimal responses/white lies" for online signing, zone enumeration implications, key hierarchy (CSK or KSK/ZSK), key storage in the envelope store, rollover schedules (ZSK 90 days pre-publish; KSK double-DS), signature validity and refresh (RRSIG validity 7 days, refresh at 1/3), clock sensitivity, and per-query signing vs pre-signing in the snapshot (pre-sign at snapshot build for static data; synthesize on-the-fly only for wildcard/NXDOMAIN proofs under policy).
2. Implement signing in the snapshot builder: DNSKEY/RRSIG/NSEC(3)/NSEC3PARAM generation, CDS/CDNSKEY publication (RFC 8078/7344) for automated DS updates where the parent supports it, deterministic signatures for ECDSA only if safe (document nonce handling), and zone size/performance impact controls (cap signed zones per plan).
3. Implement the **DS workflow** in the UI (S-049): enable signing → keys generated → DNSKEY published → UI shows the DS record to add at the registrar → verification (`delv`/in-process validation) → status `signed_and_validated`; disabling signing requires the reverse (remove DS first, wait, then disable) with enforced waiting and blockers to prevent bogus states.
4. Implement **rollover automation** with pre-publication, double signature phases, state machine with persistence, alerts, and manual override; emergency rollover procedures; time-injected tests of the schedule.
5. Handle **TCP/UDP size**: signed responses are larger; enforce TC=1 behavior with EDNS 1,232 cap, RRL tweaks for DNSKEY amplification (DNSKEY queries have bigger ratios: apply stricter limits, minimal-answers, and update the amplification suite thresholds with documented new ratio caps).
6. Update claims-lint (`dnssec_claim`) to allow statements only when the validation oracle passes for that zone; add the validation probe to monitoring (alerts on bogus/expired signatures with high priority).
7. Validate with oracles: `delv`, `dnsviz`, `ldns-verify-zone`, `unbound-host -v`, public validating resolvers (for the operator's own zones), zone transfer to secondary (signed zones via TSIG AXFR/IXFR must carry signatures; secondaries without DNSSEC support documented).
8. Write tests: key lifecycle, signature validity windows, NSEC chain correctness (property tests vs reference), rollovers, DS removal safety, amplification regression, interoperability with BIND/Knot as secondaries.
**Deliverables.**
- ADR, signing engine, key manager, UI workflow, tests, docs
**Acceptance.**
- A1: signed zones validate with `delv`, `dnsviz` and a validating Unbound in the lab.
- A2: rollovers complete without validation failures in simulated resolvers with cache behavior.
- A3: disabling signing cannot leave a DS without keys (state machine blocks).
- A4: amplification ratios stay within updated thresholds.
- A5: DNSSEC claims appear only for validated zones.
**Tests.**
- Lab validation, property tests, time-injected rollover tests.
**Notes.** DNSSEC increases operational risk; the UI recommends it only with a secondary that supports signed zones.
