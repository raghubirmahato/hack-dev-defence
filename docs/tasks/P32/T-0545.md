### T-0545 · Tier 2: antivirus scanning integration for uploads (clamd)
`P32` `[DP][SEC][OPS]` · deps: T-0297, T-0413 · size: M · owner: sec
**Objective.** Add optional malware scanning to multipart uploads on protected sites.
**Steps.**
1. ADR: ClamAV via `clamd` socket (local Unix or loopback TCP) as the first backend; interface trait `UploadScanner` for future engines; scanning happens in a separate sandboxed service (`hdd-avscan`) with its own user, seccomp, no network, memory limits, and size/time limits; HDD does not bundle signatures (operator installs ClamAV and `freshclam`; docs provided).
2. Implement streaming integration: upload parts that match configured paths are teed to the scanner with `INSTREAM` (size cap, default 25 MiB), decisions: `clean` (forward), `infected` (block with a branded response and event `malware_upload`, optional ban per policy), `error/timeout` (policy `fail_open` or `fail_closed` per site; default `fail_closed` for upload paths, with explicit warnings), and `skipped_large`.
3. Preserve fidelity: the original request is forwarded only after a clean verdict (buffer to a bounded temp file with secure permissions and cleanup) or streamed with deferred commit when the origin supports it (documented trade-offs); no scanning of encrypted archives beyond the engine's capability (reported as `unscannable`).
4. Implement events/metrics, signature database age monitoring (alerts when stale > 3 days), and S-097/S-056 settings.
5. Add privacy controls: no file contents retained after scanning; hashes (SHA-256) recorded optionally for correlation (owner opt-in).
6. Implement EICAR-based tests (the standard harmless test string) and benign upload suites, large file behavior, scanner outage behavior, concurrency limits, resource limits and sandbox escape attempts.
7. Document operator setup, performance expectations and limitations (no zero-day guarantees).
8. Update the capability matrix and claims evidence.
**Deliverables.**
- `hdd-avscan`, integration, settings UI, docs, tests
**Acceptance.**
- A1: EICAR uploads are blocked and benign uploads pass in `fail_closed` mode.
- A2: scanner outage behaves per configured policy with an alert.
- A3: temporary files are removed and permissions are 0600 (test).
- A4: the scanner service has no network access (sandbox test).
- A5: signature staleness alerts fire.
**Tests.**
- Integration with ClamAV container in the lab (UNVERIFIED if unavailable), unit tests.
**Notes.** Optional integration; documented as best-effort detection.
