### T-0557 · Tier 6: infrastructure-as-code provider (Terraform/OpenTofu) generated from the API
`P32` `[API][DOC]` · deps: T-0457, T-0458 · size: L · owner: api
**Objective.** Let customers manage HDD resources declaratively.
**Steps.**
1. ADR: build a Terraform provider (Go, using the plugin framework) generated and hand-tuned from the OpenAPI document and the Rust SDK semantics, versus a pure API-driven `hddctl apply` declarative tool; decision criteria include user demand, maintenance burden and language policy (the provider is the only non-Rust component, isolated in `ecosystem/terraform-provider-hdd/` with its own CI and clearly out of the Rust-first share calculation, recorded in DEVIATIONS).
2. Define resources: `hdd_domain`, `hdd_dns_record`, `hdd_dns_zone_settings`, `hdd_origin`, `hdd_tls_settings`, `hdd_waf_policy` (policy document), `hdd_rule`, `hdd_exception`, `hdd_access_list_entry`, `hdd_rate_limit_rule`, `hdd_alert_rule`, `hdd_webhook`, `hdd_api_key` (write-only secrets), `hdd_member`/`hdd_invitation` (limited), and data sources (domains, egress IPs, readiness score); import support for all.
3. Implement plan/apply semantics with ETags (`If-Match`) for optimistic concurrency, drift detection via read-after-write, idempotency keys, rate-limit aware retries, and clear diffs for policy documents (normalized JSON).
4. Handle sensitive values: write-only attributes for secrets, state redaction guidance, and no secret output in logs; support for provider-level API key from environment; permission scoping docs.
5. Safety features: `prevent_destroy` guidance for domains, plan-time validation using the API's dry-run/validation endpoints (policy validation without applying), and warnings when applying changes that reduce protection (WAF mode downgrade).
6. Generate docs and examples (full site example: domain, DNS, origin, TLS, WAF, alerting), registry-ready metadata (publishing is an operator decision), acceptance tests using `terraform-plugin-testing` against the local stack in CI.
7. Verify compatibility with OpenTofu.
8. Update docs, capability matrix and claims.
**Deliverables.**
- ADR, provider code, docs/examples, acceptance tests
**Acceptance.**
- A1: the full-site example applies, re-plans with no diff, and destroys cleanly against the local stack.
- A2: import works for every resource type.
- A3: secrets never appear in plan output or logs.
- A4: policy downgrade changes produce warnings at plan time.
- A5: the provider passes tests with both Terraform and OpenTofu binaries.
**Tests.**
- Acceptance tests (provider framework), CI.
**Notes.** The provider is the only non-Rust deliverable; it is isolated and optional.
