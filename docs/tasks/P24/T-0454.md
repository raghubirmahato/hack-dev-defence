### T-0454 · Integration channels (S-077): email, Slack, Discord, Telegram, Microsoft Teams, PagerDuty
`P24` `[API][UI][SEC]` · deps: T-0453, T-0109, T-0413 · size: L · owner: api
**Objective.** Deliver notifications to the tools teams already use, safely.
**Steps.**
1. Implement a `Channel` trait (`validate_config`, `send`, `test`, `classify_error`) and the concrete channels: Email (through `hdd-mailer` with per-user and shared inboxes), Slack (incoming webhook URL and optional bot token variant), Discord (webhook), Telegram (bot token + chat id), Microsoft Teams (incoming webhook / workflow webhook), PagerDuty (Events API v2 routing key with dedup keys mapped to alert groups, resolve events on clear).
2. Implement configuration forms in S-077 per channel with inline help (where to find the URL/token), secret fields write-only (stored via envelope encryption, fingerprint display), URL validation (https only; hostnames must match the provider allowlist for hosted providers, for example `hooks.slack.com`, `discord.com/api/webhooks`, `api.telegram.org`, `events.pagerduty.com`, `*.webhook.office.com`/`*.logic.azure.com`; generic hosts are not allowed here), and an egress allowlist/SSRF check at save and send time.
3. Implement message formatting from a shared message model (title, severity, summary, key facts, link to the HDD screen, Ray ID or group id) rendered per channel with length limits, markdown/escaping rules specific to each platform (escape user-influenced strings such as hostnames and paths; mention-injection prevention for `@channel`/`@everyone`/`<!here>` on Slack and Discord), accessible plain text fallback, and **content policy**: only fields from the allowlist (`event_type`, `domain`, `category`, `count`, `window`, `ip` per org truncation, `ray_id`, `link`); nothing from request bodies or evidence snippets.
4. Implement the **Test** button: sends a clearly labeled test message and reports provider status/latency/error classification (invalid URL, revoked token, rate limited, provider outage), never exposing secrets in errors.
5. Implement delivery behavior: timeouts (5 s connect, 10 s total), retry with backoff on 5xx/429 (honor `Retry-After`), no retries on 4xx other than 429, circuit breaker per integration (open after 20 consecutive failures; notify owners by email and mark the integration `needs_attention`), and delivery history with attempt outcomes.
6. Implement per-integration quotas (plan-based), ownership (org-level vs user-level), and the permission model (`PERM-integration.write` for owner/admin).
7. Implement rotation helpers (replace secret, test, then save) and the "disconnect" action that deletes secrets immediately.
8. Write tests with local fake servers implementing each provider's documented API shape (contract-tested against saved examples from provider docs; mark UNVERIFIED(`capability_not_supplied`) for live smoke tests unless the operator provides test destinations): formatting golden tests, escaping and mention-injection fuzz, retry/circuit-breaker behavior, SSRF attempts through the URL field (≥ 40 vectors), secret leakage greps in logs/errors, and UI e2e.
**Deliverables.**
- channel implementations, S-077, tests, docs for each provider
**Acceptance.**
- A1: hostile hostnames/paths in events cannot inject mentions, markup or links into any channel (fuzz corpus).
- A2: only allowlisted provider hosts are accepted per channel type; SSRF vectors are rejected.
- A3: secrets never appear in logs, API responses or error messages.
- A4: PagerDuty resolve events fire when state-based alerts clear.
- A5: the circuit breaker opens and notifies the owner in the failure simulation.
**Tests.**
- Contract, fuzz, integration, browser e2e.
**Notes.** Generic webhooks (customer-controlled URLs) are a separate, more heavily guarded path (T-0455).

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
