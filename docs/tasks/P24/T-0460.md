### T-0460 · Log forwarding and SIEM export (HTTPS JSON lines and syslog over TLS)
`P24` `[API][DP][SEC]` · deps: T-0455, T-0441, T-0413 · size: M · owner: api
**Objective.** Let organizations stream security events to their own logging stack safely and reliably.
**Steps.**
1. Implement **log sinks** per org: HTTPS endpoint (batched JSON Lines, gzip, optional custom auth header stored encrypted), syslog over TLS (RFC 5425 framing, RFC 5424 messages) with CEF and LEEF formatting options, and optional S3-compatible object storage push is explicitly out of scope (documented as Tier 6).
2. Define the **event schema** (versioned, documented): timestamp, org, domain, ray_id, verdict, mode, category, subtype, rule_ids, severity, hardness, ip (per truncation), asn, country, method, path_template, status, ban_created, ban_ttl, auth_endpoint flag, cross_site_context flag, and for audit streams the AUD-* fields; no bodies, no cookies, evidence snippet excluded by default (opt-in per sink with redaction).
3. Implement the **streaming pipeline**: a durable cursor per sink over the event stream (at-least-once), batch size and flush interval (default 500 events or 5 s), exponential backoff, a bounded disk spool (default 256 MB per org) with oldest-first drop and a `sink_overflow` event and notification, and `Retry-After` support.
4. Implement security for outbound connections: egress client with SSRF guard, TLS 1.2+ verification (pinned CA option for private PKI), mTLS client certificate option for syslog/HTTPS sinks (certificate and key stored encrypted), no redirects, per-sink timeout, and DNS pinning.
5. Implement S-077 sub-page for log sinks: create/edit, test (sends a labeled test record), health (lag in events and seconds, last success, spool usage), pause/resume, and sample payload preview for the chosen format.
6. Provide integration cookbooks: Splunk HEC, Elastic (Filebeat/Logstash and ingest pipeline mapping), Datadog (HTTP intake), Grafana Loki (push API), Graylog (GELF alternative documented), rsyslog/syslog-ng receivers; each cookbook is tested against a local container of the receiver in the lab when available (UNVERIFIED(`oracle_unavailable`) per receiver otherwise).
7. Add metrics and alerts: sink lag, spool utilization, delivery failures, dropped events; alerts to owners via the routing core.
8. Write tests: format golden tests (JSON, CEF, LEEF) with escaping rules (CEF delimiter escaping), at-least-once semantics under crashes, spool overflow behavior, TLS failure modes (expired, wrong host, self-signed without pin), mTLS, SSRF vectors, BOLA on sink config, and performance (10,000 events/s to a local sink).
**Deliverables.**
- sink implementations, schema docs, S-077 sub-page, cookbooks, tests
**Acceptance.**
- A1: CEF/LEEF output passes strict parser tests with hostile field values.
- A2: sinks resume without loss after crashes and without unbounded disk use.
- A3: TLS verification failures are never bypassed; mTLS works against the lab receiver.
- A4: the schema contains no request bodies or cookies (schema test).
- A5: lag alerts fire in a simulated sink outage.
**Tests.**
- Integration with local receivers, fault injection, golden, security.
**Notes.** For on-demand extracts use T-0450; this is continuous streaming.

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
