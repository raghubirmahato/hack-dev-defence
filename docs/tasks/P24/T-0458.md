### T-0458 · `hdd-sdk`: Rust client and generated clients
`P24` `[API][DOC]` · deps: T-0457 · size: M · owner: api
**Objective.** Give integrators typed clients that stay in sync with the API.
**Steps.**
1. Generate `hdd-sdk` (Rust) from OpenAPI using a generator chosen in a short ADR (candidate: `progenitor`; fallback: hand-written thin layer over generated models) with the following hand-written ergonomics on top: builder-style client (`Client::new(base_url).with_api_key(...)`), typed errors mapping problem details, automatic pagination iterators (`stream_all`), retry policy with backoff for idempotent calls and 429/503, idempotency key helper, request timeouts, TLS defaults (rustls, system roots), and `User-Agent` including SDK version.
2. Ship webhook signature verification helpers in the SDK (`verify_signature(body, header, secret, tolerance)`) tested against the published vectors, and event type enums with serde.
3. Generate TypeScript and Python clients with an OpenAPI generator tool (pinned in `lab/oracles/`), smoke-tested by running their test suites against the local stack when the runtimes are present; they are marked "generated, community-supported" in docs and not hand-edited.
4. Provide examples as runnable crates/scripts: list domains, add a domain and poll verification, create DNS records in bulk, manage bans, create/rotate webhook secret, stream events (SSE), export events; examples run in CI against the local stack.
5. Version the SDK in lockstep with the API (`0.x` until the first stable cut, then semver following API v1 compatibility), maintain a CHANGELOG, and make the crate publish-ready without publishing (operator decision).
6. Enforce `#![forbid(unsafe_code)]`, `deny(missing_docs)`, doc tests for all public functions, and MSRV documentation.
7. Add SDK-level security tests: API keys are never logged (the `Debug` implementation redacts), TLS verification cannot be disabled except via a feature flag named `danger_accept_invalid_certs` that is off by default and documented as test-only.
8. Write tests: SDK integration tests against the local stack covering every resource family, error mapping, pagination at scale (10,000 items), retry behavior with fault-injecting proxies, and cross-version compatibility (SDK vN against API vN and vN+1 additive changes).
**Deliverables.**
- `hdd-sdk`, generated clients, examples, docs, tests
**Acceptance.**
- A1: all examples compile and run in CI against the local stack.
- A2: SDK Debug/Display never reveals API keys (test).
- A3: pagination iterators fetch 10,000 items with bounded memory.
- A4: signature verification helpers pass all vectors.
- A5: generated TS/Python clients pass smoke tests when runtimes are available (otherwise UNVERIFIED(`tool_unavailable`)).
**Tests.**
- Unit, integration, doc tests, examples in CI.
**Notes.** Publishing crates or packages is an operator decision (out of scope).
