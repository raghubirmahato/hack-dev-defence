### T-0461 · Notifications, webhooks and API end-to-end tests (AC-45, AC-20 alert paths)
`P24` `[QA]` · deps: T-0454, T-0456, T-0457, T-0458, T-0459, T-0460 · size: L · owner: qa
**Objective.** Prove that alerts reach people, webhooks are trustworthy and the API behaves to contract, from the outside.
**Steps.**
1. Build lab fakes for Slack, Discord, Telegram, Teams and PagerDuty (HTTP servers implementing the documented request/response shapes, including rate-limit and error behaviors) and a configurable SMTP sink; run the complete alert path: attack simulation on the sandbox → event → rule → grouping → channel delivery → acknowledgment → resolve.
2. Run the live path on the pilot: trigger a real SQLi hard hit on the sandbox host (Class A, safe) with an alert rule configured to email the operator (UNVERIFIED(`capability_not_supplied`) if SMTP is not supplied) and verify delivery, link correctness and absence of sensitive data in the message.
3. Verify flood control at scale: 10,000 events → bounded notifications, suppression summary, no channel rate-limit violations in the fakes.
4. Run webhook scenarios: success, retries with timing, dead-letter, circuit breaker, redelivery, signature verification with all language snippets (where runtimes exist), replay of old timestamps rejected by the reference verifier, and SSRF vectors blocked.
5. Run API scenarios from the SDK: end-to-end domain lifecycle, DNS bulk changes with `If-Match` conflicts, ban management, key scope restrictions, idempotent POST replays, rate-limit behavior and headers, deprecation headers on a flagged test endpoint, and OpenAPI contract tests (T-0457).
6. Run security checks: API key leakage greps across logs/metrics/events after the above flows, BOLA tests for alert rules, integrations, sinks and webhooks, secret handling in the UI, and CSRF/origin checks on the UI forms.
7. Run heartbeat/alert absence checks used by AC-20 (partial): dead-man heartbeat sending, missed heartbeat detection by the external-monitor fake.
8. Record results as AC-45 and the alert portions of AC-20 with evidence and SHA-256; update STATUS lines.
**Deliverables.**
- lab fakes, test suites, evidence bundle
**Acceptance.**
- A1: the alert path works end-to-end on the fakes and (if supplied) on the real email destination.
- A2: no message or webhook payload contains cookies, bodies or credentials (scanner over all captured messages).
- A3: webhook signature verification passes for all documented vectors and rejects tampered payloads.
- A4: API contract and authorization tests pass with zero failures.
- A5: AC-45 status is PASS (or UNVERIFIED with exact reasons for live destinations).
**Tests.**
- The suites themselves.
**Notes.** Live third-party posting is limited to destinations the operator supplied and consented to (section 2.6).
