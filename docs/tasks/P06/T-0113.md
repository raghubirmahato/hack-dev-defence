### T-0113 · Session management
`P06` `[SEC][API]` · deps: T-0105, T-0081 · size: L · owner: sec
**Objective.** Implement opaque, revocable, server-side sessions with correct lifetimes.
**Steps.**
1. Decide the storage layout (ADR): Postgres as the source of truth and Redis as the cache; session ID = 256 random bits, cookie holds the ID, DB stores `SHA-256(ID)` only.
2. Implement creation with `auth_level` (`password`, `mfa`, `passkey`), device binding, coarse IP and UA summary, idle expiry (60 min) and absolute expiry (12 h) for tenants, 15 min and 8 h for platform roles (non-configurable minimums).
3. Implement rotation on privilege changes (login, MFA completion, step-up, role change) to prevent fixation, and sliding idle expiry updates limited to once per minute to reduce writes.
4. Implement the `__Host-hdd_session` cookie (`Secure; HttpOnly; SameSite=Lax`, `Strict` on admin host), admin host cookie scope separation (different cookie names/hosts), and cookie-less rejection for API-key routes.
5. Implement the session extractor/middleware returning `AuthContext` (user, session, memberships, platform role, step-up state), with per-request Redis lookup and database fallback, and constant-time comparison of hashes.
6. Implement revocation (single, all-others, all) with Redis invalidation and immediate effect (<2 s across nodes), and automatic revocation on password change, MFA changes, role downgrade and account lock.
7. Implement concurrent session limits (default 20, platform 3) with oldest eviction and notification.
8. Expose metrics `MET-hdd_sessions_active`, security timeline events, and tests with the injectable clock.
**Deliverables.**
- `crates/hdd-auth/src/session/*`, web middleware, ADR, tests
**Acceptance.**
- A1: stolen cookie after password change is rejected.
- A2: session fixation (pre-auth cookie reuse) cannot elevate privileges.
- A3: idle and absolute timeouts are enforced with the test clock.
- A4: revocation takes effect within 2 s with Redis pub/sub (and on the next DB check if Redis is down).
- A5: the admin host never accepts a tenant-surface session cookie and vice versa.
**Tests.**
- Integration: expiry and revocation; concurrency (many requests during rotation); unit: hash/compare functions.
- Security: fixation, replay and cross-host cookie tests.
**Notes.** The `dev_gallery` hook (T-0073) is removed by T-0125 using this context.
