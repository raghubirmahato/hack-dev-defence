### T-0115 · Recovery codes (S-031, S-025)
`P06` `[UI][API][SEC]` · deps: T-0114 · size: S · owner: sec
**Objective.** Provide one-time recovery codes safely.
**Steps.**
1. Generate 10 codes of 80 bits each (base32 groups like `ABCDE-FGHIJ-KLMNO-PQRST`), hash each with Argon2id (lighter parameters tuned to keep verification under 150 ms), and store hashes only.
2. Show codes once after enrollment with copy, download (`.txt`), and print actions and a required "I saved these" confirmation before continuing.
3. Implement code login (S-025): normalization (case, hyphens), constant-time handling, single use, and notifications.
4. Implement regeneration (step-up) that invalidates all old codes; show remaining count in account security.
5. Limit attempts and tie to the same throttling as TOTP.
6. Ensure codes can never be retrieved again (no "show codes" page).
7. Add audit events for generation and use.
8. Add tests for code formatting variants.
**Deliverables.**
- module, handlers, templates, tests
**Acceptance.**
- A1: each code works exactly once.
- A2: regenerating invalidates previous codes immediately.
- A3: the codes page cannot be revisited without regeneration.
- A4: using a code triggers a notification email.
- A5: the forced acknowledgment cannot be skipped by navigating away (server-side state).
**Tests.**
- Unit: normalization and uniqueness; integration: single-use under concurrency; browser: acknowledgment flow.
**Notes.** For platform staff, recovery codes are the only offline fallback besides `hddctl` (documented).
