### T-0105 · Identity data model, migrations and database roles
`P06` `[DB][SEC]` · deps: T-0094 · size: L · owner: api
**Objective.** Create migration series 1: extensions, helper functions, roles, and the identity, organization and audit tables, with RLS from day one.
**Steps.**
1. Write migration 0001: `pgcrypto`, a `gen_uuidv7()` function (SQL implementation if the server lacks one), `updated_at` trigger function, and the database roles `hdd_owner`, `hdd_api`, `hdd_worker`, `hdd_proxy`, `hdd_dns`, `hdd_readonly`, `hdd_backup` (`BYPASSRLS`, `SELECT` only, backup jobs only) with least privilege grants.
2. Write migration 0002: `users` (including `password_pepper_kid`), `user_pending_email`, `user_sessions`, `user_devices`, `login_attempts` (partitioned monthly with the composite key `(id, ts)`), `email_tokens`, `mfa_totp`, `mfa_recovery_codes`, `webauthn_credentials`, `security_events`, `data_export_requests`, `deletion_requests` exactly per B5.2 with constraints and indexes.
3. Write migration 0003: `orgs`, `memberships` (trigger keeping at least one owner), `invitations`, `org_settings`, `plans` (seed `unlimited`), `usage_counters`, `announcements`, `saved_views`, `consents` (document id, version, accepted_at, ip_trunc).
4. Write migration 0004: `audit_log` (partitioned monthly, composite key `(id, ts)`, no foreign key may reference it; B5.1) with the hash-chain columns and an append-only policy (no UPDATE/DELETE grants), `idempotency_keys`, `jobs`/`job_runs`, `platform_settings`, `platform_state`, `feature_flags`.
5. Enable RLS on all tenant-owned tables with `org_id = nullif(current_setting('app.org_id', true), '')::uuid` policies for `hdd_api` and `hdd_worker`; set `FORCE ROW LEVEL SECURITY`.
6. Add the `SECURITY DEFINER` platform functions skeletons that require a `reason` and write audit rows.
7. Commit `.sqlx` offline data; write the restore test: dump, drop, restore and re-run migrations idempotently (expand/contract discipline).
8. Document the schema in `docs/DATABASE.md` generated from the migrations.
**Deliverables.**
- `migrations/0001..0004*.sql`, `.sqlx/`, `docs/DATABASE.md`, role grants test
**Acceptance.**
- A1: migrations apply to an empty database and to a restored backup with no errors.
- A2: `hdd_api` cannot read another org's rows without the setting (test returns zero rows).
- A3: `hdd_proxy` and `hdd_dns` cannot write to config tables (permission denied tests).
- A4: `audit_log` rejects UPDATE and DELETE for all application roles.
- A5: removing the last owner of an org fails at the database level.
**Tests.**
- Integration (testcontainers Postgres): role/permission matrix tests; RLS tests with two orgs; restore drill.
- Unit: migration lint (no destructive statements in expand phase).
**Notes.** All later migrations keep `org_id` plus RLS for new tenant tables; the migration lint enforces it.
