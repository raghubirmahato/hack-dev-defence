### T-0124 · API keys: lifecycle, scopes, bearer authentication (S-080)
`P06` `[UI][API][SEC]` · deps: T-0125, T-0118 · size: L · owner: api
**Objective.** Provide scoped, auditable API keys for automation.
**Steps.**
1. Define key format `hdd_<8-char prefix>_<43-char secret>`; store `prefix` (indexed) and `SHA-256(secret)` hashed with a key-derivation (HMAC with pepper) so database leaks do not reveal keys; show the secret once.
2. Implement creation (step-up): name, scopes (permission IDs grouped in the UI), expiry (default 90 days, maximum 365, no non-expiring keys unless platform allows), optional IP allowlist CIDRs, per-key rate limit class; scopes cannot exceed the creator's current permissions.
3. Implement bearer authentication middleware: parse header, lookup by prefix, constant-time compare, check expiry/revocation/IP allowlist, compute effective permissions (intersection of scopes and the creator's current role), and record `last_used_at` and truncated IP asynchronously.
4. Implement rotation (create new, grace period, revoke old), revocation, and listing with usage graph (requests per day).
5. Implement the secret-scanning friendliness: fixed prefix `hdd_`, documentation of the format for GitHub secret scanning partner registration (optional), and a revocation endpoint accessible by key (self-revoke).
6. Ensure API-key routes ignore cookies and reject CSRF-style flows; ensure `S`-flagged actions are denied.
7. Implement audit events and rate limiting per key (429 with headers).
8. Add tests for each scope boundary and privilege change (creator demoted, key loses permissions).
**Deliverables.**
- module, handlers, UI (S-080), docs, tests
**Acceptance.**
- A1: keys cannot be retrieved after creation; DB contains only hashes.
- A2: a key's effective permissions shrink when the creator is demoted.
- A3: expired, revoked or IP-mismatched keys fail with `ERR-AUTH-012` without hints.
- A4: `S` permission routes are denied to API keys.
- A5: per-key rate limits return correct headers.
**Tests.**
- Integration: lifecycle and permission intersection; browser: create/copy/revoke flows.
- Security: brute force prefix guessing (rate limit), timing equality across invalid prefix/secret cases.
**Notes.** Webhook signing secrets are separate from API keys (T-0456).
