### T-0125 · RBAC engine and route-permission enforcement
`P06` `[API][SEC]` · deps: T-0113 · size: L · owner: sec
**Objective.** Enforce the permission matrix everywhere, deny by default, and remove the temporary gallery hook.
**Steps.**
1. Implement the permission catalog as a Rust enum (`Permission`) generated from the B4 table (`xtask permissions generate` reads the Markdown table in the spec and emits the enum and the role map; checked in CI for drift).
2. Implement `AuthContext::require(permission, scope)` returning typed errors (`ERR-PERM-001`, `ERR-PERM-002` for cross-tenant), with org resolution from the path, membership check, then permission check, then resource ownership check.
3. Wire the route table: each route's permission and step-up annotations must match `routes.toml`; `xtask routes check` fails on mismatches or missing declarations; unauthenticated routes are explicit (`public`).
4. Generate the matrix test: for every route and every role, assert the expected status (allowed / 403 / 404) using real requests against a test server and seeded data.
5. Replace the `dev_gallery` hook: the design-system route now requires `PERM-platform.infra.read` or `platform_owner` on the admin surface.
6. Implement the platform access reason header requirement (`ERR-PLAT-001`) for platform routes touching tenant data and log it.
7. Implement the impersonation write-block middleware (`ERR-AUTH-014`) reading the session flag.
8. Document the authorization model and how to add a permission.
**Deliverables.**
- `crates/hdd-auth/src/rbac/*`, generator, matrix test, route check, docs
**Acceptance.**
- A1: adding a route without a permission declaration fails `xtask verify`.
- A2: the generated matrix test passes for all roles and routes.
- A3: the gallery route is inaccessible without the platform permission.
- A4: impersonation sessions fail all non-GET requests (tests).
- A5: permission enum and B4 table are in sync (drift test).
**Tests.**
- Matrix test (generated), unit tests for resolution order, proptest for role-permission monotonicity (higher role never has fewer permissions in the same scope except by design).
**Notes.** This test is a major contributor to AC-36/AC-42 evidence.
