### T-0110 · Email templates catalog
`P06` `[UI][DOC]` · deps: T-0109, T-0019 · size: M · owner: ux
**Objective.** Provide accessible, localized, safe email templates for every product notification.
**Steps.**
1. Build the template engine integration (askama for HTML and text variants) with i18n and a layout that uses no remote images, system fonts, high contrast, and a width of 600 px max with responsive behavior.
2. Write templates: verify email, account exists notice, welcome, password reset, password changed, email change confirm/notice, new device login, MFA enrolled/removed, recovery codes regenerated, invite, appeal received, appeal resolved, domain verified, domain verification failing, certificate expiring/issuance failed, origin down/recovered, mass-ban alert, critical attack alert, weekly summary, report ready, data export ready, account deletion scheduled/canceled, platform notices (suspension), test email.
3. Define for each: purpose, trigger event, recipients, required variables, security considerations (no sensitive data, link expiry statements), and plain-text equivalent.
4. Implement the preview tool in the admin panel (T-0432) and an `xtask mail preview` renderer that outputs HTML/text for review in both themes.
5. Implement link building from configured base URLs only (never from request Host headers), with token-in-path confirm pages and UTM-free links.
6. Implement accessibility checks for HTML emails (headings, alt text policy, contrast, link text).
7. Implement the unsubscribe/preferences link for non-critical categories.
8. Add template tests (golden files per locale) and a spam-trigger lint (all-caps, excessive punctuation) as advisory.
**Deliverables.**
- `crates/hdd-mailer/templates/*`, `i18n/en/email.ftl`, preview tooling, golden tests
**Acceptance.**
- A1: every template has HTML and text variants and passes the accessibility check.
- A2: no template references a remote resource.
- A3: links use configured base URLs; a hostile Host header cannot change them (test).
- A4: golden tests exist for each template.
- A5: security-critical emails (password changed, MFA removed) cannot be disabled by preferences.
**Tests.**
- Unit/golden: render each template with edge-case data (long names, RTL names, hostile strings escaped).
- Integration: send via sink and parse with a MIME parser to confirm structure.
**Notes.** Templates are the only place email copy lives; no inline strings in code.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
