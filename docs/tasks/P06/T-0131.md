### T-0131 · Audit log core, hash chain and user-visible security timeline
`P06` `[API][SEC][DB]` · deps: T-0105 · size: L · owner: sec
**Objective.** Make audit trustworthy, tamper-evident and cheap to write from every feature.
**Steps.**
1. Implement the audit writer in `hdd-common`: `audit::record(event, actor, target, detail)` building a canonical JSON, computing `hash = SHA-256(prev_hash || canonical_row)` per scope (org, platform, user) with a serialized chain head per scope held in Postgres (advisory lock or row lock) so concurrent writers produce a linear chain.
2. Implement batched writes for high-volume events without breaking chain order (a per-scope sequencer task) and failure behavior (audit failure blocks the mutation for security-critical events; best-effort with queue for low-risk events, as defined per event).
3. Implement `hddctl audit verify` and the API `GET /orgs/{org}/audit/verify` checking the chain across partitions and reporting the first break, and a scheduled verification job with alerting.
4. Implement redaction rules (no secrets, payloads, full IPs unless policy) and size limits on `detail`.
5. Implement the user-visible security timeline as a filtered view of selected auth events.
6. Provide the typed event catalog from B8 as a Rust enum generated from the spec table, with required fields per event enforced at compile time where possible.
7. Implement export (NDJSON/CSV with formula protection) and retention (partition drop beyond `audit_retention_days`, with chain anchors recorded so later verification can start from a signed anchor).
8. Add tests for tamper detection (modify a row, delete a row, reorder) and concurrency.
**Deliverables.**
- audit module, event enum generator, verify tools, tests
**Acceptance.**
- A1: modifying or deleting any row makes verification fail and report the break location.
- A2: 100 concurrent writers produce a valid linear chain.
- A3: retention drops partitions while preserving verifiability from the recorded anchor.
- A4: events outside the catalog cannot be recorded (compile error or runtime reject).
- A5: no event stores secrets (scanner test over a sample of real flows).
**Tests.**
- Integration: tamper tests; load test of the writer; unit: canonicalization; fuzz: canonical JSON.
**Notes.** The audit log is also a forensic source for impersonation and platform support actions.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.
