### T-0106 · Password policy, hashing, breached-password check and strength estimator
`P06` `[SEC][API]` · deps: T-0105 · size: L · owner: sec
**Objective.** Implement password handling that is safe, kind to users, and resistant to DoS.
**Steps.**
1. Implement `hdd-auth::password`: NFKC normalization, length bounds (minimum 12, maximum 256 accepted, reject longer with `ERR-VAL-005` before hashing), no composition rules, reject passwords equal to the email local part or product name.
2. Implement hashing: Argon2id with `HDD_PEPPER` supplied as the algorithm's native keyed `secret` parameter (no HMAC pre-hash; the PHC string records parameters, the row records `password_pepper_kid`) (defaults `m=65536 KiB`, `t=3`, `p=1`; floors `m>=19456 KiB`, `t>=2`), PHC string storage, rehash-on-login when parameters are upgraded, and a startup benchmark that picks parameters targeting 100 to 250 ms on the host (never below the floors).
3. Implement a global hashing concurrency limiter (semaphore sized from CPU count) with a bounded wait queue so floods of login attempts cannot exhaust memory (ATK-220, ATK-285); excess requests fail fast with `ERR-RATE-001`.
4. Implement verification with a dummy hash for unknown users so timing is equalized.
5. Implement the breached/common password check in modes: `offline_list` (the operator imports a SHA-1 prefix-bucketed list via `xtask pwned import <file>`; lookups by k-anonymity prefix locally), `hibp_range` (uses the egress allowlist and the range API; fails open with a warning flag if unreachable), `off` (warns in readiness for the platform).
6. Vet and select the strength estimator (zxcvbn-style port, ADR), expose a server endpoint `POST /auth/password-strength` that returns a score, guidance keys and no echo of the password; rate-limited and not logging inputs.
7. Implement guidance generation (feedback keys such as `password-too-short`, `password-common`, `password-breached`), kind wording from the copy deck.
8. Document threat model notes (pepper rotation by kid, parameter upgrades, memory-hard DoS).
**Deliverables.**
- `crates/hdd-auth/src/password/*`, `xtask pwned import`, endpoint, docs, ADR
**Acceptance.**
- A1: parameters never fall below the floors even if the benchmark suggests it (test with simulated fast host).
- A2: login timing for unknown versus known-wrong-password differs by less than 10% median (statistical test, 1,000 samples each).
- A3: a 10,000-character password is rejected before hashing.
- A4: 500 parallel hash requests keep memory under the configured cap and excess requests fail fast.
- A5: breached passwords are rejected in `offline_list` mode with a imported fixture list.
**Tests.**
- Unit: normalization tables, pepper handling, PHC upgrade logic; proptest: arbitrary Unicode never panics.
- Integration: concurrency limiter under load; offline breached list lookups.
- Fuzz target: password policy parser.
**Notes.** Never log password lengths or hashes; the endpoint logs only outcome class.
