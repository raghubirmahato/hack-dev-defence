### T-0126 · Organization model: creation, slug rules, switcher data, quotas hooks
`P06` `[API][UI]` · deps: T-0111, T-0125 · size: M · owner: api
**Objective.** Make organizations first-class with safe slug handling.
**Steps.**
1. Implement org CRUD service functions: create (via verification flow and "create another org" for users within quota), read, update (name, slug), and deletion request.
2. Implement slug rules: 3 to 40 chars, lowercase letters, digits and hyphens, no leading/trailing hyphen, no consecutive hyphens, reserved list (platform hostnames, `admin`, `api`, `app`, `www`, `status`, `docs`, `support`, `help`, `login`, `signup`, `settings`, `billing`, brand names), and confusable-character rejection.
3. Implement slug change with permanent redirects from the old slug for 30 days and an audit event; a changed slug is never recycled for 90 days.
4. Implement the org switcher data endpoint (membership-based) and last-org preference.
5. Implement quota hooks (`QuotaGuard`) used by later features (domains, seats, keys, rules, webhooks) returning `ERR-RATE-002` and linking to S-085.
6. Implement org suspension effects (read-only UI for members, data plane behavior defined in P22).
7. Implement org deletion workflow with grace period and data deletion jobs (completed in T-0130).
8. Add tests including concurrency on slug claims.
**Deliverables.**
- org service module, handlers, tests
**Acceptance.**
- A1: reserved and confusable slugs are rejected.
- A2: slug change redirects old URLs for 30 days and not afterward.
- A3: two concurrent claims of the same slug result in one success.
- A4: quota guard integration points exist and are tested with a synthetic plan.
- A5: switcher returns only orgs where the user is a member.
**Tests.**
- Integration: concurrency; unit: slug validation table (100 cases) and proptest.
**Notes.** Org slugs appear in URLs so no personal data should be encouraged in them (copy hint).
