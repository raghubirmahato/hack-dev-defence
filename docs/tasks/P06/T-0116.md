### T-0116 · WebAuthn passkeys (S-026)
`P06` `[UI][API][SEC]` · deps: T-0113 · size: L · owner: sec
**Objective.** Support passkeys for passwordless or second-factor login.
**Steps.**
1. Evaluate `webauthn-rs` and alternatives; write the ADR covering the OpenSSL FFI dependency, `unsafe` exposure, maintenance and the decision (accept, or use a pure-Rust verifier); record `DEV` if FFI is accepted.
2. Configure the relying party ID and origins from `HDD_PLATFORM_DOMAIN` and surface hosts (app and admin hosts use distinct RP IDs or the shared parent per ADR) with strict origin checks.
3. Implement registration ceremonies (resident keys preferred, user verification preferred, attestation `none`), store credential IDs, public keys, sign counters and transports, and allow labels.
4. Implement authentication ceremonies for passwordless login (discoverable credentials) and as second factor, with challenge storage in Redis (60 s TTL, single use).
5. Detect cloned authenticators via sign counter regressions (log, alert, require re-enrollment).
6. Implement management UI (list, rename, remove with step-up, minimum one remaining factor rule).
7. Implement platform policy: staff accounts prefer passkeys and require at least one hardware-backed or platform authenticator.
8. Test with the browser's virtual authenticator via CDP.
**Deliverables.**
- module, handlers, templates, ADR, tests
**Acceptance.**
- A1: registration and login succeed with the virtual authenticator (platform and roaming profiles).
- A2: a wrong origin or RP ID fails.
- A3: challenge replay fails.
- A4: removing the last factor is refused.
- A5: sign counter regression triggers the alert path.
**Tests.**
- Browser tests with CDP WebAuthn virtual authenticators; unit: ceremony state machine; fuzz: attestation/assertion parsers through the library boundary.
**Notes.** If the ADR rejects FFI, the fallback is TOTP + recovery codes with passkeys deferred and recorded.
