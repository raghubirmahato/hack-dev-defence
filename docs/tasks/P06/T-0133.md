### T-0133 · Identity end-to-end browser tests (AC-35)
`P06` `[QA][UI]` · deps: T-0121, T-0124, T-0127, T-0130 · size: L · owner: qa
**Objective.** Verify every identity flow in a real browser with real email.
**Steps.**
1. Write e2e tests: signup (open and invite), verification with email via sink, login, MFA TOTP enrollment and login, recovery code login, passkey enrollment and login (virtual authenticator), password reset, password change, email change, session management, step-up flows, API key lifecycle, invitation acceptance, role changes, org enforcement of MFA, data export and deletion.
2. Include keyboard-only variants of the core paths and screen-reader tree snapshots for the key pages.
3. Include negative paths (expired tokens, wrong codes, closed signup, locked account) and verify the uniform messaging.
4. Include responsive and theme variants for visual baselines of all identity pages.
5. Record accessibility results (axe) for every state.
6. Capture email artifacts (HTML/text) in `acceptance-ui/mail/` for review.
7. Measure flow performance (time to complete) and report.
8. Integrate with `cargo xtask acceptance --only AC-35`.
**Deliverables.**
- `tests/e2e/identity/*`, baselines, reports
**Acceptance.**
- A1: all flows pass in dark and light at 360 and 1280 px.
- A2: no console errors or CSP violations.
- A3: every email sent in tests matches the golden templates.
- A4: zero serious/critical axe findings across states.
- A5: the suite runs in under 12 minutes on the builder.
**Tests.**
- The suite itself; flake tracking with diagnosis files if needed.
**Notes.** On the pilot, a reduced subset runs with the operator's mailbox (section 2.5).

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
