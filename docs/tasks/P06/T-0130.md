### T-0130 · Data export and account deletion (S-090)
`P06` `[UI][API][SEC]` · deps: T-0126, T-0109 · size: L · owner: api
**Objective.** Honor data subject requests safely.
**Steps.**
1. Implement export: authenticated, step-up, async job producing a ZIP of JSON files (profile, memberships, security events, sessions summary, API key metadata without secrets, audit entries about the user), encrypted at rest, with a one-time download link emailed (token page requiring login) valid 7 days.
2. Implement deletion request with a 14-day grace period: immediate session revocation of other sessions, banner on login, cancel at any time, constraints (sole owner of an org must transfer or delete the org first, with clear UI).
3. Implement deletion execution: remove or irreversibly pseudonymize personal data (email replaced by tombstone hash, name removed), delete MFA material and sessions, keep audit entries with pseudonymous IDs to preserve hash-chain integrity.
4. Implement org deletion execution: stop proxying domains safely (DNS guidance, certificates revoked on request), delete tenant data per retention rules, and release hostnames after a cooling-off period.
5. Implement operator-facing summaries (counts only) for support.
6. Implement tests for the hash-chain integrity after pseudonymization (chain verification still passes).
7. Document timelines and limits in the privacy page (generated).
8. Add audit events and notifications.
**Deliverables.**
- export and deletion jobs, UI, docs, tests
**Acceptance.**
- A1: export contains no secrets (hashes, keys, tokens) and is encrypted at rest.
- A2: deletion after grace removes personal data (database inspection test) while `hddctl audit verify` still passes.
- A3: sole owners are blocked with guidance.
- A4: cancel during grace restores the account fully.
- A5: export download links are single org/user scoped and expire.
**Tests.**
- Integration with the test clock; unit: pseudonymization function; security: link misuse.
**Notes.** Legal retention requirements differ by jurisdiction; defaults are configurable and documented as operator responsibility.
