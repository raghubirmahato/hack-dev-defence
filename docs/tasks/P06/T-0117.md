### T-0117 · MFA policy enforcement
`P06` `[SEC]` · deps: T-0114, T-0116 · size: M · owner: sec
**Objective.** Enforce when MFA is required and guide users through enrollment.
**Steps.**
1. Implement policy evaluation: platform roles always require MFA; orgs may set `require_mfa` (S-086) for all members; users may opt in.
2. Implement the enforcement middleware: authenticated sessions lacking MFA when required are restricted to the enrollment pages and logout, returning `ERR-AUTH-006` (HTML redirect to S-030, JSON problem for APIs).
3. Implement the grace period for org-level enforcement (default 7 days with banners and email reminders), after which enforcement is hard.
4. Implement the "first login" rule for the bootstrap admin: enrollment before any other action (section 8 hardening).
5. Implement the downgrade protections: cannot remove MFA when policy requires it; owners are warned before enabling org enforcement if members lack MFA (list shown).
6. Implement device-trust options ("remember this device for 30 days") disabled for platform roles and optional for org policy.
7. Add audit and timeline events and metrics.
8. Add tests for each policy combination.
**Deliverables.**
- policy module, middleware, UI banners, tests
**Acceptance.**
- A1: a platform admin without MFA can only reach enrollment and logout.
- A2: org enforcement lists members lacking MFA before activation.
- A3: grace period countdown is shown and enforced via the test clock.
- A4: removing MFA is refused when required.
- A5: API-key clients are unaffected by MFA policy but still bound by key scopes.
**Tests.**
- Integration: policy matrix tests (role x policy x enrollment); browser flows.
**Notes.** Remember-device uses the device cookie and is never accepted for step-up actions.
