### T-0109 · `hdd-mailer`: SMTP delivery, outbox, retries, suppression and domain checks
`P06` `[API][OPS][SEC]` · deps: T-0105, T-0009 · size: L · owner: api
**Objective.** Deliver transactional email reliably and safely.
**Steps.**
1. Vet `lettre` (rustls, no OpenSSL) and implement SMTP submission with `starttls` or implicit TLS only (plaintext refused), authentication from secrets, connection pooling, and timeouts; all connections go through the egress allowlist.
2. Implement the outbox: `mail_outbox` rows with encrypted recipient and params, dedupe keys, scheduled send, attempts with exponential backoff and jitter (up to 24 h), status transitions, dead-letter after final failure with an admin alert.
3. Implement the worker loop with `FOR UPDATE SKIP LOCKED`, rate limits per recipient domain, and a global per-minute send budget.
4. Implement header safety: strict address parsing, display-name quoting, CRLF rejection, `Message-ID` generation, `Date`, `Auto-Submitted: auto-generated`, `X-Auto-Response-Suppress`, and `List-Unsubscribe` plus `List-Unsubscribe-Post` for non-transactional categories.
5. Implement bounce and complaint handling: parse DSNs if the operator configures an IMAP/webhook feed (optional) or manual import; maintain `mail_suppressions` and stop sending to suppressed addresses except security-critical notices to the account email.
6. Implement DKIM options: sign in-process (key stored encrypted, selector rotation) or rely on the relay (documented); preflight checks SPF, DKIM and DMARC records for the `From` domain via the resolver allowlist and reports gaps.
7. Provide the test double-free approach: integration tests use a real SMTP sink container and read mail via its API.
8. Provide `hddctl mail test --to operator_email` limited to the operator's address (guard).
**Deliverables.**
- `crates/hdd-mailer/*`, worker integration, preflight checks, docs
**Acceptance.**
- A1: plaintext SMTP configuration is rejected at startup.
- A2: a CRLF injection in a display name cannot add headers (tested with the sink).
- A3: failures retry with backoff and finally dead-letter with an alert.
- A4: suppressed addresses are not mailed (except allowed critical notices).
- A5: preflight reports missing SPF/DKIM/DMARC for the sending domain.
**Tests.**
- Integration: sink-based tests for delivery, retries (sink fault injection), bounces import; unit: address parsing tables.
- Fuzz: address and header builder.
**Notes.** Mail to real third parties is never sent by the agent (section 2.5 email guard).
