### T-0121 · Sessions, devices and security timeline UI (S-089, S-088)
`P06` `[UI]` · deps: T-0113, T-0131 · size: M · owner: ui
**Objective.** Show users their sessions and security events and let them act.
**Steps.**
1. Implement S-089: list of sessions (current marked), device label, UA summary, approximate location (country/city only when GeoIP available), created, last active, auth level, and revoke buttons; "Sign out everywhere else" with confirmation.
2. Implement S-088: account security overview (password age, MFA status, passkeys, recovery codes remaining, recent security events) with actions linking to flows.
3. Implement the timeline from `security_events` with filters and a clear "this wasn't me" path (revokes sessions, forces reset, notifies).
4. Implement the new-device notice linking to this page.
5. Ensure privacy: show IP only truncated unless the user opts in to full display.
6. Provide empty/loading/error states and accessibility checks.
7. Provide API equivalents.
8. Add tests for revocation effects on the revoked session within 2 s.
**Deliverables.**
- pages, handlers, tests
**Acceptance.**
- A1: revoking a session logs it out on its next request within 2 s.
- A2: the current session cannot be accidentally revoked without a warning.
- A3: "this wasn't me" performs all documented steps (tested end to end).
- A4: pages pass axe and keyboard checks.
- A5: no full IP is shown by default.
**Tests.**
- Browser tests with two sessions; integration tests for the "not me" flow.
**Notes.** Coarse geolocation depends on the GeoIP database; otherwise "Location unavailable".
