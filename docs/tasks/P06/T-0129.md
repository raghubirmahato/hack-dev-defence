### T-0129 · Account profile and preferences (S-087)
`P06` `[UI][API]` · deps: T-0125, T-0083 · size: S · owner: ui
**Objective.** Let users manage profile and preferences.
**Steps.**
1. Implement display name, locale, time zone (validated against the tz database), theme, density, reduced motion override, and notification preferences by category and channel.
2. Implement validation (name length, control characters, bidi marks) and normalization.
3. Implement preference propagation: updating theme/locale sets the cookie and updates the account; changes take effect on the next response without reload artifacts.
4. Implement the notification preferences matrix (categories x channels) with locked cells for security-critical items.
5. Implement avatar initials generation (no uploads, no external fetch).
6. Implement the API (`GET/PATCH /me`) with `If-Match` and audit events.
7. Add accessibility and responsive checks.
8. Add tests for invalid time zones and locale values.
**Deliverables.**
- handlers, templates, tests
**Acceptance.**
- A1: invalid zone/locale values are rejected with field errors.
- A2: security-critical notification cells cannot be disabled.
- A3: updating preferences updates cookie and account consistently.
- A4: bidi control characters in names are stripped or neutralized.
- A5: the page passes axe and works at 360 px.
**Tests.**
- Integration and browser tests; proptest on display name normalization.
**Notes.** Display names are untrusted input everywhere they appear (escaped, bidi-safe).

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
