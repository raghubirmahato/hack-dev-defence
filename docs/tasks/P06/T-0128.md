### T-0128 · Tenant isolation: RLS plumbing and the BOLA test suite
`P06` `[SEC][DB][QA]` · deps: T-0105, T-0125 · size: XL · owner: sec
**Objective.** Make cross-tenant access structurally difficult and continuously tested.
**Steps.**
1. Implement the database access layer so that every tenant query runs inside a transaction that executes `SET LOCAL app.org_id = $1` (type-state wrapper `OrgTx` obtained only from `AuthContext`); queries without the wrapper fail to compile for tenant repositories.
2. Implement platform repositories that use `SECURITY DEFINER` functions and require a reason; the reason is stored in `audit_log`.
3. Implement automatic generation of BOLA tests: for each route in the route table with path parameters that reference tenant resources, create two orgs with resources, authenticate as org A, request org B's resource IDs (GET, PATCH, DELETE, POST subresources), and assert `404` with a body identical to a nonexistent resource and no side effects.
4. Add BOLA tests for list endpoints (no leakage in counts, cursors, suggestions, search, exports, SSE streams, webhooks, reports).
5. Add RLS bypass tests: attempt SQL with a missing setting, with a forged setting by a malicious SQL fragment in a parameter (parameterized queries prevent it; the test proves it), and with long-lived connections reused across tenants (pool contamination: setting must reset on release).
6. Implement a connection pool hook that asserts `app.org_id` is cleared at checkout and fails the request if not.
7. Document the isolation model, including shared tables (`advisories`, `plans`) and why they are safe.
8. Run the suite in CI with randomized resource IDs and record coverage of routes.
**Deliverables.**
- `OrgTx` wrapper, platform function wrappers, generated BOLA suite, docs
**Acceptance.**
- A1: a repository function without `OrgTx` cannot be used for tenant tables (compile-time test).
- A2: the BOLA suite covers 100% of tenant routes (coverage report) with zero cross-tenant successes.
- A3: pool contamination test passes: org A's setting never leaks to a later request.
- A4: cross-tenant responses are byte-identical to nonexistent resources.
- A5: platform access always writes an audit row with a reason.
**Tests.**
- The generated suite; integration tests for pool hooks; negative tests deliberately removing RLS policies to prove the suite fails.
**Notes.** The suite expands automatically as routes are added; the route check requires every new tenant route to appear in coverage.
