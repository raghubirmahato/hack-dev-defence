### T-0135 · Identity security hardening review
`P06` `[SEC][DOC]` · deps: T-0132, T-0133 · size: M · owner: sec
**Objective.** Review the identity implementation against ASVS and our own STRIDE, and fix gaps.
**Steps.**
1. Walk through ASVS level 2 chapters V2 (authentication), V3 (session management), V4 (access control), V5 (validation), V7 (error handling and logging), V8 (data protection), V13 (API), V14 (configuration) for the identity code; record each requirement as met, not applicable (reason) or gap.
2. For admin-surface-specific requirements, evaluate level 3 items (hardware-backed MFA for staff, shorter sessions, separation) and record gaps.
3. Update `docs/STRIDE.md` with identity-specific threats and abuse-case tests mapped to ATK-285 to ATK-298.
4. Review secrets handling: pepper, HMAC keys, session keys, encryption keys: generation, storage, rotation procedure (`hddctl rotate-keys` stubs implemented in T-0526), logging redaction tests.
5. Run a log review: simulate flows and scan logs for PII, tokens and secrets (automated scanner).
6. Review error messages and response uniformity across all identity endpoints.
7. Fix gaps found, add regression tests, and list accepted risks with rationale.
8. Produce `docs/security/identity-review.md`.
**Deliverables.**
- review document, fixes, regression tests
**Acceptance.**
- A1: every ASVS L2 item in scope has a status and evidence link.
- A2: log scanner finds no secrets or full emails in logs.
- A3: STRIDE updates exist with mapped tests.
- A4: all high-severity gaps are fixed.
- A5: accepted risks are documented with owner and expiry.
**Tests.**
- Log scanner as a reusable test utility; regression tests per fix.
**Notes.** The review document is an input to the final security case (P31).
