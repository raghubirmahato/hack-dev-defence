### T-0372 · Proxy metrics, tracing, performance budgets and Ray ID tests
`P18` `[DP][OPS]` · deps: T-0362, T-0361 · size: M · owner: ops
**Objective.** Make performance and behavior observable and enforceable.
**Steps.**
1. Implement the full proxy metric set from B9 with bounded labels, histograms with proper buckets (µs to seconds), and per-stage histograms.
2. Implement the **proxy-added latency** metric (the C14.9 definition: time inside HDD excluding origin I/O wait, where origin body-wait during an outbound hold counts as origin time) measured per request with monotonic clocks and exposed as a histogram (`MET-hdd_proxy_added_latency_seconds`), plus origin-time histogram.
3. Implement tracing: sampled spans with Ray ID, stage timings, decisions; OpenTelemetry export is Tier 4 (P32) but span structure is in place.
4. Create performance benchmarks (functional profile, builder-local with a fast local origin): requests/s, p50/p99 added latency, CPU per request, memory per 10k idle TLS connections (target ≤ 600 MiB initial), steady-state heap growth.
5. Add regression budgets in CI via criterion and a load test harness (`hdd-loadgen` HTTP mode, functional caps only on the builder; `load` profile only after approval).
6. Add Ray ID format/uniqueness/propagation tests across all response paths.
7. Add a dashboards-as-code panel set for the proxy.
8. Document measurement methodology (so claims cite AC-24 numbers only).
**Deliverables.**
- metrics, benchmarks, dashboards, docs
**Acceptance.**
- A1: proxy-added p99 ≤ 5 ms in the builder benchmark with the full pipeline.
- A2: memory per 10k idle TLS connections is measured and documented against the initial 600 MiB budget.
- A3: no steady-state heap growth (soak test 10 minutes).
- A4: Ray ID appears on all response paths.
- A5: CI fails on a deliberately slowed stage (meta-test).
**Tests.**
- Benchmarks, soak, meta-tests.
**Notes.** Budgets are re-baselined at this gate (*initial* values).
