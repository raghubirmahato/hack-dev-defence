### T-0360 · Request body handling: caps, decompression, chunked reassembly and 100-continue
`P18` `[DP][SEC]` · deps: T-0359, T-0249 · size: L · owner: dp
**Objective.** Acquire bodies for inspection and forwarding safely and efficiently.
**Steps.**
1. Implement the body strategy: for requests that require inspection (default for state-changing methods and for any body in `block` mode), buffer the first `inspect_body_max_bytes` while applying size caps (global 10 MiB, per-route overrides), then stream the rest after the decision; for GET/HEAD without bodies, skip.
2. Implement `Expect: 100-continue` semantics: evaluate headers/URL/cookies first (pipeline stages through detection on metadata); send `100 Continue` only if the pre-body verdict is pass; otherwise respond with the block immediately without reading the body.
3. Implement chunked and h2 DATA reassembly into the inspection buffer without unbounded growth; handle trailers (validated, inspected as headers, limited).
4. Implement bounded decompression for inspection (gzip/deflate/br/zstd, ratio ≤ 20:1, size ≤ 10 MiB), while forwarding the **original** compressed bytes upstream unchanged; reject stacked encodings beyond 2 layers.
5. Implement multipart streaming inspection hooks (T-0297): part-wise windows with memory caps and early abort if a part matches a hard rule (connection reset toward the origin if bytes were already forwarded; configurable `buffer_uploads_before_forward` for strict sites).
6. Implement body-rate enforcement hooks (T-0336) and per-route body size overrides (uploads).
7. Implement metrics (bytes buffered, truncated bodies, decompression ratios) and memory accounting per request with caps.
8. Test with large bodies, many concurrent uploads, malformed encodings, slow uploads, and payloads straddling buffer boundaries.
**Deliverables.**
- body handling stage, tests
**Acceptance.**
- A1: pre-body blocks avoid reading request bodies (verified by counting bytes read from the socket).
- A2: payloads straddling the prefix boundary are inspected per T-0257 behavior.
- A3: compressed bodies are inspected while original bytes are forwarded unchanged (byte-equality test at the origin).
- A4: memory usage per request stays within the cap (stress test of 1,000 concurrent 5 MiB uploads).
- A5: decompression bombs are rejected by caps.
**Tests.**
- Integration with real clients and capture origin; stress tests; fuzz on chunked parsing.
**Notes.** Streaming uploads trade early abort vs completeness; documented in OPERATIONS.
