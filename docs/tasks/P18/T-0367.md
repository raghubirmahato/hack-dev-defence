### T-0367 · WebSocket and gRPC passthrough
`P18` `[DP][SEC]` · deps: T-0305, T-0357, T-0365 · size: L · owner: dp
**Objective.** Support long-lived protocols without bypassing protections.
**Steps.**
1. Implement WebSocket upgrade handling for h1 (`Upgrade: websocket`) and h2 (RFC 8441 extended CONNECT, optional), applying the full pipeline to the handshake (jail, limits, inspection, origin policy) and then switching to bidirectional streaming with per-connection limits from T-0305 (message size, rate, idle timeout, ping/pong).
2. Implement frame-level processing hooks for optional text-frame inspection (bounded), masking validation, fragmentation limits, opcode validation, and close handshake semantics; reject protocol violations with proper close codes.
3. Implement gRPC passthrough over h2: trailers support, `grpc-timeout` honoring with caps, message size limits (default 4 MiB), per-stream limits, `application/grpc` content-type detection, reflection service policy (block by default on production unless allowed), and status mapping for blocks (`PERMISSION_DENIED` with `grpc-status` trailers).
4. Implement metrics (active streams, messages, bytes, closes by reason) and per-tenant concurrency caps.
5. Implement graceful behavior on config changes and ban events: when a client key becomes banned, active WebSockets are closed with code 1008 within 2 s.
6. Test with real clients (browser WebSocket, `grpcurl`-like Rust client), hostile frame sequences, and slow consumers.
7. Test CSWSH scenario with a cross-origin page.
8. Document limitations (no inspection of binary frames by default).
**Deliverables.**
- upgrade handling, gRPC support, tests
**Acceptance.**
- A1: cross-origin WebSocket handshakes are rejected per policy.
- A2: banning a client closes its active WebSockets within 2 s.
- A3: oversized/too-fast frames close the connection with correct codes.
- A4: gRPC trailers and timeouts pass through correctly (conformance tests).
- A5: reflection is blocked by default when configured.
**Tests.**
- Integration with real protocol clients; fuzz on frame parsing.
**Notes.** ATK-184 to ATK-186, ATK-183.
