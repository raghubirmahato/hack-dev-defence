### T-0368 · Event pipeline: bounded channels, batch inserts, aggregation and sampling
`P18` `[DP][DB]` · deps: T-0252, T-0364 · size: L · owner: dp
**Objective.** Record security events without ever slowing requests.
**Steps.**
1. Implement the producer side: per-worker bounded channels (capacity from `HDD_EVENT_QUEUE_CAPACITY`), event structs prepared on the hot path with minimal allocation (pre-sized buffers, interned strings), non-blocking `try_send` with drop counters by reason (`MET-hdd_events_dropped_total`).
2. Implement per-key aggregation: jail hits and rate-limit rejects aggregated per (site, key, kind, minute) with first-N full events and sampling beyond; heavy hitter detection preserves the first and the most severe events.
3. Implement the consumer: batch inserts into the partitioned `waf_events` table using `COPY` with batching (up to 1,000 rows or 200 ms), backoff on failures, a disk spill when Postgres is down (T-0364), and idempotency keys to avoid duplicates after retries.
4. Implement ordering and time handling (event time from the proxy, ingestion time recorded), clock skew tolerance, and partition routing (monthly partitions created ahead by the worker).
5. Implement live fanout to SSE: the consumer publishes selected fields to Redis `hdd:events:feed:{org}:{site}` (bounded streams) for the live monitor (P23), with redaction guarantees.
6. Implement counters flush to Redis for rollups (T-0140) with idempotent minute buckets.
7. Implement backpressure safety: events never block enforcement; when queues are 80% full raise an alert and increase sampling automatically.
8. Test with event bursts (100k/s synthetic through the real pipeline in-process), Postgres slowdowns, and restarts.
**Deliverables.**
- event pipeline, spill, tests, metrics
**Acceptance.**
- A1: requests are unaffected by Postgres slowdowns (latency within 5% in test).
- A2: a 100k events/s burst results in bounded drops counted and still-correct enforcement.
- A3: batch inserts achieve ≥ 20k rows/s on the builder-class Postgres.
- A4: spill and replay deliver all events up to the cap after recovery with no duplicates (idempotency test).
- A5: live fanout contains only redacted fields.
**Tests.**
- Load, chaos, idempotency tests.
**Notes.** The retention drop by partition is in T-0441.
