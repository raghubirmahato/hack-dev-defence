### T-0353 · Listener and accept loop; proxy-core decision (Pingora versus own)
`P18` `[DP][SEC]` · deps: T-0208 · size: L · owner: dp
**Objective.** Finalize the proxy core and build the accept layer that sheds load gracefully.
**Steps.**
1. Finalize the ADR started in T-0208: compare Pingora (hooks for custom SNI resolution, per-request pipeline, h2 limits, memory behavior, maintenance, license, build size) against the own `hyper`-based core using the walking-skeleton measurements and a hook-completeness checklist; keep own core unless Pingora demonstrably satisfies every required hook with less code and equal control; record the decision and rollback plan.
2. Implement listeners with `SO_REUSEPORT`, per-listener accept queues, backlog tuning from `somaxconn`, connection caps (global, per IP, per site), and fairness (round-robin accept across worker tasks).
3. Implement the **shed policy**: when connection or in-flight limits are exceeded, new connections are rejected cheaply (TCP close before TLS for non-allowlisted keys when over the global cap; HTTP 503 with `Retry-After` when headers can be parsed), prioritizing established clearance clients and allowlisted keys; document the order of shedding.
4. Implement TCP socket options (TCP_NODELAY, keepalive timers, `TCP_DEFER_ACCEPT` where applicable, user timeout), IPv4/IPv6 dual-stack handling with separate sockets, and PROXY protocol acceptance (opt-in, T-0315).
5. Implement graceful restart support via socket handoff (systemd socket activation or `SO_REUSEPORT` overlap) with drain-on-SIGTERM (default 5 s downtime bound per Appendix E4).
6. Implement per-connection resource accounting (buffers, streams) and a memory budget per connection class.
7. Add metrics (`MET-hdd_proxy_connections`, `shed_total`) and structured logging for shed events (rate-limited).
8. Test connection floods (functional profile on the builder), slow handshakes, and restart behavior.
**Deliverables.**
- listener layer, ADR, tests
**Acceptance.**
- A1: under a 20k-connection flood on the builder, established clients keep p99 within 2x baseline.
- A2: restart (SIGTERM with replacement process) causes at most 5 s of unavailability and no dropped in-flight requests within the drain window.
- A3: per-IP caps are enforced for IPv4 and IPv6 keys.
- A4: shed responses follow the documented order.
- A5: the ADR contains the hook checklist with evidence.
**Tests.**
- Load/chaos tests; restart tests with a client that records errors; unit: shed policy decisions.
**Notes.** Kernel-level protections complement but do not replace this layer.
