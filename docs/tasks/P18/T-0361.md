### T-0361 · Upstream header policy, Ray ID and secret origin header
`P18` `[DP][SEC]` · deps: T-0359 · size: M · owner: dp
**Objective.** Control exactly what the origin sees and receives.
**Steps.**
1. Implement the upstream header builder: strip hop-by-hop headers and untrusted inbound `X-Forwarded-*`, `Forwarded`, `X-Real-IP`, `HDD-*`, `X-Original-URL`, `X-Rewrite-URL`; set `X-Forwarded-For` (append resolved client IP), `X-Real-IP`, `HDD-Connecting-IP`, `X-Forwarded-Proto`, `X-Forwarded-Host` (site hostname, only when configured), `HDD-Ray-ID`, and the **secret origin header** `HDD-Origin-Auth: <token>` per site.
2. Implement Ray ID generation: 16 hex characters from a CSPRNG (64 bits) plus `-HDD1`; collision handling not required but uniqueness checked in tests statistically; attach to request context, upstream headers, response headers, events and logs.
3. Implement secret rotation with dual-valid windows: the origin may accept either current or previous secret during rotation (HDD sends the current; docs show snippets to accept both); expose rotation state in S-052/S-098.
4. Implement optional mTLS to the origin (client certificate from the envelope store) as an alternative to the secret header (T-0405 UI).
5. Preserve request fidelity: keep header order where possible, preserve `Cookie` and `Authorization` unchanged, pass `Content-Type`, strip `Proxy-*` headers, and avoid adding headers that change cache semantics.
6. Implement response header policy (T-0410 hook): set `Server: Hack-Dev-Defence`, strip disclosure headers, add `X-Content-Type-Options: nosniff`, `X-XSS-Protection: 0`, add `X-Frame-Options`/CSP `frame-ancestors` only if absent, HSTS per policy, and `HDD-Ray-ID` on every response.
7. Test with the canary `echo-headers` endpoint verifying origin-visible headers, spoof attempts from clients, and rotation windows.
8. Document header semantics for origin applications (trusting `HDD-Connecting-IP` only from HDD).
**Deliverables.**
- header builder, Ray ID module, tests, docs
**Acceptance.**
- A1: client-supplied spoofed headers never reach the origin (echo test with 20 variants).
- A2: Ray IDs match the format and are unique over 1M samples.
- A3: secret rotation with overlap works without errors.
- A4: `Cookie`/`Authorization` pass through byte-identically.
- A5: `HDD-Ray-ID` appears on every response type (success, block, error, 304).
**Tests.**
- Integration with echo origin; statistical uniqueness test; unit: header policy tables.
**Notes.** AC-05 and AC-22 verify live with the canary echo.
