### T-0359 · Pipeline framework: stages, budgets, short-circuit and test harness
`P18` `[DP]` · deps: T-0355 · size: L · owner: dp
**Objective.** Make every stage independently testable with timing and failure semantics.
**Steps.**
1. Define the `Stage` trait (`async fn run(&self, ctx: &mut RequestCtx) -> StageOutcome` with outcomes `Continue`, `Respond(Response)`, `Close`), a typed `RequestCtx` carrying parsed request, client IP, site handle, flags, timings, and mutation permissions per stage, and a fixed stage order (0 to 19 of C2) built at startup from the snapshot (stages may be disabled by mode).
2. Implement per-stage timing histograms (`MET-hdd_proxy_request_duration_seconds{stage}`), budgets (soft/hard per stage from C2) with metrics when exceeded, and hard-timeout handling per failure semantics (e.g., rate limiter 5 ms timeout falls back).
3. Implement panic isolation per request (catch_unwind at stage boundary, response 500/503 per mode, panic counter, alert) and ensure no shared mutable state is poisoned (use lock-free structures or parking_lot).
4. Implement the harness: `PipelineTest` builds a pipeline with fake connection inputs (bytes in) and a controllable origin, capturing outputs; allow injecting faults per stage (delays, errors) for resilience tests; **the harness uses the real stage implementations** (only the network edges are test fixtures).
5. Implement structured tracing spans with the Ray ID and stage names; sampling of detailed traces (1 in N) to bound overhead.
6. Implement stage metadata for docs generation (order, budgets, fail modes) feeding `ARCHITECTURE.md`.
7. Benchmark the empty pipeline overhead (≤ 20 µs).
8. Document how to add a stage.
**Deliverables.**
- pipeline framework, harness, docs, tests
**Acceptance.**
- A1: stage order and short-circuit semantics are verified by table tests (including jail before inspection).
- A2: panics in a stage return a safe response and do not affect other requests (concurrency test).
- A3: per-stage histograms and budgets are exported.
- A4: pipeline overhead without stages under 20 µs p99.
- A5: documentation of the stage order is generated from code.
**Tests.**
- Unit/integration/benchmark.
**Notes.** All earlier ad-hoc stage wiring (T-0208, T-0261, T-0319) is migrated onto this framework.
