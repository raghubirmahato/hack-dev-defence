### T-0355 · Host router and the multi-tenant snapshot model
`P18` `[DP]` · deps: T-0211, T-0354 · size: M · owner: dp
**Objective.** Route requests to the right tenant configuration with strong isolation.
**Steps.**
1. Implement routing tables compiled into the snapshot: SNI → certificate set; normalized Host (lowercase, trailing dot removed, IDNA ascii, port stripped) → `SiteHandle` with policy, origin pool, hostnames, flags; wildcard hostnames supported per site; reserved prefix `/__hdd/` handled before routing to origins.
2. Enforce consistency: the Host must belong to the site selected by SNI (or an HTTP/2 authority covered by the certificate); duplicate or conflicting Host headers rejected (400); unknown Host gets the neutral 404 (S-144) that never reveals tenants, and requests to the preview host require valid preview tokens.
3. Implement per-site compiled policy references (`Arc<SitePolicy>`), per-site counters, and per-site budgets (max in-flight requests, max inspection concurrency) to provide tenant fairness.
4. Implement platform surfaces routing (dogfood): `www`, `app`, `admin`, `api`, `status` hostnames route to the local `hdd-web`/`hdd-api` backends with the same pipeline (so HDD protects itself). These routes use `origin_kind=platform_internal` (a Unix domain socket by default, fixed loopback port otherwise; section 2.9 exemption (a)), which is compiled into the route table and unavailable to tenants. Mount `/api/v1/*` same-origin on `app` and `admin` (B2.1); the `api` host accepts bearer credentials only. The admin surface is restricted by `admin_cidrs` at the router before inspection and never exposed when `admin_exposure: tunnel_only`.
5. Implement domain state effects: `paused`/`safe` pass-through, `suspended` serves S-148, `removing` serves according to the end state, `pending_delegation` serves normally if reachable.
6. Implement route cache (lock-free map) with O(1) lookups and update-by-swap semantics; ensure memory usage scales sub-linearly with sites via shared structures.
7. Test isolation: requests with mismatched SNI/Host, host confusion, case/encoding tricks, thousands of sites, rapid snapshot swaps.
8. Document the routing precedence.
**Deliverables.**
- router, tests, docs
**Acceptance.**
- A1: host confusion attempts never route to another tenant (property test over random SNI/Host pairs).
- A2: the admin hostname is unreachable from non-allowlisted peers before any handler runs.
- A3: 10,000-site snapshots route with O(1) lookup latency (benchmark).
- A4: state effects (pause, suspend) are honored within 2 s.
- A5: unknown hosts always receive identical neutral 404 responses.
**Tests.**
- Property/benchmark/integration tests.
**Notes.** The platform's own surfaces are tenants of the router with built-in routes.
