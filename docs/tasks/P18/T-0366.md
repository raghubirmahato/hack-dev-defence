### T-0366 · Visitor pages: data-plane templates, CSP, shared renderer and JSON variants
`P18` `[DP][UI][SEC]` · deps: T-0065, T-0236, T-0359 · size: L · owner: ui
**Objective.** Serve all visitor-facing pages from the data plane safely and identically to the control-plane previews.
**Steps.**
1. Implement the shared renderer crate module (`hdd-ui::visitor`) producing HTML and JSON for S-140 (block), S-142 (429), S-143 (502/504), S-144 (unknown host), S-148 (suspended), plus references for S-141/S-145/S-146/S-147 delivered by `hdd-challenge` and appeals endpoints; templates compile at build time; tenant branding and message variants come from the snapshot (no raw HTML).
2. Implement a **data-plane CSP** for visitor pages: `default-src 'none'; style-src 'nonce-…'; script-src 'self' (challenge assets only); img-src data: 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, per-response nonce, plus `X-Content-Type-Options`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`.
3. Implement content negotiation (`Accept`, `Sec-Fetch-Dest: document`) between HTML and JSON (`{"error":"access_denied","ray_id":"…"}`), localization by `Accept-Language` for a limited set of strings, and size budgets (≤ 20 KB HTML).
4. Implement uniform responses: bans, blocks, jail hits and soft blocks look identical; no rule names or internal hostnames; origin errors avoid leaking origin addresses.
5. Implement logo/asset serving under `/__hdd/assets/` with immutable caching and content hashing, size limits and sanitization (T-0236).
6. Implement previews in the control plane using the same renderer (byte-identical test).
7. Add accessibility tests for each page (axe) and visual baselines, including 320 px width and large text.
8. Document how pages change per status code and header.
**Deliverables.**
- renderer module, templates, tests
**Acceptance.**
- A1: control-plane preview bytes equal data-plane output for identical inputs (test).
- A2: pages pass axe, keyboard and reflow checks and stay within size budgets.
- A3: no page includes rule names, stack traces or internal hostnames (scanner test).
- A4: CSP has no violations in the browser harness.
- A5: JSON variants are returned for API clients.
**Tests.**
- Browser tests; snapshot tests; scanner tests.
**Notes.** These pages define the visitor experience of every block (J-22).

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
