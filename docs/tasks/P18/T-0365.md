### T-0365 · Origin client: pooling, TLS verification, SSRF connect guard, redirects and loop detection
`P18` `[DP][SEC]` · deps: T-0163, T-0359 · size: XL · owner: dp
**Objective.** Talk to origins efficiently and safely.
**Steps.**
1. Implement the origin connector with DNS resolution via the SSRF guard (pinned, validated addresses with TTL-based refresh and rebinding protection), connection pooling (per origin, bounded idle connections, idle timeout 30 s, max lifetime 5 min), connect timeout 3 s, read timeout 30 s, write timeout, and h2 to origin when ALPN permits.
2. Implement TLS verification per mode: `webpki` roots (bundled `webpki-roots` or system roots per ADR), `pinned_ca` (custom roots), `pinned_spki` (hash check after chain verification or in addition), correct SNI and verification name from config, TLS 1.2+; **no code path disables verification** (a test greps for dangerous verifier implementations and fails).
3. Implement `http_origin_ack` plaintext mode with explicit flag checks and readiness penalties.
4. Implement connect-time SSRF validation on every new connection and re-validation after DNS refresh; reject platform addresses (loop prevention) and detect loops via a hop header (`HDD-Hop` counter) and `Via`: if the request already carries our hop marker the proxy responds 508 Loop Detected.
5. Implement redirect behavior: origin 3xx responses are passed to the client unmodified (HDD never follows redirects); `Location` rewriting is not performed unless configured for host mapping with strict rules (default none).
6. Implement upstream request/response limits (response header size, body streaming), `100-continue` handling toward origins, and retry policy (idempotent requests only, once, on connection reset before response bytes).
7. Implement metrics (origin latency, errors by class, pool stats, TLS failures) and error mapping to branded 502/504 pages.
8. Test with faulty origins: slow, reset mid-body, bad certificates, wrong SNI behavior, huge headers, redirect loops, DNS rebinding sequences, IPv6-only origins.
**Deliverables.**
- origin client, tests
**Acceptance.**
- A1: origin certificate errors always yield 502 with no downgrade (tests with 10 certificate failure modes).
- A2: DNS rebinding to private addresses is refused at connect time.
- A3: redirect responses are passed through, never followed; loop detection returns 508.
- A4: retries occur only for idempotent methods and pre-response failures.
- A5: the grep guard prevents custom verifiers that disable checks.
**Tests.**
- Integration with fault-injecting origins; unit: pool logic; static guard test.
**Notes.** SSRF guard parity with T-0009 is property-tested.
