### T-0363 · Streaming, backpressure, graceful drain and overload behavior
`P18` `[DP][OPS]` · deps: T-0353, T-0360 · size: M · owner: dp
**Objective.** Keep the proxy stable under slow clients, slow origins and overload.
**Steps.**
1. Implement bidirectional streaming with bounded buffers and flow-control awareness (h1 and h2), propagating backpressure from slow clients to origins and vice versa; limit memory per connection and per site; abort when buffers exceed caps for too long.
2. Implement origin concurrency limits per site (max in-flight upstream requests, default 512) and queueing with timeouts (3 s) before returning 503 (branded) to protect origins; per-site "origin protection" to avoid amplifying load on struggling origins.
3. Implement overload signals: global CPU/memory pressure triggers shedding of low-priority traffic (e.g., unknown clients, scrapers) before core traffic (priority classes: allowlisted/cleared > known good > unknown > suspected bots).
4. Implement graceful drain on shutdown/reload: stop accepting, finish in-flight within window (5 s default for restart bound), send `Connection: close`/GOAWAY, then exit.
5. Implement admission control for expensive features (inspection concurrency budget, regex budgets) with fail-closed semantics in block mode.
6. Implement metrics and logs for backpressure events and sheds.
7. Test with slow clients (builder-local), slow origins (delay injection), flood scenarios, and memory profiling.
8. Document tuning.
**Deliverables.**
- streaming layer, overload manager, tests
**Acceptance.**
- A1: a slow client downloading a large response does not cause unbounded memory growth (assert RSS plateau).
- A2: origin queueing returns 503 after the timeout and never overwhelms the origin beyond the concurrency cap.
- A3: overload shedding prioritizes cleared and allowlisted traffic (measured success rates).
- A4: drain meets the downtime bound.
- A5: all limits are observable via metrics.
**Tests.**
- Load/chaos tests; memory profiling; unit: priority classification.
**Notes.** Complements kernel-level defenses.
