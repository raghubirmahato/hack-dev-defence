### T-0193 · DNS analytics views and control-plane DNS tests
`P09` `[UI][QA]` · deps: T-0140, T-0181 · size: M · owner: qa
**Objective.** Provide DNS query analytics UI and a thorough control-plane DNS test suite.
**Steps.**
1. Define DNS counters in the rollup pipeline (`dns_queries` by qtype, rcode, transport, zone, source class) fed by `hdd-dns` counters later; implement the query services and the UI panel (qps, NXDOMAIN rate, top names, truncation rate, TCP share) with Unknown states until the DNS server reports.
2. Implement privacy rules: no client IPs stored, names aggregated with cardinality caps (top 100 per hour), and random-subdomain floods collapsed into a single "random labels" bucket.
3. Build the control-plane DNS test suite: record API plus compile plus answer engine across 200 generated zones; round-trip export/import; rollback; safety engine; and a snapshot determinism test (same inputs give the same snapshot hash).
4. Add differential tests comparing the answer engine with a reference server loaded from exported zone files.
5. Add UI tests for the DNS pages across states.
6. Run property tests that random sequences of valid operations never produce an unserviceable snapshot.
7. Measure compile time for 10,000-record zones (budget 100 ms).
8. Record results with SHA-256.
**Deliverables.**
- analytics views, test suites, reports
**Acceptance.**
- A1: DNS analytics show Unknown with reason until the server reports counters.
- A2: no client IPs appear in any DNS analytics table.
- A3: snapshot determinism holds across 1,000 random zones.
- A4: compile time budget is met.
- A5: differential tests agree with the oracle on defined behaviors.
**Tests.**
- The suites; benchmarks.
**Notes.** After P11, the same tests run against the live `hdd-dns` binary.
