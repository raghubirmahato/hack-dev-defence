### T-0188 · SOA, TTL policy and zone settings
`P09` `[UI][API]` · deps: T-0177 · size: S · owner: dns
**Objective.** Expose the few zone-level knobs safely.
**Steps.**
1. Implement zone settings: default TTL, negative-caching TTL (SOA minimum, bounded 60 to 3,600 s), proxied-record virtual TTL (default 300 s), SOA refresh/retry/expire for secondaries (bounded to sane ranges), and contact mailbox (`hostmaster@...` default derived from platform).
2. Implement validation, safety checks (lowering TTLs before cutover recommendation), and audit.
3. Implement the UI panel (S-045 side panel) with explanations and "lower TTLs before migration" guidance.
4. Implement the effects on the snapshot compile and the serial bump.
5. Implement presets: "Migration (low TTLs)" and "Steady state".
6. Implement display of the effective values to customers (what resolvers will see).
7. Add tests for bounds and compile effects.
8. Document TTL strategy.
**Deliverables.**
- settings UI and API, tests
**Acceptance.**
- A1: out-of-range values are rejected with field errors.
- A2: changing settings bumps the serial and creates a version.
- A3: presets apply atomically.
- A4: UI explains TTL impact in plain language.
- A5: settings appear in exports as `$TTL`/SOA fields.
**Tests.**
- Unit: bounds; integration: compile effects; browser: panel.
**Notes.** Low TTLs are recommended at least one old-TTL period before cutover (C17.2).
