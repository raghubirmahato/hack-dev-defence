### T-0182 · DNS record editor (S-046) with "what will resolve" preview
`P09` `[UI][API]` · deps: T-0181 · size: L · owner: ui
**Objective.** Provide type-specific forms with real-time validation and exact previews.
**Steps.**
1. Implement forms per type (A, AAAA, CNAME, MX, TXT, NS (subzone delegation), SRV, CAA, HTTPS) with field-level help, examples, validation messages from the library, and TTL presets (Auto 300 s, 1 min, 5 min, 1 h, 1 day).
2. Implement the preview panel: before/after answers for the affected name for common query types (A, AAAA, CNAME, MX, TXT) rendered from the answer engine, including the effect on wildcard matches and on existing records at the same name.
3. Implement the proxied option with consequences and disabled states; show "HDD addresses will be returned" and that the origin value is hidden.
4. Implement multi-value RRsets editing (add/remove values) with a single transaction.
5. Implement duplicate and conflict detection (CNAME exclusivity) with fix suggestions.
6. Implement cancel/leave-guard and error summary integration.
7. Add accessibility checks and the keyboard map.
8. Add tests including hostile inputs (very long TXT, unicode names, injection strings).
**Deliverables.**
- editor pages, preview endpoint, tests
**Acceptance.**
- A1: the preview equals the answer engine output for the saved result (property test).
- A2: CNAME conflicts offer actionable alternatives.
- A3: TXT longer than 255 bytes is chunked correctly and previewed.
- A4: hostile inputs are rejected or escaped everywhere.
- A5: the editor works without JavaScript (full-page post).
**Tests.**
- Browser flows; property test linking preview to engine; fuzz on form field parsing.
**Notes.** Previews never query live DNS; they simulate HDD's answers only.
