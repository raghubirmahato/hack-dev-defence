### T-0186 · DNS change-safety engine
`P09` `[API][SEC]` · deps: T-0179, T-0183 · size: L · owner: dns
**Objective.** Block or warn on changes that would break a domain.
**Steps.**
1. Implement a rule engine that evaluates a proposed change set against the current zone: removal of apex SOA/NS (system), deleting the last A/AAAA for a proxied hostname, creating CNAME loops or chains longer than 8, CNAME/other-data coexistence, wildcard shadowing (new specific record hides wildcard behavior for some types), dangling references (CNAME/MX/SRV targets within the zone that do not exist), MX/SRV pointing at CNAMEs, orphaned `_acme-challenge` helper records, deleting records required for verification, proxied toggles on hostnames referenced by MX/SPF, TTL changes below 60 s or above 86,400 s, and bulk deletions above thresholds.
2. Classify findings as `Block` (cannot proceed), `Warn` (needs acknowledgment) or `Info`.
3. Run the engine in every mutation path (API, UI, import, rollback) so API clients receive the same findings in the problem response with an `acknowledge` flow for warnings.
4. Provide an "impact" summary derived from the answer engine (names whose answers change) and the readiness effect (score delta).
5. Implement a self-lockout analog for DNS: warn when a change would break the HDD admin or HDD-managed names in platform zones (platform admins only).
6. Add configuration for thresholds per plan.
7. Add comprehensive tests (60 scenarios).
8. Document the catalog of rules with IDs (`DNSSAFE-001...`).
**Deliverables.**
- safety engine, rule catalog, API integration, tests
**Acceptance.**
- A1: every rule has a positive and negative test.
- A2: API and UI show identical findings for identical changes.
- A3: blocked changes cannot be forced by any client (no override flag).
- A4: warnings require explicit acknowledgment tokens bound to the change set hash.
- A5: impact summaries match the answer engine diff.
**Tests.**
- Table tests (60); property tests (random change sets never panic and findings are deterministic).
**Notes.** The engine is also used by imports to flag problematic source records.
