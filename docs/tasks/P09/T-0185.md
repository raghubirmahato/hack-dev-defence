### T-0185 · Zone version history, diff and rollback (S-048)
`P09` `[UI][API]` · deps: T-0177, T-0044 · size: M · owner: dns
**Objective.** Make every DNS change reviewable and reversible.
**Steps.**
1. Implement the history list (version, time, author, summary, record counts, source: manual/import/rollback/system) with filters and links to diffs.
2. Implement the diff view (unified and side-by-side) using DiffViewer with record-level semantics (added/removed/changed) and text prefixes.
3. Implement rollback: select a version, preview the resulting answers diff and safety checks, require confirmation (type-to-confirm for versions older than 24 hours), create a new version (rollback is a forward change), and publish.
4. Implement retention: keep all versions for 90 days and the last 100 versions beyond, with hash anchors.
5. Implement annotations (user note on a version) and labels (for example "pre-cutover").
6. Implement export of a specific version.
7. Add audit events and permission checks (`dns.rollback`).
8. Add tests including rollback conflicts with concurrent edits.
**Deliverables.**
- history UI, rollback service, tests
**Acceptance.**
- A1: rollback creates a new version whose records equal the target version's records.
- A2: concurrent edit during rollback is detected (`ERR-CONC-001`).
- A3: diff view is understandable without color (text prefixes).
- A4: old versions are retained per policy.
- A5: rollback preview lists changed answers for common types.
**Tests.**
- Integration: rollback equality; unit: diff semantics (proptest random edits).
- Browser: history and diff interactions.
**Notes.** The rollback preview uses the answer engine for before/after.
