### T-0190 · Propagation checker (S-099)
`P09` `[UI][API][OPS]` · deps: T-0161 · size: M · owner: dns
**Objective.** Show how the world sees the domain's DNS right now.
**Steps.**
1. Implement the checker job: query a configured list of allowlisted public resolvers (at least two; operator may add) and optional vantage points for selected names and types, with a TTL-aware interpretation (cached stale vs not propagated).
2. Show a matrix (resolver x name/type) with answers, response time, TTL remaining, and match status versus HDD's expected answer from the engine (including orange-cloud rewrite).
3. Implement manual check with rate limits (6 per minute per org) and scheduled checks after changes (T-0161 integration).
4. Provide shareable permalinks for results (expire after 24 hours) containing no secrets.
5. Provide interpretation guidance (what mismatches mean, how long to wait).
6. Respect egress: only resolvers on the allowlist; clear message when fewer than two are configured.
7. Add accessibility via table semantics and status text.
8. Test against a controllable local resolver farm (multiple loopback recursive servers with different cache states).
**Deliverables.**
- checker, UI, tests
**Acceptance.**
- A1: stale-cache vs wrong-answer cases are distinguished.
- A2: expected answers come from the answer engine, not user input.
- A3: rate limits are enforced.
- A4: permalinks expire and contain no tenant secrets.
- A5: the UI explains each mismatch class.
**Tests.**
- Integration with loopback resolvers; unit: interpretation logic; browser: matrix.
**Notes.** Results also feed the delegation completion notifications.
