### T-0181 · DNS records screen (S-045) with proxy toggles and bulk actions
`P09` `[UI]` · deps: T-0179, T-0044, T-0045 · size: L · owner: ui
**Objective.** Implement the records table with safe inline editing.
**Steps.**
1. Implement the table: columns (name, type, value, TTL, proxy status, source, updated), filters (type, name contains, proxied only, source), sorting, density, column visibility, cursor pagination, and saved views.
2. Implement inline edit of value/TTL with HTMX (optimistic concurrency with `version`), validation errors inline, and an undo toast referencing the version history.
3. Implement the `CloudToggle` interaction: clicking opens the consequence popover with the **answer preview** (before/after answers from the engine) and applies on confirm; mail types and non-proxiable types show disabled controls with reasons.
4. Implement bulk actions: set TTL, proxy on/off for selected eligible records, delete selected (type-to-confirm when more than 5), export selection.
5. Implement the empty states (no records; imported records pending acknowledgment) and the partial-mode view (only helper records HDD controls, with explanatory banner).
6. Implement server-rendered rows for 2,000 records within the performance budget using pagination.
7. Add keyboard shortcuts for editing (Enter to edit, Esc cancel) documented in the overlay.
8. Add visual baselines and accessibility checks including table semantics.
**Deliverables.**
- screen, row partials, tests
**Acceptance.**
- A1: the proxy toggle shows an answer preview from the engine and requires confirmation.
- A2: bulk delete of more than 5 records requires typing the zone name.
- A3: inline edits handle version conflicts with a recoverable UI.
- A4: the table is fully operable by keyboard and passes axe.
- A5: 2,000-record zones render within the performance budget.
**Tests.**
- Browser tests for edit, conflict, bulk flows; performance test; unit: filter model.
**Notes.** Mail names show a lock icon plus text "DNS only (mail)".
