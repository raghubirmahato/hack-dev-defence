### T-0191 · Secondary DNS and TSIG settings (data model and UI hooks)
`P09` `[DB][API][SEC]` · deps: T-0177 · size: M · owner: dns
**Objective.** Prepare configuration for external secondaries and hidden-primary topology.
**Steps.**
1. Add data model for `zone_secondaries` (provider label, addresses, TSIG key name, algorithm, key encrypted, allowed transfer sources, NOTIFY targets, status, last transfer result) and platform-level defaults.
2. Implement validation (addresses public unicast, key length minimum 256 bits for HMAC-SHA256+, name format) and secret handling (generated by HDD and shown once for configuring the secondary, or imported).
3. Implement platform admin UI/API (S-113 hooks) and per-zone read-only status view for owners ("Your DNS is also served by ...").
4. Implement preflight warnings: both NS names in one IP/provider, no secondary configured.
5. Implement the settings that the `hdd-dns` transfer module (T-0394) will consume, with status fields updated by the DNS service via a queue.
6. Implement audit events and permission checks (platform only for secondary definitions in Tier 1).
7. Write documentation for hidden-primary setup (generic steps; provider-specific only when supplied).
8. Add tests for validation and encryption.
**Deliverables.**
- migration, services, UI hooks, tests, docs
**Acceptance.**
- A1: TSIG keys are encrypted at rest and shown once.
- A2: private/loopback transfer sources are rejected.
- A3: preflight shows warnings for single-point NS configurations.
- A4: status fields update via the queue (simulated by a test publisher using the real queue).
- A5: only platform roles can create or modify secondaries in Tier 1.
**Tests.**
- Integration: encryption and permissions; unit: key validation; BOLA additions.
**Notes.** Transfers are implemented and verified in P20 (AC-21).
