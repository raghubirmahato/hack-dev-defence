### T-0482 · Component inventory: model, importers (SBOM, lockfiles, package lists) and ownership
`P27` `[DB][API][UI]` · deps: T-0481, T-0153, T-0126 · size: L · owner: api
**Objective.** Let owners tell HDD what actually runs on the origin, in the formats they already have.
**Steps.**
1. Implement the `components` model per B5 with extensions: `name`, `version` (nullable = unknown), `purl`, `cpe`, `ecosystem`, `internet_facing`, `source` (`profile|sbom|lockfile|scan|manual`), `confidence` (`declared|verified|inferred`), `owner_user_id`, `site_id` (optional scope), `first_seen`, `last_seen`, `notes`; unique per (org, site, purl or name+ecosystem, version).
2. Implement importers with strict parsing and size caps (10 MB, 50,000 components): CycloneDX JSON (1.4–1.6), SPDX JSON (2.2/2.3), `Cargo.lock`, `package-lock.json` (v1–v3) and `yarn.lock`/`pnpm-lock.yaml`, `composer.lock`, `requirements.txt` (pinned only; unpinned entries recorded as unknown with a warning), `Pipfile.lock`/`poetry.lock`, `Gemfile.lock`, `go.mod`/`go.sum`, `pom.xml` (direct dependencies, property resolution limited and documented), `*.csproj` PackageReference, OS package lists (`dpkg -l`, `rpm -qa` text), container image SBOM from `syft` JSON, and the platform detectors list (WordPress core/plugins/themes from a pasted list or `wp plugin list --format=json`).
3. Implement **safe parsing**: no external entity resolution for XML-based formats, no code execution, depth/size limits, zip-bomb protection for archives, encoding validation, and strict purl parsing (`packageurl` rules) with canonicalization.
4. Implement import semantics: dry-run preview (counts added/changed/removed, unknown versions), merge strategies (replace source, merge, add only), provenance tags, and soft delete of components no longer present after a replace import (`last_seen` cutoff) so exposure history remains.
5. Implement the **ownership and SLA contact** model: every component has an owner (user or team label), default owner per site, and unowned components appear as attention items; owners get SLA alerts.
6. Build the tenant UI as the **Exposure tab of S-043** (`/domains/{id}/exposure`; the platform view S-125 aggregates): import wizard (choose format, upload or paste, preview), component table (filters: ecosystem, internet-facing, unknown version, owner), manual add/edit with purl helper, and clear explanations ("HDD can only match what you tell it or what it can passively observe").
7. Implement API endpoints (`/domains/{id}/components`, `/components:import`, bulk), quotas, audit events and permission `PERM-exposure.write` (owner/admin) / read for analyst.
8. Write tests: importer fixtures for every format (≥ 3 real-world-shaped files each), malformed and hostile inputs (XXE, billion laughs, zip bombs, giant strings), purl canonicalization, merge strategy correctness, RLS/BOLA, UI e2e with file upload and preview, and performance (50,000 components import < 10 s).
**Deliverables.**
- model, importers, UI tab, API, tests, docs
**Acceptance.**
- A1: all fixture formats import with expected component counts and purls.
- A2: hostile inputs are rejected without resource blow-up (time and memory caps verified).
- A3: unknown versions are stored as unknown and never guessed.
- A4: imports are previewable and reversible (soft delete retains history).
- A5: components are tenant-isolated (BOLA tests).
**Tests.**
- Unit/fixture, security, performance, browser e2e.
**Notes.** Passive fingerprinting (T-0486) adds `source=scan` rows with explicit confidence levels.

## Definition of done for this task's tags (section 0.7)

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
