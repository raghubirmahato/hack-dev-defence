### T-0484 · Exposure board backend, SLA clocks, alerts and the R-11 invariant
`P27` `[API][DB][UI]` · deps: T-0483, T-0453, T-0436 · size: L · owner: api
**Objective.** Track what remains unpatched, who owns it and how overdue it is, and make it impossible to hide a bug behind a virtual patch.
**Steps.**
1. Implement `vuln_matches` lifecycle with statuses `unpatched | virtually_patched | patched | not_affected`, transitions with preconditions: `patched` requires the component inventory to show a fixed version (or a manual attestation with evidence and reviewer), `not_affected` requires VEX, `virtually_patched` requires an active virtual patch in `monitor` or `block` state (T-0485); a lapsed virtual patch automatically reverts the status to `unpatched` with an alert.
2. Implement **SLA policy** from the profile: KEV or known-exploited 48 h, critical 7 d, high 30 d, medium 90 d, low 180 d (configurable with floors), clock start at match creation, **clock never stops while `unpatched` or `virtually_patched`** (R-11 enforced in code by a single function and a database constraint that forbids setting `closed_at` for `virtually_patched`), days overdue computed server-side.
3. Implement alerts at 50% and 90% of SLA and when overdue (trigger catalog entries `vuln_sla_*`), plus KEV additions affecting known components (`kev_added`) with immediate notification, routed through the notification core (T-0453).
4. Implement the platform **Exposure board** wiring (S-125): components view (all orgs, counts only for tenants without `platform.tenant.read`), matches view with filters, SLA/overdue columns, owner, VEX actions; replace the contract-fixture mode of T-0436 with real data.
5. Implement the tenant **Exposure tab** (S-043): summary tiles (open, overdue, mitigated-not-fixed, unknown-version components), match table, per-item detail with remediation steps (upgrade to fixed-in, vendor links), owner assignment, snooze (max 7 days, reason, cannot snooze KEV/critical overdue), and export.
6. Implement the **virtual-patch debt** metric (count, age, oldest expiry, components needing a real fix) and show it on both views and in weekly digests.
7. Integrate with the **readiness score** (T-0172) and the **cutover gate** indicator (no overdue KEV/critical for the origin and no expired virtual patch); expose `GET /api/v1/.../exposure/summary`.
8. Write tests: SLA math with time injection (including weekends, no business-day calendar), R-11 invariant tests (try to close a virtually patched item through API, SQL and bulk operations; all must fail), alert thresholds, automatic reversion on virtual-patch expiry, snooze rules, RLS, and UI e2e.
**Deliverables.**
- lifecycle service, SLA engine, alerts, UI wiring, tests
**Acceptance.**
- A1: no path (API, UI, direct SQL with the app role) can mark a `virtually_patched` item as closed or stop its clock.
- A2: SLA alerts fire exactly at 50%, 90% and overdue (injected time).
- A3: expiry of a virtual patch reverts the item to `unpatched` and alerts.
- A4: the tenant and platform views agree on counts.
- A5: KEV/critical overdue items cannot be snoozed.
**Tests.**
- Unit (SLA), DB constraint tests, integration, browser e2e.
**Notes.** "Mitigated, not fixed" is the permanent label for virtually patched items.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
