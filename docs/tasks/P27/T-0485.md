### T-0485 · Virtual-patch lifecycle engine, evidence harness and signed packs (V10)
`P27` `[DP][API][SEC]` · deps: T-0484, T-0310, T-0245, T-0425 · size: XL · owner: sec
**Objective.** Make scoped CVE mitigations safe to create, test, deploy, expire and retire, without giving anyone a false sense of security.
**Steps.**
1. Implement the `virtual_patches` lifecycle: `draft → monitor → block → retired`, with fields `cve`, `component_id`, `affected_range`, `fixed_in`, `created`, `expires` (default 90 days, max 180), `owner`, `evidence`, `rule_id`, `scope` (path/parameter/method constraints), and `would_block_count` in monitor; transitions enforce preconditions (evidence present, monitor ran at least 24 h with zero benign hits on the baseline replay before `block`, owner assigned).
2. Define the **evidence format**: exploit-shaped request vectors that must block (Class A inert shapes, or Class B/C vectors kept to the inspect API), benign requests that must pass, and the target path/parameter scoping; the harness runs both sets through `hdd-waf-core` in CI for packs and on demand for tenant-authored patches; **minimal detection patterns only**, never working exploit code (lint rejects payloads over size limits or matching a denylist of weaponized artifacts).
3. Provide the **authoring assistant** (human-reviewed): builds a draft rule from an advisory (path/parameter hints, known vulnerable endpoint patterns from advisory references, scoped to the component's detected paths), requires manual completion and review; platform-authored packs are signed (T-0425) and distributed as the "virtual patch pack"; tenant-authored patches live in the tenant's rule set with the same lifecycle.
4. Implement **expiry enforcement**: patches past `expires` raise an alert and block release gates (`xtask verify` fails if a shipped pack contains expired patches); extension requires an explicit audited decision with reason (max 2 extensions); expiring-soon notifications at 14 and 3 days.
5. Implement **retirement**: automatic suggestion when the inventory shows the component at or above `fixed_in`; confirmation by the owner; retirement keeps history; retirement of a patch also re-evaluates the match status.
6. Implement pack integration: virtual patch rules compile into the policy snapshot with their own category (`virtual_patch`), scoped; rollbacks via config revisions; auto-rollback triggers apply as for other rules (C14.8) and false-positive reports link back to the patch.
7. Implement the **debt dashboard** data (count, age, oldest expiry, components still needing a real fix) for admin and tenant views, and metrics (`MET-hdd_vpatch_*`).
8. Write tests: lifecycle preconditions, evidence harness with a seeded pack (≥ 25 patches with block/pass vectors), scope narrowness tests (a patch scoped to `/vuln.php?id=` must not affect other paths), expiry and extension flows, release-gate failure on expired patches, retirement suggestion logic, and signed-pack tamper tests.
**Deliverables.**
- lifecycle engine, evidence harness, authoring assistant, pack tooling, tests, docs
**Acceptance.**
- A1: moving a patch to `block` without monitor evidence or baseline replay is refused.
- A2: each seeded patch blocks its evidence vectors and passes its benign set (100%).
- A3: expired patches fail `xtask verify` and create alerts.
- A4: patches are path/parameter scoped and do not affect unrelated requests in the baseline corpus.
- A5: the lint prevents weaponized payloads from entering evidence.
**Tests.**
- Unit, harness runs, CI gate tests, tamper tests.
**Notes.** AC-31 verifies the lifecycle end to end.

## Definition of done for this task's tags (section 0.7)

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
