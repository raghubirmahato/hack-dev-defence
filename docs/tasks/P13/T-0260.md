### T-0260 · Inspect API (`POST /api/v1/waf/inspect`) and dry-run semantics
`P13` `[API][SEC]` · deps: T-0252, T-0237, T-0125 · size: L · owner: api
**Objective.** Provide the dry-run endpoint that the UI, SDK and acceptance runner rely on.
**Steps.**
1. Implement `POST /api/v1/orgs/{org}/domains/{dom}/waf/inspect` and the alias `POST /api/v1/waf/inspect` (body includes `site`), accepting a described request (method, URL or path+query, headers, cookies, body as UTF-8 text or base64 up to 64 KB, content type, client context: IP optional, `Sec-Fetch-*` values, field-kind hints) and optionally `mode_override` (`block` for evaluating would-ban semantics).
2. Run the full engine with the site's compiled policy and return: `would_block`, decision details (category, subtype, rule IDs and versions for the owner role, score and threshold, hardness), `would_ban` with the TTL ladder step the IP would receive (read-only computation using offence counters), evidence (redacted), explanation, `config_revision`, `engine_version`, flags (`truncated`, etc.).
3. Guarantee side-effect freedom: never forwards, never bans, never increments offence counters or rate limiter state, never writes events (an audit event with a hash of the sample is written for compliance); enforced by types (the engine invoked with a `DryRun` context that has no mutators).
4. Enforce permissions (`waf.inspect`), rate limits (60 per minute per user, 600 per hour per org), size limits, and idempotency not required.
5. Return the exact `config_revision` so callers (acceptance runner) can verify the policy did not change between inspection and live test.
6. Provide OpenAPI documentation with examples (inert samples only) and SDK method.
7. Implement a batch mode (up to 50 samples per call) for the acceptance matrix with total size limit.
8. Add tests including hostile payloads in all fields and consistency with proxy decisions (differential test: same request through the proxy test harness in monitor mode yields the same verdict).
**Deliverables.**
- endpoints, DTOs, OpenAPI, SDK stubs, tests
**Acceptance.**
- A1: dry-run calls cause no events, bans or counter changes (store snapshots before/after).
- A2: inspect results equal proxy monitor-mode verdicts for the same inputs (differential test on 500 samples).
- A3: the response includes `config_revision` and `would_ban` details.
- A4: rate limits and size caps are enforced.
- A5: audit events contain only sample hashes, not payloads.
**Tests.**
- Integration (API + engine + Redis counters); differential test; security tests for oversize/rate abuse.
**Notes.** Rule IDs are hidden from viewer roles and never shown to visitors.
