### T-0253 · Redaction library
`P13` `[DP][SEC]` · deps: T-0252 · size: M · owner: sec
**Objective.** Ensure stored evidence and logs never contain credentials or tokens.
**Steps.**
1. Implement redaction rules for headers (`Authorization`, `Cookie`, `Set-Cookie`, `X-API-Key`, `X-Auth-Token`, and any header name matching `(token|secret|key|auth|session)`), query/form/JSON fields whose names match password/secret/token patterns, and value-pattern detectors (JWTs `eyJ...`, AWS access key IDs, long hex/base64 secrets, `Bearer ...`, private key headers, credit card numbers with Luhn validation, US SSN-like numbers as optional).
2. Implement replacement with fixed markers (`[redacted:header]`, `[redacted:token]`) preserving length class (short/medium/long) but not content; the evidence span tied to a SQL payload in a password field is shown in redacted form when the field kind is `password` (the payload structure is kept in the *rule metadata*, not the value).
3. Implement streaming-friendly operation with bounded cost and no regex backtracking.
4. Provide a configuration for additional site-specific patterns and sensitive field names (bounded count).
5. Implement a verification scanner reused in logs/tests: given a string, report any unredacted secret-like content.
6. Implement tests with a corpus of real-looking secrets generated at runtime.
7. Document policy and limitations (redaction is heuristic; do not store more than needed).
8. Fuzz the redactor.
**Deliverables.**
- `redact` module, scanner, tests
**Acceptance.**
- A1: all secret-like samples in the corpus are redacted in evidence and logs.
- A2: password-field evidence never reveals the value (only the matched rule/subtype).
- A3: redaction does not break escaping or offsets (property tests).
- A4: the scanner finds no secrets in 100k generated events.
- A5: the redactor never panics (fuzz) and is linear time.
**Tests.**
- Table/proptest/fuzz; end-to-end event scan test.
**Notes.** Redaction applies before events are queued, not at display time.
