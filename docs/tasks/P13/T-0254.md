### T-0254 · Fixture system, payload classes and held-out sets
`P13` `[QA][SEC]` · deps: T-0245 · size: L · owner: qa
**Objective.** Organize attack and benign fixtures with the safety classes of section 2.2.
**Steps.**
1. Define the fixture file format: UTF-8 text with line-oriented entries and a YAML/TOML front-matter header declaring `class: A|B|C`, `category`, `vector`, `atk`, `source` (original/derived/public corpus with license), `heldout: true|false`, and optional per-entry annotations (`# expect: block subtype=tautology`).
2. Implement `xtask fixtures`: validate headers, classes (Class C files never loadable by live tooling, enforced by a type-level flag), license records for public corpora (only permissive or explicitly allowed sources; unknown licenses are rejected), duplicates, and encoding.
3. Implement the loader library used by tests and by `hdd-acceptance` (class-aware: live runs refuse Class C and require the inspect-first gate for A and B).
4. Create the directory structure `tests/fixtures/{sqli,xss,lfi,rce,xxe,ssrf,upload,evasion,protocol,api,cms,bots}` and `heldout/` (excluded from rule-authoring workflows: a lint prevents rule files from referencing held-out entries and a CODEOWNERS-style rule marks the directory as read-only for tuning tasks).
5. Seed fixtures from Appendix E1 (mandated SQLi payloads and families; other categories), written by hand as original material; document sources and tagging.
6. Implement statistical reporting (`xtask fixtures report`): counts per class/category/vector, held-out coverage, and detection rates per run.
7. Implement the held-out discipline: held-out detection is reported at gates but never used for tuning; an audit log records every read of held-out results by task ID.
8. Document fixture contribution rules.
**Deliverables.**
- fixture format, loader, xtask commands, seed fixtures, docs
**Acceptance.**
- A1: Class C entries cannot be loaded by any live-capable tool (compile-time or runtime guard tests).
- A2: fixtures with missing headers or unknown licenses fail validation.
- A3: rule files cannot reference held-out entries (lint).
- A4: the report lists counts and rates per category.
- A5: seed fixtures include the six mandated SQLi payloads in the core set.
**Tests.**
- Unit: parser/validator; integration: loader class enforcement; lint tests.
**Notes.** Payload strings are detection fixtures only, kept at textbook level; no working exploit chains.
