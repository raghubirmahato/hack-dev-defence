### T-0243 · Normalizer property tests, differential tests and fuzz targets
`P13` `[QA][SEC]` · deps: T-0242 · size: M · owner: qa
**Objective.** Prove the normalizers are safe to run on untrusted input at line rate.
**Steps.**
1. Write proptests: idempotence, bounded growth, offset-mapping validity, order-independence of independent decoding layers, flag stability, monotonicity (adding noise characters from the noise set never removes a detection target in the canonical view).
2. Write differential tests against oracles: percent-decoding versus `percent-encoding` crate and a second independent implementation on valid inputs; HTML entities versus a reference entity table; NFKC versus `unicode-normalization` directly; assert agreement on the common subset.
3. Create the fuzz target `normalize_all` (all views on arbitrary bytes with random context flags) and `canon_contexts`, seeded with the evasion corpus (C4.8) and the fixtures.
4. Run `cargo fuzz` smoke (60 s per target) in `verify`; nightly longer runs on the builder (1 h per target) with crash triage to `docs/diagnoses/`.
5. Run the sanitizers where available (ASan/UBSan for fuzz builds on nightly).
6. Add regression tests for each fuzz-found issue with minimized inputs.
7. Measure and record throughput and worst-case time per byte (adversarial inputs: deep nesting, huge repeated entities).
8. Document the invariants as machine-checked properties in the crate docs.
**Deliverables.**
- proptests, differential tests, fuzz targets, corpus seeds, docs
**Acceptance.**
- A1: all properties pass at 10,000 cases per run.
- A2: fuzz smoke runs 60 s per target with no crash or timeout.
- A3: adversarial inputs never exceed 50 ns/byte worst case in the benchmark.
- A4: differential tests agree on the common subset.
- A5: every found crash has a regression test.
**Tests.**
- The suites themselves; CI nightly jobs.
**Notes.** Crashes block release (C12.6).
