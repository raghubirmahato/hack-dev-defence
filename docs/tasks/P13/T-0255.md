### T-0255 · Benign corpora v1 and the false-positive gate
`P13` `[QA][SEC]` · deps: T-0254 · size: L · owner: qa
**Objective.** Create the corpora that keep detection honest, and gate on zero false positives.
**Steps.**
1. Build `tests/fixtures/benign-general.txt` (500+ entries) covering: names with apostrophes and hyphens (O'Brien, D'Angelo, Nguyen, María-José), addresses (`Apt #4`, `12/B`, `St. John's`), emails (valid edge cases incl. `o'brien@example.com`, plus-addressing), URLs and paths (`/blog/2024/10/my-post`, encoded unicode paths), search queries (everyday and technical), product titles, markdown and code snippets in prose, JSON/XML samples, form values (dates, phone numbers, currencies), user agents of mainstream browsers, referers, cookies (opaque tokens), and password-like strings (random, passphrases, symbols).
2. Build `tests/fixtures/benign-sql-prose.txt` (400+ entries): English sentences using SQL words as normal language (`select a gift`, `drop shipping`, `union station`, `or else`, `1=1 is true in math`, `how to use the UPDATE statement`, tutorial text, forum questions that mention `--` and `;` in code blocks) with annotations of expected soft-only outcomes where applicable.
3. Build `benign-structured.json` samples (real-looking API payloads for common frameworks) and `benign-multipart` samples with filenames (`résumé (1).pdf`, `IMG_2024-10-01.jpg`).
4. Implement the gate test: run every entry through the full detector stack under the Balanced preset at paranoia 1 and 2, in each plausible vector/field-kind context, requiring **zero** block decisions and zero hard matches; soft matches are reported with scores for review.
5. Record exceptions only as documented counter-examples inside rule files, never by removing entries (R-02).
6. Add a CI job that fails on any new false positive and prints the minimal reproducer.
7. Add a procedure for adding real-world reports to the corpus (privacy-scrubbed) with provenance.
8. Document the gate and the policy "fix the rule, never the corpus".
**Deliverables.**
- corpora files, gate test, docs
**Acceptance.**
- A1: corpora meet the size minimums (500 and 400).
- A2: the gate runs across the vector/field-kind matrix and fails on a seeded false positive (meta-test).
- A3: every entry has provenance (original/written for this project).
- A4: no entry is removed without a recorded reason.
- A5: the gate output includes counts and top soft scores.
**Tests.**
- Gate test and meta-tests; end-to-end through the inspect API.
**Notes.** The corpora also feed AC-06 (false-positive baseline) and later regression tests.
