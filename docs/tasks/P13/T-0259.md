### T-0259 · Fuzz targets, corpora and nightly campaign for the engine
`P13` `[QA][SEC]` · deps: T-0243, T-0249 · size: M · owner: qa
**Objective.** Continuously attack the engine with random and structured inputs.
**Steps.**
1. Create fuzz targets: `inspect_request` (structured fuzzing with arbitrary request shapes via `arbitrary`), `normalize_all`, `canon_contexts`, `parse_multipart`, `parse_json`, `parse_xml`, `parse_graphql`, `decompress`, `custom_rule_parse`, `redact`.
2. Seed corpora from fixtures (Class A/B inputs only as inert data) and from previous crashes; minimize corpora periodically.
3. Configure the nightly campaign on the builder (never on the production VPS): 1 hour per target, logging crashes and timeouts to `docs/diagnoses/`; coverage-guided with sanitizer builds.
4. Add the time/memory limits per input (timeouts of 1 s, RSS caps) to detect algorithmic complexity bugs.
5. Add structure-aware dictionaries (SQL keywords, HTML tags, shell binaries) to improve coverage.
6. Create a script to triage crashes into minimized regression tests automatically (`xtask fuzz triage`).
7. Add fuzz stats to the gate reports (executions, coverage, crashes).
8. Document how to run fuzzers locally and interpret results.
**Deliverables.**
- fuzz targets, dictionaries, corpora, nightly config, triage tool
**Acceptance.**
- A1: all targets build and run 60 s in `verify` without crashes.
- A2: nightly campaign has run for at least one night before the gate with zero unresolved crashes.
- A3: every crash found has a regression test.
- A4: dictionaries are checked in and used.
- A5: the triage tool produces minimized reproducers.
**Tests.**
- Meta-test: inject a deliberate panic path in a branch and confirm fuzz detection within the smoke run.
**Notes.** Any crash blocks release (C12.6).
