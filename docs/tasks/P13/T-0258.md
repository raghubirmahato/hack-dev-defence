### T-0258 · Mutation testing and test-quality gates
`P13` `[QA]` · deps: T-0243, T-0246, T-0247, T-0248, T-0252 · size: M · owner: qa
**Objective.** Make sure the test suite would actually catch bugs in the engine.
**Steps.**
1. Configure `cargo-mutants` for `hdd-waf-core` (exclude generated tables and logging), with timeouts and test selection to keep runs practical (nightly on the builder; a sampled subset in `verify`).
2. Run the first full mutation pass and record the score, surviving mutants by module, and equivalent-mutant annotations (documented exclusions with reasons).
3. Kill survivors by writing missing tests (boundary conditions, operator flips, off-by-one), prioritizing scoring, normalization offset mapping, exceptions scope, and custom rule evaluation.
4. Set the gate: mutation score at least 80% (Appendix E4) for `hdd-waf-core`, with module-level minimums (scoring 90%, exceptions 90%, normalizer 80%).
5. Add `cargo-llvm-cov` coverage reporting with a threshold of 85% line coverage for the crate and report uncovered critical paths.
6. Add a mutation-regression check: new code must not reduce the score (diff-based mutation on changed files in CI where feasible).
7. Document how to add tests for survivors.
8. Archive reports with SHA-256.
**Deliverables.**
- mutants configuration, reports, new tests, coverage reports
**Acceptance.**
- A1: the mutation score meets the thresholds or the shortfall has a diagnosis document and a plan.
- A2: coverage ≥ 85% for the crate.
- A3: equivalent-mutant exclusions are documented.
- A4: reports are archived and linked in the gate report.
- A5: the sampled mutation job runs in `verify` within 10 minutes.
**Tests.**
- The mutation and coverage jobs themselves.
**Notes.** Mutation testing is repeated after P14 and P15 add detectors.
