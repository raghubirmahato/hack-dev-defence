### T-0252 · Verdict and event model, evidence extraction and ban intents
`P13` `[DP][API][SEC]` · deps: T-0246, T-0251 · size: L · owner: waf
**Objective.** Produce explainable, privacy-safe results that the proxy, API and UI share.
**Steps.**
1. Finalize `Verdict` (C2.1) and `Match`, `Evidence`, `PolicyBranch`, `BanIntent` types with serde, stable JSON schemas, `non_exhaustive`, and conversion to the `waf_events` row shape and the SSE fragment model.
2. Implement evidence extraction: from the `decoded` view, a window around the match (up to 512 bytes total after redaction) with the match span marked, mapped back to raw offsets, with truncation markers and escape-safe representation (no control characters; bidi controls replaced by visible markers).
3. Implement `BanIntent` creation rules: reason mapping (`waf_hard_hit`, `waf_score`, `honeypot`, `scanner`, `campaign`), scope hints, cross-site context flag copied from request context, explanation of the policy branch.
4. Implement stable `rule_id` plus `rule_version`, `engine_version`, `config_revision` fields in the verdict.
5. Implement deduplication of matches (same rule on duplicate parameters aggregated with counts) and a cap on matches recorded per request (default 20) with an `overflow` marker.
6. Implement size caps and ensure no raw values beyond evidence are retained in the verdict.
7. Provide the JSON representation used by the inspect API and the event stream (versioned).
8. Add golden tests for verdict JSON and evidence rendering with hostile inputs.
**Deliverables.**
- `verdict` module, schemas, tests
**Acceptance.**
- A1: evidence never exceeds 512 bytes and is always escape-safe.
- A2: evidence spans map to correct raw offsets (property test).
- A3: ban intents carry the cross-site flag and policy branch.
- A4: JSON schemas are stable (golden test).
- A5: match overflow is bounded and flagged.
**Tests.**
- Golden/proptest; security: hostile evidence strings.
**Notes.** The UI renders evidence only through `PayloadViewer` (T-0045).
