### T-0248 · Custom rule evaluation
`P13` `[DP][API]` · deps: T-0246 · size: L · owner: waf
**Objective.** Evaluate tenant rules safely and predictably.
**Steps.**
1. Define the match tree evaluation: groups (OR between groups, AND within), fields (path, query, parameter name/value, header, cookie, method, client IP/CIDR via radix trie, country, ASN, user agent, body contains, JSON path, request size, TLS/HTTP version), operators (equals, contains, starts/ends with, matches regex, in list, in CIDR, numeric comparisons, exists), negation, case-insensitivity flag.
2. Compile regexes with the restricted syntax (linear-time), plus Aho-Corasick for large `contains any of` lists, and radix trie for IP/CIDR lists; reject at compile with diagnostics (position, code, suggestion).
3. Implement action semantics: `allow` (terminal skip of further detections; recorded), `block`, `ban` (ban intent), `challenge`, `log`; priorities and short-circuit evaluation order documented.
4. Implement resource budgets per rule (maximum scanned bytes) and per request (maximum rules evaluated), with `BudgetExceeded` flagged and handled by policy (fail closed in block mode for deny rules).
5. Implement GeoIP/ASN trait usage with absence handling (`ERR-WAF-003` at compile if country rules are used without a database).
6. Implement evaluation explanations (which condition matched with values redacted).
7. Implement determinism (stable ordering, no randomness), size caps (rule size 16 KB, list entries 1,000).
8. Test with 300 rules (valid/invalid) and hostile regexes (ReDoS shapes) ensuring compile-time rejection or linear behavior.
**Deliverables.**
- `custom` module, compiler diagnostics, tests
**Acceptance.**
- A1: unsupported constructs are rejected with exact positions.
- A2: hostile regexes complete in bounded time (time-limited test across 200 shapes).
- A3: `allow` rules cannot bypass platform hard bans (platform deny wins by design, tested).
- A4: IP/CIDR lists of 1,000 entries evaluate in under 2 µs.
- A5: explanations never include raw sensitive values.
**Tests.**
- Table (300) / proptest (tree evaluation equals reference interpreter on small domains) / fuzz target on the rule parser.
**Notes.** The control plane rule builder (T-0228) calls the same validation and the same evaluator for dry-runs.
