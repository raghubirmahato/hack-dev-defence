### T-0247 · Exceptions engine
`P13` `[DP][SEC]` · deps: T-0246, T-0226 · size: M · owner: waf
**Objective.** Apply scoped exclusions without weakening rules globally.
**Steps.**
1. Implement the compiled exception structure: per-rule or per-category exceptions with scope matchers (path pattern, methods, vector/field name, CIDR) and expiry timestamps (evaluated against an injected `now`).
2. Implement application order: exceptions remove matching **matches** before scoring; hard matches excepted only if the exception explicitly targets the rule/subtype and scope is narrow (path + field), mirroring the control-plane validation.
3. Record in the verdict which matches were excepted (`excepted_by: exception_id`) so analysts can see what would have happened.
4. Implement performance: exceptions indexed by rule ID and path prefix for O(log n) evaluation; cap per site (200).
5. Implement tests for scoping correctness, expiry edge cases, overlap behavior and the rule that exceptions cannot reduce hard-ban categories on auth endpoints without explicit flag.
6. Implement metrics (`MET-hdd_waf_exceptions_hits_total`).
7. Add property tests: an exception never affects requests outside its scope.
8. Document semantics.
**Deliverables.**
- exceptions module, tests, docs
**Acceptance.**
- A1: out-of-scope requests are never affected (property test over 100k random requests).
- A2: expired exceptions are ignored using the injected clock.
- A3: excepted matches are visible in the verdict explanation.
- A4: hard-match exceptions require explicit narrow scope.
- A5: lookup cost stays within budget for 200 exceptions.
**Tests.**
- Unit/proptest/bench.
**Notes.** Control-plane validation (T-0226) and engine semantics share the same scope matcher crate.
