### T-0239 · `hdd-waf-core` skeleton, public API and purity enforcement
`P13` `[DP][SEC]` · deps: T-0237 · size: M · owner: waf
**Objective.** Define the crate boundary so the engine stays pure, testable and fast.
**Steps.**
1. Define the public API: `Engine::new(Compiled)`, `Engine::inspect(&InspectRequest, &SitePolicy, &mut Scratch) -> Verdict`, `Engine::inspect_response_head/ body_window` hooks for the outbound filter (P21), and `Compiler::compile(RulePacks, SitePolicy) -> Compiled` with deterministic output hashes.
2. Define `InspectRequest` (method, normalized path and raw path, query pairs, headers, cookies, content type, body prefix bytes with `truncated` flag, client context: IP key, country, ASN, browsing context flags from `Sec-Fetch-*`, TLS facts, HTTP version, site/auth-endpoint tags) and `Scratch` (reusable buffers to avoid allocation).
3. Define error and flag types (`InspectFlag`: `Truncated`, `BudgetExceeded`, `OverlongUtf8`, `InvalidUtf8`, `NullByte`, `MultibyteQuote`, `DecodeDepthExceeded`, `ParserLimit`, ...), and `Budget` (max bytes per field, per request, max fields, max decode iterations, max regex scans).
4. Add the purity lint to `xtask verify`: forbid `std::fs`, `std::net`, `std::thread::sleep`, `std::time::SystemTime/Instant` (except in `cfg(test)` and benches), `tokio`, `reqwest` in this crate; check dependency list against an allowlist.
5. Define the stability policy: `Verdict` and `Evidence` are `#[non_exhaustive]` with serde for API use; add a versioned `engine_version` string embedded in events.
6. Create the crate docs with the module map and the invariants above.
7. Create `tests/support` utilities: request builders, hostile string sets, golden verdict snapshots (`insta`).
8. Set up benches skeleton and fuzz target stubs (filled by later tasks).
**Deliverables.**
- `crates/hdd-waf-core` skeleton, lints, docs, test support
**Acceptance.**
- A1: adding `std::fs` or `tokio` to the crate fails `xtask verify`.
- A2: the public API compiles and a trivial inspection returns `Pass` with zero allocations in steady state (alloc counter test).
- A3: `engine_version` changes when compiled rule sets change (hash test).
- A4: docs describe every flag.
- A5: the crate has `#![forbid(unsafe_code)]`.
**Tests.**
- Unit/compile-fail tests for purity; allocation test with a counting allocator in tests.
**Notes.** The control plane uses the same crate for dry-runs, ensuring identical semantics.
