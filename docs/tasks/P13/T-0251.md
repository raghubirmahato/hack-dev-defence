### T-0251 · Field-kind context typing
`P13` `[DP][SEC]` · deps: T-0240 · size: M · owner: waf
**Objective.** Infer what kind of value each field carries to reduce false positives and tighten hard families.
**Steps.**
1. Implement name-based inference with token matching on normalized parameter names (split on `_`, `-`, camelCase, brackets) mapping to `password`, `username`, `email`, `numeric_id`, `search`, `free_text`, `filename`, `header`, `cookie`, `unknown` per the C4.6 tables, with locale-aware synonyms configurable per site (for example `pwd`, `passwd`, `pass`, `contrasena`).
2. Implement overrides: site-declared mappings (S-057) and auth-endpoint declarations take precedence; learned shapes (opt-in) provide type/charset/length hints (`numeric` fields with digits only produce `numeric_id`).
3. Implement value-based hints when names are unhelpful: all digits and short implies numeric; contains `@` and dots implies email-shaped; long natural language implies free text; used only to relax or tighten **soft** weights, never to relax hard families except in the documented password case.
4. Implement the field-kind policy table API (`policy_for(kind, family) -> Hardness`) used by detectors (P14, P15), including the Balanced/Paranoid differences.
5. Implement deterministic behavior and caching of name inference.
6. Add tests with 200 parameter names across languages and frameworks (WordPress, Laravel, Rails, Django, Spring, ASP.NET naming).
7. Document the heuristics and how to override.
8. Add fuzz/property tests for the tokenizer of names.
**Deliverables.**
- `context` module, tables, tests, docs
**Acceptance.**
- A1: 200-name corpus classified as expected (table).
- A2: overrides take precedence and are reflected in verdict explanations.
- A3: password-kind handling matches C4.6 exactly.
- A4: unknown kinds are treated as `search` (documented).
- A5: inference is deterministic and allocation-free in the steady state.
**Tests.**
- Table/proptest; alloc test.
**Notes.** Field kinds are metadata only; hard-family coverage for password fields is not relaxed except for H2 (C4.6).
