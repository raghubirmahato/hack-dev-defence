### T-0249 · Bounded parsers: forms, multipart, JSON, XML and decompression
`P13` `[DP][SEC]` · deps: T-0239 · size: XL · owner: waf
**Objective.** Parse hostile bodies safely and cheaply for inspection.
**Steps.**
1. Implement `application/x-www-form-urlencoded` parsing (duplicates preserved, nested notations, limits) and `multipart/form-data` parsing (vetted `multer` or own streaming parser; boundary validation, maximum 100 parts, 8 MiB per part inspect cap, header limits, filename extraction including `filename*` RFC 5987 decoding, duplicate `Content-Disposition` tolerance handling by inspecting all variants).
2. Implement JSON parsing with a streaming tokenizer: depth cap 32, key/length caps, big-number handling, duplicate keys preserved as separate occurrences, NaN/Infinity tolerance flags, BOM and encoding detection (UTF-8/16/32 sniffing), and extraction of keys and string leaves with JSON path labels.
3. Implement XML parsing with a tokenizer that **never** resolves entities or DTDs: detect `DOCTYPE`, `ENTITY`, `SYSTEM`, `PUBLIC`, `xi:include`, `xsl:` and report them as signals; extract text, attributes, CDATA with depth cap and size cap; protect against billion-laughs by never expanding entities and by counting entity declarations.
4. Implement bounded decompression for `gzip`, `deflate`, `br`, `zstd` (and stacked encodings up to 2 layers) with output cap 10 MiB, ratio cap 20:1, time budget, and streaming to the extractor; reject invalid combinations (`Content-Encoding` on multipart parts).
5. Implement chunked body reassembly interplay: the engine receives the reassembled prefix; chunk-boundary payload tests verify detection.
6. Implement content sniffing helpers (JSON/XML/form detection) for confusion defense.
7. Implement archive peeking for uploads (zip/tar/gzip headers only: entry names, uncompressed sizes, entry count) with strict caps (used by T-0297).
8. Create fuzz targets per parser and a corpus of malformed and malicious samples (including Class C shapes used only as inert test inputs bounded by limits).
**Deliverables.**
- `parsers` modules, fuzz targets, corpora, tests
**Acceptance.**
- A1: XML with a billion-laughs DTD is flagged and consumes bounded memory/time (limits asserted).
- A2: zip bombs and gzip bombs are rejected by ratio/size caps without full expansion.
- A3: JSON depth 33 is rejected with `ParserLimit`.
- A4: duplicate and tricky multipart headers are all inspected (table tests).
- A5: parsers are panic-free under fuzz.
**Tests.**
- Table/fuzz/property tests; memory/time bound tests.
**Notes.** Class C resource-exhaustion shapes exist only as small descriptors that trigger limits, never as large real bombs.
