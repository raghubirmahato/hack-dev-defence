### T-0244 · Prefilter and signature engine (Aho-Corasick plus regex automata)
`P13` `[DP]` · deps: T-0242 · size: XL · owner: waf
**Objective.** Make scanning fast: cheap token prefilter, then linear-time pattern sets.
**Steps.**
1. Implement the compile pipeline: rule definitions to (a) an Aho-Corasick automaton over required literal tokens per rule (extracted by a literal-extraction pass from the regex AST) and (b) per-group `regex-automata` sets (DFA/hybrid with size limits) for verification; groups by category and context so a field scans only relevant sets.
2. Implement size and complexity budgets at compile time: maximum DFA states per group (reject or fall back to the lazy/hybrid engine with a memory cap), maximum pattern length, total compiled memory per site (cap by plan), and reporting of the heaviest rules.
3. Implement the scan API: `scan(field_view, contexts, scratch) -> SmallVec<Match>` with early exit for hard matches when configured, per-request regex-scan budget (maximum bytes scanned across all sets) and `BudgetExceeded` handling.
4. Implement hot swap: compile in a background task off the hot path, validate against the self-test corpus (rule examples and counter-examples), then publish via `ArcSwap`; compile failures keep the last good set.
5. Implement match metadata: rule ID, group, start/end offsets in the scanned view, mapped back to raw offsets via the normalizer map.
6. Implement caching: LRU cache of verdicts keyed by (field hash, context, ruleset hash) for repeated identical values (headers like `User-Agent`) with strict size limits and TTL, safe because the engine is pure.
7. Provide a benchmark suite with realistic traffic corpora and adversarial inputs (long runs of near-matches).
8. Document engine limits and the rationale for linear-time-only.
**Deliverables.**
- `signatures` module, compiler, benches, tests, docs
**Acceptance.**
- A1: no pattern can cause super-linear scan time (property test with adversarial strings across all shipped rules).
- A2: compile rejects patterns exceeding budgets with precise errors.
- A3: hot swap does not drop requests and applies within 2 s of publication (integration with T-0211).
- A4: p50 scan time for a 200-byte field across all default rules is under 20 µs on the builder.
- A5: matches map back to correct raw offsets for 1,000 randomized encoded inputs.
**Tests.**
- Property/adversarial tests; benchmarks; unit: literal extraction correctness vs regex semantics (differential with plain `regex`).
**Notes.** Backtracking engines (PCRE) are never used.
