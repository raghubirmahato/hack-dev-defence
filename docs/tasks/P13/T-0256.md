### T-0256 · Performance engineering and global inspection budgets
`P13` `[DP]` · deps: T-0244, T-0246 · size: L · owner: waf
**Objective.** Meet the latency budgets (inspection p50 < 1 ms) and protect the process from overload.
**Steps.**
1. Build criterion benchmarks for typical requests (GET with 5 params, login POST, JSON API POST 2 KB, multipart 100 KB) and adversarial ones (long near-matches, deep nesting, many parameters), reporting p50/p99 and throughput.
2. Optimize hot paths: avoid allocations (SmallVec, reusable scratch), single-pass normalization where possible, lazy canonical views (only when prefilter hits), early exits for obviously benign fields (alphanumeric-only strings skip heavy scans), and cache identical header values.
3. Implement per-request budgets (CPU time proxy via scanned-bytes and operation counters, since wall-clock is forbidden in the pure crate) and a **global inspection budget** in the proxy (semaphore of concurrent inspections sized from cores; queue limits) with documented shed policy (fail closed in block mode: 503 with Ray ID; monitor mode: pass and mark `skipped_budget`).
4. Measure memory per in-flight inspection and enforce limits (cap scratch size, 1 MiB).
5. Add regression budgets to CI: benchmark results compared with stored baselines (criterion), failing on > 20% regression for key benchmarks.
6. Profile with flamegraphs on the builder and record findings; optimize the top three hotspots.
7. Validate tail latency under concurrency with a load test (functional profile only, builder-local).
8. Document tuning knobs.
**Deliverables.**
- benches, budgets, optimizations, perf report
**Acceptance.**
- A1: inspection p50 under 1 ms and p99 under 5 ms on the reference corpus (builder-class hardware recorded).
- A2: no steady-state heap growth per request (alloc counter).
- A3: overload behavior follows the shed policy (test by saturating the budget).
- A4: CI detects a deliberately slowed function (meta-test).
- A5: scratch memory per request stays under 1 MiB.
**Tests.**
- Criterion benches; load tests; allocation tests.
**Notes.** Hardware used for numbers is recorded; claims in docs cite the AC-24 measurements only.
