### T-0323 · Org-wide propagation and platform-wide global jail promotion
`P16` `[DP][API][SEC]` · deps: T-0317, T-0320 · size: M · owner: dp
**Objective.** Share intelligence about clearly malicious sources across domains and tenants responsibly.
**Steps.**
1. Implement org-level propagation: with `propagate_to_org` enabled, a hard-hit ban on one domain creates an org-scope ban covering the org's other domains (still subject to cross-site rules), displayed as scope "organization" with the originating domain.
2. Implement **global promotion** (default on in `saas`, off in `owner_only`): when the same key receives hard-hit bans in ≥ 3 distinct orgs (excluding orgs with the same owner/billing identity) within 60 minutes, create a platform-scope ban at the ladder TTL with evidence listing the contributing ban IDs (no tenant identifiers shown to other tenants).
3. Implement privacy: tenants never see which other tenants were attacked; they see "Platform-wide ban" with a generic explanation and an appeal path; platform admins see full evidence.
4. Implement safeguards: never promote never-ban keys, require hard-hit reasons only (not rate-limit bans), cap global ban TTL growth (max 7 d unless platform admin extends), allow platform admins to opt out specific ASNs/keys (shared CGNAT blocks flagged with collateral estimates and require manual review before promotion for keys in CGNAT/mobile ASNs).
5. Implement appeal and unban behaviors for global bans (platform admin only for unban).
6. Implement metrics and alerts (`global_jail_promoted`), audit events.
7. Add tests with simulated multi-tenant attacks (three orgs, same attacker).
8. Document the policy and tenant disclosures in the privacy page (T-0101).
**Deliverables.**
- propagation and promotion logic, tests, docs
**Acceptance.**
- A1: three-org hard-hit scenario promotes to a platform ban; two orgs do not.
- A2: tenants cannot discover other tenants' identities from global bans (API/UI inspection test).
- A3: CGNAT-class keys require manual review.
- A4: promotion respects never-ban and excludes same-owner orgs.
- A5: platform admins can revoke global bans with audit.
**Tests.**
- Multi-tenant integration; privacy inspection; unit: promotion rules.
**Notes.** Global jail is also visible and manageable in the admin panel (S-106, T-0424).
