### T-0322 · Ban stream contract for the host agent and enforcement acknowledgments
`P16` `[DP][OPS]` · deps: T-0316 · size: M · owner: infra
**Objective.** Define the protocol the kernel firewall agent consumes, so P25 only implements enforcement.
**Steps.**
1. Define the `BanStream` contract: Redis stream/pubsub messages (`ban`, `unban`, `snapshot_begin/end`, `reconcile_request`) with fields (key, family, expiry, scope, reason class, revision), signed with an internal HMAC key so a compromised Redis writer cannot inject arbitrary kernel rules; message size caps and rate limits.
2. Define acknowledgments: the agent writes back `hdd:fw:ack:{revision}` with status and timing so the control plane can display propagation per layer; define missing-ack timeouts and states (`pending`, `applied`, `failed`, `unsupported`).
3. Define reconcile semantics: the agent every 30 s requests/derives the authoritative active set (from Postgres via a read-only role or Redis snapshot) and diffs against the kernel set; failures are metrics and alerts.
4. Implement a `NoopEnforcer` reference consumer in the repository that acknowledges messages (used in tests and when no kernel backend is available) and a contract test suite that any real enforcer must pass.
5. Define restricted addressing: kernel enforcement applies to destination ports 80/443 and UDP 443 only; never to 22, 53; never to keys in the never-ban list (agent double-checks against the list).
6. Define capacity limits: maximum kernel set size (default 100k), eviction rules consistent with L7 (agent reports overflow).
7. Document the contract and security model (signing, least privilege, no shell).
8. Write chaos tests for message loss, duplication, reordering, and replay (replay protection via revision monotonicity and expiry).
**Deliverables.**
- contract docs, message types in `hdd-common`, `NoopEnforcer`, contract tests
**Acceptance.**
- A1: forged (unsigned) messages are rejected by the reference consumer.
- A2: duplicated and reordered messages converge to the right state (property test).
- A3: acknowledgments appear in the control plane propagation view.
- A4: never-ban keys are refused by the agent logic even if present in a message.
- A5: the contract suite is runnable against any `Enforcer` implementation.
**Tests.**
- Property/chaos tests; contract suite.
**Notes.** The nftables implementation and XDP loader land in P25 (T-0463 to T-0467).
