### T-0315 · Client IP resolution and IP keys
`P16` `[DP][SEC]` · deps: T-0208, T-0262 · size: M · owner: dp
**Objective.** Determine the true client address safely, and derive stable ban keys.
**Steps.**
1. Implement `resolve_client_ip(peer, headers, trusted_cidrs) -> ClientIp`: the TCP peer unless the peer is in the site/platform trusted proxy list (`upstream_cdn.trusted_cidrs`, `HDD_TRUSTED_PROXIES`), in which case parse `X-Forwarded-For` from right to left to the first untrusted entry, validate each entry (IP syntax, no ports or garbage), cap chain length (20), and ignore `Forwarded`/`X-Real-IP` unless the peer is trusted and the header is configured; default trusts nothing.
2. Strip inbound `X-Forwarded-*`, `Forwarded`, `X-Real-IP`, `HDD-*` headers from untrusted peers before setting HDD's own (also for h2).
3. Implement IP key derivation: IPv4 `/32`; IPv6 to configurable prefix (default `/64`, options `/56`, `/48`, `/128`), IPv4-mapped IPv6 collapsed to IPv4, zone IDs rejected, canonical text and compact binary forms.
4. Provide `ClientIp` with both the address (for display and kernel enforcement) and key (for lookups), plus `source: Peer | Xff(depth)` for audit.
5. Handle PROXY protocol (v1/v2) as an opt-in listener mode for operators behind L4 load balancers, with an allowlist of sender addresses; reject unsolicited PROXY headers otherwise.
6. Write spoofing tests: untrusted peers sending `X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `HDD-Connecting-IP`; chained headers with mixed trusted/untrusted hops; IPv6 forms; malformed lists.
7. Add property tests: resolved IP is never an entry to the right of the first untrusted hop; keys are stable under textual variations.
8. Document operational guidance for CDNs and load balancers.
**Deliverables.**
- `hdd-common::clientip`, listener support for PROXY protocol, tests, docs
**Acceptance.**
- A1: spoofed headers from untrusted peers never influence the resolved IP.
- A2: with a trusted CDN peer, the right-to-left rule yields the expected client in 30 table cases.
- A3: IPv6 addresses within the same /64 map to one key; different /64s do not.
- A4: unsolicited PROXY protocol headers are rejected.
- A5: resolution is allocation-free in the common case (alloc test).
**Tests.**
- Table (80) / proptest / fuzz on header parsing / alloc test.
**Notes.** AC-22 verifies this live with spoofed headers from the runner.
