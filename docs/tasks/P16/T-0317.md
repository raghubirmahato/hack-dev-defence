### T-0317 · Ban policy engine: intent to ban, TTL ladder, scopes and attack diversity
`P16` `[DP][SEC]` · deps: T-0316, T-0273 · size: L · owner: dp
**Objective.** Implement C6.4 so all ban sources share one decision point.
**Steps.**
1. Implement the `BanPolicy` service in `hdd-proxy` consuming `BanIntent`s from detection (hard hits, honeypots, scanners, rate limiter, credential stuffing, campaigns, shield) and producing `Ban`/`NoBan` with reasons, following the C6.4 decision order: never-ban check, tenant allowlist, mode check, cross-site rule, scope selection, ladder TTL.
2. Implement offence counters (`hdd:offence:{org}:{ip_key}` with TTL = decay window, default 30 days) updated atomically (Redis Lua) with local fallback; TTL ladder step = min(offence count, ladder length) using the site's `ban_ttl_ladder` (default 1 h, 6 h, 24 h, 7 d), test bans 60 s (acceptance flag via signed header or runner token), rate-limit bans 10 min first then ladder.
3. Implement the **attack-diversity rule** (V15): maintain per-key set of distinct categories in a 10-minute window (small bitset in Redis/local); three or more categories → ban intent `attack_diversity` even if each was soft.
4. Implement cross-site counter: cross-site hard hits increment a separate counter and convert to a rate-limit ban at 3 per 60 s (C6.5).
5. Implement scope selection: site-level default; org-level propagation when `propagate_to_org` is on and the reason is a hard hit; platform-level only via promotion (T-0323).
6. Implement idempotency: repeated intents for an already banned key extend or keep the existing ban per rule (do not increment offences for requests rejected by the jail).
7. Implement explainability: `PolicyBranch` identifiers, evidence references (Ray ID, rule), config revision.
8. Write the decision table tests (reuse T-0273 rows plus ladder, scope, diversity and cross-site conversions), property tests, and an end-to-end test with real Redis.
**Deliverables.**
- `BanPolicy` service, Lua scripts, tests, docs `docs/BAN-POLICY.md` additions
**Acceptance.**
- A1: the ladder yields 1 h, 6 h, 24 h, 7 d for repeated hard hits, with decay after the quiet window (test clock).
- A2: three distinct categories within 10 minutes produce an attack-diversity ban.
- A3: cross-site hits never ban until the 3-in-60-s conversion.
- A4: jail-rejected requests do not increment offence counters.
- A5: policy decisions carry branch IDs present in the docs table.
**Tests.**
- Table (150) / proptest / integration with Redis; chaos with Redis down (local fallback).
**Notes.** Platform-wide promotion is T-0323.
