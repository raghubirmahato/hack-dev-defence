### T-0325 · Ban evasion defenses: campaign detector and fingerprint-linked escalation
`P16` `[DP][SEC]` · deps: T-0317, T-0306 · size: L · owner: dp
**Objective.** Defend against attackers who rotate IPs.
**Steps.**
1. Implement the campaign detector: for each (site, endpoint pattern, signature id) maintain a bounded set (HyperLogLog) of distinct IP keys producing hard or soft matches in a 10-minute window; when distinct keys ≥ N (default 20) open a `campaign_cluster` row, mark the (site, endpoint) as **elevated**, alert owners and platform, and apply the campaign policy.
2. Define campaign policies: challenge all *new* clients (no clearance cookie, no prior good sessions) on that endpoint; tighten rate limits for that endpoint; optionally block the signature entirely for new keys; auto-expire after 30 minutes of calm.
3. Implement fingerprint-linked escalation: after a hard-hit ban, remember a salted hash of (header order, selected header values, UA, accept-language) and the TLS fingerprint if available for the ban duration; new IP keys presenting the same fingerprint **and** the same attack signature are challenged first and banned on the second hit; fingerprints alone never ban.
4. Implement IPv6 rotation defense: when ≥ 5 distinct /64s inside the same /48 (or /56) are banned within 60 minutes, escalate to a ban of the covering prefix (/56 or /48) for a short TTL with owner notification, never above the prefix of a known ISP aggregate without review (ASN-based allowlist of broad prefixes).
5. Implement residential-proxy handling: no per-IP bans for low-evidence cases; rely on challenge and endpoint hardening.
6. Provide UI: campaign view in the security overview (active campaigns, endpoints, counts, actions, end), and events grouped into incidents.
7. Add tests simulating rotating-IP attacks (builder-local multi-source via loopback aliases/netns) and measuring detection time.
8. Document limitations.
**Deliverables.**
- campaign detector, escalation logic, UI, tests
**Acceptance.**
- A1: 30 rotating sources hitting one endpoint with the same payload shape open a campaign within the window and trigger challenge for new clients.
- A2: legitimate users with clearance cookies are unaffected during a campaign.
- A3: fingerprint-only matches never ban.
- A4: IPv6 prefix escalation respects ASN safeguards.
- A5: campaigns auto-close after calm and restore normal policy.
**Tests.**
- Simulation tests (netns/aliases); unit: HLL thresholds and window logic; UI tests.
**Notes.** Implements V16 and ATK-208.
