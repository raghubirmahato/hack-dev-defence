### T-0326 · Shared-address (CGNAT) collateral mitigation
`P16` `[DP][SEC][UI]` · deps: T-0317, T-0325 · size: M · owner: dp
**Objective.** Reduce harm to innocent users behind shared addresses.
**Steps.**
1. Implement shared-address indicators: ASN class lists (mobile carriers, universities, large ISPs with CGNAT, corporate egress, Tor exits, public proxies/VPNs — from `hdd-intel` data when available), observed behavior (many distinct user agents and session cookies per key with legitimate traffic in the last 24 h), reverse DNS hints.
2. Implement the site option `shared_address_policy`: `ban` (default for keys without indicators), `challenge_first` (soft-score blocks challenge instead of ban for flagged keys), `short_ban` (hard-hit bans for flagged keys limited to 5 minutes and logged), `review` (queue for owner review).
3. Implement dynamic indicators: if a key has many distinct *clean* sessions (cleared via challenge or authenticated traffic) in the last hour, treat as shared and apply the policy.
4. Display collateral risk in ban dialogs (T-0321) and events with explanation and recommended action; report an estimated number of distinct sessions possibly affected after a ban (from sample data).
5. Implement "protect this network" quick action to add an allowlist with expiry or change policy.
6. Implement tests with scripted shared-address scenarios (many clean sessions plus one attacker).
7. Document tradeoffs openly (an attacker behind CGNAT may get softer treatment; hard hits still block each request).
8. Add metrics for shared-address decisions.
**Deliverables.**
- indicators, policy options, UI hooks, tests
**Acceptance.**
- A1: with `challenge_first`, soft-score blocks on shared keys produce challenges, not bans.
- A2: hard hits from shared keys still get blocked (403) and banned for the short TTL when `short_ban`.
- A3: indicators come from data sources (no hand-wired lists in logic) and unknown ASNs default to normal policy.
- A4: collateral hints appear in the UI.
- A5: policy is documented with the tradeoffs.
**Tests.**
- Scenario tests; unit: indicator computation; browser: hints.
**Notes.** Requires GeoIP/ASN data for ASN-class indicators; otherwise only behavioral indicators apply.
