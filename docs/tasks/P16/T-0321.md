### T-0321 · IP jail UI (S-067) and ban detail (S-068)
`P16` `[UI]` · deps: T-0320, T-0045 · size: L · owner: ui
**Objective.** Let analysts see, understand and manage bans.
**Steps.**
1. Implement the jail table with IP chip (country, ASN), reason pill and rule, scope badge, created, countdown badge (static text for reduced motion), hits since ban, source (auto/manual), filters, saved views, density, export, and bulk unban with a confirmation listing counts.
2. Implement the manual ban form with live validation, TTL presets, self-lockout warning, collateral hint panel (ASN class, shared-address indicators, distinct session counts), and typed confirmation for wide ranges.
3. Implement ban detail (S-068): offence history timeline, TTL ladder step with the next TTL, original evidence (redacted, `PayloadViewer`), policy branch, propagation status per layer (L7 nodes, Redis, kernel, XDP) with polling, related events link, and unban/extend/convert-to-allow actions.
4. Implement "Unban" feedback: "Effective within 2 seconds", then a verification status update; failures show actionable errors.
5. Implement empty, loading, error states and the mass-ban anomaly banner (T-0331).
6. Implement keyboard operability, announcements for bulk results, and responsive stacked view.
7. Implement permission-aware controls and BOLA tests.
8. Add visual baselines and accessibility checks.
**Deliverables.**
- screens, partials, tests
**Acceptance.**
- A1: unban shows verified propagation status within 2 s in the test environment.
- A2: wide manual bans require typed confirmation and show collateral hints.
- A3: countdowns have static textual equivalents and do not spam assistive tech.
- A4: bulk operations announce results politely.
- A5: the screens pass axe and keyboard checks.
**Tests.**
- Browser flows; integration; visual regression.
**Notes.** Event drawer links (S-066) deep-link to ban detail.
