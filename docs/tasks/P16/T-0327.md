### T-0327 · Self-lockout prevention across ban, access and rule changes
`P16` `[API][UI][SEC]` · deps: T-0320, T-0232 · size: M · owner: sec
**Objective.** Make it hard for any user to ban themselves or their own infrastructure.
**Steps.**
1. Implement a shared `SelfLockoutGuard` service: given a proposed change (ban, access entry, rule, geo policy, mode change), compute whether the acting user's current IP key (as HDD resolves it for the request), session country/ASN, the org's declared admin CIDRs, HDD platform IPs and the site's origin IP would be affected, and produce a structured preview (affected keys, match explanation).
2. Integrate with all mutation paths: bans (manual), access lists, custom rules (evaluating the rule against the caller's recent requests), geo/ASN policies, mode switches (using recent would-block events from the caller's IP), DNS safety (platform zone), origin lockdown (warn that HDD admin access paths rely on SSH tunnel).
3. Define response semantics: `ERR-WAF-007`/`ERR-BAN-002` with preview and `acknowledge_self_*` flags; for platform/never-ban keys no acknowledgment is possible.
4. Implement the acceptance-runner special case: the runner IP is bannable and tests rely on it; the guard recognizes runner sessions via the signed runner token header and allows runner self-bans with short TTL only.
5. Implement UI components: blocking warning dialogs with the preview, "Run as dry-run first" links, and undo toasts after confirmed actions.
6. Implement tests for each mutation path with the caller's IP matching, and for IPv6 /64 equivalence.
7. Implement audit entries recording acknowledged self-affecting changes.
8. Document recovery paths (break-glass `hddctl unban`, safe mode).
**Deliverables.**
- guard service, integrations, UI components, tests
**Acceptance.**
- A1: each mutation path refuses self-affecting changes without acknowledgment.
- A2: never-ban/platform keys cannot be acknowledged.
- A3: runner-specific rules work only with the signed token and TTL ≤ 60 s.
- A4: previews list affected keys accurately.
- A5: acknowledged actions are audited.
**Tests.**
- Table tests across paths; browser: dialogs; security: header spoofing cannot fake the runner token.
**Notes.** R-19 realized.
