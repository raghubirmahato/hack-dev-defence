### T-0318 · Never-ban list and tenant allowlist semantics
`P16` `[DP][SEC][API]` · deps: T-0317 · size: M · owner: sec
**Objective.** Make it hard to ban the wrong addresses and clear what allowlisting means.
**Steps.**
1. Implement the platform never-ban list: loopback, `admin_cidrs`, platform public IPs, origin IPs of managed sites, provider health-probe ranges from the profile, DNS secondary addresses, and operator-added entries (`HDD_NEVER_BAN_CIDRS`, platform admin UI); **excluded by design:** the acceptance runner IP (preflight enforces).
2. Implement tenant allowlist entries (`access_entries` with action allow): behavior defined as (a) bypass jail and rate limiter, (b) inspection still runs and records `would_block` in monitor-style (no enforcement), unless `skip_inspection=true` (explicit risk acknowledgment), (c) never create bans for these keys.
3. Implement precedence rules: platform deny/global jail > tenant allow? Decision: **platform never-ban beats everything** (they can't be banned by anyone), tenant allow beats tenant deny at equal specificity, platform global bans override tenant allowlists only for abusive hard hits across tenants (documented; the key is also protected if in never-ban).
4. Implement the safety event: a hard hit from a never-ban key emits a critical `never_ban_attack_attempt` (possible compromise of a trusted host) and alerts owners/platform admins once per hour per key.
5. Implement matcher structures (radix tries) for fast lookup, compiled into the snapshot, with the same matcher crate used by the control-plane "Test an IP" tool (T-0232).
6. Implement API/UI hooks for platform never-ban management (T-0424) with runner-IP guard.
7. Add tests for precedence matrices (60 cases) and for IPv4/IPv6 CIDR edge cases.
8. Document semantics and risks of `skip_inspection`.
**Deliverables.**
- matchers, policy integration, tests, docs
**Acceptance.**
- A1: never-ban keys are never banned by any path (property test over random intents).
- A2: tenant allowlisted keys with inspection on record `would_block` and are not blocked.
- A3: `skip_inspection=true` entries require the acknowledgment and are shown prominently.
- A4: hard hits from never-ban keys raise the critical event with rate limiting.
- A5: the runner IP is rejected from the never-ban list by validation.
**Tests.**
- Table/proptest; integration; unit: radix trie correctness against a naive implementation.
**Notes.** Anti-self-harm baseline (C9.2).
