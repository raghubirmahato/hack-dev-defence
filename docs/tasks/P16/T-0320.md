### T-0320 · Ban APIs, events and audit
`P16` `[API][SEC]` · deps: T-0317, T-0125 · size: L · owner: api
**Objective.** Provide complete, safe ban management endpoints.
**Steps.**
1. Implement `GET D/bans` and `GET O/bans` (filters: key, reason, scope, source, created range, expiring soon, rule, category), `GET D/bans/{ip}` (accepts address or /64 key), `POST D/bans` (manual ban: key/CIDR up to /24 IPv4 or /48 IPv6 with typed confirmation for wider, TTL options, reason note), `POST D/bans:bulk`, `DELETE D/bans/{ip}` (404 if not banned), with permissions (`ban.read`, `ban.create`, `ban.delete`).
2. Implement self-lockout protection: manual bans matching the acting user's current IP/session IP, never-ban entries, platform IPs or the origin return `ERR-BAN-002` unless `acknowledge_self_ban=true` (and still never for never-ban keys).
3. Implement unban propagation verification: the DELETE returns after local+Redis updates, then returns a `propagation` object (status per layer: local nodes acknowledged via pub/sub echo, kernel set (once P25), XDP) with a poll endpoint; target completion within 2 s.
4. Implement ban evidence retrieval and the collateral-hint endpoint (`GET D/bans/collateral-hint?ip=`: ASN class, rDNS class, distinct session counts observed from that key in the last 24 h, CGNAT/mobile indicators).
5. Implement export (CSV with formula protection) and idempotency for creates.
6. Implement audit events (`AUD-ban.*`), metrics, OpenAPI.
7. Implement rate limits and quotas on manual bans (max 10,000 active manual bans per org).
8. Add BOLA and permission tests (analyst can ban; viewer cannot).
**Deliverables.**
- endpoints, DTOs, tests
**Acceptance.**
- A1: DELETE of a non-banned key returns 404 (`ERR-BAN-001`).
- A2: self-ban attempts are refused without acknowledgment and always refused for never-ban keys.
- A3: unban becomes effective on all nodes within 2 s (measured).
- A4: IPv6 addresses within a banned /64 are matched by DELETE of any member address or the key.
- A5: BOLA suite shows no cross-tenant access.
**Tests.**
- Integration (multi-node); table tests of validation; security tests.
**Notes.** Platform-wide ban endpoints are in P22.
