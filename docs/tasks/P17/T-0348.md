### T-0348 · Threat-intel feed engine (platform-managed)
`P17` `[OPS][SEC][API]` · deps: T-0346 · size: M · owner: ops
**Objective.** Operate feeds safely at the platform level.
**Steps.**
1. Implement feed definitions (`threat_feeds`: key, URL, format, schedule, max bytes, signature policy, enabled, license note) with SSRF-guarded fetch through the egress client and exact host allowlisting (operator must add the host).
2. Implement the scheduler and fetcher in `hdd-worker`: conditional requests (ETag/Last-Modified), retry with backoff, size and time limits, parsing in a sandboxed task with memory caps, signature/checksum verification (minisign for signed feeds), and atomic publication through the config bus.
3. Implement per-feed metrics (age, entries, last error), alerting on failures and staleness, and an admin API (T-0426 UI).
4. Implement entry expiry (feeds can supply TTLs; otherwise default 24 h) and size caps per feed (default 1M entries).
5. Implement a dry-run import mode (parse and report counts without publishing).
6. Provide a catalog doc with well-known feed candidates **without bundling any** (operator chooses; examples include abuse-focused lists and Tor exit lists) and licensing cautions.
7. Test with a local feed server producing edge cases (huge, malformed, duplicates, slow, redirects).
8. Document operational guidance.
**Deliverables.**
- feed engine, admin API, tests, docs
**Acceptance.**
- A1: redirects to non-allowlisted hosts are refused.
- A2: slow/huge feeds are cut off by limits without affecting the platform.
- A3: bad signatures prevent publication.
- A4: dry-run reports entries without publishing.
- A5: metrics and alerts exist for stale feeds.
**Tests.**
- Integration with local feed server; fuzz parsers.
**Notes.** The admin UI for feeds is T-0426.
