### T-0341 · Verified bots: forward-confirmed reverse DNS and published ranges
`P17` `[DP][SEC]` · deps: T-0340, T-0009 · size: M · owner: dns
**Objective.** Let legitimate crawlers pass and fake crawlers fail.
**Steps.**
1. Implement the verification pipeline: for requests claiming a known crawler UA (Googlebot, Bingbot, DuckDuckBot, Applebot, Baiduspider, YandexBot, Slurp, facebookexternalhit, LinkedInBot, Twitterbot and operator-added ones), do a PTR lookup of the client IP, check the domain suffix list for that crawler, then forward-resolve the PTR hostname and require the original IP to appear (FCrDNS), caching results (positive 24 h, negative 1 h) per IP with bounded cache.
2. Implement optional IP-range validation using the vendors' published ranges when the operator allowlists their fetch locations (egress); store ranges as signed/checksummed data with expiry.
3. Implement asynchronous verification so the request path does not block: first request from an unknown claimant is treated per policy (default: allow-with-log for 1 request while queueing verification, then challenge on repeat if unverified); verification workers rate-limited (50 lookups/s) with a bounded queue and timeouts (2 s).
4. Implement failure handling: DNS errors → treat as unverified (fail closed for the claim) but do not ban; fake crawlers (claim + failed FCrDNS) are class `automation_suspected` and are challenged.
5. Provide the owner test tool (S-062): input IP/UA → shows verification steps and result (DNS only; the tool never sends requests to the IP).
6. Provide metrics and cache stats.
7. Test with local DNS servers simulating PTR/A records for good and bad crawlers and spoofers.
8. Document supported crawlers and extension.
**Deliverables.**
- verification module, caches, tool endpoint, tests
**Acceptance.**
- A1: a spoofed Googlebot UA from a random IP is challenged after failing FCrDNS.
- A2: a valid crawler (simulated PTR chain) passes and is cached.
- A3: DNS failures do not ban and are retried later.
- A4: the verification queue is bounded and rate limited.
- A5: the owner tool performs no HTTP to the tested IP.
**Tests.**
- Integration with local DNS; unit: suffix matching; load test of the queue.
**Notes.** ATK-201.
