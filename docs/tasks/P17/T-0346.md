### T-0346 · IP reputation: local scores, Tor/VPN/datacenter lists and feed ingestion
`P17` `[DP][SEC][OPS]` · deps: T-0009, T-0317 · size: L · owner: sec
**Objective.** Build the reputation data layer used by bot scoring and policy.
**Steps.**
1. Implement the `hdd-intel` reputation store: local reputation score per IP key built from events (hard hits, bans, honeypots, challenge failures) with exponential decay (half-life default 7 days), bounded size (500k keys, LRU by low score), and exposure as a feature for scoring and an optional policy (challenge above threshold).
2. Implement list ingestion: Tor exit lists, public proxy/VPN/datacenter ranges, and operator-enabled threat feeds from `threat_feeds` (format adapters: plain CIDR list, CSV, JSON), downloaded by the worker through the egress client with size caps, checksum or signature verification, scheduled refresh, validation (CIDR parsing, count limits), expiry per entry, and atomic swap into compiled radix tries.
3. Implement feed provenance and licensing metadata; refuse unknown-license feeds unless the operator accepts explicitly; record `UNVERIFIED(capability_not_supplied)` when no feeds are configured.
4. Implement policies per site and per list (allow, log, challenge, block) with defaults: Tor/VPN allow, datacenter challenge only on auth endpoints and signup, threat feeds log (block opt-in), local reputation challenge above 80.
5. Implement explainability: events show which list matched (name, age).
6. Implement staleness handling (stale lists beyond max age are ignored with alert).
7. Test ingestion with fixtures and with a local feed server serving good, malformed and oversized data.
8. Link ATK-202 to ATK-204.
**Deliverables.**
- reputation store, ingestion pipeline, tests
**Acceptance.**
- A1: malformed or oversized feeds are rejected without replacing the current list.
- A2: list lookups cost under 200 ns p99 for 1M CIDRs.
- A3: stale lists are ignored and alerted.
- A4: local reputation decays per the half-life (test clock).
- A5: policies apply per site and are explained in events.
**Tests.**
- Unit/integration/benchmark; fuzz on feed parsers.
**Notes.** Defaults avoid blocking Tor/VPN users broadly.
