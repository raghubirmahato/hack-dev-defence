### T-0340 · Bot scoring engine
`P17` `[DP][SEC]` · deps: T-0306, T-0307, T-0333 · size: L · owner: waf
**Objective.** Combine weak signals into explainable bot classes with owner-controlled policy.
**Steps.**
1. Implement feature extraction per request and per client key window: header completeness/consistency vs UA family (browser UAs should send `Accept`, `Accept-Language`, `Accept-Encoding`, `Sec-Fetch-*` on modern versions), header order fingerprint vs known browser families (table versioned in packs), cookie support after challenge, request timing regularity (coefficient of variation of inter-request times), path diversity/entropy, 404 ratio, referrer patterns, asset-fetch behavior (browsers fetch CSS/JS; scripts do not), HTTP/2 SETTINGS fingerprint (when available), TLS fingerprint family (T-0342), reputation (T-0346), ASN class (T-0347).
2. Implement scoring 0 to 100 with documented weights and caps, hysteresis, per-class thresholds (`human_likely` < 20, `unknown` 20 to 49, `automation_suspected` 50 to 79, `malicious` ≥ 80 or hard indicators), and class overrides (scanner, honeypot hit → `malicious`).
3. Implement actions per class from the site policy (T-0231): allow, log, challenge, block, block-and-ban; apply only to configured scopes (all paths or auth endpoints and sensitive paths) to limit blast radius; verified bots bypass.
4. Implement explanation output (top contributing features) for events and the UI.
5. Implement privacy-aware windows (bounded in-memory sketches per key, 15 minutes), no persistent per-visitor profiles beyond ban evidence.
6. Evaluate on replayed benign traffic corpora (mainstream browsers, mobile, API clients, monitoring tools) and attack tool traffic; target precision/recall report; tune thresholds without using held-out sets.
7. Implement tests for score monotonicity and caps.
8. Document features and limitations (spoofable signals, fingerprint drift).
**Deliverables.**
- scoring engine, packs for header-order tables, tests, evaluation report
**Acceptance.**
- A1: benign traffic replays (browser/mobile/API/monitoring) produce zero blocks and challenge rate under 0.5% at defaults.
- A2: scanner traffic classes score `malicious`.
- A3: explanations list the top features deterministically.
- A4: memory per active key under 1 KB.
- A5: score computation overhead under 20 µs.
**Tests.**
- Replay tests; proptest on scoring invariants; benchmark.
**Notes.** Fingerprint tables are updated via signed packs without redeploying binaries.
