### T-0351 · Behavioral defense end-to-end tests (AC-11, AC-44, stuffing lab, AC-48 subset)
`P17` `[QA][SEC]` · deps: T-0335, T-0338, T-0343, T-0345, T-0350 · size: L · owner: qa
**Objective.** Verify rate limiting, challenge and bot defenses live and in the lab.
**Steps.**
1. AC-11 on the pilot: one capped burst (≤ 100 requests to `ok.txt` on `test_hostname`) yields 429 with `Retry-After` and then an auto-ban of the runner key (60 s TTL), recovery after TTL, legit visitors unaffected (second vantage point if provided).
2. AC-44: challenge flows in the browser harness (humans pass within target times; scripted clients without JS fail; replay/cross-site token tests fail), under-attack mode behavior, clearance behavior with inspection/bans, accessibility of the challenge page.
3. Credential-stuffing lab tests against the Vuln-Lab login (or builder-local vulnerable origin) with distributed sources via lab network namespaces: assert detection thresholds and success-after-spray alert.
4. AC-48 subset: scanner UA and payload-marker detection with nikto/wapiti/nuclei (lab only) in monitor and block modes; record coverage and bans.
5. Collect false-positive data: replay benign traffic corpora (browser/mobile/API/monitor) through the full behavioral stack and report challenge/block rates.
6. Record timings (challenge solve times by device profile), CPU overhead of bot scoring under load.
7. Document UNVERIFIED items (lab-dependent).
8. Fix failures at the root cause under R-14.
**Deliverables.**
- check implementations, reports
**Acceptance.**
- A1: AC-11 PASS (or UNVERIFIED with reason) with evidence.
- A2: AC-44 PASS in the harness.
- A3: stuffing detection meets thresholds in lab/builder-local runs.
- A4: benign replays show zero blocks and challenge rate under 0.5%.
- A5: evidence files have SHA-256.
**Tests.**
- The suites; lab runs when available.
**Notes.** Oracle tools run only in lab mode against lab targets.
