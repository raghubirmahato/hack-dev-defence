### T-0345 · Form abuse defenses: signup, contact, comment, checkout
`P17` `[DP][SEC]` · deps: T-0337, T-0312 · size: M · owner: dp
**Objective.** Reduce spam and fraud on public forms without CAPTCHAs.
**Steps.**
1. Define form endpoint declarations (path/method, kind: signup, contact, comment, checkout, search, newsletter) with per-kind presets: rate limits, challenge-on-suspicion, PoW requirement thresholds, disposable-email hints (the platform's disposable list applied to email-like fields), content heuristics (link count, repeated payload hashes, keyword stuffing) as soft signals.
2. Implement the challenge-before-submit option: for declared form endpoints, issue a challenge clearance on GET of the form page (when a cookie is absent) so POSTs from clients without clearance are challenged; configurable and off by default.
3. Implement duplicate-submission detection (identical body hashes across many keys) as a spam-campaign signal feeding the campaign detector.
4. Implement timing signals only as soft inputs (very fast form completion) when the origin provides a rendered-at token (optional integration via a documented JS snippet or header — otherwise skip).
5. Implement the hidden-field honeypot integration (T-0309).
6. Provide UI in S-062 under "Form protection" with templates and dry-run counts.
7. Test with scripted spam bots and benign human submission traces.
8. Link ATK-199, ATK-200, ATK-170, ATK-198.
**Deliverables.**
- declarations, presets, signals, UI hooks, tests
**Acceptance.**
- A1: scripted spam from 20 sources is challenged/limited while human traces pass.
- A2: identical payload floods are detected as campaigns.
- A3: challenge-before-submit works and is optional.
- A4: disposable-email hints are soft signals.
- A5: UI shows dry-run counts.
**Tests.**
- Simulation tests; benign replay; browser tests.
**Notes.** The platform's own signup uses the same mechanisms (dogfood).
