### T-0344 · Account-enumeration and user-differential signals
`P17` `[DP][SEC]` · deps: T-0343 · size: S · owner: sec
**Objective.** Alert owners when their login/reset endpoints reveal account existence.
**Steps.**
1. Implement passive differential analysis on declared auth/reset endpoints: cluster responses by (status, redirect target, size class, selected header set) and correlate with attempted username HMACs; if responses for different usernames differ systematically (e.g., "user not found" vs "wrong password" size patterns) with statistical confidence, raise `account_enumeration_possible` (low severity) with remediation text.
2. Detect enumeration behavior from clients: many requests varying only the username with response-differential harvesting patterns (sequential or dictionary-like usernames); treat as `credential_stuffing`-adjacent soft signal.
3. Implement timing differential signal (response time differences across usernames beyond noise) as a weaker hint with minimum samples.
4. Surface in the Security overview and readiness ("Authentication responses are uniform: Unknown/Pass/Fail with confidence").
5. Respect privacy: only aggregates and HMACs.
6. Provide guidance in docs for fixing enumeration in the origin.
7. Test with controllable origin endpoints returning different responses.
8. Link ATK-161, ATK-287.
**Deliverables.**
- analyzer, UI hooks, tests
**Acceptance.**
- A1: a test origin with differing responses triggers the finding; a uniform origin does not.
- A2: the finding includes confidence and sample counts.
- A3: no plaintext identifiers are stored.
- A4: false positives are minimized by minimum sample thresholds.
- A5: remediation text is present.
**Tests.**
- Simulation tests with two test origins; statistical unit tests.
**Notes.** This is an advisory finding, not a blocking rule.
