### T-0339 · Under-attack mode (site-level) and automatic triggers
`P17` `[DP][API][SEC]` · deps: T-0337, T-0235 · size: M · owner: dp
**Objective.** Provide a fast switch that challenges all new clients during an attack, with safe automation.
**Steps.**
1. Implement the under-attack state in the snapshot (`under_attack_until`, level, scope: all paths or selected, exclusions for verified bots/API paths) and the pipeline logic: clients without valid clearance receive the interstitial; clients with clearance proceed; challenge difficulty increases with level.
2. Implement manual enable/disable (S-093) with durations (15 min to 24 h) and auto-expiry, plus the exclusion list (health checks, webhooks, API paths with bearer tokens) to avoid breaking integrations; show a preview of affected path classes.
3. Implement automatic triggers: shield signals (P26), campaign detection (T-0325) for specific endpoints, request-rate anomaly vs adaptive baseline (T-0349) for the site, and origin saturation signals (origin latency and error spike); triggers create time-boxed under-attack states with an audit trail and owner notification.
4. Implement de-escalation: after 15 minutes below 50% of the trigger thresholds, step down one level and then off.
5. Implement protections against self-harm: clients behind clearance continue; API clients using bearer tokens are exempt by default; webhooks from known providers (declared) are exempt.
6. Implement metrics and incident timeline entries.
7. Test with simulated floods (functional profile, builder-local) and verify real-user experience via the harness.
8. Document operational guidance.
**Deliverables.**
- state machine, triggers, tests
**Acceptance.**
- A1: during under-attack, clients without clearance get the interstitial and cleared clients pass (browser test).
- A2: exempt paths remain reachable without clearance.
- A3: automatic triggers create time-boxed states with notifications and can be ended by owners.
- A4: de-escalation follows the specified timing (test clock).
- A5: API clients with bearer tokens are unaffected by default.
**Tests.**
- Integration with the proxy harness; unit: trigger logic; browser tests.
**Notes.** Shield-driven triggers connect in T-0475.
