### T-0338 · Challenge page UX (S-141) and under-attack interstitial (S-147)
`P17` `[UI][DP]` · deps: T-0337, T-0065 · size: M · owner: ui
**Objective.** Make the challenge calm, accessible and light.
**Steps.**
1. Implement the page as a data-plane template with inline critical CSS (nonce), no external requests, dark/light via `prefers-color-scheme`, tenant branding slots, total size under 20 KB including the solver script.
2. Implement the solver as a small first-party script loaded with SRI from `/__hdd/assets/` (CSP allows it): runs in a Web Worker when available (fallback to chunked main-thread with yielding), shows progress text without animation under reduced motion, announces status through a polite live region ("Checking your browser. This usually takes a few seconds."), supports cancel/retry, and handles failures with clear messages.
3. Implement `noscript` content explaining the requirement and offering the appeal/contact path; do not provide a JavaScript-free bypass.
4. Implement the under-attack variant (S-147) copy (`under-attack-*`), expected delay messaging, and the auto-redirect upon success.
5. Implement keyboard accessibility (focusable status, no traps), screen-reader announcements, and high-contrast support.
6. Implement localization (visitor locale by `Accept-Language`, limited set).
7. Test across browsers (Chromium, Firefox, WebKit via harness where available) and slow devices (CPU throttling).
8. Add visual baselines and size checks in CI.
**Deliverables.**
- templates, solver script, tests
**Acceptance.**
- A1: the page passes axe and works without layout shift.
- A2: total transfer size is under 20 KB for the HTML and under 8 KB for the script.
- A3: with JavaScript disabled the page explains what to do (no bypass).
- A4: reduced-motion users see static progress text.
- A5: cancel/retry works and does not loop automatically more than 3 times.
**Tests.**
- Browser tests (throttled CPU, JS disabled, reduced motion); size budget checks.
**Notes.** The challenge page is shown only when policy requires it.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
