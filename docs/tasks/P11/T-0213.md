### T-0213 · Kernel tuning v0 (L2 subset) with undo
`P11` `[OPS][SEC]` · deps: T-0212 · size: M · owner: ops
**Objective.** Apply safe stack tuning and prove it is reversible.
**Steps.**
1. Implement `hddctl tune apply|status|undo`: set `net.ipv4.tcp_syncookies=1`, `tcp_max_syn_backlog`, `net.core.somaxconn`, `net.core.netdev_max_backlog`, `net.ipv4.conf.all.rp_filter=1` (strict) with a guard when asymmetric routing is detected, `tcp_rfc1337=1`, ICMP rate limits, and file-descriptor limits via systemd `LimitNOFILE`; values scaled from RAM and CPU with documented formulas.
2. Persist the settings in `/etc/sysctl.d/90-hdd.conf` and record the prior values in `/var/lib/hdd/tune-undo.json` for exact reversal.
3. Validate in preflight that the host supports each knob (some containers/VPS types do not); unsupported settings are skipped with a WARN and recorded in the report.
4. Apply with the lockout-protection pattern for settings that could affect connectivity (rp_filter).
5. Print the NIC ring/RSS/IRQ recommendations (read-only inspection with `ethtool` where available) without applying them.
6. Document each setting with purpose, risk and undo.
7. Add tests in a VM verifying apply and undo restore the original values.
8. Record the results into the pilot report (the L2 full set including NOTRACK is P25).
**Deliverables.**
- `hddctl tune`, docs, undo data format, tests
**Acceptance.**
- A1: `undo` restores every changed value (compare before/after).
- A2: unsupported knobs are skipped gracefully with a recorded reason.
- A3: rp_filter strict is not applied when asymmetric routing is detected without acknowledgment.
- A4: the settings survive reboot and the undo also persists correctly.
- A5: the report lists effective values.
**Tests.**
- VM tests for apply/undo; unit: scaling formulas (table tests).
**Notes.** Conntrack and NOTRACK tuning arrive with the full firewall baseline (T-0468).
