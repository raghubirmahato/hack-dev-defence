### T-0212 · `hddctl deploy` v0: systemd, services, firewall baseline, rollback
`P11` `[OPS][SEC]` · deps: T-0207, T-0208, T-0211 · size: XL · owner: ops
**Objective.** Deploy HDD to the pilot VPS repeatably, with lockout protection and undo.
**Steps.**
1. Decide and document the production path in an ADR (systemd with signed release binaries as default; compose as alternative): target triple and libc recorded; binaries are built on the builder, never on the VPS.
2. Implement `hddctl deploy --dry-run|--apply` over SSH (`russh`) or locally: root check, OS detection (Debian/Ubuntu), backup of existing firewall rules and any existing DNS zone export, creation of the `hdd` system users, directories (`/etc/hdd`, `/var/lib/hdd`, `/run/hdd`), permissions, installation of release binaries and checksums, systemd units with hardening (`NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, `CapabilityBoundingSet` minimal, `RestrictAddressFamilies`, `SystemCallFilter`, `MemoryMax`, `TasksMax`).
3. Install and configure Postgres and Redis (packages), listening on loopback or Unix sockets only, with authentication; TLS or socket-only per section 8; create roles and run migrations; confirm they are never published.
4. Safely disable the `systemd-resolved` stub listener on :53 while keeping local resolution; verify the host can still resolve names.
5. Apply the baseline firewall (nftables `inet` table) exposing only 22 (from `ssh_allow_cidrs`), 53, 80, 443, with a `systemd-run --on-active=120` auto-revert job that is canceled only after the operator opens a second SSH session (section 2.5); record the cloud-firewall mirroring note.
6. Generate secrets with `xtask gen-secrets` (0600 files in `/etc/hdd/secrets`, systemd credentials where supported) and fail on weak or missing secrets.
7. Implement idempotency (re-running changes nothing), `--rollback` to the previous release, and a post-deploy health check suite (`/readyz` of each service, DNS and proxy self-test).
8. Write the deploy report with command outputs and hashes.
**Deliverables.**
- `hddctl deploy`, systemd units, nftables baseline, ADR, runbook
**Acceptance.**
- A1: `--dry-run` prints every planned change and touches nothing.
- A2: a deliberately broken firewall change auto-reverts after 120 s without operator action (tested on a disposable VM).
- A3: Postgres and Redis are not reachable from outside (capped self-scan of the VPS, AC-01 subset).
- A4: re-running deploy is a no-op; rollback restores the previous release in under 60 s.
- A5: no secret appears in the deploy output or logs.
**Tests.**
- VM-based integration tests (disposable local VM or container with systemd) for apply, rerun, rollback and lockout revert; unit: unit-file generator golden tests.
**Notes.** The lockout-protection pattern is mandatory for every later host-changing command.
