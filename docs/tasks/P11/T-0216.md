### T-0216 · STOP #1: instruction generator and human-step detection
`P11` `[OPS][HUMAN][DOC]` · deps: T-0210, T-0212, T-0215 · size: M · owner: ops
**Objective.** Hand the operator exact steps for the first human-gated actions, detect completion with real probes, and wait.
**Steps.**
1. Implement `hddctl stop1` (also callable from `xtask acceptance --stop1`): prints (a) the canary installation instructions for the operator's origin with exact file paths and a checksum list, (b) the pilot delegation records: `NS` records for `test_hostname` and `sandbox_hostname` pointing to `ns1/ns2.<platform_domain>`, plus `A` (and `AAAA` if applicable) records for `ns1/ns2` in the existing zone (explaining why glue is unnecessary for out-of-bailiwick names), with TTL guidance, (c) the hosting provider AUP confirmation prompt to be answered in chat with the date recorded.
2. Back up the existing DNS zone (export in BIND format via the profile's `existing_dns.export_method`) and snapshot the VPS firewall rules before anything else; store under `backups/` (git-ignored) and print their hashes.
3. Implement real probes for each human step: canary files reachable directly (HTTP GET with the profile's origin), NS delegation visible from the runner's resolver and at least two named public resolvers, `A` records for the nameserver names resolve to the VPS, and the AUP confirmation recorded in `docs/` (date).
4. Show a live status table (done/pending/failed with reasons) and wait; re-probe on operator command.
5. Provide troubleshooting hints per failure (typical registrar mistakes, propagation delays, caching, missing glue/A records).
6. Record STOP #1 state transitions in `STATUS.md` and `HANDOFF.md` so a new session resumes properly.
7. Verify that the apex is untouched (apex NS and A remain unchanged) and report it.
8. Pause the agent until the operator confirms; do not proceed to T-0217.
**Deliverables.**
- `hddctl stop1`, instruction templates, backup artifacts, status updates
**Acceptance.**
- A1: the instructions contain exact record names, types and values derived from the profile.
- A2: probes detect each step's completion independently.
- A3: the zone backup and firewall snapshot exist before any live change and their hashes are printed.
- A4: the agent does not run live checks until all required steps are PASS or the operator explicitly overrides in writing.
- A5: the apex records are verified unchanged.
**Tests.**
- Unit: instruction rendering; integration: probe logic against simulated states; dry-run output review.
**Notes.** This is the first of two mandatory human stops (STOP #2 in P31).
