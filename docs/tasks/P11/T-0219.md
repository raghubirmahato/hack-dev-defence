### T-0219 · Walking-skeleton report and decision confirmations
`P11` `[DOC][OPS]` · deps: T-0218 · size: M · owner: ops
**Objective.** Record what the pilot proved, what surprised us, and which decisions are now confirmed.
**Steps.**
1. Write `docs/WALKING-SKELETON.md`: environment details (kernel, virtualization, NIC), the measured numbers (DNS latency, TLS handshake time, proxy-added latency under the functional profile), the deploy timeline, issues encountered and resolutions.
2. Confirm or amend ADRs: crypto provider (`ring` vs `aws-lc-rs`) with FFI implications and binary size, DNS server core, proxy core (own vs Pingora), deployment path, systemd hardening profile, Postgres/Redis TLS strategy.
3. Record which assumptions held (port 53 binding, ACME validation path, glue/NS delegation behavior) and which failed, with spec patches where needed.
4. Run the rollback rehearsal for deploy (`--rollback`) and record timing.
5. Run a short soak test (functional profile for 5 minutes) to check memory growth and descriptor leaks.
6. List risks for the deep phases (for example XDP support level, kernel constraints).
7. Update `STATUS.md` risk list and `docs/DEVIATIONS.md` for any deviations.
8. Review the report with the operator at the next batched message.
**Deliverables.**
- `docs/WALKING-SKELETON.md`, ADR updates, soak results
**Acceptance.**
- A1: every ADR touched by the pilot has a recorded confirmation or amendment.
- A2: soak test shows no memory growth beyond 5% and no leaked descriptors.
- A3: rollback rehearsal completes within 60 s.
- A4: numbers are labeled as measured with method and conditions.
- A5: no claim exceeds the evidence (claims-lint passes).
**Tests.**
- Soak test script run by the runner; lint on the document.
**Notes.** Findings that change the spec become entries in `docs/UX/spec-patches.md` or `DEVIATIONS.md`.
