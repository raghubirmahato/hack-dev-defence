### T-0210 · `hdd-canary` sidecar and canary files
`P11` `[DP][OPS][DOC]` · deps: T-0004 · size: M · owner: ops
**Objective.** Provide inert, verifiable test fixtures on the operator's real origin host.
**Steps.**
1. Implement the `hdd-canary` binary: a tiny HTTP(S) static server bound to a configurable interface, serving only the files in section C16.1 and `GET <base_path>echo-headers` (JSON of received request headers, `nosniff`, no cookies, no request body reading), with strict limits (1 KB request line, 8 KB headers), read-only filesystem access, no directory listing, and fixed response headers.
2. Generate the canary files with `hddctl canary generate`: `ok.txt` (`hdd-canary-ok`), `leak.txt` (the harmless MySQL-error-like sentence), `static.css`/`static.js` with a published SHA-256, `search.html` that echoes nothing; also produce a manifest with hashes.
3. Write `CANARY.md`: how to install either the sidecar (systemd unit provided) or the plain static files into the web root of the origin (nginx/apache snippets, or any static handler), including how to ensure query strings do not change what is served and how the files are removed again.
4. Implement verification probes (`hddctl canary verify`) that check the files directly while `lockdown_state=pending`, through HDD, and with query strings.
5. Ensure the sidecar cannot reflect or execute anything: tests send hostile requests (long headers, odd methods, bodies) and assert uniform behavior.
6. Provide packaging: static binary build instructions via `xtask release` and checksum.
7. Document security considerations (bind to private interface, access only from HDD IPs once lockdown is applied).
8. Provide uninstall steps.
**Deliverables.**
- `crates/hdd-canary`, `hddctl canary generate|verify`, `CANARY.md`, systemd unit template
**Acceptance.**
- A1: file hashes match the manifest.
- A2: hostile requests never produce reflected content or errors that echo input.
- A3: `echo-headers` returns only received header names and values, with a size cap.
- A4: the sidecar runs with no capabilities and minimal syscalls (systemd sandbox options recorded).
- A5: `canary verify` reports PASS/UNVERIFIED with reasons.
**Tests.**
- Integration tests with hostile clients; fuzz the request parser; unit: manifest.
**Notes.** If the operator can only place static files, header-echo checks become UNVERIFIED(`capability_not_supplied`).
