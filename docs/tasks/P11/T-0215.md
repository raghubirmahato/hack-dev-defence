### T-0215 · Acceptance runner skeleton
`P11` `[QA][SEC]` · deps: T-0009, T-0006 · size: L · owner: qa
**Objective.** Create the runner that will carry every acceptance check, with safety limits enforced in code.
**Steps.**
1. Implement `hdd-acceptance` core: profile loading and validation, `TargetGuard`, egress allowlist enforcement, load profiles (`functional`, `burst`, `protocol-abuse`, `load`, `lab`) with caps enforced by a token-bucket limiter shared by all checks, the kill-switch watcher, and lifecycle-stage rules (production refuses destructive checks).
2. Implement the check framework: `Check` trait (id, requirements, destructive flag, profile), dependency ordering, `finally` cleanup stack (unban, remove temporary rules/records), signal handlers for SIGINT/SIGTERM, and per-check timeouts.
3. Implement the reporter: JSON and Markdown outputs with one status line per check ID (PASS/FAIL/UNVERIFIED(reason)), evidence blocks (DNS answers, HTTP status/headers, event IDs, timestamps), secrets redacted, full logs saved under `acceptance-*/` with SHA-256, and the tail embedded in the report.
4. Implement control-plane access out-of-band: SSH tunnel or WireGuard client management, never through the data plane; verify before each run that the runner IP is bannable (not in `admin_cidrs`).
5. Implement the inspect-first gate helper (`InspectGate`): calls `POST /api/v1/waf/inspect`, requires `would_block=true` and unchanged `config_revision`, otherwise FAIL without sending.
6. Implement vantage point support (`vantage_points` via SSH) and the sequential-with-unban strategy when absent; record the vantage count in reports.
7. Implement the registry of all AC IDs (AC-00 to AC-62) with status `UNVERIFIED(stage_not_reached)` until implemented, enabling dry runs of the full list.
8. Document how to add a check and how safety limits are enforced.
**Deliverables.**
- `crates/hdd-acceptance` core, reporter, registry, docs, tests
**Acceptance.**
- A1: sending to a non-allowlisted target aborts before any packet leaves (test).
- A2: the rate limiter caps the `functional` profile at 20 req/s and 5 minutes (measured).
- A3: the kill switch aborts a running check within 1 s and cleanup runs.
- A4: reports include status lines for all registered IDs, with `stage_not_reached` where not implemented.
- A5: the inspect-first gate refuses to send when `would_block` is false.
**Tests.**
- Unit: limiter and guard tests; integration: cleanup under SIGINT; golden reports.
**Notes.** The runner is built from the start with the safety envelope encoded, not as a later addition.

## Definition of done for this task's tags (section 0.7)

### `[QA]`: Test infrastructure

Real services only (no mocks); deterministic or seeded; evidence output stored under git-ignored `acceptance-*/` with sha256.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
