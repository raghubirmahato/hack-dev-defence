### T-0287 · Stored-XSS controls: write-path emphasis and response-side hooks
`P15` `[DP][SEC][UI]` · deps: T-0285, T-0276 · size: M · owner: waf
**Objective.** Reduce persistence of script payloads and help owners harden their output.
**Steps.**
1. Apply write-path strictness (T-0276) to XSS detectors for storage-likely fields: executable constructs in names, titles, bios and comments are hard in `block` mode regardless of `code_friendly` (unless the owner declares the field as rich-text with a scoped exception).
2. Implement response-side checks (outbound hooks, executed in P21): when a response body contains an unescaped reflection of a request parameter value that matched an XSS detector (reflection detection by hashing normalized matched substrings), raise `xss_reflected_response` event (critical) in monitor mode and block in outbound block mode.
3. Implement the **CSP advisor**: analyze the site's observed responses (headers only, from samples) and suggest a Content-Security-Policy in report-only form with explanations; the UI (S-097) shows suggestions and a one-click "add report-only header" option via the response header policy (T-0410) that never overrides origin headers unless the owner opts in.
4. Implement the CSP report ingestion endpoint on customer domains (`/__hdd/csp-report`, size-capped, rate-limited, aggregated) to help owners find inline script use before enforcing.
5. Provide Trusted Types guidance in docs.
6. Implement events for stored-XSS risk: write requests with XSS soft signals in storage-likely fields are logged with subtype `stored_xss_risk`.
7. Test with a local origin that reflects input (test-only) to verify reflection detection and monitor/block behavior.
8. Document limits (HDD cannot sanitize output; origin code must escape).
**Deliverables.**
- rules, outbound hooks interfaces, CSP advisor logic, tests
**Acceptance.**
- A1: executable XSS constructs in names/titles are blocked on write paths.
- A2: reflected payload detection works for HTML text and attribute contexts in the test origin.
- A3: CSP report endpoint is bounded and aggregated.
- A4: advisor suggestions are report-only by default.
- A5: documentation states that output escaping at the origin is the fix.
**Tests.**
- Integration with a reflecting test origin; unit: reflection hashing; browser: advisor UI.
**Notes.** Matrix ATK-071, ATK-267, ATK-268.
