### T-0312 · Business-logic abuse signals (rate, sequence and parameter tampering heuristics)
`P15` `[DP][SEC]` · deps: T-0303 · size: M · owner: waf
**Objective.** Add low-noise signals for abuse that no signature can detect.
**Steps.**
1. Implement sequence/velocity detectors configured per path pattern: rapid repeated state-changing actions (checkout, coupon redemption, gift-card checks, account creation, password-reset requests, vote/like endpoints, referral claims) beyond human-plausible rates per client key and per session, with defaults and presets.
2. Implement parameter tampering heuristics on declared endpoints: negative or zero quantities, price/amount fields modified (when a price field is declared as server-owned), unusually large numbers, repeated identical requests in parallel bursts (race-condition probing: ≥ 10 identical state-changing requests within 100 ms).
3. Implement coupon/gift-card guessing detection: many distinct code attempts per client key with high failure ratio (learned response patterns).
4. Provide response actions: log, challenge, rate-limit, or block per rule; no bans by default (high false-positive risk), with an explicit option.
5. UI: "Abuse protections" panel under Bots and challenge (S-062) with templates and a dry-run simulation from traffic samples.
6. Link ATK-281 to ATK-283, ATK-198, ATK-199.
7. Tests with simulated abuse and legitimate bursty users (double-click submits, mobile retries).
8. Document limits (business logic cannot be fully protected at the edge).
**Deliverables.**
- detectors, templates, UI wiring, tests
**Acceptance.**
- A1: parallel identical state-changing bursts are detected as race probing.
- A2: coupon guessing patterns trigger challenge.
- A3: legitimate double-clicks (2 identical requests within 500 ms) do not trigger.
- A4: default actions are non-banning.
- A5: templates are documented with caveats.
**Tests.**
- Simulation tests; false-positive tests with benign bursty patterns.
**Notes.** Signals feed bot scoring (P17).
