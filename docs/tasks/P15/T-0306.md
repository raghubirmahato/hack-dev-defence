### T-0306 · Scanner and attack-tool fingerprints
`P15` `[DP][SEC]` · deps: T-0262 · size: L · owner: waf
**Objective.** Identify automated attack tools and ban them on first contact.
**Steps.**
1. Build the tool signature set from original research notes (user agents and request shapes), covering at least: sqlmap, nikto, nmap scripting engine, masscan, zgrab, acunetix, nessus, openvas, wpscan, w3af, zap, burp (default markers), gobuster, dirb, dirbuster, ffuf, feroxbuster, wfuzz, nuclei, whatweb, wapiti, arachni, havij, jaeles, skipfish, httprobe, httpx scanners, `python-requests` default UA (policy: soft), `Go-http-client` (soft), `curl`/`wget` (policy only), empty UA, UA strings with known attack markers.
2. Add payload-marker signatures: sqlmap's characteristic `AND 1=1` patterns with random identifiers, nuclei's `{{interactsh-url}}` residue, scanner header markers (`X-Scan-Memo`, `Acunetix-*`), OAST callback domains in parameters, canary strings (`testing_wvs`, `acunetix`, `nessus`).
3. Define classes: `scanner` (known offensive tool: hard, ban) vs `automation` (generic libraries: soft score + challenge) and allow the owner to exempt their own scanner IPs or a signed header token (`HDD-Scan-Allow: <hmac>` generated per site, short-lived, for the owner's authorized scans; validated in the pipeline; documented).
4. Detect header-set anomalies typical for tools (missing `Accept`, constant `Accept: */*`, header order fingerprint vs UA), feeding bot scoring (P17).
5. Implement update mechanism through signed rule packs (platform rollout) so new tool signatures ship without code releases.
6. Fixtures for ATK-189, ATK-190, ATK-024; counter-examples (legitimate monitoring agents declared by owner, search engines, `curl` used by developers: not hard).
7. Test false positives with a corpus of real browser UAs (500+ strings) and API client UAs.
8. Document how owners authorize their own security scans.
**Deliverables.**
- signature set, owner exemption mechanism, tests
**Acceptance.**
- A1: known tool UAs are hard and produce bans in block mode.
- A2: browser UA corpus (500+) has zero matches.
- A3: owner exemption token works and expires.
- A4: generic libraries are soft/challenge, not hard.
- A5: signature updates ship via packs without redeploy.
**Tests.**
- Table / corpus tests; integration for exemption tokens.
**Notes.** UA matching alone is weak (spoofable); combined signals appear in T-0340.
