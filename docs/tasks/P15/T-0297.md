### T-0297 · File upload defenses
`P15` `[DP][SEC]` · deps: T-0249, T-0262 · size: XL · owner: waf
**Objective.** Block malicious uploads (webshells, polyglots, bombs) at the edge.
**Steps.**
1. Inspect multipart filenames: normalize (decode, strip path components, handle `filename*`, null bytes, trailing dots/spaces, Unicode RTL override tricks (U+202E) flagged), extension analysis (all extensions in double/multiple extension names: `shell.php.jpg`, `shell.jpg.php`, `shell.php;.jpg`, `shell.pHp`, `.phtml`, `.php5`, `.phar`, `.jsp`, `.jspx`, `.asp`, `.aspx`, `.ashx`, `.cgi`, `.pl`, `.py`, `.sh`, `.bat`, `.cmd`, `.exe`, `.dll`, `.msi`, `.jar`, `.war`, `.htaccess`, `.user.ini`, `web.config`, `.config`), with a deny list and per-site allow list of permitted extensions for upload endpoints.
2. Inspect content: magic-byte sniffing (`infer`) vs declared type vs extension (mismatch soft 3 or hard when executable types hide behind image extensions), polyglot detection (valid image header plus embedded `<?php`, `<script`, `<%`), webshell signatures (`eval(`, `base64_decode(`, `system(`, `passthru(`, `shell_exec(`, `assert(`, `$_POST[`, `$_REQUEST[`, `c99`, `r57`, `b374k`, `ASPXSpy`, `cmd.exe /c`), SVG/HTML scripts, archives (entry names with traversal, absolute paths, excessive entries, ratio bombs; nested archives depth cap), Office documents with macros indicators (`vbaProject.bin`), EXIF fields with script content (bounded EXIF parser).
3. Enforce size/dimension caps: per-file limits by endpoint policy, image dimension headers (PNG/JPEG/GIF/WebP) checked for pixel-flood (width*height cap 100 MP), animated GIF frame counts.
4. Implement per-site upload endpoint declarations (path patterns where uploads are expected, allowed extensions/types/size) and treatment of unexpected multipart on other endpoints (soft 3, ATK-134).
5. Hardness: executable extensions, webshell signatures and polyglots are hard (`upload` category); size/bomb violations are `R` (reject 413/422 with event) not bans unless repeated.
6. Streaming design: inspect headers and the first 64 KB of each part plus filename immediately; for larger parts scan sliding windows up to the part cap, discarding after scan to bound memory; the proxy streams the remainder to the origin only after a pass decision on the prefix with an abort path (connection reset) if later windows match (documented: partial data may have reached the origin in streaming mode; configurable `buffer_uploads_before_forward` for stricter sites).
7. Fixtures (inert byte strings generated at runtime in tests; no real malware), counter-examples (legitimate images with EXIF, PDFs, zip files with normal entries).
8. Benign gate, fuzz (multipart + archive peeking), bounded-memory tests.
**Deliverables.**
- upload inspector, endpoint declarations, rules, tests
**Acceptance.**
- A1: double-extension and polyglot test files are blocked (generated at runtime).
- A2: archive bombs (descriptor-based) and zip slip names are rejected without extraction.
- A3: image pixel-flood headers are rejected without decoding pixels.
- A4: memory usage per upload inspection stays below 1 MiB beyond streaming buffers (measured).
- A5: legitimate images/PDFs/zips pass.
**Tests.**
- Table (200 generated files) / fuzz / memory tests.
**Notes.** ClamAV-style AV scanning is an optional Tier 2 integration (documented).
