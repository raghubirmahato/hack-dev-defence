### T-0305 · WebSocket protections
`P15` `[DP][SEC]` · deps: T-0262 · size: M · owner: waf
**Objective.** Secure upgrade handshakes and bound WebSocket abuse.
**Steps.**
1. Inspect the upgrade handshake as a normal request (all detectors on query, cookies, headers) and enforce `Origin` policy: require `Origin` header to match site hosts or allowlist (CSWSH defense, ATK-184), configurable per path (default on when cookies are present).
2. Enforce limits: maximum concurrent WebSockets per IP and per site, message size (default 1 MiB), message rate (default 100/s per connection), idle timeout, ping/pong requirements, compression settings (disable permessage-deflate by default or cap ratio).
3. Implement optional text-frame inspection (opt-in): inspect text frames with the normal detectors up to a per-frame cap (64 KB) and rate cap; binary frames are not inspected; on a hard hit close the connection with code 1008 and emit events; bans per policy.
4. Implement connection-level fairness (per-tenant caps) and metrics.
5. Handle subprotocols (GraphQL over WS, STOMP, MQTT over WS) without breaking: inspection only for text frames when enabled; protocol-specific parsers are out of scope (documented).
6. UI in S-056 (WebSocket panel).
7. Fixtures: handshake payloads, cross-site handshake attempts; counter-examples (legitimate chat messages with apostrophes).
8. Test with the harness (browser WebSocket clients, hostile frame sequences).
**Deliverables.**
- handshake and frame policy, UI, tests
**Acceptance.**
- A1: cross-origin handshakes are rejected when policy requires origin match.
- A2: oversized or too-fast messages close the connection with the expected code.
- A3: frame inspection (when enabled) blocks hard hits in text frames.
- A4: per-IP and per-site caps work under load.
- A5: legitimate chat traffic passes (benign corpus).
**Tests.**
- Integration with real sockets and browser clients; fuzz on frame handling.
**Notes.** WebSocket passthrough plumbing is T-0367.
