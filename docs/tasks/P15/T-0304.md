### T-0304 · GraphQL protection policy enforcement
`P15` `[DP][SEC]` · deps: T-0250, T-0262 · size: M · owner: waf
**Objective.** Enforce depth, cost, alias, batch and introspection policy on GraphQL endpoints.
**Steps.**
1. Detect GraphQL endpoints by path patterns (`/graphql`, `/api/graphql`, `/gql`, declared), content types, and body shape; allow explicit declarations in settings.
2. Apply the metrics from T-0250 against policy: depth, field count, alias count, batch size, introspection (`block` default in production unless allowed), field-suggestion enumeration prevention (response header `x-hdd-note`? no; instead, outbound rewrite of "Did you mean" suggestions in error messages optionally via the outbound filter), mutation rate limits (stricter limit class for mutations).
3. Implement cost estimation heuristic: weights for list fields and nested lists, `first/last` arguments, bounded to a configurable maximum (default 1,000).
4. Implement persisted-query allowlist mode (only known hashes allowed) for hardened sites (hash list import).
5. Define subtypes (`depth`, `alias_overload`, `batch`, `introspection`, `cost`) and ATK links (ATK-179 to ATK-182, ATK-056).
6. UI in S-056 (GraphQL panel) with thresholds and dry-run replay.
7. Fixtures: depth bombs, alias overload, introspection queries; counter-examples (legitimate large queries under limits).
8. Benign gate, benchmark.
**Deliverables.**
- policy enforcement, UI, tests
**Acceptance.**
- A1: queries exceeding depth/alias/batch limits are blocked at exact boundaries.
- A2: introspection is blocked by default and allowed when configured.
- A3: persisted-query mode rejects unknown hashes.
- A4: mutation-specific limits apply.
- A5: no false positives on legitimate query corpus.
**Tests.**
- Table / fuzz / benchmark.
**Notes.** Error-message rewriting for suggestions is delivered with outbound modes (P21).
