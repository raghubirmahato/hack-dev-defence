### T-0299 · Host header and virtual-host confusion
`P15` `[DP][SEC]` · deps: T-0262 · size: S · owner: waf
**Objective.** Prevent host-header based attacks (reset poisoning, cache poisoning, routing confusion).
**Steps.**
1. Validate `Host` syntax (hostname or IP literal with optional port; reject underscores unless declared, control characters, spaces, multiple hosts, absolute URI conflicts), require equality with SNI for TLS requests (421 on mismatch as per the proxy rule), and require membership in the site's configured hostnames.
2. Reject duplicate `Host` headers and conflicting `X-Forwarded-Host`/`Forwarded: host=` on untrusted peers (stripped); treat attempts to carry a different host in these headers as `host_header` events (soft 3, hard when combined with password-reset paths declared auth endpoints).
3. Detect attempts to use `Host` values referencing internal names or other tenants' domains (cross-tenant confusion) and respond with the neutral 404 without leaking.
4. Detect absolute-URI request lines with mismatching host and ports in `Host` that differ from the listener (policy: allow standard ports only).
5. Define subtype `host_header` (category `host_header`) and ATK-046, ATK-152, ATK-104 links.
6. Fixtures (GET-safe), counter-examples (host with port, uppercase, trailing dot normalization).
7. Test cross-tenant host confusion in multi-tenant proxy harness.
8. Document password-reset poisoning mitigation (the platform's own app also builds links from config, not Host).
**Deliverables.**
- rules, router checks, tests
**Acceptance.**
- A1: SNI/Host mismatch yields 421 and event.
- A2: duplicate and malformed hosts are rejected.
- A3: another tenant's hostname in `Host` over a different SNI never routes (neutral 404).
- A4: normalization of case/trailing dot is correct.
- A5: zero false positives on benign requests.
**Tests.**
- Table / integration with TLS clients.
**Notes.** Interacts with T-0355 router.
