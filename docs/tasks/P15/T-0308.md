### T-0308 · CMS and framework probe detection
`P15` `[DP][SEC]` · deps: T-0262 · size: L · owner: waf
**Objective.** Block reconnaissance and exploit attempts against common platforms, scoped to what each site actually runs.
**Steps.**
1. Build probe path catalogs per platform with provenance and review dates: WordPress (`xmlrpc.php` system.multicall, `?author=N` enumeration, `/wp-json/wp/v2/users`, plugin/theme probes `/wp-content/plugins/*/readme.txt`, `wp-config.php.bak`, `/wp-admin/install.php`), Drupal (`/user/register?element_parents`, `CHANGELOG.txt`, `#post_render`), Joomla (`/administrator/`, `?option=com_`), Magento (`/downloader/`, `/app/etc/local.xml`, `/admin_`), Laravel (`/.env`, `/storage/logs/laravel.log`, `/_ignition/execute-solution`), Spring Boot (`/actuator/*`, `/heapdump`, `/jolokia`, `/env`), Java servers (`/manager/html`, `/jmx-console`, `/invoker/`, `/solr/admin`), phpMyAdmin/Adminer (`/pma`, `/phpmyadmin`, `/adminer.php`), ThinkPHP (`s=/index/\think\app/invokefunction`), Django/Flask debug (`/console`, `?__debugger__=yes`), data stores (`/_search`, `/_cat`, `/v1/kv`, `/v2/keys`, `/containers/json`, `/api/v1/pods`), CI/CD (`/script`, `/jenkins`, `/gitlab`, `/grafana` known exploit paths), router/IoT panels.
2. Implement platform-aware policy: when `site.platform` or detected technology indicates a platform, its *real* endpoints are not honeypots (WordPress `/wp-admin`, `/wp-login.php` are auth endpoints) while probes for **other** platforms are hard (a WordPress site receiving `/phpmyadmin` is a probe).
3. Implement technology detection from observed responses (generator tags, headers, asset paths) in aggregate form to avoid false bans when a site truly runs the probed software (e.g., a site that runs phpMyAdmin deliberately declares it).
4. Define subtypes (`cms_probe`, `component_probe`, `debug_endpoint`, `data_store_exposure`, `xmlrpc_abuse`, `user_enum`) and hardness: probes for software the site does not run are hard (ban); user enumeration is configurable (default log on WordPress with a toggle to block).
5. Provide per-site overrides: declared installed components (UI list in S-057/S-095) to suppress irrelevant probe rules and enable relevant hardening (for example WordPress `xmlrpc.php` block unless declared used).
6. Link ATK-245 to ATK-266, ATK-247, ATK-250.
7. Fixtures: GET-safe probe URLs; counter-examples (a WordPress site's normal paths, a Laravel app's real routes).
8. Benign gate with typical site browsing traces for each platform (generated crawl fixtures).
**Deliverables.**
- catalogs with provenance, platform-aware policy, tests
**Acceptance.**
- A1: probes for non-installed platforms are hard; real platform endpoints are not.
- A2: WordPress xmlrpc multicall is blocked unless declared in use.
- A3: catalogs have provenance and review dates validated by `xtask`.
- A4: declared components suppress the corresponding probe rules.
- A5: crawl fixtures for each platform produce zero false positives.
**Tests.**
- Table (300 paths) / crawl replay / catalog lint.
**Notes.** Catalogs are data in signed packs for quick updates.
