### T-0301 · CSRF enforcement mode (Fetch Metadata and Origin) and CORS anomaly signals
`P15` `[DP][SEC][UI]` · deps: T-0262 · size: M · owner: waf
**Objective.** Offer opt-in cross-site request protection at the edge for apps that lack it.
**Steps.**
1. Implement the enforcement modes per site and per path pattern: `off` (default), `log`, `block`; rules: for state-changing methods (`POST/PUT/PATCH/DELETE`) from a browser context (`Sec-Fetch-Site` present), require `same-origin` (or `same-site` if configured) or an allowlisted `Origin`; if `Sec-Fetch-*` is absent but `Origin` is present, require match; requests with neither header (non-browser clients) pass by default (configurable strict mode for cookie-authenticated paths).
2. Implement path scoping so API routes with bearer tokens (not ambient credentials) can be excluded; provide presets ("Cookie-authenticated forms", "All state-changing requests").
3. Implement allowlists of trusted origins (SSO, payment return flows) with validation; special-case top-level navigation POSTs (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`) from cross-site that are common in payment gateway returns (documented risk; require explicit allowlist).
4. Implement CORS anomaly detection (signals only): responses with `Access-Control-Allow-Origin: *` plus `Allow-Credentials: true`, reflected origin patterns, `null` origin allow; surfaced as posture findings (outbound phase) and events, not blocks.
5. Provide UI controls in S-056 (CSRF category) with warnings about breaking third-party POST flows and a dry-run preview from sampled traffic (how many past requests would have been blocked).
6. Define category `csrf` and ATK-172, ATK-273 links.
7. Test with a local origin and browser-driven cross-site POST attempts using the harness (attacker page on another origin).
8. Benign gate and compatibility tests (same-origin AJAX, form posts, CORS preflight).
**Deliverables.**
- enforcement logic, UI wiring, tests
**Acceptance.**
- A1: cross-site auto-submitted forms are blocked in `block` mode (browser test).
- A2: same-origin and allowlisted requests pass.
- A3: bearer-token API routes are not affected when excluded.
- A4: the preview reports counts from sampled traffic.
- A5: warnings about payment-return flows are displayed.
**Tests.**
- Browser tests with two origins; table tests of header combinations (50 cases).
**Notes.** This complements, never replaces, CSRF tokens in the origin.
