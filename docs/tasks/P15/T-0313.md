### T-0313 · Attack-matrix coverage check and detector registry
`P15` `[QA][DOC]` · deps: T-0310, T-0311, T-0312 · size: M · owner: qa
**Objective.** Make coverage claims mechanically verifiable.
**Steps.**
1. Implement `xtask attack-matrix check`: parse the ATK table from the spec, build the registry of rules (rule IDs with ATK references), fixtures (files with `atk:` headers), tests (functions referencing ATK IDs via a naming convention or attribute), and tasks.
2. Fail when any ATK row lacks: at least one fixture file or an explicit `limit` justification, at least one test referencing it, and a mapped task; generate `docs/ATTACK-COVERAGE.md` with per-row status (detected, partial, limit, posture, platform-level) and links.
3. Compute per-group detection rates from the last fixture matrix run (core and held-out) and include them in the doc and in the gate report; mark rows lacking held-out data as `UNVERIFIED`.
4. Cross-check the actions in the spec table with actual default policies (category defaults per preset) to detect drift (for example BB vs B).
5. Generate the public "limits" list for S-003 from `limit` rows.
6. Add the check to `verify`.
7. Add a mutation of the spec table in tests to prove the check fails on drift.
8. Document the workflow for adding new attack classes (new ATK IDs, fixtures, rules, tests).
**Deliverables.**
- `xtask attack-matrix check`, `docs/ATTACK-COVERAGE.md`, tests
**Acceptance.**
- A1: the check passes only when all 300 rows meet the requirements or are justified limits.
- A2: drift between spec actions and default policies is detected (meta-test).
- A3: the generated document lists detection rates and statuses.
- A4: the limits list is generated and non-empty (DNS cache poisoning etc.).
- A5: adding an ATK row without coverage fails `verify`.
**Tests.**
- Unit tests of the parser and checker; meta-tests.
**Notes.** Rows in groups AG-13 (DNS), AG-14 (network), AG-17 (platform) are covered by later phases; until then they are marked `stage_not_reached` and the check treats them as pending with owning task IDs.
