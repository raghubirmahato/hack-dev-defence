### T-0294 · CRLF, header and email-header injection
`P15` `[DP][SEC]` · deps: T-0241 · size: M · owner: waf
**Objective.** Block newline-based injection into headers, logs and mail.
**Steps.**
1. Detect CR (`%0d`), LF (`%0a`), CRLF, Unicode line separators (U+2028/9, U+0085) in parameters, path, headers and cookies after decoding, particularly when followed by header-like text (`Set-Cookie:`, `Location:`, `Content-Type:`, `Content-Length:`, `HTTP/1.1 200`, `Bcc:`, `To:`, `Cc:`, `Subject:`, `MIME-Version`).
2. Hardness: CRLF followed by a header name pattern is hard (`crlf`, `response_splitting`, `email_header`); lone newlines in multi-line fields (textarea) are normal and not flagged except in single-line field kinds (`email`, `username`, `subject`, `name`, `url`, `redirect`); headers containing CR/LF/NUL are rejected at the protocol layer (R) before inspection.
3. Detect HTTP response splitting payloads (`%0d%0aContent-Length:0%0d%0a%0d%0aHTTP/1.1 200`), log forging shapes (`\n[ERROR]`, fake log lines) as soft 2.
4. Detect SMTP command injection (`\r\nMAIL FROM:`, `RCPT TO:`, `DATA`) and IMAP/POP injection tokens in mail-related fields.
5. Provide field-kind sensitivity: `subject`, `from`, `to`, `reply-to`, `email`, `name` fields (name-based inference) treat any newline as hard.
6. Fixtures for ATK-042 to ATK-045 and counter-examples (multi-line comments, addresses with newlines in textarea fields).
7. Add tests for header/URL contexts and multipart part names.
8. Benign gate and fuzz.
**Deliverables.**
- detector, rules, fixtures (≥ 80), tests
**Acceptance.**
- A1: CRLF plus header-name injections are hard.
- A2: newlines in textarea fields are not flagged.
- A3: single-line field kinds with newlines are hard.
- A4: SMTP/IMAP command injections are detected.
- A5: zero false positives on benign corpora (multi-line text included).
**Tests.**
- Table (120) / fuzz.
**Notes.** Protocol-layer rejection of CR/LF/NUL in raw header values is in T-0356.
