### T-0311 · Information-disclosure controls: debug endpoints and error masking
`P15` `[DP][SEC]` · deps: T-0308 · size: M · owner: dp
**Objective.** Reduce what a vulnerable origin reveals to attackers.
**Steps.**
1. Implement header stripping/replacement policy (response phase, applied in the pipeline): remove `Server`, `X-Powered-By`, `X-AspNet-Version`, `X-AspNetMvc-Version`, `X-Generator`, `X-Drupal-Cache`, `X-Pingback` (WordPress), `Via` details when requested; set `Server: Hack-Dev-Defence` (override allowed).
2. Implement error page masking: origin 5xx responses with HTML bodies matching debug/stack-trace patterns (Django/Flask debug pages, Laravel Ignition, Spring Whitelabel with stack traces, ASP.NET yellow screen, PHP errors/warnings with file paths) are replaced with the branded generic error page (`block` outbound mode) or only recorded (`monitor`); detection patterns shared with the outbound filter (T-0408).
3. Block direct access to common debug endpoints (`/debug`, `/_debug`, `/console`, `/__debug__/`, `/_profiler`, `/telescope`, `/horizon`, `/elmah.axd`, `/trace.axd`, `/server-status`, `/server-info`, `/status` for Apache) unless declared in use (these are also in the honeypot catalog with distinct policy: a hit on a debug endpoint that returned 200 raises a critical exposure event in monitor mode).
4. Implement the **exposure detector**: when a probe path from the catalogs returns 200 with a signature body (e.g., `.env` content with `APP_KEY=`, `.git/HEAD` with `ref:`, directory listing), raise a critical `exposure_detected` event and notify owners (even if the request was from a scanner), because this indicates a real exposure to fix.
5. Implement settings in S-097 with explanations.
6. Link ATK-258, ATK-266, ATK-274 to ATK-280.
7. Fixtures with local origins serving fake sensitive content (test-only), plus benign pages.
8. Benign gate (legit pages with words like "debug" in content).
**Deliverables.**
- header policy, error masking hooks, exposure detector, tests
**Acceptance.**
- A1: stack-trace pages are masked in outbound block mode and recorded in monitor mode.
- A2: a scanner hit that receives a real `.env` response triggers a critical exposure event.
- A3: headers are stripped/replaced per policy and do not break the origin's own cache headers.
- A4: declared debug endpoints are not blocked.
- A5: zero false positives on benign pages.
**Tests.**
- Integration with test origins; unit: patterns.
**Notes.** The exposure event is one of the most valuable signals for owners of vulnerable sites.
