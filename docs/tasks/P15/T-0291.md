### T-0291 · JNDI/Log4Shell, OGNL, SpEL and expression-language injection
`P15` `[DP][SEC]` · deps: T-0290, T-0242 · size: L · owner: waf
**Objective.** Block JVM expression and lookup injection including nested obfuscation.
**Steps.**
1. Implement the lookup unwrapper (shared with the canonical view, T-0242) and detection of `${jndi:` with schemes `ldap`, `ldaps`, `rmi`, `dns`, `iiop`, `nis`, `corba`, `http`, even when assembled from nested lookups `${${lower:j}ndi:`, `${${::-j}${::-n}di:`, `${${env:X:-j}ndi:`, `${${upper:j}ndi:`, `${j${sys:x:-}ndi:`, `${date:'j'}`; hard, subtype `jndi`.
2. Detect Log4j-style secondary lookups used for exfiltration (`${env:AWS_SECRET_ACCESS_KEY}`, `${sys:java.version}`, `${ctx:...}`, `${hostName}`, `${java:...}`) as hard when combined with network-looking strings or as soft otherwise, and `${script:`/`${dns:`/`${url:` (Text4Shell family) as hard.
3. Detect OGNL (`%{...}`, `${...}`, `#_memberAccess`, `#context`, `@java.lang.Runtime@getRuntime()`, `#cmd=`, `(#_='multipart/form-data')`, `new java.lang.ProcessBuilder`), Struts content-type payloads in the `Content-Type` header, SpEL (`T(java.lang.Runtime)`, `new java.lang.ProcessBuilder`, `#{...}`), MVEL, and Groovy (`@groovy.transform.ASTTest`), including Spring Cloud Function routing expression header and Spring4Shell parameter shapes (`class.module.classLoader`).
4. Scan **all headers** (User-Agent, Referer, X-Api-Version, X-Forwarded-For, Authorization, Cookie, and custom) because Log4Shell exploitation commonly uses headers; also scan JSON keys and values, URL path, and multipart parts.
5. Define subtypes (`jndi`, `lookup_exfil`, `ognl`, `spel`, `class_loader`) and link ATK-039, ATK-040, ATK-041, ATK-112 to ATK-115, ATK-120.
6. Build the virtual patch rules (cross reference T-0310) with CVE metadata.
7. Fixtures (Class A inert shapes with `.invalid` hosts; Class B exfil shapes) and counter-examples (documentation of Log4j configuration, `${name}` placeholders in templating text; user-entered `${HOME}` in shell tutorials as soft).
8. Benign gate and fuzz on the unwrapper depth limits.
**Deliverables.**
- detectors, rules, fixtures (≥ 150), tests
**Acceptance.**
- A1: nested obfuscations (at least 20 documented variants) are detected as `jndi` hard.
- A2: header-borne payloads in User-Agent, Referer, X-Forwarded-For and custom headers are detected.
- A3: Struts Content-Type OGNL shapes are hard.
- A4: deep nesting beyond depth 8 is flagged and treated as hard when it unwraps to a lookup.
- A5: zero false positives on benign corpora.
**Tests.**
- Table (200) / proptest nesting / fuzz.
**Notes.** CVE references: CVE-2021-44228 and related; verify against OSV/NVD at build time.
