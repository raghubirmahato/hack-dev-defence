### T-0436 · Exposure board (S-125) and virtual patches (S-126) admin screens
`P22` `[UI][API]` · deps: T-0417, T-0310 · size: M · owner: web
**Objective.** Build the operator's views over component vulnerabilities and virtual patches, wired to real data when the vulnerability service lands.
**Steps.**
1. Define the exposure API contract (`GET P/exposure/components`, `matches`, `PUT .../vex`, `GET/POST P/virtual-patches`, transition endpoint) and generate OpenAPI and the typed client now so the UI can be built and tested against the contract using contract fixtures (clearly labeled "Design artifact: contract fixture" in tests only, never in production code paths).
2. Implement S-125: component table (name, version, source of version (declared/SBOM/fingerprint), internet-facing flag, owner), matches list (advisory id, CVSS, EPSS, KEV flag, fixed-in, status `unpatched/virtually_patched/patched/not_affected`, SLA due and days overdue), filters, VEX action dialog (justification required, reviewer), SLA clock display, and **virtual-patch debt** card.
3. Implement S-126: virtual patch list with lifecycle (draft → monitor → block → retired), evidence summary (vectors that must block, benign that must pass), expiry date and countdown, `would_block` hits in monitor, transition actions with preconditions (evidence present, monitor ran ≥ 24 h with zero benign hits to move to block), extension request with reason (audited), and retirement upon patched confirmation.
4. Wire empty states: until `hdd-vuln` is deployed (P27) the screens show "No inventory yet" with the setup steps (import SBOM/lockfile, declare components), never fake rows; pages show "Exposure data source: not configured".
5. Enforce R-11 in the UI: a `virtually_patched` item never appears as resolved and still shows the SLA clock; a clear label "Mitigated, not fixed".
6. Implement the SLA alerts display (50%, 90%, overdue), and the cutover-gate indicator (no overdue KEV/critical, no expired virtual patch).
7. Write tests: contract tests (client/server), empty states, R-11 display invariants, transition preconditions, expiry blocking indicators, permission gating (`platform.exposure`), a11y of dense tables.
**Deliverables.**
- API contract, UI, tests
**Acceptance.**
- A1: with no inventory configured the screens show honest empty states and setup guidance (no placeholder data).
- A2: a virtually patched item is visibly "Mitigated, not fixed" with its SLA clock running (UI test).
- A3: transitions enforce preconditions server-side.
- A4: the contract tests pass against the real service when P27 lands (placeholder test marked `#[ignore]` with a tracked task id until then).
- A5: all actions are audited.
**Tests.**
- Contract tests, browser e2e, unit.
**Notes.** The real data wiring and matching engine are in P27 (T-0481 onward).

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
