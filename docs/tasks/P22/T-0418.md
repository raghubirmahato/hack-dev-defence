### T-0418 · Admin overview (S-100): real platform health and attention list
`P22` `[UI][API]` · deps: T-0417, T-0214, T-0140 · size: L · owner: web
**Objective.** Show operators the true state of the platform in one screen, with honest unknowns.
**Steps.**
1. Define the overview data contract (`GET P/overview`): edge health (proxy/DNS up, config revision, p99 proxy-added latency, snapshot age), control health (API/web/worker up, queue depth and oldest job), data stores (Postgres/Redis health, replication lag if any, disk), certificates expiring within a quarter of their lifetime, ban set size and kernel enforcement mode, shield state, attack summary for the last hour (top categories, top ASNs, blocked count, bans created), abuse queue size, signups in 24 h, pending upgrades, backup recency, and exposure board counters.
2. Implement collectors in `hdd-analytics`/`hdd-worker` that read from real sources (Prometheus-style internal registry, Postgres, Redis, heartbeats); every field carries `value`, `as_of`, `source` and `status` (`ok`, `warn`, `crit`, `unknown(reason)`).
3. Build the screen with a card grid (tokens from the design system), each card with title, primary number, a text status (not color-only), a sparkline (SVG, with a table alternative), an "as of" timestamp and a drill-down link to the owning screen.
4. Implement the **attention list**: derived from rules (certificate expiring, queue stuck, replication lag, backup stale, secondary lag, shield state, exposure overdue, mass ban anomalies, failed upgrades, disk usage), ranked by severity then age, each item with an owner suggestion and a deep link; items can be snoozed with a reason (audited) and reappear after the snooze.
5. Implement live updates through SSE at 5 s intervals for the top row of cards; if SSE is blocked, refresh via HTMX polling (30 s) and show "Live updates paused" state.
6. Implement time-range selector (1 h, 24 h, 7 d) for the attack summary, with data from rollups (T-0140); an empty rollup shows "No data in range" rather than zeros when the collector was down.
7. Add the "platform mode" strip: lifecycle stage, deployment mode, active maintenance/safe mode/signup freeze, and `lockdown` status of the admin surface.
8. Write tests: unknown handling (kill each source and verify the card shows `unknown(reason)`), attention rule unit tests (≥ 20 rules, each with trigger and clear conditions), snooze behavior, SSE fallback, performance (overview renders in ≤ 300 ms server time with warm caches), a11y.
**Deliverables.**
- API, collectors, screen, attention rules, tests
**Acceptance.**
- A1: killing Redis/Postgres/worker in a test shows the correct card status within one collection interval and creates the matching attention item.
- A2: no card ever displays a zero where the source is unavailable.
- A3: every number links to its source screen.
- A4: attention items clear automatically when the condition clears.
- A5: the screen meets contrast, keyboard and screen-reader checks.
**Tests.**
- Integration with fault injection; unit (rules); browser e2e; axe.
**Notes.** The overview is read-only; actions live on the owning screens.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
