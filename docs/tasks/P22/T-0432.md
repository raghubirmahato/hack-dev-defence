### T-0432 · Email template management (S-120) with preview in both themes and locales
`P22` `[UI][API]` · deps: T-0417, T-0110, T-0082 · size: M · owner: web
**Objective.** Let operators edit transactional emails safely, with previews and linting.
**Steps.**
1. Implement the template catalog (from T-0110): verification, welcome, invitation, password reset, MFA changes, login alerts, security notices, domain verification reminders, certificate expiry, attention alerts, report delivery, impersonation notices, tenant lifecycle notices, appeal outcomes, weekly digest.
2. Implement the editor: subject, preheader, HTML and plain-text parts side by side, per-locale versions with fallback indication, variable palette (documented placeholders with sample values), and **safe templating** (Fluent/askama-style placeholders only; no arbitrary expressions or HTML-injecting variables; variables are escaped by default).
3. Implement the **preview tool**: render with fixture data in light and dark email client simulations (prefers-color-scheme in an iframe sandbox), desktop and mobile widths, plain-text view, and a link checker that lists all URLs and flags non-allowlisted hosts; expose `xtask mail preview` parity.
4. Implement **linting**: required placeholders per template (e.g., verification link), forbidden content (external images/trackers unless allowlisted, `<script>`, inline event handlers, `javascript:` URLs), size limits (≤ 100 KB), accessible HTML checks (alt text, contrast tokens, language attribute), claims-lint, and spam-score heuristics (subject length, ALL CAPS, link density).
5. Implement versioning and rollback per template/locale, with publish workflow (draft → preview → publish with step-up for security-critical templates, i.e., verification/reset/MFA).
6. Implement a **test send** to the editor's own address with a "[TEST]" subject prefix and rate limit.
7. Implement guard: security-critical templates must contain the required warning lines (e.g., "If you did not request this, ignore this email") enforced by lint; templates cannot remove security notices.
8. Write tests: sandboxed rendering (no script execution), placeholder escaping with hostile values (HTML, CRLF header injection in subject), link checker, lint rules, locale fallback, version rollback, send throttling, permission gating (`platform.email.write`, step-up for security templates), and a11y of the editor.
**Deliverables.**
- API, UI, preview renderer, lint rules, tests
**Acceptance.**
- A1: hostile variable values never break out of escaping or inject headers (fuzz).
- A2: lint blocks publishing templates missing required placeholders or security warnings.
- A3: previews render in both themes and plain text identically to what the mailer sends (byte compare of the rendered output).
- A4: rollback restores a prior version exactly.
- A5: test sends are throttled and clearly marked.
**Tests.**
- Unit/fuzz, integration with the mailer outbox and a local SMTP sink, browser e2e.
**Notes.** The mailer uses the same render function as the preview, so there is no preview/production divergence.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
