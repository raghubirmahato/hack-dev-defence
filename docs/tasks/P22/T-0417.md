### T-0417 · Admin surface foundation: isolation, session scope, layout shell and navigation
`P22` `[UI][SEC]` · deps: T-0134, T-0125, T-0118, T-0073, T-0137 · size: L · owner: web
**Objective.** Build the secure frame in which every admin screen lives.
**Steps.**
1. Route the `admin_host` surface in `hdd-web` with a dedicated router and middleware stack: platform-role session required, host-header verification (admin routes are unreachable on app/www hosts and app routes are unreachable on the admin host; 404 without hints), `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, strict CSP with nonces, no third-party assets, frame denial.
2. Enforce the admin session policy from B4.1: separate cookie `__Host-hdd_adm` (distinct from the app cookie), forced MFA at login, idle timeout 15 min, absolute 8 h, step-up TTL 5 min for `S` permissions, session binding to the admin CIDR rule when `admin_exposure=routed_with_cidr`, concurrent session cap of 3 with a visible list.
3. Honor `admin_exposure`: in `tunnel_only` the listener binds to loopback or a private interface; in `routed_with_cidr` requests from outside `admin_cidrs` receive the neutral 404 before any application logic; document the tunnel setup (SSH/WireGuard) in the runbook.
4. Implement the admin layout: a left navigation grouped as Overview; Tenants (tenants, users, domains); Security (global jail, never-ban, rule packs, threat intel, abuse); Infrastructure (nodes and services, certificates and zones, releases, backups, shield and firewall, exposure); Platform (plans, signup policy, settings, email templates, announcements and flags, emergency); Audit and Support. A persistent top banner shows "ADMIN" with environment (pilot/production), the lifecycle stage and any active emergency state; the banner is not color-only (text + icon) and passes contrast checks.
5. Implement the permission-aware navigation: items the role cannot access are hidden, but direct URLs still return 403 with a calm explanation (no hint of existence beyond the permission name).
6. Implement global admin components: reason dialog (required for sensitive mutations, min 10 chars, stored in audit), typed-confirmation dialog (e.g., type the tenant slug), step-up prompt integration (T-0118), "audit event preview" panel showing the event that will be written before the owner confirms.
7. Implement the admin command palette (platform scope: search tenants, users by exact email, domains, Ray IDs, IPs; actions limited by permission) with results capped and no autocomplete of emails.
8. Add the admin breadcrumbs, page titles and keyboard shortcuts consistent with the app shell, plus a compact density default for tables.
9. Add structured logging of every admin request (actor, route, outcome) to the platform audit stream (reads for sensitive screens are logged too), and rate-limit admin endpoints (60 req/min/session; 10 failed step-ups per hour lock the session).
10. Write tests: route-permission matrix for all admin routes (generated from the route registry), host confusion tests, org-role session rejection, timeout behavior, cookie flags, CSP presence, neutral 404 behavior outside CIDR, step-up gating, and a negative test that no admin asset URL is cacheable.
**Deliverables.**
- admin router and middleware, layout, components, tests, runbook section
**Acceptance.**
- A1: every admin route is covered by the permission registry and the generated matrix test passes (no unregistered routes).
- A2: an org-role session (including org owner) cannot load any admin page or API; platform sessions cannot use app routes.
- A3: idle 15 min and absolute 8 h timeouts are enforced (time-injected tests).
- A4: outside `admin_cidrs` in routed mode, all admin paths return the identical neutral 404.
- A5: the banner and navigation pass axe and keyboard traversal tests.
**Tests.**
- Integration (HTTP), browser e2e, property test on the route registry, security headers snapshot.
**Notes.** The admin surface is the highest-value target in the system; this task's tests are re-run in every later phase gate.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
