### T-0419 · Tenants list and tenant detail (S-101, S-102)
`P22` `[UI][API][DB]` · deps: T-0417, T-0126, T-0146 · size: L · owner: web
**Objective.** Let operators find and understand tenants without exposing their traffic data.
**Steps.**
1. Implement `GET P/tenants` with filters (plan, status, abuse flag, created range, domain count range, mode `owner_only/saas`), search by org name/slug/`org_` id or by a domain name (exact or suffix), sorting, cursor pagination, saved views and CSV export (without member emails, permission-gated).
2. Implement the tenants table (T-0087 infrastructure): name, slug, plan, status, domains, members, 30-day request volume, abuse flag count, created, last activity; row actions via a menu (view, change plan, suspend) respecting permissions.
3. Implement tenant detail (S-102) with tabs: Overview (usage versus quota with progress bars + text), Domains (state, WAF mode, abuse flags, verification status; no hostnames of other tenants), Members (roles, last active, MFA state; emails masked unless the viewer holds support permission and supplies a reason), Abuse (reports and actions), Notes (internal staff notes with author and timestamp, markdown-lite, max 4 KiB each), Audit (filtered view of platform and org events for this org).
4. Implement actions: change plan (step-up, reason, effective date, preview of limit effects), adjust quota overrides (per-limit with expiry), suspend/unsuspend (T-0423), impersonate (T-0422), export tenant summary (JSON without secrets), add/remove abuse flag, add staff note.
5. Show an "audit event preview" before each action and link the produced event after completion.
6. Implement protections: platform staff cannot see API key secrets, webhook secrets, TLS private keys or request bodies; a regression test lists all fields returned and asserts none is sensitive.
7. Implement the tenant health score (explainable: unresolved domain issues, repeated policy violations, abuse reports, failed payments if billing exists) used only to sort the queue; never auto-actions.
8. Write tests for filters and pagination (10,000 tenants), permission variants for each platform role (owner/admin/support/auditor), field-level redaction assertions, quota override expiry, concurrency (two admins editing the plan), and accessibility of the detail tabs.
**Deliverables.**
- API, screens, repositories, tests
**Acceptance.**
- A1: support role sees read-only data and no action buttons; auditor sees only audit-related pages.
- A2: plan changes require step-up and reason and appear in both platform and org audit trails.
- A3: sensitive fields are never present in any admin API response (schema test).
- A4: pagination and filters respond in ≤ 200 ms at 10,000 tenants.
- A5: notes are stored and rendered escaped (XSS test).
**Tests.**
- Integration, browser e2e, schema/field tests, performance.
**Notes.** Tenant health score is advisory; the UI never presents it as a security rating.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.
