### T-0434 · Platform emergency controls (S-122): safe mode, signup freeze, global challenge
`P22` `[UI][API][SEC][OPS]` · deps: T-0417, T-0370, T-0339, T-0428 · size: M · owner: sec
**Objective.** Provide the big red buttons, with guard rails, time limits and clarity about their effects.
**Steps.**
1. Implement `POST P/emergency/safe-mode` (global pass-through: every site stops inspection, jail and limits with TLS, routing and the access gate intact; explicit consequences text; typed confirmation "SAFE MODE"; duration 15 min–24 h with auto-expiry default 1 h; step-up; reason) and `DELETE P/emergency/safe-mode`.
2. Implement `signup-freeze` (new signups closed with a neutral message; existing users unaffected; duration or indefinite until lifted; audited), and `global-challenge` (all new clients to all protected domains must pass the lightweight challenge; excludes verified bots and API clients per policy; duration up to 6 h, default 1 h).
3. Implement the UI: three cards with current state (off/on, who, when, expires, reason), a plain-language "what happens" list and an "undo" description; active states appear in the admin top banner and in the app shell banner for org users where relevant ("Platform-wide safe mode is active").
4. Implement the **dead-man** behavior: all emergency controls expire automatically; a prompt re-confirms before auto-expiry extends (extension needs step-up); the expiry job is tested with time injection.
5. Implement parity with `hddctl safe-mode on|off`, `hddctl signup freeze|unfreeze`: the CLI works with the API down by writing the kill-switch/flag files and the shared state, and the UI reflects those states.
6. Implement the notifications to platform staff and tenant owners (for safe mode only if it lasts longer than 15 minutes), plus a status page note.
7. Add a **drill mode**: operators can run the emergency controls in `drill` (applies to the sandbox host only) to rehearse; drill results are stored.
8. Write tests: state transitions, auto-expiry, CLI/API parity, data-plane effects (safe mode makes SQLi payloads pass on the sandbox host and re-blocks after off), global challenge exemptions, banner visibility, permission/step-up gating, and audit.
**Deliverables.**
- API, UI, CLI parity, jobs, tests, runbook entries
**Acceptance.**
- A1: safe mode on/off changes behavior within 2 s and the same attack is blocked again after off (live check on sandbox).
- A2: all controls expire automatically and cannot be set to unbounded durations (except signup freeze, which requires reason and weekly reminder).
- A3: `hddctl` and the UI agree on state in all transitions.
- A4: the drill mode never touches non-sandbox hosts.
- A5: notifications fire as specified.
**Tests.**
- Integration with proxy; live sandbox checks; time-injected tests.
**Notes.** AC-13 and AC-42 reference these controls.
