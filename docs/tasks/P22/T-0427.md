### T-0427 · Infrastructure screens: nodes, services, queues, certificates and zones (S-110 to S-113)
`P22` `[UI][API][OPS]` · deps: T-0417, T-0214, T-0211, T-0198 · size: L · owner: web
**Objective.** Show operators the machines, processes, jobs, certificates and zones that make up the platform and let them act on stuck work.
**Steps.**
1. Implement S-110 nodes: role (edge/control/dns/agent), hostname, version, build commit, last heartbeat, config revision applied vs expected (drift indicator), uptime, resource summary; heartbeat staleness thresholds (warn 30 s, crit 120 s).
2. Implement S-111 services and queues: service list with readiness probe results and last restart reason; queue list with depth, oldest job age, running/failed counts, retry policy; failed job inspector (job type, attempts, last error message with secrets redacted); retry/skip/dead-letter actions with confirmation and audit; queue pause/resume for maintenance with a visible banner.
3. Implement S-112 certificates inventory: all certificates (host list, issuer, not_after, state, last renewal, errors), CA rate-limit budget view (counts by registered domain vs limits from configuration with provenance), CT anomaly list (unexpected issuance, T-0379), forced renewal action with budget warning, and export.
4. Implement S-113 DNS zones: zones (org, apex, topology, serial, last transfer, secondary lag status, record count, state), delegation observation (is the registrar delegating to us), query rate summary (from T-0400), random-subdomain defense status, and quarantine/unquarantine actions (step-up, reason).
5. Add cross-linking: node drift links to the config revision timeline; certificate rows link to the owning domain (tenant-visible name shown only with `platform.domain.read`).
6. Implement action safety: no action here edits tenant data; actions are limited to platform operations (retry jobs, renew certificates, quarantine zones), each audited.
7. Implement refresh behavior: tables auto-refresh every 15 s via HTMX when the page is visible; pause when hidden (Page Visibility API) and show "last updated" text.
8. Write tests: drift calculation, staleness thresholds, failed job redaction (secrets in error messages are masked using the redaction library), retry semantics (idempotent), budgets display accuracy against fixtures, permissions, and a11y on dense tables.
**Deliverables.**
- API, screens, tests
**Acceptance.**
- A1: stopping a worker shows the node/service as stale within the threshold and the queue's oldest job age grows visibly.
- A2: failed job errors never expose secrets (redaction test over 50 error fixtures).
- A3: the rate-limit budget display matches the stored counts and shows the config provenance.
- A4: quarantining a zone makes the DNS service REFUSE within 2 s.
- A5: all actions require the right permission and produce audit events.
**Tests.**
- Integration with fault injection; browser e2e; redaction tests.
**Notes.** Heavy diagnostic views link to Grafana dashboards when the operator configured a Grafana base URL.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.
