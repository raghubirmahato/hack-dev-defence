### T-0437 · Shield (S-127) and firewall/XDP (S-128) admin screens
`P22` `[UI][API][OPS]` · deps: T-0417, T-0214 · size: M · owner: web
**Objective.** Provide the operator views for DDoS readiness, shield state and kernel enforcement, honest about capacity.
**Steps.**
1. Define API contracts: `GET P/shield` (state, entered_at, dwell, signals with thresholds, upstream mitigation details, standby edge info, three capacity numbers), `POST P/shield/state|hold|release`, `GET P/firewall` (backend, ban set size, last reconcile, errors), `GET P/xdp` (mode native/generic/none, attached interface, drops by reason, detach timer), `POST P/xdp/detach|reload`.
2. Implement S-127: state machine diagram with the current state highlighted (text + shape, not color-only), signal table (current value, 50%/80%/90% thresholds, trend), upstream section (provider, mode, advertised capacity, activation procedure link, dry-run status), standby edge and failover readiness, the **three capacity numbers** (lab-proven, provider-advertised, verified-live) with explicit "verified-live: not measured" when empty, the incident timeline, and manual controls (`set state`, `hold`, `release`) with typed confirmation and step-up.
3. Implement S-128: firewall backend and health, ban set size and drop counters, reconcile status, XDP status with mode warning ("generic mode: modest gains"), **dead-man detach timer** countdown after load/reload with a "confirm from this session" action, per-reason drop counters, allowlist (never-drop) display, and `detach/reload` buttons (step-up, reason).
4. Implement honest unknown states: if the shield or host agent is not deployed, show "Not deployed" with a link to the setup task rather than a green tick.
5. Add alert wiring display: heartbeat configuration status, last heartbeat sent, external monitor URL set or not.
6. Write tests with contract fixtures (test-only), UI states for all four shield states, the countdown behavior (time-injected), permission gating (`platform.shield`: owner/admin step-up for mutations; support/auditor read), and claims-lint (no statement of volumetric protection beyond measured data).
**Deliverables.**
- API contracts, UI, tests
**Acceptance.**
- A1: the page never displays a capacity figure without its provenance label.
- A2: manual state changes require typed confirmation and step-up and are audited.
- A3: the XDP detach timer is displayed and confirm resets it (integration with the fake agent).
- A4: claims-lint passes on all strings.
- A5: undeployed components show "Not deployed", not healthy status.
**Tests.**
- Contract tests, browser e2e, claims-lint.
**Notes.** Real data wiring completes in P25 and P26.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.
