### T-0424 · Global jail (S-106) and never-ban list (S-109) management
`P22` `[UI][API][SEC]` · deps: T-0417, T-0318, T-0323 · size: L · owner: web
**Objective.** Operate platform-wide bans and protections with safety checks that prevent self-harm.
**Steps.**
1. Implement S-106: table of global jail entries (IP or CIDR within limits, reason, origin: manual/promoted/feed, creator, created, expiry, hit counts, propagation status), filters (origin, reason, expiring soon), search by IP/CIDR, and detail (evidence summary of how it was promoted, orgs affected count only, sample Ray IDs without tenant names).
2. Implement add/remove: `POST P/jail` (single IP or CIDR up to /24 v4 and /48 v6; reason required; TTL choice with ladder defaults; step-up) with **collision checks**: warns when the target overlaps the never-ban list, `admin_cidrs`, ssh allow list, known verified-bot ranges (FCrDNS-verified), the runner IP (hard refusal), HDD's own egress addresses, major resolver ranges, or a CIDR that would affect more than N addresses (default 256) which requires a second confirmation.
3. Implement S-109: never-ban list with CIDR, reason, creator, expiry (optional), scope (platform/tenant), collisions with existing bans listed; adding an entry that overlaps active bans offers "lift overlapping bans" with preview counts; the **runner-IP guard** shows the current runner source address and prevents removing its protection entry during a live acceptance run.
4. Implement propagation display: bans reach the data plane (Redis → proxy memory ≤ 2 s) and the host agent/XDP; per-entry `proxy_ack`, `firewall_ack`, `xdp_ack` timestamps (T-0322), with "not yet applied" explanations.
5. Implement import/export of entries (CSV/JSON) with validation, dry-run summary, a size cap and audit.
6. Implement "promotion review": a queue of auto-promoted candidates (3 orgs within 1 h) with approve/reject and automatic expiry if unreviewed per policy; reasons recorded.
7. Provide metrics and alerts for sudden mass additions (poisoning detection T-0331).
8. Write tests: collision matrix (≥ 40 cases), CIDR size rules, runner guard, propagation ack display, import dry-run, promotion queue, permission matrix, and XSS in reasons.
**Deliverables.**
- API, screens, import/export, tests
**Acceptance.**
- A1: attempts to ban the runner IP, an admin CIDR or HDD egress addresses are refused server-side.
- A2: a global ban is enforced on a test tenant within 2 s and displayed with acks.
- A3: removing an entry unbans within 2 s across proxy and kernel layers.
- A4: collision warnings appear for all listed classes in the matrix.
- A5: every change is audited with reason.
**Tests.**
- Integration (with proxy and fake fw-agent), browser e2e, unit (collisions).
**Notes.** AC-51 covers global jail and never-ban end to end.
