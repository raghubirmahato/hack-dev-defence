### T-0439 · Admin panel security and end-to-end test suite (AC-01 admin isolation, AC-42 operations)
`P22` `[QA][SEC]` · deps: T-0418, T-0419, T-0420, T-0421, T-0422, T-0423, T-0424, T-0425, T-0426, T-0427, T-0428, T-0429, T-0430, T-0431, T-0432, T-0433, T-0434, T-0435, T-0436, T-0437, T-0438 · size: L · owner: qa
**Objective.** Prove the admin plane is isolated, least-privileged, audited and usable.
**Steps.**
1. Generate the **privilege matrix test** from the route registry: for every admin route × each of the 9 roles (4 org, 4 platform, anonymous) × step-up fresh/stale, assert the expected status per B4.2; any route missing from the registry fails the build.
2. Run **horizontal/vertical privilege escalation** tests: org owner session against admin APIs, platform support against mutations, platform admin against staff management, tampered role claims, forged cookies, cross-host cookie replay (app cookie on admin host and vice versa), CSRF on every mutating route, origin/referer checks, and clickjacking.
3. Run the **audit completeness test**: execute every mutation once via the UI and API and assert exactly one audit event with actor, reason (when required), before/after and a valid chain; no mutation without audit (static scan of handlers for the audit macro plus runtime assertion).
4. Run **secret non-disclosure** tests across all admin responses (SMTP password, webhook secrets, API key material, TLS keys, MFA secrets, backup keys).
5. Run **UI end-to-end flows** with a headless browser: bootstrap admin login, tenant suspend/unsuspend with S-148 verification, impersonation start/end with banner, global jail add/remove with propagation, rule pack stage/rollback with signed fixture packs, emergency safe mode with auto-expiry, settings save with secret handling, email template publish with lint failure and success, announcement scheduling, and support lookup.
6. Run accessibility (axe plus keyboard traversal plus zoom/reflow), visual regression in both themes, and performance budgets across all admin screens (LCP lab ≤ 2.0 s, no layout shift above 0.05 on the 1280×800 profile).
7. Run the **abuse simulations**: staff enumeration, bulk lookups, rapid step-up failures, repeated impersonation, mass jail changes; verify alerts and rate limits.
8. Run the **deletion and restore** scenario: delete a tenant, restore from backup in the drill instance, verify the ledger replay keeps it deleted.
9. Record results in the acceptance runner (AC-01 admin part, AC-42), producing evidence with SHA-256.
**Deliverables.**
- test suites, evidence bundle, fixes for findings
**Acceptance.**
- A1: privilege matrix passes with zero unexpected statuses across all routes and roles.
- A2: every mutation is audited exactly once with a valid chain.
- A3: no secret appears in any admin response in the corpus scan.
- A4: all e2e flows pass in both themes; axe reports zero serious/critical issues.
- A5: abuse simulations raise the expected alerts.
**Tests.**
- The suites themselves, run in CI nightly and at gate time.
**Notes.** This suite is part of every later gate's regression set.
