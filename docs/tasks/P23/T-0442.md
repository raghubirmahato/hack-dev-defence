### T-0442 · Analytics API and the analytics overview (S-070)
`P23` `[API][UI]` · deps: T-0441, T-0088, T-0087 · size: L · owner: web
**Objective.** Let owners see traffic, blocked traffic, bandwidth, status classes and latency over any period with fast, honest charts.
**Steps.**
1. Implement `GET D/analytics/overview|timeseries|status|bandwidth|latency` with parameters `from`, `to`, `granularity` (auto selects minute/hour/day by range with documented thresholds), `compare=previous_period`, `tz`; responses include `data_complete_until`, `gaps[]`, `granularity_used` and `approximate: true` for percentiles.
2. Enforce guards: maximum range per granularity (minute ≤ 48 h, hour ≤ 31 d, day ≤ 400 d), RLS, `PERM-analytics.read`, response size caps, and ETag + `Cache-Control: private, max-age=10` on stable ranges.
3. Implement server-side computation with SQL over rollups (no unbounded scans), prepared statements, and a query timeout of 2 s with a clear `ERR-ANALYTICS-002` message.
4. Build S-070 with KPI tiles (requests, blocked, block rate, bandwidth out, p50/p95/p99 latency, error rate), a requests-and-blocked time series (SVG renderer with table alternative and pattern fills for color-blind safety), status class stacked chart, bandwidth chart, latency percentile chart with the "approximate" footnote, a period selector (presets and custom range with validation), time zone indicator, comparison toggle, and domain selector (org-wide or per domain).
5. Handle empty/partial states: new domain with no traffic shows the honest empty state with the verification/cutover checklist link; ranges overlapping a gap show hatched regions labeled "no data".
6. Add chart interactions that do not require a mouse: arrow-key navigation among points with a live-region readout, a "view as table" toggle, CSV download of the displayed series.
7. Add performance work: pre-aggregated queries per granularity, covering indexes, and a small in-process cache keyed by (site, range, granularity) with invalidation by rollup watermark.
8. Write tests: API contract tests (OpenAPI), range/granularity selection edge cases (DST boundaries, leap days), comparison math, gap rendering, RLS/BOLA, a11y (axe, keyboard chart navigation), visual regression in both themes, and performance (p95 API latency ≤ 150 ms with 100M rollup rows).
**Deliverables.**
- API, screen, chart configurations, tests
**Acceptance.**
- A1: displayed totals equal the sum of the underlying rollup rows for random ranges (property test).
- A2: gaps are visible and never plotted as zero.
- A3: every chart has a working table view and CSV export that match its numbers.
- A4: DST and leap-day ranges produce correct buckets in the tested time zones.
- A5: performance budget is met on the reference dataset.
**Tests.**
- Contract, property, browser e2e, performance.
**Notes.** Percentiles are labeled approximate; the bound is stated in the footnote link.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
