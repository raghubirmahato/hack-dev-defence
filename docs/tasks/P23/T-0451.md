### T-0451 · Analytics correctness, scale and accessibility test suite (AC-52)
`P23` `[QA]` · deps: T-0442, T-0443, T-0444, T-0445, T-0446, T-0448, T-0450 · size: L · owner: qa
**Objective.** Prove the numbers are right, fast and readable by everyone.
**Steps.**
1. Build the **ground-truth traffic generator** (`hdd-loadgen analytics-seed` plus a deterministic synthetic proxy-counter source): produce known numbers of requests across status classes, countries, ASNs, paths and categories with known timestamps across multiple time zones, DST boundaries, month ends and gaps; the generator emits the expected aggregates alongside the data.
2. Assert equality between expected aggregates and the API/UI outputs for all analytics endpoints (requests, blocked, status classes, bandwidth, percentiles within the documented error, geo/ASN, top lists, timeline), and between snapshots and reports.
3. Test late and duplicate data, out-of-order batches, clock skew between proxy and database (±5 min), counter reset on proxy restart, multiple proxy nodes writing the same minute, and partition boundary crossing at month end.
4. Test scale: 10 million events and 100 million rollup rows on the lab database; record query latency percentiles for each endpoint and explain plans; validate the budgets (API p95 ≤ 250 ms, event explorer filter p95 ≤ 400 ms, report snapshot for 30 days ≤ 5 s).
5. Test the live monitor under load (T-0446 A1) and measure the end-to-end latency from proxy event to browser row (p95 ≤ 2 s).
6. Run accessibility tests for all analytics screens: axe, keyboard-only flows through charts and tables, screen-reader smoke scripts (NVDA/VoiceOver notes recorded as manual evidence with UNVERIFIED if not performed), 200% zoom and reflow at 320 CSS px, forced-colors, reduced-motion, and contrast checks for chart palettes (including color-blind simulations).
7. Test the report outputs: HTML golden, PDF accessibility oracle, CSV export correctness, and digest claims-lint.
8. Test privacy: IP truncation honored everywhere (grep over API responses and exports), no raw user agents, no query strings in path groups, retention bounds respected.
9. Record results in the acceptance runner as AC-52 with evidence and SHA-256.
**Deliverables.**
- generators, test suites, evidence, performance report
**Acceptance.**
- A1: all computed numbers equal ground truth within documented tolerances on every scenario.
- A2: performance budgets are met or documented deviations exist with optimization tasks.
- A3: accessibility checks report zero serious/critical violations across analytics screens.
- A4: privacy greps find no untruncated IPs where truncation is configured.
- A5: AC-52 status line updated with evidence.
**Tests.**
- The suite itself (CI nightly, plus gate run).
**Notes.** The ground-truth generator is also used by the demo data policy: demo data is generated only for tests and design prototypes, never shipped as product data (R-16).
