### T-0441 · Event storage, partition retention and the rollup pipeline v1
`P23` `[DB][DP][API]` · deps: T-0140, T-0368, T-0214 · size: XL · owner: data
**Objective.** Store events and counters so that queries are cheap, retention is a partition drop, and totals reconcile.
**Steps.**
1. Finalize `waf_events` as a monthly-partitioned table with a covering index set: `(site_id, ts desc)`, `(site_id, ip_key, ts desc)`, `(site_id, category, ts desc)`, `(ray_id)` unique per partition plus a global lookup table `ray_index(ray_id, site_id, month)` for O(1) Ray ID resolution, and a trigram index on the normalized path template; confirm RLS policies on every partition (partition creation job copies policies and grants).
2. Implement the partition manager job: creates next-month partitions ahead of time (two months), detaches and drops partitions older than the maximum retention across plans (default 30 days events, 400 days audit, 90 days webhook deliveries), refuses to drop a partition while a legal hold flag exists, and writes an audit event for every drop. No row-by-row deletes on hot partitions.
3. Implement per-plan retention visibility: queries are bounded by `now - plan.event_retention_days` regardless of physical presence; for orgs with shorter retention than the global max, an off-peak batched purge deletes eligible rows from **closed** partitions only (bounded batches of 5,000 with sleep), documented as the only row-level delete.
4. Implement counter ingestion: the proxy flushes per-site per-minute counters (requests by status class, mode, verdict; bytes in/out; blocked by category; challenge issued/solved; rate-limited; origin errors; latency histograms in fixed log-scale buckets) through the queue table `proxy_counter_batches` (insert-only); the worker folds them idempotently into `rollup_minute` using batch ids to prevent double counting.
5. Implement rollups to hour and day by upsert from minute rows; dimensions as in the data model (`all`, `category`, `status_class`, `country`, `asn`, `rule`, `path_group`) with cardinality caps (top 200 keys per bucket plus `other`), `path_group` derived from path templates (never raw paths), and `asn`/`country` from enrichment done at event time.
6. Implement percentile handling: store HDR-style fixed bucket histograms per minute and merge buckets for hour/day (never average percentiles); document the relative error bound (≤ 2%) and show "approximate" labeling on percentile charts.
7. Implement late-data handling (5-minute window), backfill (`xtask rollup backfill --from --to`), reconcile job (sum of minutes equals hour equals day for additive metrics; mismatches raise an alert and are auto-repaired from minutes), and gap detection (a minute with no counter batch while the proxy was up is marked `gap`, never zero).
8. Implement privacy: events store the IP key (v4 /32, v6 /64) or the org's truncated form per setting; analytics rollups hold no IPs; top-IP queries run on events within retention only.
9. Write tests: idempotent folding (replay the same batch 10 times), partition lifecycle on a scratch database, retention bounds, RLS on partitions, reconcile repairs, histogram merge accuracy against exact percentiles on generated data (error ≤ 2%), and a migration-forward/rollback test.
**Deliverables.**
- migrations, partition manager, counter ingestion, rollup jobs, `xtask rollup`, docs `docs/ANALYTICS.md`
**Acceptance.**
- A1: replaying counter batches never changes totals (property test).
- A2: dropping a partition removes data older than retention without long locks (lock time < 50 ms measured).
- A3: hour and day rollups reconcile with minutes exactly for additive metrics.
- A4: percentile merge error ≤ 2% on the reference datasets.
- A5: a proxy outage produces `gap` markers, never zeros.
**Tests.**
- Integration (Postgres), property tests, performance (ingest 5,000 counter rows/s).
**Notes.** Totals come from counters and not from events; `docs/ANALYTICS.md` explains why event counts differ from request counts.

## Definition of done for this task's tags (section 0.7)

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.
