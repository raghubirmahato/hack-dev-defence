### T-0445 · Event explorer and event detail (S-066)
`P23` `[API][UI][DB]` · deps: T-0441, T-0252, T-0253 · size: L · owner: web
**Objective.** Let owners search events, understand a single decision and act on it.
**Steps.**
1. Implement `GET D/events` with keyset pagination and filters: time range, verdict (`blocked|would_block|challenged|rate_limited|allowed_notable|banned`), category/subtype, rule id, severity, hardness (hard/soft), IP or CIDR (respecting truncation), ASN, country, method, status, path template contains, query parameter name, user-agent family, mode, ban state, Ray ID exact, auth endpoint flag, cross-site context flag, `partial_scan`; combine with AND, support NOT for selected fields, and saved views per user.
2. Implement `GET D/events/{ray}` with a decision timeline: stages passed, normalization views used (raw/decoded/canonical flags), matched rule ids with scores, the policy branch (mode, thresholds, exceptions considered), whether a ban was created and why (ladder step, TTL), redacted evidence snippet (≤ 512 B with the matched span marked), related events from the same IP in the last hour, and cross-links to the ban and appeal.
3. Build the explorer table (T-0087 infrastructure): column chooser, density, keyboard navigation, selection with bulk actions (ban IPs, create exceptions from selection requires a single rule/scope), export (T-0450), and URL-addressable state.
4. Build the event drawer/page: copy Ray ID, copy "support summary" (no sensitive data), "This is a false positive" (creates a scoped exception with a preview of what it would have affected, links to T-0226) and "Block this IP" actions, and a **"Why was this blocked?"** explanation in plain language derived from the verdict components (never revealing proprietary rule bodies to visitors; owners see rule ids and descriptions).
5. Add the evidence display safety: evidence is shown in a monospace block that is HTML-escaped, never rendered, with zero-width characters made visible, long values truncated with "show more" bounded to 512 bytes total, and the redaction library's markers visually distinct.
6. Implement privacy controls: evidence snippet display requires `PERM-event.read`; orgs can disable evidence snippet storage (events still record category and rule); the setting is respected at write time.
7. Implement performance: keyset pagination on `(ts, ray_id)`, query planner checks (`EXPLAIN` tests ensure index use for the main filter combinations), 30-day default window, and an early error for filter combinations lacking a time bound.
8. Write tests: filter matrix (≥ 60 combinations vs. a naive in-memory filter), keyset pagination under concurrent inserts (no duplicates/gaps), evidence XSS corpus (200 payloads escaped), RLS/BOLA (Ray ID of another org returns 404), explanation text snapshot tests, and a11y/keyboard tests.
**Deliverables.**
- API, screens, saved views, explanation generator, tests
**Acceptance.**
- A1: no combination in the matrix causes a sequential scan on the main events table (planner assertions).
- A2: Ray IDs of other orgs always return 404 with identical timing within noise (timing test).
- A3: every evidence XSS payload is displayed inert.
- A4: the false-positive action creates an exception whose preview matches subsequent behavior.
- A5: pagination never skips or repeats rows under concurrent inserts.
**Tests.**
- Integration (Postgres), property, browser e2e, security.
**Notes.** S-066 is linked from notifications, bans, appeals and reports; the deep link format is stable (`/domains/{id}/events/{ray}`).

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.
