### T-0446 · Live threat monitor (S-065): SSE event source, backpressure and accessible live regions
`P23` `[UI][API][DP]` · deps: T-0086, T-0445, T-0368 · size: L · owner: web
**Objective.** Provide a real-time view of what the shield is doing that remains usable and honest under load.
**Steps.**
1. Implement the event source: the proxy publishes notable events through the `Bus` trait (`hdd:events:{site}`: Redis streams or pub/sub when hosted, an in-process bounded broadcast in the local profile; capped, e.g., 5,000 entries) in addition to the batch insert; the API exposes `GET D/events/stream` as SSE on the same-origin `/api/v1` mount with RLS, `Last-Event-ID` resume, 15 s heartbeats, and server-side filters (verdict, category, severity); per-user and per-org concurrent stream caps (3 per user, 20 per org).
2. Implement sampling and backpressure: a display rate cap of 20 events/s per stream; excess events are summarized into `skipped` messages ("312 events not shown; use filters"), counts remain exact in the tiles; slow consumers are disconnected with a reconnect hint; the server never buffers unboundedly.
3. Build S-065 per B12.2: top tiles (events/min, blocked/min, active bans, top category), the live table (time, IP key, country, method, path template, category, verdict, mode, ban chip), row click opens the detail drawer, pause/resume with buffered count, filters, "freeze on hover/focus" so rows do not move while the user reads, clear, and a mode banner when the site is in `monitor` ("Would block" labels instead of "Blocked").
4. Implement accessibility: the live region defaults to `aria-live="off"`, with an opt-in "announce critical events" toggle using polite announcements limited to one per 10 s; keyboard shortcuts for pause, filter focus and row navigation; reduced-motion respected; contrast checked for all verdict chips (text + icon + color).
5. Implement the fallback path: if SSE fails twice, switch to HTMX polling every 5 s with a visible "Polling" indicator; offline detection shows a stale banner.
6. Implement the attack-mode overlay: when the event rate exceeds a threshold, show a banner summarizing the dominant category and suggested actions (links), and avoid DOM thrash by batching DOM updates per animation frame.
7. Add security: events rendered via safe templates, evidence not shown in the live table (details only on click), CSP-compatible island with no inline handlers, per-stream authorization re-checked on every reconnect.
8. Write tests: SSE reconnect with `Last-Event-ID` (no duplicates, no loss within the stream cap), backpressure behavior with a slow client, 5,000 events/s injection (UI remains responsive, memory bounded), filter correctness, polling fallback, a11y live-region behavior with a screen-reader smoke script, and cross-tenant isolation (stream of org A never delivers org B events).
**Deliverables.**
- stream endpoint, island, screen, tests
**Acceptance.**
- A1: at 5,000 events/s injected the server memory stays bounded and the UI shows exact counts with a sampled table.
- A2: resume after disconnect delivers missed events within the stream cap without duplicates.
- A3: org isolation holds under adversarial stream subscription attempts (BOLA tests).
- A4: the live region does not announce by default and critical announcements are rate limited.
- A5: reduced-motion and keyboard-only operation pass.
**Tests.**
- Integration, load (lab), browser e2e, a11y.
**Notes.** The monitor is a convenience view; the authoritative record is the event store.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
