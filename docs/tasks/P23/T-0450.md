### T-0450 · Data export and portability (events, analytics, configuration)
`P23` `[API][SEC][OPS]` · deps: T-0445, T-0447, T-0130 · size: M · owner: api
**Objective.** Let owners take their data out safely, within limits, with audit and no accidental leaks.
**Steps.**
1. Implement asynchronous export jobs: `POST D/exports` with type (`events`, `bans`, `dns_zone` (BIND format), `config` (YAML/JSON policy and rules without secrets), `audit`), filters, format (CSV, JSON Lines), field selection from an allowlist, and redaction options (IP truncation level, evidence snippet inclusion); job status polling, completion notification.
2. Enforce limits: max rows per export by plan (default 1,000,000), max concurrent jobs per org (2), max export frequency, size caps (500 MB compressed), and expiry of artifacts (24 h) with signed one-time-ish links (valid for 24 h, revocable).
3. Stream results from the database using server-side cursors in bounded memory, gzip them, compute SHA-256, write a manifest (filters, row count, time, tool version), and store encrypted at rest with the same envelope store; downloads are authenticated (session or API key) in addition to the signed link when the org setting `require_auth_for_downloads` is on.
4. Implement CSV safety: formula injection protection (prefix `'` for cells starting with `=`, `+`, `-`, `@`, tab, CR) with an option "raw" disabled by default; correct quoting; UTF-8 BOM option for spreadsheet compatibility.
5. Implement the configuration export/import round trip (`config` type) supporting dry-run import diffs and validation (T-0237 policy document), so owners can version control their policy.
6. Implement audit: every export request, completion and download is audited with filter summary and row counts.
7. Implement the org-level account export (T-0130) reuse and the platform legal-hold export pathway with dual approval (admin screens).
8. Write tests: large export memory profile (1M rows, memory < 100 MB), CSV injection corpus, redaction options, plan limits, link expiry/revocation, BOLA on job and artifact ids, config round trip, and failure cleanup (no orphan artifacts).
**Deliverables.**
- export service, jobs, UI controls in S-066/S-072/S-048/S-084, tests, docs
**Acceptance.**
- A1: exports of 1,000,000 rows stay within the memory bound.
- A2: CSV injection payloads are neutralized in all cells.
- A3: artifacts and links expire and cannot be fetched cross-org.
- A4: config export contains no secrets (schema test) and imports back to an identical policy hash.
- A5: all exports are audited.
**Tests.**
- Integration, property, security, performance.
**Notes.** SIEM streaming is separate (T-0460); this task covers on-demand exports.

## Definition of done for this task's tags (section 0.7)

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.
