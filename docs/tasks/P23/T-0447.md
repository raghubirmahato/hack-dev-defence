### T-0447 · Report data model, section library and generated runs (S-073)
`P23` `[DB][API][UI]` · deps: T-0441, T-0442, T-0444 · size: L · owner: data
**Objective.** Define reports as reproducible snapshots of defined sections, independent of output format.
**Steps.**
1. Create the report schema: `report_templates` (system-defined and org-defined), `report_schedules`, `report_runs` (status, period, domain scope, snapshot hash, output artifacts), `report_artifacts` (HTML, PDF, CSV, JSON; storage path; size; SHA-256; expires_at), with RLS and retention (default 12 months for snapshots, 90 days for artifacts).
2. Define the **section library** with versioned section types: Executive summary, Traffic overview, Attack summary (categories, trends), Top attackers (with IP truncation honored), Bans and appeals, Rule and exception changes (from audit), DNS and TLS health (certificates, expiries, DNS changes), Origin protection status (lockdown state, readiness score), Vulnerability exposure summary (when P27 data exists; otherwise the section reports "not configured"), Operational notes (free text by the author), Data completeness (gaps, partial scans, truncated bodies counts).
3. Implement the **snapshot builder**: given (org, domains, period, sections, locale, time zone) it queries the analytics layer within a single consistent read (repeatable-read transaction) and produces an immutable JSON snapshot with a schema version and hash; all renderers consume only the snapshot; re-rendering never re-queries live data.
4. Provide system templates: Weekly summary, Monthly security review, Incident report (period around an event cluster, includes timeline), DNS/TLS health, Exposure and patch status; org-defined templates cloned from them with section selection and ordering.
5. Build S-073: template gallery, generated runs table (period, domains, status, size, generated by/at), run detail (preview of the HTML rendering, downloads, share link management with expiring signed URLs and optional password disabled by default), delete run, and permission gating (`PERM-report.read/write`).
6. Implement the honest-language rules in sections (claims-lint for generated text): "Detected N requests matching attack patterns; N were blocked in block mode" and statements of limits ("Signature-based detection may miss novel attacks"); never "prevented all attacks".
7. Implement the **completeness block**: every report lists known data gaps and the percentage of requests whose bodies were only partially inspected during the period.
8. Write tests: snapshot determinism (same inputs → same hash), renderer purity (renderers do no I/O), consistency between snapshot totals and analytics API totals, section versioning migrations (old snapshots still render), RLS/BOLA on runs and artifacts, signed link expiry, and claims-lint over all generated strings.
**Deliverables.**
- schema, snapshot builder, section library, S-073, tests, docs
**Acceptance.**
- A1: re-rendering a stored snapshot after data changes yields byte-identical HTML (golden test).
- A2: snapshot totals equal analytics API totals for the same period.
- A3: a report generated for an org never contains data from another org (BOLA tests over all sections).
- A4: shared links expire and are revocable.
- A5: claims-lint passes for all templates and locales.
**Tests.**
- Unit, golden, integration, security.
**Notes.** The PDF pipeline (T-0448) is one renderer of the snapshot; the HTML renderer is canonical.

## Definition of done for this task's tags (section 0.7)

### `[DB]`: Adds or changes schema

Expand/contract migration only; `org_id` and RLS policy for tenant-owned tables; indexes justified; `sqlx` offline data refreshed; forward migration plus restore-from-backup test; data-retention rule documented.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.
