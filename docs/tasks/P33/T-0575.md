### T-0575 · Access gate (S-131): protect sensitive paths before they reach the origin
`P33` `[UI][API][DP][SEC]` · deps: T-0355, T-0362, T-0343, T-0232, T-0242, T-0337, T-0562, T-0106, T-0114 · size: XL · owner: dp
**Objective.** Let an owner put an HDD-enforced barrier in front of administration areas, database tools and debug endpoints of an origin that may itself be vulnerable.
**Steps.**
1. Add `access_gate_rules` and `access_gate_credentials` (B5.6) with migrations, RLS and indexes; add `PERM-gate.*`, `AUD-gate.*`, `ERR-GATE-*` and `MET-hdd_gate_decisions_total` (B4.2, B7, B8, B9).
2. Implement stage 8a: a compiled path trie per site with both raw and canonical match, priority and `allow_paths`, executed before rate limiting and inspection with a 20 µs budget; build the canonicalization (decode, dot-segments, repeated slashes, path parameters, optional case folding) on the WAF canonicalizer (T-0242) so both agree.
3. Implement the policies: `ip_allowlist`; `hdd_login` (gate login page, HDD-generated secrets stored as HMAC-SHA-256 and operator-chosen passwords through the password library of T-0106 behind the hashing semaphore, optional TOTP via T-0114, server-side session in `KvStore`, `__Host-hdd_gate` cookie, binding to user-agent hash and IP bucket, CSRF, proof of work when under attack); `basic` (consume and strip `Authorization`, cache a successful verification for at most 60 s, warn on origin challenge conflict); `signed_link` (secret in the URL fragment, nonce-protected confirm page then POST, single-use server state, path-scoped `__Secure-hdd_gate_p` cookie, 24 hours default and 7 days maximum, revocable); `mtls` rejected with `ERR-VAL-005`.
4. Implement failure behavior (`deny`, `challenge`, `redirect_login`) and identical responses for unknown user and wrong secret; the cost controls of C19.2 (per-address token bucket and the global hashing semaphore with `ERR-GATE-005` before any hash); throttling on (username, address bucket) pairs (5 failures per 10 minutes) where a per-username global counter above a threshold escalates to proof of work and an alert and never hard-locks the account (R-19), and recognised devices (a valid gate cookie, an earlier success from the same address bucket) are exempt; feeding credential-stuffing detection (T-0343) and the ban policy.
5. Implement the templates (WordPress admin with `admin-ajax.php` allowed and `xmlrpc.php` denied, phpMyAdmin and Adminer, Spring actuator, `/admin`, `/manager`, `/server-status`, `/.env`, `/.git`, `/debug`, API docs pages) and the self-lockout preview (`ERR-GATE-004`, R-19) in API and UI, plus `hddctl gate disable --site`.
6. Build S-131 (rule list, editor, template picker, credentials with one-time reveal, link generator) and the API of B6.7 with OpenAPI entries and the permission matrix tests.
7. Write the **bypass suite**: at least 200 path shapes (encoding layers, dot segments, double slashes, case, path parameters, trailing characters, h2 `:path` forms, absolute-form request targets, `Host` tricks, method override headers) against gated prefixes, each of which must be gated.
8. Write abuse tests: credential guessing against the gate login, gate cookie theft and replay from another address, signed-link replay after use or expiry, enumeration differences, CSRF on the login form.
**Deliverables.**
- migrations, stage 8a, policies, templates, S-131, API, bypass and abuse suites
**Acceptance.**
- A1: all 200+ bypass shapes against a gated `/wp-admin/` receive the gate decision, none reaches the origin (origin access log check on `hdd-canary`).
- A2: unknown user and wrong secret are indistinguishable in status, body and timing (statistical test).
- A3: a gate cookie replayed from a different IP bucket or user agent requires re-authentication.
- A4: a rule that would block the acting user's current address returns `ERR-GATE-004` until acknowledged.
- A5: gate decisions add at most 20 µs p99 on non-gated paths and 100 µs on gated paths (benchmark; session lookups served from the in-process cache, paths up to 2 KiB).
- A6: 10,000 unauthenticated requests per second carrying Basic credentials to a gated path never run more concurrent password hashes than the semaphore allows, and a distributed wrong-password flood against `admin` does not lock the real operator out.
**Tests.**
- Unit and property tests for matching; integration with proxy and canary; abuse suite; browser tests for S-131 and the login page.
**Notes.** The gate narrows exposure; it does not replace the WAF, which still inspects authenticated traffic.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).
