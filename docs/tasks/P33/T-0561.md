### T-0561 · Runtime profile model, capability matrix and the parity contract
`P33` `[OPS][SEC][DOC]` · deps: T-0004, T-0006, T-0009 · size: L · owner: infra
**Objective.** Make `local` and `hosted` first-class, validated profiles that share one code path, and make "same behavior in both" a tested contract.
**Steps.**
1. Write the ADR "One code path, two runtime profiles" recording R-31, the list of things a profile may change, and the enforcement mechanisms below.
2. Add `runtime:` to the live-profile schema (section 8) and the environment variables of B10 (`HDD_RUNTIME_PROFILE`, `HDD_DATA_DIR`, `HDD_LOCAL_*`, `HDD_KV_BACKEND`, `HDD_HOSTING_PROFILE`) in `hdd-common::profile`, with typed validation and JSON Schema output.
3. Encode the capability matrix of C18.2 as code (`Profile::capabilities()`): for each capability (authoritative DNS on 53, kernel enforcement, ACME, `saas`, open signup, `full_ns`, LAN exposure, embedded database, memory store) the result is `allowed`, `allowed_with_ack`, or `unavailable(ERR-LOCAL-001, reason)`. Every refusal path in the API and UI goes through this function.
4. Implement `xtask profile-lint`: fails if `runtime.profile`, `Profile::` or profile `cfg` checks appear in the detection, pipeline, authentication or tenancy crates, or if any crate other than `hdd-common::kv` uses the Redis client (`xtask kv-lint`).
5. Implement `xtask profile-parity`: runs the core SQLi set (M1 to M6 plus variants), the benign corpus, the BOLA suite and a ban lifecycle scenario under both profiles with the same fixtures and compares the decision fields (action, category, subtype, rule_id, hardness, score, threshold, vector, field, evidence) and the ban intent (reason, scope, TTL step), excluding identity key, enforcement backend, `config_revision` and timestamps; any other difference fails (AC-55).
6. Extend `hddctl preflight` with a "what can run here" section: for the detected platform and profile, which acceptance checks can run and which are UNVERIFIED(`environment_unsupported`) with the reason, so a Windows builder without Docker gets an honest plan instead of an error.
7. Extend the first-response protocol output (section 9) with the build-track decision (Track H or Track L) computed from discovery results.
8. Write `docs/LOCAL.md` and `docs/HOSTING.md` skeletons with the comparison table of C18.2.
**Deliverables.**
- profile schema and validation, capability matrix, `profile-lint`, `kv-lint`, `profile-parity` skeleton, preflight section, ADR, docs skeletons
**Acceptance.**
- A1: `local` with `deployment_mode: saas`, open signup or `full_ns` is refused with `ERR-LOCAL-001` at config load and in the API.
- A2: `xtask profile-lint` fails when a profile check is added to `hdd-waf-core` (injected-violation test) and passes on the clean tree.
- A3: `xtask kv-lint` fails when a Redis client call appears outside `hdd-common::kv`.
- A4: `profile-parity` runs on the available backends and reports zero differences on the seed corpus.
- A5: on a machine without Docker, Postgres, Redis, `nft` and `dig`, `hddctl preflight` prints Track L and a correct list of runnable and UNVERIFIED checks, and exits 0 for the build track.
**Tests.**
- Unit: matrix table tests; config validation; integration: parity harness; xtask lint tests with injected violations.
**Notes.** The matrix is the single place that decides what a profile may do. Adding a capability without adding it to the matrix fails `xtask profile-lint`.

## Definition of done for this task's tags (section 0.7)

### `[OPS]`: Deployment, operations, runbooks

Idempotent; dry-run mode; documented undo; SSH-lockout protection for host-affecting changes; restore or rollback exercised.

### `[SEC]`: Security-relevant logic

Abuse cases written as tests; STRIDE delta in `docs/STRIDE.md`; no secret in logs; constant-time comparison where secrets are compared; failure modes fail closed; panic-free on hostile input (proptest or fuzz target).

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
