### T-0571 · Hosting profiles H1 to H5 and `hddctl hosting check`
`P33` `[OPS][API][UI]` · deps: T-0561, T-0522, T-0217 · size: L · owner: ops
**Objective.** Tell an operator, with evidence, whether a server is ready to run HDD unattended, and what to fix.
**Steps.**
1. Implement the check engine with the 23 checks HC-01 to HC-23 of C18.10, each returning PASS, FAIL or UNVERIFIED(reason) and a remediation key; checks run read-only and contact third parties only through the egress allowlist.
2. Implement the port checks carefully: bindability tests (bind and release), detection of the `systemd-resolved` stub listener and exact remediation text, reachability from outside through an operator-supplied vantage point, the runner, or an allowlisted probe; without one the result is UNVERIFIED(`capability_not_supplied`).
3. Implement `hddctl hosting reboot-test`: schedules a reboot only after an explicit operator confirmation, with the SSH-lockout protection timer, then verifies that all services return within 5 minutes with no manual step and records the evidence.
4. Implement the profile classification (H1 to H5) with the reasons, including the explicit "unsupported" result for platform-as-a-service targets and the NAT/dynamic-address warnings for H5.
5. Implement `GET/POST P/hosting/check` and `PUT P/hosting/profile`, the S-136 hosted screen, `AUD-hosting.*` events, and the readiness integration (hosting checks feed the 24/7 readiness list, never the security score).
6. Write `docs/HOSTING.md`: choosing a profile, minimum specs, provider notes (ports, SMTP blocks, reverse DNS), DNS and glue steps, a step-by-step first deployment, and the remediation text for every HC item.
7. Add the unit tests with simulated host facts and the integration test on the pilot VPS.
**Deliverables.**
- check engine, reboot test, profile classifier, API and screen, `docs/HOSTING.md`, tests
**Acceptance.**
- A1: on the pilot VPS all HC items are PASS or UNVERIFIED with a reason; none is silently skipped.
- A2: on a machine whose `systemd-resolved` holds port 53, HC-06 FAILs with the exact remediation.
- A3: a platform-as-a-service target is classified H4 "unsupported" with the reason.
- A4: the reboot test refuses to run without the operator confirmation and succeeds on the pilot VPS with evidence.
- A5: running the check twice yields identical results on an unchanged host.
**Tests.**
- Unit with host-fact fixtures; integration on a VM; operator-confirmation test.
**Notes.** The check measures readiness; it never certifies availability.
