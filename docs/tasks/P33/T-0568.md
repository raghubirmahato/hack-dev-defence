### T-0568 · Local sites, names and the hosts helper; `local_only` onboarding and embedded DNS
`P33` `[UI][API][OPS]` · deps: T-0564, T-0566, T-0153, T-0155, T-0163, T-0168, T-0172, T-0207, T-0355 · size: L · owner: ui
**Objective.** Let a person add a site and see it protected within minutes locally, with no DNS, no certificate authority and no router changes.
**Steps.**
1. Add the `local_only` integration mode to the domain model (T-0153) and to the wizard (T-0058 design): step 1 name (slug to `<slug>.hdd.localhost`), step 2 origin (loopback or LAN origin through `egress.private_origin_allowlist`, the readiness warning, never the metadata ranges), step 3 protection preset (Monitor first by default), step 4 go live; DNS scan, delegation and ownership proof steps are skipped for `local_only` and explained.
2. Implement the certificate path for local sites (T-0566) and the data-plane host router entries (T-0355) for local names, including `sandbox.<suffix>` backed by `hdd-canary` on loopback.
3. Implement the hosts helper of C18.8 (`apply`, `remove`, `status`): a marked block, diff display, consent, backup of the original, elevation instructions, idempotence, and Windows and Unix path differences; add `AUD-runtime.hosts_changed`.
4. Implement the optional embedded DNS server on port 5300 from the T-0207 core for `hdd.localhost` and operator zones, with the protocol hardening already present (no recursion, minimal `ANY`, RRL) and a clear note that the OS resolver does not use it.
5. Implement the tunnel guidance screen (S-136 local): steps to run a tunnel to the `tunnel_http` listener, the CNAME to create, and the origin-lockdown requirement, without HDD calling any provider.
6. Add local-mode readiness checks to the Protection Readiness engine (T-0172): "origin reachable only from HDD or loopback", "exposed to LAN", "TLS trusted on this machine", "running only while awake".
7. Write end-to-end tests: add a site, browse it over HTTPS, send the six mandated payloads as GET shapes to the site and as bodies to the sandbox route only (section 2.2), confirm block, ban and event; remove the site and confirm the hosts block and certificate are cleaned up.
**Deliverables.**
- `local_only` mode, wizard variant, hosts helper, embedded DNS option, readiness checks, tests
**Acceptance.**
- A1: a new local site is reachable over HTTPS in a browser within 3 minutes of effort on a clean machine, with zero DNS or router changes.
- A2: `hosts apply` then `remove` leaves the hosts file byte-identical to the original when nothing else changed it in between (golden test), and never touches lines outside the block when something else did.
- A3: `dig @127.0.0.1 -p 5300 hdd.localhost` answers authoritatively and refuses recursion.
- A4: the metadata and link-local ranges are rejected as origins even with the private-origin allowlist enabled.
- A5: the six mandated payloads sent to the local site as GET shapes, and to the sandbox route as bodies, are blocked and the sending identity is banned (inspect-first gate honored).
**Tests.**
- Browser end-to-end; hosts-file golden tests; DNS conformance subset; SSRF-range tests.
**Notes.** Local sites make the product demonstrable in minutes; they are not a substitute for the hosted onboarding checks.
