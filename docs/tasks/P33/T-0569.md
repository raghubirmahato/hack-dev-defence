### T-0569 · Packaging, installers, autostart and the cross-platform CI matrix
`P33` `[OPS][QA]` · deps: T-0564, T-0566, T-0516, T-0518 · size: L · owner: infra
**Objective.** Produce signed, verifiable local-run artifacts for Windows, macOS and Linux, and prove them on each operating system in CI.
**Steps.**
1. Implement `cargo xtask package` producing: Windows x64 zip (and an optional MSI manifest), macOS arm64 and x64 archives (and pkg metadata), Linux x64 and arm64 tarballs; each contains `hdd-local`, `hddctl`, licenses, the SBOM, a README with the verification commands and a `SHA256SUMS` file; signing with the release key of T-0518 (and platform code signing as an operator-supplied option, UNVERIFIED if absent).
2. Generate declarative service definitions from Rust structs: Task Scheduler XML, launchd plist and `systemd --user` units for `hdd-local autostart enable|disable`, never installing anything without an explicit command.
3. Implement `hdd-local upgrade` (verify signature, stage, swap, health check, rollback) and the version-skew rule with the embedded database (dump and restore for major upgrades).
4. Implement uninstall (`hdd-local reset --purge` with typed confirmation), which removes the data directory, trust entries and hosts block that HDD created, and nothing else.
5. Add the CI matrix: Windows Server, macOS (arm64) and Ubuntu runners build, run unit and integration tests with the embedded database, run `hdd-local selftest`, run the browser smoke tests, and run `profile-parity`; Linux also runs the hosted subset with Docker.
6. Add cross-platform conformance tests for path handling, line endings, file permissions (ACL checks on Windows), console signals, long paths, and non-ASCII user directories.
7. Document installation, verification, antivirus and firewall prompts, and uninstall in `docs/LOCAL.md`.
**Deliverables.**
- packaging tool, service templates, upgrade and uninstall paths, CI matrix, docs
**Acceptance.**
- A1: the artifacts for all three operating systems build reproducibly from a tagged commit and verify with the published checksums and signature.
- A2: the CI matrix runs the self-test green on Windows, macOS and Linux.
- A3: `autostart enable` then `disable` leaves no scheduled item behind (per-OS check).
- A4: `reset --purge` removes only HDD-created data and trust entries (before/after inventory).
- A5: upgrade with a corrupted artifact is refused and the old version keeps running.
**Tests.**
- CI jobs per OS; signature tests; before/after inventory tests.
**Notes.** Unsigned local artifacts are labeled as such; platform notarization is an operator option, not a promise.
