### T-0576 · API discovery, inventory and enforcement preview (S-132)
`P33` `[UI][API][DP]` · deps: T-0302, T-0303, T-0304, T-0250, T-0368 · size: XL · owner: dp
**Objective.** Know the API surface a site really exposes, flag shadow and zombie endpoints, and let the owner enforce schemas safely.
**Steps.**
1. Add `api_inventory` and `api_specs` (B5.6), `PERM-apidisc.*`, `AUD-apidisc.*`, `ERR-APIDISC-*`, and the metrics of B9 with migrations and RLS.
2. Implement the learner as an asynchronous consumer of the event pipeline (T-0368) so the hot path only emits compact observations: path templating by the rules of C19.3 (typed shape patterns become `{param}` immediately, before counting; otherwise literal segments stay unless at least 50 distinct values appear at that position under the same parent template with no value above 20% of requests), parameter type and bound statistics, JSON property names (collapsed beyond 64 distinct per object), credential presence, and no values except enumerations of at most 20 short values for parameters whose names are not on the sensitive-name list.
3. Implement the states of C19.3 (`discovered`, `approved`, `shadow`, `deprecated`, `blocked`) with the 30-day zombie rule and the proposal rule (200 requests over 24 hours).
4. Implement import of OpenAPI 3.0 and 3.1 (JSON, YAML; 5 MiB; depth 64; local `$ref` only; no remote fetch) and GraphQL SDL with hard parser limits, fuzz targets and `ERR-APIDISC-001` pointers.
5. Wire the inventory to the enforcement engine of T-0302 and the GraphQL policy of T-0304: per-endpoint method, content type, schema, size and auth-presence checks, plus the response-property monitor, all as soft signals that never ban alone.
6. Implement the **seven-day preview**: replay stored observation summaries (not bodies) against the proposed enforcement and list would-have-blocked counts per endpoint; switching to `block` requires acknowledging it (`ERR-APIDISC-002`).
7. Build S-132 (tiles, table, drawer, enforcement panel, spec import) per B12.2 and the API of B6.7 with OpenAPI entries.
8. Write tests with a real sample API (the `hdd-canary` API fixtures and the Vuln-Lab API apps in the lab): shadow endpoint detection, mass-assignment rejection, type confusion, GraphQL depth and alias limits, spec import round trips, and a privacy test proving no request value appears in the stores.
**Deliverables.**
- learner, inventory, import, preview, S-132, API, tests
**Acceptance.**
- A1: after 200 mixed requests, the inventory lists every exercised endpoint with correct templates (no more than 2% wrong templates on the fixture API).
- A2: an endpoint absent from an imported spec but present in traffic is marked `shadow` within one learner cycle.
- A3: an approved schema with `additionalProperties: false` rejects a mass-assignment request in `block` mode and only logs in `monitor` mode.
- A4: no request or response value is present in the inventory tables or logs except enumerations of non-sensitive parameters (privacy test with canary values in sensitive-named parameters, free-text fields, JSON keys and path segments).
- A5: a malicious 5 MiB OpenAPI document (deep nesting, remote `$ref`, entity-like expansion) is rejected within limits without memory growth.
**Tests.**
- Integration with fixture APIs; fuzz targets for importers; privacy test; browser tests for S-132.
**Notes.** Positive security is only as good as the description; the product says which endpoints are enforced and which are only observed.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DP]`: On the data-plane hot path (proxy, DNS, WAF, firewall)

Hot path never awaits the database; bounded memory and queues; criterion benchmark or histogram; fuzz or proptest; behavior when Redis or Postgres is down specified and tested; metric with drop counter.
