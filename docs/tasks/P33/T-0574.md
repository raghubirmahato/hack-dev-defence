### T-0574 · 24/7 operations: off-site backups, restore automation, upgrade windows, uptime measurement and runbooks
`P33` `[OPS][DOC]` · deps: T-0523, T-0524, T-0525, T-0527, T-0572 · size: L · owner: ops
**Objective.** Operations that continue without the operator being present, and evidence that they work.
**Steps.**
1. Extend backups (T-0523) with the targets of C18.11 item 6 (`local`, `sftp`, `s3` through the egress client and the allowlist), client-side encryption with an operator-held key, retention (14 daily, 8 weekly, 12 monthly), optional WAL archiving for a 15-minute RPO, and escrow separation (master key and pepper never in the data archive).
2. Implement automatic weekly restore-to-scratch verification and the monthly drill, with `MET-hdd_backup_age_seconds`, alerts when the last good backup is older than 26 hours or the last drill older than 35 days, and a clear "your backups are not verified" banner in S-124/S-136.
3. Implement upgrade windows: `hddctl upgrade --window "Sun 03:00-04:00"` with health-check gates, automatic rollback, socket-handoff proxy restarts, and a pre-upgrade backup; add the OS-patching coordination (reboot window, `needrestart` handling) to the runbooks.
4. Implement measured uptime: combine the external heartbeat and an operator-vantage probe into an uptime figure with the measurement method stated; show it in S-100 and S-008 only with its method and observation window, never as a promise.
5. Write the runbooks listed in C18.11 item 9 under `docs/RUNBOOKS/`, each with symptoms, checks, commands, expected output, escalation, and the metric or alert that triggers it.
6. Run a game-day: power loss, disk full, Postgres down, certificate failure and a bad rule rollout against the pilot; record time to recovery and gaps found.
7. Add the 24/7 readiness list (watchdog, backups verified, drill current, heartbeat live, upgrades tested, runbooks present) to S-136 with PASS/FAIL/UNKNOWN per item.
**Deliverables.**
- backup targets and verification, upgrade windows, uptime measurement, runbooks, game-day report
**Acceptance.**
- A1: a backup to a remote target is created, downloaded, decrypted and restored into a scratch database with row-count and hash equality.
- A2: a missed backup raises the alert within 30 minutes of the 26-hour threshold.
- A3: an upgrade that fails its health check rolls back automatically with the old version serving (fault injection).
- A4: the displayed uptime figure always carries its method and window; a unit test fails any template that renders it without them.
- A5: every runbook contains symptoms, commands and a verified expected output (docs test).
**Tests.**
- Backup and restore integration; upgrade fault injection; claims-lint on uptime copy; docs tests.
**Notes.** HDD measures uptime; the provider's SLA and the operator's practices decide it.
