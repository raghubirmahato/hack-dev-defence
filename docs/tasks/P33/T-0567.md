### T-0567 · Local control-plane hardening: rebinding, CSRF, Private Network Access, bootstrap and loopback-only proof
`P33` `[UI][SEC]` · deps: T-0564, T-0075, T-0080, T-0134 · size: L · owner: sec
**Objective.** Make a browser-reachable control plane safe against hostile web pages and rebinding.
**Steps.**
1. Implement the exact `Host` allowlist (`HDD_ALLOWED_HOSTS`, derived from the surface names only) as the first middleware on every control-plane listener, answering `ERR-LOCAL-003` without routing or detail, plus the loopback-alias behavior of C18.7 item 1 (308 to the surface name, no cookies, `/healthz` only).
2. Implement the `Origin` and `Sec-Fetch-Site` checks of C18.7 item 2 for cookie-authenticated requests only (bearer-only requests are exempt), with the separate rules for WebSocket upgrades, SSE and other GET requests (browsers send no `Origin` on same-origin GET) and mutations, including browsers that omit `Sec-Fetch-*` (fall back to a strict `Origin`/`Referer` rule; missing both on a cookie-authenticated mutation is refused).
3. Ensure no CORS headers are ever emitted by the control plane and that Private Network Access preflights (`Access-Control-Request-Private-Network`) are answered without an allow header; add tests for each.
4. Implement the `/setup` flow (S-136 local): bootstrap token verification (constant time, hash compare, single use, 15-minute expiry, rate limit), disappearance after the first platform owner exists, and MFA enrollment before the first admin session is usable.
5. Implement the loopback-only verification used by `hdd-local selftest`: enumerate own listeners, then from a non-loopback local address try to connect to each control-plane port and fail on any success.
6. Ensure secrets never appear on command lines or child-process environments (inspect the process table in a test).
7. Build a **hostile-page test fixture**: a page served from another origin (and a DNS rebinding server in the lab) that tries fetch, form POST, EventSource, WebSocket and image-beacon CSRF against the local control plane; every attempt must fail.
8. Document the shared-machine limitation and the residual risks in `docs/LOCAL.md`.
**Deliverables.**
- middleware, `/setup` flow, verification routines, hostile-page fixture, tests, docs
**Acceptance.**
- A1: requests with a rebinding `Host` header receive `ERR-LOCAL-003` before any handler runs (test with 50 shapes: case, trailing dot, port variants, IDN, IPv6 literal).
- A2: the hostile-page fixture cannot read or mutate anything through fetch, form, SSE or WebSocket (browser test).
- A3: the bootstrap token works once, expires after 15 minutes, and `/setup` returns 404 after the first owner exists.
- A4: the self-test fails when a control-plane port is deliberately bound to `0.0.0.0` (injected-fault test).
- A5: no secret appears in the process table or `/proc`-equivalent listings during a run.
**Tests.**
- Browser tests; lab rebinding server; fault injection; process-listing test.
**Notes.** This is AC-55's security core; a failure here blocks the local profile from release.
