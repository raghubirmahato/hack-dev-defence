### T-0564 · `hdd-local` supervisor: lifecycle, readiness, crash policy, first run, doctor and self-test
`P33` `[OPS][SEC][DP]` · deps: T-0562, T-0563, T-0073, T-0134, T-0208, T-0211 · size: XL · owner: infra
**Objective.** One command that starts, supervises and stops the whole product on a personal computer, safely, with honest status.
**Steps.**
1. Create the `hdd-local` binary with the commands of C18.4 and the in-process service runner: each service crate exposes `run(ctx)`; the supervisor owns the shared `MemoryKv`, the configuration, the data directory and the embedded database handle.
2. Implement the start order and readiness gates of C18.4 (lock, light doctor, database, migrations, rehydrate, snapshot compile and cache, api/web/worker, listeners, DNS), with a 60 s database timeout and precise error messages.
3. Implement task supervision: panic isolation per task (R-09), exponential backoff restarts (1 s to 30 s), the five-in-ten-minutes stop rule with a UI banner and `AUD-` event, and `MET-hdd_watchdog_restarts_total`.
4. Implement graceful shutdown (signal and console-close handling per OS, 10 s drain, database fast shutdown, lock release; on Windows the abbreviated path and a Job Object, C18.4) and the single-instance lock with stale-lock detection.
5. Implement first run: secret generation into the data directory, one-time bootstrap token file (hash stored, 15-minute expiry), printing only the setup URL and the token file path, and `hdd-local token show` for interactive terminals.
6. Implement sleep and wake detection (OS power events with the late-ticker fallback), re-validation of listeners and database, correct expiry of time-bound state, and `resumed_after_seconds` in the runtime page.
7. Implement `hdd-local doctor` (ports, disk, permissions, clock, antivirus or firewall hints, database, certificates, listeners) and `hdd-local selftest` (starts a temporary instance, runs the six mandated payloads through the inspect API and a sandbox route, verifies loopback-only binding of the control plane, verifies backup and restore of a scratch database, and prints PASS/FAIL per item with evidence).
8. Implement `status` with real values only (profile, stores, uptime, listeners, last restarts, snapshot age) and `logs --follow`, with JSON logs rotating at 10 MiB × 5.
**Deliverables.**
- `hdd-local` binary and library, supervisor, doctor, self-test, tests
**Acceptance.**
- A1: from an empty data directory, `hdd-local run` reaches "ready" and `selftest` passes on Windows, macOS and Linux CI runners without Docker.
- A2: killing any single service task results in a restart within 5 s and no outage of the other services (fault injection).
- A3: `Ctrl+C`, SIGINT and SIGTERM produce a clean shutdown within 15 s; on Windows console-close, logoff and shutdown produce the abbreviated shutdown within 5 s; in every case no database process is orphaned, and a stale one is stopped at the next start.
- A4: a second `hdd-local run` against the same data directory refuses to start with a clear message.
- A5: a simulated 10-minute sleep triggers the resume path, and bans that expired during the sleep are treated as expired.
- A6: after a restart of `hdd-local`, bans and sessions created earlier are enforced before the first request is accepted (restart test with the real tables).
**Tests.**
- Integration with real processes; fault injection; clock-jump test; per-OS signal tests.
**Notes.** The supervisor never needs administrator rights for its default configuration.
