### T-0565 · Loopback client identity, local ban semantics and the tunnel listener
`P33` `[DP][SEC]` · deps: T-0564, T-0315, T-0316, T-0318, T-0327 · size: M · owner: dp
**Objective.** Make bans, rate limits and reputation work when every local client is `127.0.0.1`, without banning the operator's own browser.
**Steps.**
1. Extend client-IP resolution (T-0315) with the local identity rules of C18.5: keyed `lo:` identities from a user-agent and accept-language HMAC, `X-HDD-Test-Client` labels, bounded registry (4,096 entries, LRU), and the per-listener trust rule (provider headers trusted only on the dedicated tunnel listener).
2. Implement the dedicated `tunnel_http` listener (default loopback port 8081) with provider header mappings (`CF-Connecting-IP`, `X-Forwarded-For`, configurable header) and strict header parsing (single value, valid address, no private ranges accepted as client addresses from the internet side).
3. Scope `lo:` bans to the protected site and make sure the platform surfaces (served directly by `hdd-web` and `hdd-api` in the local profile, or through the proxy when `dogfood` is on) never consult them (R-19); implement one-click unban in S-067 and `hdd-local unban --all-loopback`.
4. Implement the `loopback_client_identity: single` guard (allowed only when every site is in `monitor` or `log` mode, otherwise `ERR-LOCAL-001`).
5. Make the never-ban rules (T-0318) profile-aware: in `local`, loopback is not never-banned, platform addresses and the operator's configured LAN addresses are.
6. Add the UI explanation in S-067/S-068 ("This is a local identity: browser and tool, not an internet address") and the honest limit text of C18.5.
7. Write tests: sqlmap-like user agent banned while the browser identity is unaffected; same user agent from two tools shares an identity (documented); registry flood stays bounded; header spoofing on the normal listener is ignored; spoofing on the tunnel listener uses the header only when the provider is configured; label rotation through the tunnel listener creates no new identities; a tunnel-listener request without the provider header gets 421.
**Deliverables.**
- identity resolver changes, tunnel listener, ban scoping, unban paths, tests
**Acceptance.**
- A1: sending M1 to M6 from a `sqlmap` user agent bans `lo:<hash>` and the dashboard (same machine, browser user agent) stays fully usable.
- A2: a banned `lo:` identity is not blocked on `app` and `admin` surfaces, with `dogfood` off and on.
- A3: `X-Forwarded-For` on the normal listener never changes the client identity (property test).
- A4: 100,000 distinct user agents keep registry memory within its cap.
- A5: `single` mode is refused while any site is in `block` mode.
**Tests.**
- Integration against `hdd-local`; property tests; memory-bound test.
**Notes.** Honest limit: a local process can change its user agent; these bans demonstrate and test the shield, they do not contain a hostile local process.
