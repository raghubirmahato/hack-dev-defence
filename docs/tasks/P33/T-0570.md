### T-0570 · Local-mode product surfaces: first-run setup, runtime page (S-135), mode banner, outbox viewer and docs
`P33` `[UI][API][DOC]` · deps: T-0564, T-0567, T-0134, T-0137, T-0417, T-0109 · size: M · owner: ui
**Objective.** Make the local profile understandable and honest in the product itself.
**Steps.**
1. Build the first-run setup (S-136 local) as specified in B12.2: token, platform owner with MFA, trust choice, self-test results.
2. Build S-135 per B12.2: runtime profile pill, stores, listeners, uptime, restarts with reasons, snapshot age, disk guard, backup age, and the persistent local-mode notice on every app and admin page.
3. Implement the admin-only outbox viewer for installs without SMTP (messages to the local administrator only, nothing sent externally, content redacted after 24 hours), with a clear "no email was sent" label.
4. Implement the API endpoints `GET P/runtime`, `GET P/runtime/outbox` and `GET P/runtime/outbox/{id}` with the permissions of B4.2 and the audit events.
5. Add i18n keys, empty states and a11y checks for all new screens; add the local-profile disclosures to claims-lint (section 4.4).
6. Write the user guide: "Run HDD on your computer in 10 minutes", "What local mode is and is not", "Moving to a server".
7. Add browser tests of the setup flow and the runtime page on three browsers where available.
**Deliverables.**
- S-135, S-136 (local), endpoints, outbox viewer, docs, tests
**Acceptance.**
- A1: the local-mode notice appears on every app and admin page in local profile and never in hosted (browser test over the route table).
- A2: S-135 shows only real values; killing the embedded database changes the page within 10 s.
- A3: the outbox viewer is reachable only by platform roles with step-up and never shows messages to other recipients.
- A4: zero serious or critical axe findings on S-135 and S-136.
- A5: claims-lint passes on all new copy.
**Tests.**
- Browser e2e; axe; permission matrix; claims-lint.
**Notes.** The notice is wording from section 4.4, not marketing.

## Definition of done for this task's tags (section 0.7)

### `[UI]`: Renders HTML to a human

Server-side escaped output only; empty, loading, error, offline and permission-denied states implemented honestly (no fake data); keyboard-only operation verified; focus order and visible focus; WCAG 2.2 AA via the axe oracle with zero serious or critical findings; contrast tokens only (no ad-hoc colors); responsive screenshots at 360, 768, 1280 px in dark and light; i18n keys only (no literal user-facing strings in templates); CSP clean (no inline script or style, no console errors); size budgets (E4) respected; visual-regression baseline updated with reviewer note.

### `[API]`: Adds or changes an HTTP endpoint

OpenAPI entry via `utoipa`; RFC 9457 problem responses using the error catalog; authz check by permission ID (deny by default); tenant scoping test (BOLA); input validation with explicit limits; idempotency key on create; `ETag`/`If-Match` on update; rate limit class assigned; audit event; metric; contract test generated from the OpenAPI document.

### `[DOC]`: Documentation

Every claim backed by a test ID or a command the reader can run; passes claims-lint; included in the docs site if user-facing.
