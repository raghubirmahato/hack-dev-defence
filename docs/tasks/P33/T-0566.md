### T-0566 · Local certificate authority, trust installation and TLS modes
`P33` `[SEC][OPS]` · deps: T-0564, T-0375, T-0354 · size: L · owner: sec
**Objective.** Serve `https://*.hdd.localhost` with certificates a browser can trust, without weakening anyone's trust store.
**Steps.**
1. Implement the name-constrained local CA of C18.6 with `rcgen` (ECDSA P-256, 2-year validity, name constraints for `localhost`, the configured suffix, `127.0.0.0/8` and `::1/128`), key wrapping by DPAPI on Windows, Keychain on macOS and a 0600 file on Linux, and key rotation with overlap.
2. Implement a `local_ca` certificate source in the certificate store (T-0375) alongside `acme`: per-site leaves, 90-day validity, renewal at two thirds, hot reload through the same SNI resolver.
3. Implement `hdd-local trust install|remove|status`: display the fingerprint, require explicit consent, use only non-elevated mechanisms (Windows current-user root store, macOS login keychain, NSS databases for Chrome on Linux, and the Firefox profile database on every OS), record exactly what was installed, and remove exactly that; system-wide Linux install is documented, never automatic.
4. Implement `http_only` mode with its cookie differences (C18.6), the readiness warning, and the refusal when `lan_exposure` is true.
5. Add a verification test that a leaf for a name outside the constraints (`example.com`) fails path validation in a constraint-aware client, and that the CA certificate carries the critical name-constraints extension.
6. Add `AUD-runtime.trust_installed` and `trust_removed`, and the S-136 setup step with the three options (install, browser exception instructions, HTTP-only).
7. Write the browser tests: Chromium trusts a leaf after install in a profile-scoped NSS database; without install the browser shows the expected interstitial; Safari behavior is documented (manual).
**Deliverables.**
- local CA, `local_ca` certificate source, trust commands, tests, docs
**Acceptance.**
- A1: the CA certificate has critical name constraints limiting it to the configured names and loopback addresses (certificate inspection test).
- A2: a certificate for `example.com` signed by the local CA is rejected by a constraint-aware verifier.
- A3: `trust remove` leaves the OS and browser stores exactly as before (before/after snapshots).
- A4: the CA private key is never present in plaintext on disk on Windows and macOS.
- A5: no trust-store change occurs without an explicit consent step (interactive test with consent denied).
**Tests.**
- Unit and integration; browser tests with `chromiumoxide`; negative validation test.
**Notes.** HDD never installs a trust root silently, and never asks for elevation by default.
