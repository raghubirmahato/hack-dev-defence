### T-0468 · Full L2 tuning and the nftables baseline: NOTRACK, conntrack sizing, ICMP limits and exact undo
`P25` `[OPS][SEC]` · deps: T-0213, T-0463 · size: L · owner: ops
**Objective.** Complete the stack tuning and the host firewall baseline so state exhaustion and trivial floods fail cheaply.
**Steps.**
1. Extend `hddctl tune` to the full L2 set from C11.5: `tcp_syncookies=1`, tuned `tcp_max_syn_backlog`, `somaxconn`, `netdev_max_backlog`, `rp_filter` strict (with the asymmetric-route guard), `tcp_rfc1337`, ICMP rate limits (`icmp_ratelimit`, `icmp_ratemask`), socket buffer sizes, `tcp_fin_timeout`, `tcp_tw_reuse` (documented), `nf_conntrack_max` and hash sizes computed from RAM, and file-descriptor limits.
2. Implement the **baseline nftables ruleset** (`hddctl firewall apply`): `inet filter` with default-drop input; allow loopback, established/related, TCP 80/443 (and UDP 443 if HTTP/3 enabled), TCP+UDP 53, TCP 22 from `ssh_allow_cidrs`, ICMP/ICMPv6 essentials (PMTUD, ND) rate limited, and the monitoring ports from allowlisted collectors; output chain allows what the platform needs (DNS to resolvers, ACME CA, feeds, SMTP, NTP, package mirrors) as a documented allowlist (egress filtering is optional but recommended and off by default to avoid breaking installs).
3. Implement the **raw-table NOTRACK** rules **per direction** (valid only because the proxy and DNS use the host network without NAT): `prerouting` for inbound `tcp dport {80, 443}`, `tcp dport 53`, `udp dport {53, 443}`; `output` for the replies (`tcp sport {80, 443}`, `tcp sport 53`, `udp sport {53, 443}`); never a rule that matches an outbound client flow by remote port; add explicit accept rules in input/output for untracked packets; prove with tests that established return traffic of the host's own outbound connections still works (ACME, feeds, SMTP) and that Docker NAT scenarios are detected and refused (the command warns and skips NOTRACK when NAT/masquerade rules exist).
4. Implement conntrack sizing from available RAM (`nf_conntrack_max = RAM_MB * 64` bounded, `hashsize = max/4`) and expose usage and drops as metrics; document the memory implications.
5. Wrap every apply in the **timed auto-revert** (section 2.5), requiring a second-session confirmation `hddctl confirm <id>`; previous rules are saved for exact rollback; `hddctl firewall undo` restores them.
6. Implement **IPv6 parity**: identical policy for v6, with correct ICMPv6 allowances, and tests proving ND/RA/PMTUD still work.
7. Implement mirroring guidance: generate the equivalent cloud-firewall rule list (provider-agnostic table) to apply at the provider's firewall; HDD does not call provider APIs here.
8. Write tests on disposable VMs/containers with systemd and nftables: apply, rerun (idempotent), lockout simulation (deliberately drop SSH → auto-revert within the timer), undo equality (before/after ruleset hash), NOTRACK return-traffic tests, IPv6 tests, and a documentation test that every sysctl and rule has a documented undo.
**Deliverables.**
- extended `hddctl tune|firewall`, rulesets, docs, VM tests
**Acceptance.**
- A1: `undo` returns the sysctl values and the ruleset to the exact prior state (hash comparison).
- A2: the lockout simulation auto-reverts within the timer without operator action.
- A3: with NOTRACK active, outbound ACME, SMTP and resolver traffic (client flows to remote ports 53 and 443) still succeeds and stays tracked (VM test reads `conntrack -L`).
- A4: NOTRACK is skipped with a WARN when NAT is detected.
- A5: IPv6 ND/RA/PMTUD work under the baseline.
**Tests.**
- VM integration, golden rulesets, unit (formulae).
**Notes.** Closes T-0213's pointer (L2 full set); AC-29 verifies in T-0471.
