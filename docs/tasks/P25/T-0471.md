### T-0471 · Host defense acceptance: AC-26 (XDP), AC-29 (tuning), kernel ban enforcement and port-scan signals
`P25` `[QA][LAB]` · deps: T-0464, T-0467, T-0468, T-0469, T-0470 · size: L · owner: qa
**Objective.** Prove the host-level defenses with measurements and evidence, and be honest about what the environment can show.
**Steps.**
1. Run AC-26 in the closed lab across modes (no mitigation, nftables raw only, XDP generic, XDP native if supported): for each attack class (SYN, UDP, fragments, invalid flags, reflection-pattern, bogon spoofing) record legitimate success rate, drop ratio, pps handled and CPU; verify that XDP drops only the intended categories (legitimate-traffic corpus replay shows zero collateral drops).
2. Verify XDP safety behaviors: dead-man detach, self-test auto-detach, never-drop list precedence (admin CIDR and SSH source traffic during a flood), map update atomicity under load, and recovery after loader crash.
3. Run AC-29 on a VM resembling the pilot VPS: apply the full tuning and firewall baseline, rerun idempotently, undo, reapply; measure SYN flood survivability (accept queue overflow counters, SYN cookies activation, conntrack occupancy under NOTRACK vs tracked) with before/after numbers.
4. Verify kernel-level ban enforcement on the pilot: trigger a Class A SQLi ban on the sandbox host (private profile, 60 s TTL for the runner, runner IP protected by the never-ban guard unless the test explicitly uses a second source) and a ban of a test address through the API; measure time-to-drop and time-to-unban at the proxy, nftables and XDP layers; AC-08's kernel portion and AC-34 resilience.
5. Verify **port-scan detection** (ATK-239, level `L`): connection attempts to closed ports from a lab source are counted by nftables counters and surface as low-severity events (log only), with no automatic bans in v5; confirm no false positives from legitimate clients.
6. Verify observability: all counters and metrics appear in the admin screens (S-128), alerts fire for agent divergence and XDP self-test failure, and the audit log records all manual XDP/firewall operations.
7. Record environment facts (kernel, driver, XDP mode, NIC, CPU) with every measurement and mark numbers lab-only; update `docs/DDOS-READINESS.md` with measured lab-proven values and keep provider-advertised and verified-live fields separate.
8. Archive evidence with SHA-256; set status lines: AC-26 PASS/UNVERIFIED(`environment_unsupported`|`capability_not_supplied`), AC-29 PASS, AC-08 kernel portion PASS.
**Deliverables.**
- evidence bundle, updated readiness doc, status updates
**Acceptance.**
- A1: AC-26 evidence shows zero collateral drops on the legitimate corpus and the dead-man timer working.
- A2: AC-29 apply/undo/idempotency pass and the lockout simulation reverts.
- A3: kernel ban and unban propagation meet ≤ 2 s p95 on the pilot.
- A4: unsupported environments (for example no native XDP) are reported honestly, with the fallback demonstrated.
- A5: no traffic left the closed lab (audit and interface counters verified).
**Tests.**
- Lab and pilot runs.
**Notes.** The runner's IP is protected by the never-ban list unless the test explicitly requires otherwise (section 2.4).
