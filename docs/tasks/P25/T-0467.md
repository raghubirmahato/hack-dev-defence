### T-0467 · `hdd-xdp` loader: maps, atomic updates, counters, native/generic probe and the dead-man timer
`P25` `[DP][OPS][SEC]` · deps: T-0466, T-0464 · size: L · owner: infra
**Objective.** Operate the XDP program safely in production: attach, update, observe and always be able to get out.
**Steps.**
1. Implement the loader inside the host agent (separate service `hdd-xdp` or a module of `hdd-fw-agent` selected by ADR; default separate unit so a crash in one does not disable the other): attach to the configured interface(s) using the best mode (`native` → `generic` fallback) with a **probe**: attempt native, verify with a loopback packet test, record the mode used, warn on fallback, and publish the mode, interface, driver and measured pps in the status.
2. Implement map management: **atomic updates** (build new map contents off-line and swap via map-in-map or double-buffered generation counter), ban stream applied to the LPM tries with TTL bookkeeping in userspace (the kernel entries are removed by the loader when the TTL expires and by reconcile), config updates (published ports, reflection port list, thresholds) with versioning, and a bounded operations queue.
3. Implement the **dead-man detach timer**: after every load, reload or policy change that tightens drops, start a countdown (default 120 s) that detaches the program unless a confirmation arrives from a second session (`hddctl xdp confirm` or the admin console button); detach is clean (`XDP_FLAGS` unset) and recorded; the timer cannot be disabled in `pilot` stage and requires an explicit documented flag in `production` once the operator has run 30 days without incident.
4. Implement commands: `hddctl xdp status|attach|detach|reload|confirm|counters|dump-bans`, all idempotent, with `--dry-run` for reload (shows the diff of config and ban set), and a preflight that refuses to attach if the interface has an unsupported configuration (for example XDP already attached by another program, bonded interface without native support, MTU > supported for generic mode).
5. Export **per-reason drop counters** and per-CPU totals, map occupancy, update latency, and mode as Prometheus metrics; a periodic self-test sends a loopback probe packet to a controlled port to verify the program still passes legitimate traffic (a failing self-test auto-detaches and alerts).
6. Implement graceful failure handling: on loader crash the program stays attached by default (so protection persists) unless the dead-man timer is running; on host reboot the unit re-attaches with the timer armed; the status shows `attached`, `unconfirmed`, `detached`.
7. Implement `Noop` behavior: if neither XDP nor nftables raw is available, the service runs in `Noop` mode with a WARN and AC-26 marked `UNVERIFIED(environment_unsupported)`.
8. Write tests: attach/detach cycles in a namespace (veth with native-capable driver or generic), timer expiry detaching the program (time-accelerated), confirm resetting the timer, map update atomicity under traffic (no dropped legitimate flow during a swap), self-test failure auto-detach, and crash/restart persistence.
**Deliverables.**
- `hdd-xdp` loader, systemd unit, `hddctl xdp`, metrics, tests, runbook
**Acceptance.**
- A1: without confirmation the program detaches at the timer expiry (±5 s) in the lab.
- A2: a map swap during a traffic flow drops no legitimate packets (zero loss in a 60 s test at 100k pps).
- A3: the status reports the actual mode (native/generic) and warns on fallback.
- A4: the self-test detaches the program if it starts dropping the probe.
- A5: all commands are idempotent and `--dry-run` shows changes without applying.
**Tests.**
- Privileged lab tests, time-accelerated unit tests, chaos.
**Notes.** The detach timer is the XDP equivalent of the SSH-lockout revert (section 2.5).
