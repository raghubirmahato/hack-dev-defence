### T-0465 · `hdd-xdp-logic`: pure packet-verdict logic (no_std) with exhaustive tests
`P25` `[DP][SEC][QA]` · deps: T-0463 · size: L · owner: infra
**Objective.** Put every XDP decision in safe, natively testable Rust so the kernel program is a thin shell.
**Steps.**
1. Create `hdd-xdp-logic` as `#![no_std]` (with `alloc` disabled) and `#![forbid(unsafe_code)]`: parse Ethernet (optionally VLAN tags), IPv4, IPv6 (extension headers bounded to a fixed number), TCP, UDP, ICMP/ICMPv6 from a `&[u8]` with explicit bounds checks, returning a typed `PacketView`.
2. Define the verdict function `decide(view: &PacketView, maps: &dyn MapView, cfg: &Config, now_ns: u64) -> (Verdict, Reason)` with verdicts `Pass`, `Drop`; reasons: `Banned`, `SynNoAckUnpublished`, `InvalidTcpFlags`, `Bogon`, `OwnAddressSource`, `Fragment`, `ReflectionSource`, `RateSyn`, `RatePps`, `RateBps`, `RateIcmp`, `Malformed`.
3. Implement the **rules per C11.4**: banned-IP check via the LPM views (v4 /32, v6 /64) for destination ports 80/443 and UDP 443 only; TCP SYN without ACK to ports not in the published set; invalid flag combinations (NULL, FIN+URG+PSH "Xmas", SYN+FIN, SYN+RST, FIN without ACK as policy, URG without PSH not dropped); bogon/martian sources (RFC 1918, 100.64/10, 169.254/16, 127/8, 224/4, 240/4, 0/8, documentation ranges, IPv6 equivalents) unless the interface is private-routed per config; own-address source; fragments (configurable: drop first/non-first fragments to published ports); unsolicited UDP from reflection source ports in the configurable list (53, 123, 389, 1900, 11211, 19, 161, 5353, 3702 by default) unless allowlisted peers; and **per-source token buckets** for pps, bps, SYN/s and ICMP/s on published ports (keys = /32 or /64; table size bounded; eviction by LRU approximation).
4. Implement the **never-drop list** logic: loopback, `admin_cidrs`, SSH source CIDRs for port 22, provider probe ranges and DNS secondary addresses are `Pass` before any other rule (the order is part of the contract and tested).
5. Make time and map access abstract (`MapView` trait) so the same logic runs in the kernel (maps) and in tests (in-memory maps with deterministic time).
6. Write **exhaustive tests**: table tests for each reason (≥ 200 packet fixtures built with `etherparse`-style builders in the test crate), property tests (random packets never panic and never read out of bounds; the verdict is deterministic; never-drop beats every drop reason), differential test against a naive reference implementation written in the test crate for random packet streams, and fuzz targets (`xdp_decide` with arbitrary bytes).
7. Add **legitimate-traffic regression corpus**: captured shapes of normal TCP handshakes, TLS flows, QUIC initial packets, DNS responses from the host's resolvers (source port 53 to ephemeral ports must not drop when it is return traffic for the host's own queries because the source port rule applies only to unsolicited UDP to published ports), NTP responses to the host, ACME/HTTPS return traffic; the policy ensures these `Pass`.
8. Add benchmarks (`criterion`) for decisions per second to guide the in-kernel instruction budget.
**Deliverables.**
- `hdd-xdp-logic`, fixtures, fuzz targets, benches, `docs/XDP.md` (verdict table)
**Acceptance.**
- A1: all fixtures produce the documented verdict and reason.
- A2: property tests find no panics or out-of-bounds in 10,000,000 generated packets.
- A3: legitimate-traffic corpus never drops.
- A4: never-drop precedence holds in all property cases.
- A5: the crate builds for the BPF target configuration without `std`.
**Tests.**
- Unit/property/differential/fuzz.
**Notes.** Keeping the logic pure also lets the userspace fallback (nftables) mirror the same rule table for parity checks.
