### T-0469 · Host hardening baseline and verification (SSH, services, systemd sandboxing, integrity, updates)
`P25` `[OPS][SEC]` · deps: T-0212, T-0468 · size: L · owner: ops
**Objective.** Make the VPS itself hard to compromise and verify it continuously.
**Steps.**
1. Implement `hddctl harden plan|apply|verify|undo` (dry-run first) covering: SSH (key-only auth, `PermitRootLogin prohibit-password` or no, `AllowUsers`, modern ciphers/MACs/KEX, `MaxAuthTries`, idle timeouts, no agent/TCP forwarding unless required, optional non-default port with firewall alignment), with the timed auto-revert for `sshd` changes and a second-session confirmation.
2. Harden the OS: unattended security upgrades (configured, with reboot windows documented), `sysctl` security settings (`kernel.kptr_restrict`, `dmesg_restrict`, `unprivileged_bpf_disabled=2`, `kernel.yama.ptrace_scope`, `fs.protected_*`, `net.ipv4.conf.*.accept_redirects=0`, `accept_source_route=0`, `log_martians`), disable unused services (verified by `systemctl list-unit-files` baseline), time sync (chrony with authenticated NTS if available), kernel module blacklist for unneeded protocols, core dump limits, `umask`, and `/tmp` mount options (`noexec,nosuid,nodev` where compatible).
3. Verify **systemd sandboxing** of each HDD unit with `systemd-analyze security` scores (target ≤ 2.5 for exposed services) and unit-specific allowlists; ensure the DNS unit has only `CAP_NET_BIND_SERVICE`, the proxy unit also (for 80/443), the fw-agent only `CAP_NET_ADMIN`, the XDP loader `CAP_BPF/NET_ADMIN/PERFMON`, and the control plane services none.
4. Implement **file integrity and secrets hygiene checks**: ownership/mode verification for `/etc/hdd/**` (0600/0640 as specified), secrets not world-readable, no secrets in the process environment of services (`/proc/<pid>/environ` scan), no secrets in unit files, swap encryption or disabled swap for the secrets-bearing processes (documented: `mlock` use), core dumps disabled for HDD services, and AIDE-style baseline hashes of binaries (`hddctl harden baseline` records, `verify` compares).
5. Implement **exposure scanning from the VPS and the runner**: confirm only intended ports are open (self-scan on all interfaces and an external capped scan from the runner against the operator's own IP within the functional profile limit), no Postgres/Redis/metrics ports exposed, `/metrics` endpoints on loopback/private only, Docker daemon socket not exposed, and the admin surface exposure matches `admin_exposure`.
6. Implement an **audit trail on the host**: `auditd` rules for changes to `/etc/hdd`, binaries, sudoers and SSH config, shipped (optionally) through the log sink; and login/sudo alerts through the notification routing (platform-level).
7. Generate `docs/HARDENING-REPORT.md` with pass/fail per check, evidence and remediation, plus an overall status; checks map to CIS-style categories without claiming CIS compliance.
8. Write tests on a disposable VM: apply/verify/undo cycle, lockout protection for SSH, detection of deliberately introduced drift (world-readable secret, extra open port, modified binary) with each check failing as expected, and idempotency.
**Deliverables.**
- `hddctl harden`, baselines, report generator, VM tests, docs
**Acceptance.**
- A1: every injected drift is detected by `verify` (≥ 10 cases).
- A2: SSH changes auto-revert if the second session does not confirm.
- A3: `systemd-analyze security` scores meet targets for exposed units.
- A4: the external capped scan finds only the intended ports open (pilot VPS).
- A5: no secret appears in any service environment.
**Tests.**
- VM tests, scan tests, drift injection.
**Notes.** Claims are limited to "checks performed"; HDD does not claim the host is unhackable.
