### T-0537 · Supervised cutover execution and the monitor-first period (only after written go-ahead)
`P31` `[HUMAN][OPS]` · deps: T-0536, T-0538 · size: L · owner: ops
**Objective.** Execute the cutover with the operator, measure continuously and be ready to roll back. **Run T-0538 first**; this task needs its certificate.
**Steps.**
1. Confirm the written go-ahead is present and still valid (evidence freshness: backups < 24 h, certificate pre-issued and valid, TTLs lowered ≥ one old TTL ago, secondary live, gates re-evaluated within the last 2 hours); otherwise stop and re-run the checks.
2. Start the **monitoring window**: dashboards, external probes and alert thresholds from T-0535; announce maintenance as planned; take a final backup and `export-zone` backup; confirm the old provider zone remains live and mirrored.
3. Guide the operator (or execute via documented commands where the agent has legitimate access) through: registrar host objects/glue, then the NS change (or pointing NS at the secondary for `hidden_primary`); the agent itself does not hold registrar credentials and does not call registrar APIs.
4. Run the **propagation and correctness probes** repeatedly from several public resolvers (A/AAAA/MX/TXT/NS/SOA, proxied vs grey answers, DNSSEC validation probe), TLS handshake checks on all proxied names, HTTP checks through HDD, mail flow tests (operator sends/receives test mail), and compare with the old provider's answers for continuity; record timelines.
5. Operate in **monitor mode first** (default 48 h baseline): WAF mode `monitor` for the apex site with the Monitor-first preset, outbound filter in monitor, challenge off; review would-block events hourly (first 6 h), then every 6 h; classify each as true positive, false positive or unclear; create scoped exceptions or rule fixes with dry-run evidence for each false positive family.
6. Apply the **abort criteria** continuously; if any triggers, advise rollback (the operator decides), execute the fast path (safe mode and grey records) or slow path (registrar NS restore) per the runbook, and record the timeline.
7. Keep the **old provider live** for at least one full old-TTL period after stable operation; document the plan for decommissioning old records only after the operator confirms.
8. Produce the **cutover log** (timestamps, commands, outputs, probe results, decisions) with hashes for the final report.
**Deliverables.**
- cutover log, probe timelines, FP review notes
**Acceptance.**
- A1: no cutover action occurs without a valid recorded go-ahead (audit check).
- A2: continuity probes show no sustained resolution failure and mail flow is intact.
- A3: monitor-first results are reviewed with false-positive families fixed or documented.
- A4: abort criteria were monitored throughout (dashboard evidence).
- A5: the cutover log is complete.
**Tests.**
- Live probes and operator-in-the-loop verification.
**Notes.** If the operator defers cutover, this task is marked UNVERIFIED(`human_step_pending`) with preconditions preserved.
