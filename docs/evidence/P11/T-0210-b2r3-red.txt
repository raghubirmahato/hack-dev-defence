## Q-1 (delegation semantics)
Red tests: hdd-canary tests::t0210_delegation_pending_is_only_a_resolve_of_a_profile_test_hostname;
hddctl t0210_verify_override_transport_failure_is_a_fail_not_a_pending_step; hddctl
t0210_verify_non_200_through_response_does_not_claim_no_response_arrived.
Facts checked on disk: hdd.live.example.yaml line 45 defines lockdown_state = origin firewall / secret header (STOP #2);
the profile type (crates/hdd-common/src/profile/types.rs) has NO delegation field (`ns_hostnames`/`acme_cname_zone` are
DNS configuration, not a delegation state). So only EgressError::Resolve on a profile-named test_hostname may be pending.
Pre-fix: lockdown_state was used as "delegation done", every through transport failure was UNVERIFIED(human_step_pending)
(so `--local-only --through-url http://127.0.0.1:1` printed "Delegate the pilot subzones" and exited 0), and a non-200
through response used the phrase "no response arrived".

## Q-3 (echo redaction)
Red tests: hdd-canary tests::t0210_echo_headers_are_an_allowlist_not_a_denylist,
t0210_origin_auth_kid_is_echoed_only_for_the_exact_v1_shape, hostile

## Q-4 (served 200 with trailing bytes)
Red test: hdd-canary::hostile a_served_response_survives_trailing_client_bytes (5,000 and 60,000 trailing bytes, and
Content-Length: 0 with trailing data). Pre-fix only the reject path shut the write side down and drained; a served
response closed with unread bytes, which can reset the connection and lose the body the client was reading.

## Q-5 (override scheme and port)
Red test: hddctl t0210_verify_profile_overrides_must_match_scheme_and_port. Pre-fix only the host was compared with the
profile, so an override with another scheme/port on a profile-named host was accepted (`--direct-url https://<origin
host>:9`), i.e. the check could be pointed at an unrelated service on the same host. The --base-path help text also
claimed the profile wins, while the code lets an explicit flag override it.

## Q-6 (listener outage export and one idle client)
Red tests: hdd-canary tests::t0210_start_propagates_a_real_listener_panic_and_counts_it (real start() path, not a fake
Running). Pre-fix the exit error did not export the panic count, and the single-threaded accept loop let one idle client
block every other request for its deadline.
Decision taken (allowed by the review): implement a small bounded worker pool (4 workers, accept queue 16) instead of
documenting the single-connection limit; the idle-client latency test t0210_verify_... (hostile a_connection... suite)
shows another connection is served immediately.

## Q-7 (symlinked root/dir)
Status: NOT REPRODUCED end-to-end on this host. Creating a directory symlink/junction in the test needs a privilege the
builder session does not hold, so the new test t0210_start_refuses_a_symlinked_root_directory_when_the_privilege_exists
reports UNVERIFIED(environment_unsupported) itself and returns; the unix-only library symlink test is already
UNVERIFIED(environment_unsupported) here. The fix is structural: start(), generate() and check_manifest() now call
ensure_real_directory(), which refuses a symlinked root, a Windows reparse point (junction) and a non-directory root; the
check-then-use window between symlink_metadata and opening a child is documented in the code as accepted because the
directory is root-controlled (an attacker who can replace it is already the host owner).
