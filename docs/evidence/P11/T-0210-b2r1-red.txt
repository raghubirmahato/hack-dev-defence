## Notes on two findings that are not product failures
C-2 is a test-quality defect, not a product defect: the old uniform-random-bytes sweep produced essentially zero accepted
heads (terminator almost never generated), so its assertions lived in an `if let Ok(..)` that never ran. The rewritten
sweep first failed with "the structured sweep produced only 416 accepted heads" (under-generated); the generation was made
structured (half well-formed, half mixed, plus byte mutations and noise) so that the test now asserts both classes >= 500.
The mutation demo restores the old parser-feeding style (the sweep no longer feeds the parser) and the rewritten test fails
with "produced only 0 accepted heads" - which is exactly the weak-test defect.
C-8's symlink rejection test is `#[cfg(unix)]` and therefore UNVERIFIED(environment_unsupported) on this Windows host; the
regular-file rejection test (directory in place of a file) and the hard size-limit test run here, and the size limit was
already partly covered by the metadata check before this round (the `take()` read is defence in depth).

## F-B2-0 pre-fix reproduction (stress run, before the fix)
The flake was reproduced before the fix in a stress loop (12 iterations of the combined suite, 4 CPU busy loops,
--test-threads=16), on iteration 3:
  FAIL [   0.315s] (46/49) hddctl::canary t0210_verify_reports_a_static_install_echo_as_unverified
  CANARY-QUERY FAIL: static.js: HTTP 404 without a query and 200 with one (expected 200/200)
Root cause: the accepted socket inherited the listener's non-blocking mode on Windows, so a request whose bytes arrived a
few milliseconds after accept() made read() return WouldBlock; read_head treated that as an incomplete/rejected request and
answered with the opaque 404, and the probe failed. The deterministic regression test is
a2_a_request_that_arrives_after_accept_is_served_not_rejected (it fails pre-fix with left: 0, right: 200). The fix is
set_nonblocking(false) on the accepted stream, plus the absolute per-connection deadline.
