## PHASE P15: All other attack detectors (T-0285 to T-0314) · milestone M6 · gate G15

Requirement prefix `DET`. Goal: implement the detector families of the attack coverage matrix (Part C, C5) beyond SQL injection, using the same engine rules: pure functions, linear-time patterns, structural tokenizers where syntax matters, rule files with examples and counter-examples, fixtures in Class A/B/C form, benign gates, and ATK traceability enforced by `xtask attack-matrix check` (T-0313).

For each detector task the common deliverables are: rule files under `crates/hdd-waf-core/rules/<category>/`, a detector module where logic is structural, fixtures under `tests/fixtures/<group>/` (Class A for live-safe GET shapes, Class B/C inert strings), held-out sets under `heldout/`, benign counter-examples added to the corpora, proptest permutations of the evasion catalog applicable to the family, fuzz coverage through `inspect_request`, metrics and event subtypes, docs for the rules reference, and ATK links.

Every detector defines its hard/soft split explicitly, its field-kind behavior (C4.6 equivalents), and the ban policy branch (hard hits ban outside cross-site context unless the matrix row says `B`).

Gate G15 passes when: every ATK row marked as detected has fixtures and tests; held-out detection ≥ 95% per group; the benign gate stays at zero false positives; the mutation score for new modules ≥ 80%; fuzz smoke is clean; and inspection latency budgets still hold with all detectors enabled.

### T-0285 · XSS: HTML and JavaScript-context tokenizer and vector library
`P15` `[DP][SEC]` · deps: T-0262 · size: XL · owner: waf
**Objective.** Detect script injection by understanding HTML/JS context rather than only matching strings.
**Steps.**
1. Implement an HTML tokenizer (`html5gum` or equivalent, wrapped for bounded memory) over the `decoded` and html-canonical views producing tag open/close, attribute name/value, comment, doctype, and text tokens, with tolerant parsing for broken markup.
2. Implement detectors on tokens: `<script>` start tags; event-handler attributes (`on*` for the full HTML event list, case-folded, with whitespace/slash separators); URL-valued attributes (`href`, `src`, `action`, `formaction`, `data`, `poster`, `srcset`, `xlink:href`, `background`) carrying `javascript:`, `vbscript:`, `data:text/html`, `data:image/svg+xml`; dangerous tags (`iframe`, `object`, `embed`, `base`, `meta http-equiv=refresh`, `link rel=import`, `svg` with scripts, `math`, `template` with events); `srcdoc`; `style` with `expression(`/`url(javascript:`/`-moz-binding`.
3. Implement JS-context detectors for reflected payloads in script/attribute contexts: `</script>` breakouts, quote breakouts into handlers (`" onmouseover="`, `'-alert(1)-'`), template literal injection, `eval(`, `Function(`, `setTimeout("string"`, `document.cookie`, `document.write`, `innerHTML`, `location=`, `window.name` with suspicious patterns.
4. Define categories/subtypes (`xss`: `script_tag`, `event_handler`, `uri_scheme`, `dangerous_tag`, `css`, `dom_sink`, `breakout`) with hardness rules: hard when a complete executable construct is present (tag + handler, scheme URL in a URL attribute, `<script` start tag), soft for lone keywords (`alert`, `onerror` without tag context), field-kind relaxations for code-friendly sites (docs, blogs) limited to soft weights.
5. Provide the XSS fixture vectors (Class A: `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`, `<svg/onload=alert(1)>`, `javascript:alert(1)`, `"><script>`, etc.) and counter-examples (legitimate text about HTML, code samples in markdown fields with explicit code fences are still hard in non-code-friendly sites but soft in `code_friendly`).
6. Write rule metadata linked to ATK-061 to ATK-066, ATK-073, ATK-075.
7. Test across vectors including headers (`Referer`, `User-Agent`) and cookies.
8. Benchmark the tokenizer (p50 under 30 µs for 200-byte strings that pass the prefilter; strings without `<`, `>`, quotes, `javascript:` skip tokenization).
**Deliverables.**
- `xss` module, rules, fixtures (≥ 150), tests, bench
**Acceptance.**
- A1: all Class A XSS fixtures are hard in query, form, JSON, header and cookie vectors.
- A2: counter-examples are not hard.
- A3: the tokenizer is bounded (fuzz and adversarial nesting tests).
- A4: strings without relevant characters skip tokenization (performance test).
- A5: zero false positives on benign corpora (including HTML-rich comment samples marked benign soft-only where code-friendly).
**Tests.**
- Table (250) / proptest / fuzz; benign gate.
**Notes.** CSP and response sanitization are complementary and covered in T-0287 and the outbound phase.

### T-0286 · XSS: encoding evasion, polyglots, mutation vectors and DOM hints

6. Write fixtures for ATK-067 to ATK-070 and ATK-074 (AngularJS/Vue expression `{{constructor.constructor('alert(1)')()}}`) and rule metadata.

8. Validate against benign corpora; document soft-only constructs.

**Acceptance.**

- A2: mutation and polyglot fixtures are hard (or documented soft with scores).
- A3: JSFuck-like inputs score proportionally but short symbol runs in normal text do not.

**Tests.**

- A5: zero false positives on benign corpora.
**Tests.**

### T-0294 · CRLF, header and email-header injection
`P15` `[DP][SEC]` · deps: T-0241 · size: M · owner: waf
**Objective.** Block newline-based injection into headers, logs and mail.
**Steps.**
1. Detect CR (`%0d`), LF (`%0a`), CRLF, Unicode line separators (U+2028/9, U+0085) in parameters, path, headers and cookies after decoding, particularly when followed by header-like text (`Set-Cookie:`, `Location:`, `Content-Type:`, `Content-Length:`, `HTTP/1.1 200`, `Bcc:`, `To:`, `Cc:`, `Subject:`, `MIME-Version`).
2.
