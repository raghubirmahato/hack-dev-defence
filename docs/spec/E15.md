## E15. Coverage map (new in v5.1)

This appendix is the seed for `design/coverage/*.toml` (C19.5, T-0578). It maps standards categories to HDD mechanisms, attack groups (`AG-nn`, C5), acceptance checks (E3) and tasks (Part D), and states the limit of each. **The statuses are design targets.** `cargo xtask coverage check` fails a `covered` or `partial` row that lacks an ATK group, an AC and a task, and T-0578 downgrades any row whose evidence is missing; the generated public page (S-134) shows the counts of rows with PASS evidence. The category lists below are the editions current when this was written; T-0578 re-verifies each against the published list and records the edition and date.

Status vocabulary: **covered** = a detector is tested on held-out data with published detection and false-positive rates, the latest run has PASS evidence, and the limits name no structural blind spot for the main attack path; **partial** = part of the category is handled, or the lab proof is limited to inert interpreters, or detection depends on application behavior HDD cannot see; **signal only** = HDD raises a signal or a monitor-mode event but does not claim prevention; **not covered** = outside what HDD can see or do, stated plainly.

### E15.7 What HDD does not cover (always shown on S-134)

1. Flaws in an application's own business logic that look like valid use.
2. Vulnerabilities in client-side code that never cross HDD.
3. Zero-day techniques with no signature, structural, behavioral or learned (Sentinel) signal.
4. Volumetric floods larger than the server uplink, unless an upstream provider is contracted and measured.
5. A compromised origin, its credentials, its CI/CD pipeline or its dependencies' build process.
6. Insider misuse and stolen valid sessions used normally.
7. Services that can be reached without crossing HDD (a directly reachable origin address, other open ports on the origin) until the Bypass Guard reports the lockdown `verified`, and only for as long as that verification stays current.
8. Malicious content inside encrypted or opaque protocols that HDD does not terminate or parse.
9. Memory-safety and logic bugs inside the origin's own runtime, frameworks and databases.
10. Anything outside the HTTP, DNS and TLS paths that HDD terminates.
11. In the local profile: protection while HDD is not running or the computer is asleep, kernel-level enforcement, authoritative DNS on port 53, and any availability claim.
