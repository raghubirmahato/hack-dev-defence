## 5. Rust-first policy, with the frontend exceptions made explicit

Rust is the default for everything that runs, builds, tests, deploys or verifies HDD. Non-Rust is allowed only where listed; the exception list lives in `ARCHITECTURE.md` and is machine-checked by `cargo xtask rust-share`.

| Concern | Implementation (Rust) | Allowed non-Rust |
| --- | --- | --- |
| Proxy, WAF, DNS, API, web UI server, background workers, host agent (firewall + XDP) | workspace crates | none |
| Build, verify, secrets, SBOM, release, bench, fixtures, claims-lint, spec split, task index, UI asset build, i18n check, contrast check, report rendering | `cargo xtask` (`hdd-xtask`) | none |
| Deploy, PKI, backup/restore, key rotation, preflight, rollback, upgrade | `hddctl` (SSH via `russh`) | one `install.sh` bootstrapper (50 lines max) that fetches and verifies `hddctl` |
| Acceptance, protocol attacks, lab floods, load generation | `hdd-acceptance`, `hdd-loadgen` (raw sockets, `h2`, `hickory-client`, `rustls`) | `dig`, `delv`, `openssl s_client`, `h2spec`, `testssl.sh` as external **oracles** only |
| Lab-only attack oracles | driven by `hdd-acceptance` in `lab` mode | `sqlmap`, `nikto`, `wapiti`, `nuclei`, OWASP ZAP baseline, `ffuf`: **only** against Vuln-Lab addresses (section 2.8) |
| Browser e2e (login, CSP, CSRF, SSE, XSS escaping, keyboard, visual diff) | `chromiumoxide` (CDP) + `image` diffing | a Chromium binary; `axe-core` vendored as a **test-only** JS oracle with recorded checksum |

| Styling | hand-written CSS using design tokens, bundled by `lightningcss` (Rust) inside `xtask`; cascade layers; no runtime CSS-in-JS | CSS files |
| Fonts and icons | self-hosted WOFF2 fonts under open licenses and an SVG sprite from a permissively licensed icon set, license text recorded in `design/LICENSES.md` | font and SVG files |
| Charts and maps | server-rendered SVG generated in Rust (custom writer unless the ADR picks a crate); optional tooltip island | none |
| Docs site and legal pages | Markdown rendered in Rust (`pulldown-cmark` + `ammonia`) with a build-time search index | Markdown sources |
| PDF reports | headless Chromium print (via `chromiumoxide`) from the print stylesheet, or a Rust PDF crate per ADR | none |
| Local runtime: supervisor, embedded PostgreSQL manager, local CA, hosts helper, doctor, self-test, local backups | `hdd-local` | none |
| Installers and service definitions (Windows zip and optional MSI manifest, macOS pkg metadata, systemd, launchd and Task Scheduler templates, `cloud-init.yaml`) | generated by `cargo xtask package` from Rust structs | declarative manifests and unit files only |

| Grafana dashboards and alert rules as code | JSON generated by `xtask` from Rust structs | none |
| Datastores | Postgres, Redis | the servers themselves |

**Enforcement (`DEV-V5-002`).** `cargo xtask rust-share` runs `tokei` and fails if hand-written **Rust is below 90%** of hand-written *programming-language* lines (Rust, JavaScript, SQL outside migrations, shell). The expected figure is above 97%. Declarative markup is reported separately and capped: hand-written CSS at most 12,000 lines, askama HTML templates at most 40,000 lines, first-party JS at most 3,000 lines. Generated code, vendored files (HTMX, axe-core, fonts, icons, map data), migrations, YAML/TOML configuration and Markdown documents are excluded **and listed** in the report. The number is reported at every gate.

### 5.1 Component notes

- **Kernel filter:** `hdd-xdp-logic` is `no_std`, has no `unsafe`, is unit- and proptest-tested natively, and is compiled into the eBPF object, so it must be verifier-friendly: bounded loops, no recursion, no allocation, stack within 512 bytes. `hdd-xdp-ebpf` is the only crate allowed `unsafe`, under an ADR with verifier and packet-level tests.
- **Telemetry and escalation:** `procfs`/`sysinfo` for NIC, conntrack, softirq and socket counters; `hdd-shield` state machine; provider API clients with `reqwest` (rustls) behind a trait and the egress client, one real implementation per configured provider.
- **Vulnerability management:** `hdd-vuln` with `serde`, `semver`, `purl`, `cvss`, CycloneDX/SPDX parsers, pinned hosts through the egress client, `minisign-verify` for signed feeds; feeds are fetched only by the worker.
- **Posture scanning:** `hdd-scan` with `hyper`, `rustls`, `scraper`; read-only by design.
- **Self-update:** `hddctl upgrade` with signature verification (`cosign` bundle or `minisign-verify`), staged swap, health check, automatic rollback.
- **Product services:** `hdd-web` (SSR UI, three surfaces by Host), `hdd-api` (JSON API and SSE), `hdd-worker` (jobs: email outbox, webhook deliveries, rollups, ACME scheduling, feed fetch, verification polling, report generation, retention), `hdd-auth` (password, MFA, WebAuthn, sessions, API keys, RBAC), `hdd-mailer`, `hdd-notify`, `hdd-analytics`, `hdd-intel`, `hdd-challenge`.

## 6. Fixed technology stack (substitutions need a written ADR)

- Rust stable, workspace, pinned `rust-toolchain.toml`, `#![forbid(unsafe_code)]` in every workspace crate except `hdd-xdp-ebpf`. Dependency `unsafe` is tracked with `cargo-geiger` (or the documented substitute); any FFI dependency (aws-lc-rs, OpenSSL through `webauthn-rs`, xmlsec for SAML) needs an ADR. `thiserror` in libraries, `anyhow` only in binaries, `clap` for CLIs, `figment` or equivalent for config, `secrecy`/`zeroize` for secrets.
- Async/HTTP: `tokio`; `hyper` 1.x + `hyper-util`; `h2` for low-level control; control plane and UI via `axum` + `tower` + `tower-http`. Pingora is allowed for the proxy core only with an ADR and a spike showing it supports the required hooks (custom SNI resolver, per-request pipeline, h2 limits).
- TLS: `rustls`/`tokio-rustls` with a custom SNI `ResolvesServerCert`; **choose the crypto provider explicitly** (`ring` vs `aws-lc-rs`) in an ADR; `instant-acme` for ACME (HTTP-01, DNS-01 through the own DNS server, wildcard, ARI if supported); `tls-parser` for raw ClientHello parsing; `rcgen` only for the internal PKI and the optional default cert, never for a customer domain; HTTP/1.1 and HTTP/2 via ALPN. The origin client always verifies the origin certificate per the site's TLS verification mode; there is no switch to disable verification (an explicit, acknowledged `http_origin` mode exists for plaintext origins and is flagged in readiness).
- DNS: `hickory-proto` for wire format; `hickory-server` if the spike shows it allows EDNS cookies, RRL, CNAME flattening and minimal responses, otherwise a custom server loop over `hickory-proto`. `hickory-client` for tests and for onboarding scans.
- Data: PostgreSQL via `sqlx` (compile-checked in **offline mode**, `.sqlx` committed, migrations). Redis via `fred` (Lua for atomic ops). Both require auth and TLS (or a private Unix socket) in every mode. Row-level security on tenant tables. **Runtime stores sit behind traits** in `hdd-common::kv`: `KvStore` (get, set, incr, expire, hash and sorted-set subset, named atomic operations that replace the Lua scripts), `Bus` (pub/sub and bounded streams with monotonic revisions) and `Limiter` (counter and exact algorithms). `RedisKv` (hosted, `fred`) and `MemoryKv` (local and tests; sharded maps plus `tokio::sync::broadcast`) pass one conformance suite (T-0562). Hosted installs with more than one service process require Redis or Valkey. **Embedded PostgreSQL (local profile):** `hdd-local` manages a private PostgreSQL 16+ server from verified binaries (the `postgresql_embedded` crate or an equivalent chosen by ADR; SHA-256 and signature verified, fetched once through the egress client from a pinned host or installed offline from a local bundle), bound to a Unix socket or loopback with a generated password. Alternatives are an external server (`HDD_DATABASE_URL`) or Docker Compose. Migrations, roles and RLS are identical in all modes.
- WAF: `regex` and `regex-automata` (linear time), `aho-corasick`, `unicode-normalization`, `percent-encoding`, an HTML-entity decoder, bounded `flate2`/`brotli`/`zstd`, `multer`, `serde_json`, an XML tokenizer with DTD/entity processing disabled, `arc-swap`, `moka`, `ipnet` + a CIDR radix/trie crate, `maxminddb`, `governor`, `infer` (magic bytes). Own Rust SQL tokenizer/fingerprinter, HTML tokenizer (`html5gum` or equivalent) and shell lexer for the structural detectors (Part C).
- Auth/crypto: `argon2` (the pepper is passed through its native keyed `secret` parameter, T-0106), `jsonwebtoken` (service tokens only; browser sessions are opaque server-side), `aes-gcm`, `totp-rs`, `webauthn-rs` (passkeys preferred over TOTP when enrolled), `subtle`, `rand`, `hmac`, `sha2`, a password-strength estimator (ADR), `qrcode` for TOTP enrollment (rendered as server-side SVG).
- Web product: `askama`, `tower-http` (compression, trace, set-header, request-id), `pulldown-cmark` + `ammonia` (sanitized Markdown), `fluent`/`fluent-bundle` (i18n), `lightningcss` (CSS bundling), `lettre` (SMTP), `url` + `idna` + a public-suffix crate (registrable-domain logic), `schemars` + `utoipa` (schemas and OpenAPI), `image` (visual diff).
- Cross-platform (local profile): Windows 10/11 x64, macOS 13+ (arm64 and x64) and Linux (x64 and arm64) are supported for `local`; hosted is Linux only. Linux-only crates (`hdd-firewall` backends, `hdd-xdp*`, the `hdd-shield` host collectors) compile everywhere but select their `Noop` implementations off Linux (cfg-gated; the `Enforcer` trait is unchanged). OS integration (service or login-item registration, DPAPI and Keychain key wrapping, hosts-file edit) lives in `hdd-local::os`, uses audited safe wrappers (`unsafe` only inside vetted dependencies, tracked by `cargo-geiger`), and has per-OS tests in the CI matrix (T-0569).
- Observability: `tracing` (JSON), `metrics` + Prometheus exporter, `opentelemetry` (Tier 4), `/healthz`, `/readyz`, `/metrics`. API docs via `utoipa`.
- Test and quality: `cargo-nextest`, `proptest`, `cargo-fuzz`, `criterion`, `insta`, `testcontainers` (real Postgres, Redis, an SMTP sink) or, on a builder without Docker, the embedded PostgreSQL and in-process stores of `hdd-local` started by `cargo xtask db up` (still real services, never mocks), `loom` or `shuttle` for concurrency-critical structures, `cargo-mutants` on `hdd-waf-core`, `cargo-llvm-cov`, `cargo-machete` (or `cargo-udeps` on nightly), `cargo-deny`, `cargo-audit`, `cargo-vet` (import published audit sets, document exceptions), `cargo-cyclonedx`, `cargo-auditable`, `cosign` signing of release artifacts, digest-pinned base images, `cargo-chef` Docker builds.

**Standards the product is built and reviewed against (verify the current edition at build time):** OWASP ASVS (level 2 target; level 3 for the admin surface), OWASP Top 10, OWASP API Security Top 10 (2023), OWASP Cheat Sheet Series, WCAG 2.2 AA, NIST SP 800-63B password and authenticator guidance, RFC 9110/9112/9113 (HTTP), RFC 9457 (problem details), RFC 8555 (ACME), RFC 6797 (HSTS), RFC 9111 (caching), RFC 9460 (SVCB/HTTPS), RFC 7873/9018 (DNS cookies), RFC 8482 (ANY), RFC 2308 (negative caching), RFC 7208/6376/7489 (SPF/DKIM/DMARC).

### 8.2 Local-profile rules

With `runtime.profile: local` the only required fields are `runtime`, `operator_email` and `signup` (mode `disabled` or `invite_only`; `open` is refused). `platform_domain` defaults to `hdd.localhost`, `deployment_mode` must be `owner_only`, and `surfaces.admin_exposure` is forced to `tunnel_only` (loopback). Domains are added from the UI, not the profile. The fields `platform.*`, `dns.*`, `registrar`, `acme`, `upstream_ddos` and `secondary_dns` are ignored and reported as "not applicable in local". `hddctl preflight` and `hdd-local doctor` print which acceptance checks can run (the `local` tier of AC-55 and every unit, integration and browser test) and which are UNVERIFIED(`environment_unsupported`) (authoritative DNS on 53, kernel enforcement, ACME, DDoS and cutover checks). Moving to a server later is a profile change plus `hdd-local export` and `hddctl import` (C18.12).
