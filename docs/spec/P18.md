## PHASE P18: Proxy core pipeline and HTTP hardening (T-0353 to T-0374) · milestone M8 · gate G18

Requirement prefix `PRX`. Goal: turn the walking-skeleton proxy into the full production data plane: hardened HTTP/1.1 and HTTP/2 front ends, the complete ordered pipeline with budgets, request body handling, upstream header policy, a robust origin client, visitor pages, WebSocket/gRPC passthrough, the event pipeline, resilience behaviors, safe mode, automatic rollback and raw-socket protocol tests.

Non-negotiables: inspection never fails open in `block` mode (R-26); the hot path never awaits the database; a panic in one request never affects others (task isolation, `MET-hdd_panics_total`); every buffer, queue and loop is bounded; origin certificate verification cannot be disabled; HDD never follows origin redirects.

Gate G18 passes when: AC-14 (protocol hardening) passes against the sandbox hostname with process health maintained, AC-15 resilience scenarios (pilot stage) pass, AC-13 (modes, safe mode, auto-rollback) passes, AC-16 convergence subsets pass, performance budgets (proxy-added p99 ≤ 5 ms functional profile) hold, and fuzz smoke on HTTP parsers is clean.

### T-0353 · Listener and accept loop; proxy-core decision (Pingora versus own)
`P18` `[DP][SEC]` · deps: T-0208 · size: L · owner: dp
**Objective.** Finalize the proxy core and build the accept layer that sheds load gracefully.
**Steps.**
1. Finalize the ADR started in T-0208: compare Pingora (hooks for custom SNI resolution, per-request pipeline, h2 limits, memory behavior, maintenance, license, build size) against the own `hyper`-based core using the walking-skeleton measurements and a hook-completeness checklist; keep own core unless Pingora demonstrably satisfies every required hook with less code and equal control; record the decision and rollback plan.
2. Implement listeners with `SO_REUSEPORT`, per-listener accept queues, backlog tuning from `somaxconn`, connection caps (global, per IP, per site), and fairness (round-robin accept across worker tasks).
3. Implement the **shed policy**: when connection or in-flight limits are exceeded, new connections are rejected cheaply (TCP close before TLS for non-allowlisted keys when over the global cap; HTTP 503 with `Retry-After` when headers can be parsed), prioritizing established clearance clients and allowlisted keys; document the order of shedding.
4. Implement TCP socket options (TCP_NODELAY, keepalive timers, `TCP_DEFER_ACCEPT` where applicable, user timeout), IPv4/IPv6 dual-stack handling with separate sockets, and PROXY protocol acceptance (opt-in, T-0315).
5. Implement graceful restart support via socket handoff (systemd socket activation or `SO_REUSEPORT` overlap) with drain-on-SIGTERM (default 5 s downtime bound per Appendix E4).
6. Implement per-connection resource accounting (buffers, streams) and a memory budget per connection class.
7. Add metrics (`MET-hdd_proxy_connections`, `shed_total`) and structured logging for shed events (rate-limited).
8. Test connection floods (functional profile on the builder), slow handshakes, and restart behavior.
**Deliverables.**
- listener layer, ADR, tests
**Acceptance.**
- A1: under a 20k-connection flood on the builder, established clients keep p99 within 2x baseline.
- A2: restart (SIGTERM with replacement process) causes at most 5 s of unavailability and no dropped in-flight requests within the drain window.
- A3: per-IP caps are enforced for IPv4 and IPv6 keys.
- A4: shed responses follow the documented order.
- A5: the ADR contains the hook checklist with evidence.
**Tests.**
- Load/chaos tests; restart tests with a client that records errors; unit: shed policy decisions.
**Notes.** Kernel-level protections complement but do not replace this layer.

### T-0354 · TLS termination: crypto provider ADR, SNI resolver, policy and refusal behavior
`P18` `[DP][SEC]` · deps: T-0353, T-0195 · size: L · owner: sec
**Objective.** Terminate TLS correctly, quickly and with strict defaults.
**Steps.**
1. Decide the `rustls` crypto provider (`ring` vs `aws-lc-rs`) in an ADR using measurements (handshake throughput, binary size, FIPS considerations, FFI implications recorded as `DEV` if `aws-lc-rs`), and set the build features accordingly.

6. Implement HTTP→HTTPS redirect handling on port 80 (except ACME and verification paths), HSTS header emission per policy, and HTTP/2 coalescing rules (421 when the authority is not covered by the negotiated certificate).
7. Verify with external oracles: `openssl s_client` for version/cipher checks and SNI behavior, `testssl.sh` in lab/builder for a configuration report (oracle only), and Rust-based assertions.
8. Document the TLS policy and its rationale.
**Deliverables.**
- TLS layer, ADR, tests, docs
**Acceptance.**
- A1: TLS 1.0/1.1 handshakes fail; 1.2/1.3 succeed; the cipher list matches the policy (oracle output).
- A2: unknown and absent SNI are refused with the documented behavior.
- A3: certificate swap occurs without dropping existing connections.
- A4: 421 is returned for h2 requests whose authority is outside the certificate.
- A5: 0-RTT is disabled and renegotiation refused (tests).
**Tests.**

### T-0356 · HTTP/1.1 server hardening
`P18` `[DP][SEC]` · deps: T-0353 · size: XL · owner: dp
**Objective.** Make HTTP/1.1 parsing strict and smuggling-resistant.
**Steps.**
1. Choose and configure the HTTP/1 parser (`hyper`/`httparse` with strict options) and wrap it with additional validation: reject requests with both `Content-Length` and `Transfer-Encoding`, multiple differing `Content-Length` values, signs/hex/whitespace in lengths, `Transfer-Encoding` values other than a single `chunked`, obsolete line folding, bare LF line endings (strict CRLF), spaces/tabs before the header colon, control characters/NUL in header names/values, invalid methods/targets, absolute-form request targets with mismatched hosts, request lines over 8 KiB, header blocks over 32 KiB (431), too many headers (default 100), duplicate singleton headers (`Host`, `Content-Length`, `Content-Type`), and chunk-size lines/extensions over limits (chunk extension disabled).
2. Enforce body limits (10 MiB, 413), header-read timeout 10 s, idle timeout 60 s, and keep-alive limits (max requests per connection 1,000; close on any parse anomaly).
3. Ensure that after any framing anomaly the connection is closed and responses use `Connection: close` to prevent desync propagation.
4. Disable unsupported features: HTTP/1.0 keep-alive quirks (treated per RFC), `Expect` handling (100-continue after headers pass pipeline preflight), `Upgrade` only for WebSocket (and h2c disabled), `TRACE` rejected, `CONNECT` rejected.
5. Implement the HTTP/1 response writer hardening: strip CR/LF from header values set by HDD, disallow header injection through proxied values (origin responses are validated too), normalize header casing for HTTP/1, remove hop-by-hop headers properly.
6. Generate events for protocol violations (aggregated) with category `proto` and ban rules for repeated/obvious smuggling attempts.
7. Write the raw-socket test corpus (ambiguity cases: 80 requests) and a differential test against a reference parser to ensure HDD rejects anything ambiguous.
8. Fuzz the parser wrapper and run sanitizer builds.
**Deliverables.**
- hardened HTTP/1 layer, corpus, tests
**Acceptance.**
- A1: all 80 ambiguity cases are rejected with 400/431/413/501 and connection close.
- A2: valid pipelined and chunked requests still work (compatibility suite of 50 cases).
- A3: header injection through proxied values is impossible (tests).
- A4: fuzzing runs 60 s in `verify` without crash.
- A5: protocol violations produce aggregated events.
**Tests.**
- Raw-socket table tests; differential tests; fuzz.
**Notes.** ATK-135 to ATK-141, ATK-146, ATK-154.

### T-0357 · HTTP/2 server hardening
`P18` `[DP][SEC]` · deps: T-0353, T-0354 · size: XL · owner: dp
**Objective.** Contain h2 resource-exhaustion attacks with enforceable limits.
**Steps.**
1. Configure the `h2` server with limits from Appendix E4: max concurrent streams 100, header list size 64 KiB, initial window sizes bounded, max frame size 16 KiB, HPACK dynamic table 4096 B and decoded header size cap, max pending accept reset streams, and connection-level flow-control limits.
2. Implement frame-rate limiters wrapping the transport/frame layer (own frame sniffer where `h2` lacks hooks): RST_STREAM at most 100 per 10 s per connection (Rapid Reset), then GOAWAY(ENHANCE_YOUR_CALM); SETTINGS at most 10 per 10 s; PING at most 10 per s; empty DATA frames at most 100 per 10 s; PRIORITY frames limited (ignored per RFC 9113 deprecation, with a counter); WINDOW_UPDATE flood limits; CONTINUATION header-block size cap and frame count cap (CONTINUATION flood).
3. Implement stream-level protections: cancel streams exceeding header size, reject streams that send pseudo-headers after regular headers, malformed pseudo-headers, duplicate pseudo-headers, uppercase header names, connection-specific headers (`connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `upgrade`), `te` other than `trailers`.
4. Implement idle/keepalive timers, GOAWAY on graceful shutdown, and limits on total streams per connection lifetime (e.g., 10,000) forcing reconnection.
5. Disable h2c upgrade and prior-knowledge cleartext HTTP/2 unless explicitly enabled for internal listeners.
6. Implement metrics (frames by type, resets, GOAWAY reasons) and events (`proto` subtype `h2_abuse`) with ban policy for repeated abusers.
7. Build raw-socket attack generators in `hdd-acceptance` (`protocol-abuse` profile: 5 connections, 2,000 frames, 10 MiB caps): rapid reset, CONTINUATION flood, HPACK bomb, SETTINGS/PING/empty-frame floods, priority flood, window-update flood; cross-check with `h2spec` as an oracle in the builder.
8. Test that the process stays healthy (memory/CPU bounds) during attacks.
**Deliverables.**
- hardened h2 layer, generators, tests
**Acceptance.**
- A1: each attack class is contained: connection closed with GOAWAY or reset within the thresholds and the process remains healthy (memory growth under 5%, p99 for other clients within 2x).
- A2: `h2spec` conformance results are recorded (oracle) with documented deviations only for intentional hardening.
- A3: invalid pseudo-header and connection-specific header requests are rejected.
- A4: limits are configurable only within safe ranges (validated).
- A5: metrics count each abuse class.
**Tests.**
- Raw-socket attack suite (sandbox/builder only); `h2spec`; fuzz of frame parsing.
**Notes.** CVE-2023-44487 mitigation is verified here; CONTINUATION flood (2024) likewise.

### T-0358 · h2-to-h1 downgrade safety and header normalization
`P18` `[DP][SEC]` · deps: T-0356, T-0357 · size: M · owner: dp
**Objective.** Prevent request smuggling when translating HTTP/2 requests to HTTP/1.1 upstream.
**Steps.**
1. Implement strict translation rules: derive `Host` from `:authority` (validated against the site), build the request line from validated `:method` and `:path` (reject spaces, CR/LF, NUL, fragments), and reject requests whose `:authority` and `Host` headers disagree.
2. Always compute framing for the upstream request from the actual body: set exactly one `Content-Length` (or use chunked for unknown length), never forward client `Content-Length`/`Transfer-Encoding` values unvalidated; reject h2 requests with `content-length` not matching the sum of DATA frames.
3. Reject or normalize header names/values that are valid in h2 but dangerous in h1 (CR/LF/NUL, leading/trailing whitespace, header names with special characters, extremely long values), and drop h2-only pseudo semantics.
4. Convert cookies: multiple `cookie` header fields in h2 are joined with `; ` per RFC 9113.
5. Prefer h2 or h1.1 upstream per origin capability negotiation (ALPN); when the origin supports h2, use h2 end to end with the same hardening; otherwise downgrade safely.
6. Test with a corpus of h2 smuggling vectors (H2.CL, H2.TE, CRLF in header values/names/pseudo-headers) against a back-end test server that would be vulnerable if bytes were forwarded verbatim.
7. Add differential tests that reconstruct the upstream bytes and verify equivalence with a canonical serializer.
8. Fuzz the translator.
**Deliverables.**
- translation layer, corpus, tests
**Acceptance.**
- A1: all H2.CL/H2.TE/CRLF vectors are rejected before any byte reaches the origin (origin socket capture shows zero bytes).
- A2: valid requests translate identically to a reference serializer (differential).
- A3: mismatched `:authority`/`Host` is rejected.
- A4: DATA length mismatches are rejected.
- A5: fuzzing is clean.
**Tests.**
- Raw h2 test client + capture origin; differential; fuzz.
**Notes.** ATK-138.
