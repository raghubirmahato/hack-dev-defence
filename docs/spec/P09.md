## PHASE P09: DNS management (T-0177 to T-0194) · milestone M4 · gate G09

Requirement prefix `DNM`. Goal: everything an owner needs to manage a zone served by HDD: validated records, a pure answer engine that previews exactly what will resolve, mail-safety helpers, import/export with parity, versioned history with rollback, change-safety checks, templates, zone settings, DNSSEC awareness, propagation checks, secondary DNS settings, dangling-record detection and DNS analytics views. The authoritative server itself arrives in P11 (minimal) and P20 (complete); here the control plane produces the same immutable zone snapshot those servers will serve, and the answer engine is shared code so previews cannot drift from reality.

Gate G09 passes when: records, zones, versions and imports work through UI and API with RLS; the answer engine passes the protocol-correctness table tests; previews agree with the answer engine in 100% of property tests; safety checks block the unsafe changes in the catalog; and all screens meet the UI definition of done.

### T-0177 · DNS data model, zone lifecycle and records API
`P09` `[DB][API]` · deps: T-0153 · size: L · owner: dns
**Objective.** Persist zones and records and expose a safe CRUD API.
**Steps.**
1. Write migration 0007: `zones`, `dns_records`, `zone_versions`, `zone_imports`, `ns_pairs` per B5.4, with RLS, unique constraints (zone, normalized name, type, value), `proxied` check constraint (only A/AAAA/CNAME), and indexes for name lookups and version queries.
2. Implement zone creation tied to `sites` (one zone per apex site in `full_ns`/`hidden_primary` modes; none in partial modes except the platform-operated edge/acme zones), NS pair assignment from the pool, default SOA values, and serial initialization `YYYYMMDDnn`.
3. Implement the records API (`GET/POST D/dns/records`, `GET/PATCH/DELETE D/dns/records/{rec}`, `POST D/dns/records:bulk` with atomic semantics up to 200 operations) with `If-Match`, idempotency keys, cursor pagination, filters (type, name, proxied, source) and audit events.
4. Implement every mutation as a transaction that writes a new `zone_versions` row (diff + snapshot hash), bumps the SOA serial, and publishes a snapshot revision to the config outbox.
5. Enforce zone limits by plan (records per zone, zones per org) via `QuotaGuard`.
6. Implement soft system records (SOA, NS at apex, edge/acme helper records) as read-only `source=system` rows.
7. Generate OpenAPI for the endpoints.
8. Write tests for concurrency (two simultaneous edits), atomic bulk failure, and RLS.
**Deliverables.**
- migration 0007, repositories, handlers, OpenAPI, tests
**Acceptance.**
- A1: a failed bulk operation changes nothing (atomicity test).
- A2: every successful mutation creates exactly one version and one serial bump.
- A3: system records cannot be edited or deleted by tenants (`ERR-DNS-005`).
- A4: RLS prevents cross-org record access (BOLA suite additions).
- A5: record limits per plan are enforced with `ERR-DNS-007`.
**Tests.**
- Integration (Postgres): concurrency, atomic bulk, RLS; unit: serial computation (same-day increments, rollover at nn=99 uses next-day carry rule documented).
- Property: any sequence of valid mutations keeps invariants (unique tuple, serial monotonic).
**Notes.** Serial rollover beyond 99 changes per day uses a documented arithmetic rule so serials remain strictly increasing.

### T-0178 · Per-type record validation library
`P09` `[API][SEC]` · deps: T-0177 · size: L · owner: dns
**Objective.** Make invalid or dangerous records impossible to store.
**Steps.**
1. Implement `hdd-common::dns::validate` with per-type parsers and canonical forms: A (valid IPv4, not in disallowed ranges when `proxied`), AAAA, CNAME (hostname, no trailing-dot ambiguity, loop check hooks), MX (priority 0 to 65535, target hostname not IP), TXT (strings split into 255-byte chunks, total 4,096 bytes, printable and escape handling), NS (delegation records only for subzones), SRV (priority, weight, port, target), CAA (flags, tag in `issue/issuewild/iodef`, value syntax), HTTPS/SVCB (priority, target, params with known keys, `ipv4hint/ipv6hint` handling), and read-only SOA.
2. Enforce name rules: labels 1 to 63, total 253, allowed characters (LDH plus underscore for service labels), wildcard only as a leftmost label, relative vs absolute handling, IDNA conversion for Unicode input.
3. Enforce structural rules: CNAME cannot coexist with other types at the same name (`ERR-DNS-002`), no CNAME at apex, NS at apex is system-managed, MX/SRV targets must not be CNAMEs (warning), TTL bounds (min 60 s, max 86,400 s; proxied records report a virtual TTL).
4. Enforce proxy rules: only A/AAAA/CNAME can be `proxied` (`ERR-DNS-003`); mail-related names cannot be proxied (`ERR-DNS-004`); proxied CNAME targets must be within the same zone or resolvable by the flattening resolver.
5. Return structured diagnostics (field path, code, message key, suggestion) suitable for inline UI display.
6. Provide lenient/strict modes: import uses a parse that reports unsupported items rather than failing the entire import.
7. Provide fuzz targets and a large fixture corpus (valid and invalid examples per RFC).
8. Document each rule with RFC references.
**Deliverables.**
- validation module, fixtures (200+ cases), docs
**Acceptance.**
- A1: all fixtures produce the expected accept/reject result and diagnostic code.
- A2: validators are panic-free on arbitrary bytes (fuzz).
- A3: TXT chunking is exact (round trip equality with RFC-style parsing).
- A4: proxied rules reject mail names and non-proxiable types.
- A5: diagnostics include field paths usable by the form library.
**Tests.**
- Table tests; proptest (parse(print(x)) == x for canonical records); fuzz targets per type.
**Notes.** The server (P20) reuses these types for zone loading so rules are enforced twice.

### T-0179 · Zone snapshot model and the pure answer engine
`P09` `[DP][DNS][SEC]` · deps: T-0178 · size: XL · owner: dns
**Objective.** Implement the shared logic that decides what a zone answers, used by previews and by `hdd-dns`.
**Steps.**
1. Define `ZoneSnapshot` (immutable, indexed by lowercase name with a name tree for wildcard and empty-non-terminal handling) and `compile(records, settings, platform) -> Result<ZoneSnapshot>` including system records and orange/grey rewriting inputs.
2. Implement `answer(snapshot, question, client_ctx) -> Answer` as a pure function covering: exact match, wildcard match with the "closest encloser" rule, NODATA vs NXDOMAIN with correct SOA in authority, CNAME chains within the zone (loop detection, depth limit 8), CNAME at queried type vs `CNAME` target handling, empty non-terminals, `ANY` minimal answer (RFC 8482), AA flags, delegation (NS below apex returns referral), refusal for names outside the zone.
3. Implement the orange-cloud rewrite: proxied A/AAAA/CNAME answers return only HDD addresses (shuffled deterministically per query for testability with a seeded RNG), AAAA NODATA when HDD has no IPv6, HTTPS/SVCB hint rewriting, and no origin data anywhere.
4. Implement CNAME flattening hooks at the apex as a trait (`FlatteningResolver`) with the bounded cache implementation in P20; the engine treats flattened answers as synthesized A/AAAA.
5. Implement response size estimation to decide truncation (UDP payload 1232 default) and minimal-response rules.
6. Implement canonical text rendering of answers for previews (dig-like) and wire-conversion helpers in `hdd-dns` later.
7. Build a comprehensive table test suite from RFC 1034/1035/2308/4592/8482 behaviors plus a differential test against a reference implementation used as an oracle (`dig` against a loopback BIND-class or hickory server where available).
8. Provide criterion benchmarks (answer p99 under 20 µs for 10k-record zones).
**Deliverables.**
- `hdd-common::dnsmodel` (snapshot, compile, answer), tests, benches, docs
**Acceptance.**
- A1: 300 table cases pass (wildcards, ENTs, CNAME chains, NODATA, NXDOMAIN, referrals, ANY).
- A2: proxied names never expose origin data in any section (property test over random zones).
- A3: the engine is pure and `no I/O` (compile-time: no async, no network types).
- A4: differential tests against an oracle agree on all non-implementation-defined cases.
- A5: p99 answer time meets the benchmark target.
**Tests.**
- Table/proptest/differential/benchmarks; fuzz target on zone compile inputs.
**Notes.** This module is the single source of truth for DNS answer semantics (AC-03).

6. Add configuration for thresholds per plan.
7. Add comprehensive tests (60 scenarios).
8. Document the catalog of rules with IDs (`DNSSAFE-001...`).
**Deliverables.**
- safety engine, rule catalog, API integration, tests
**Acceptance.**
- A1: every rule has a positive and negative test.
- A2: API and UI show identical findings for identical changes.
- A3: blocked changes cannot be forced by any client (no override flag).
- A4: warnings require explicit acknowledgment tokens bound to the change set hash.
- A5: impact summaries match the answer engine diff.
**Tests.**
