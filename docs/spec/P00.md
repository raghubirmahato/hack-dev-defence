## PHASE P00: Bootstrap and governance (T-0001 to T-0010) · milestone M0 · gate G00

Requirement prefix `GOV`. Goal: the agent can be resumed from files alone, the workspace builds and verifies itself, the live profile is validated, and safety libraries exist before any feature work. This is the only phase that precedes UX work, because the persistent state files and the egress guard are preconditions for everything else.

Gate G00 passes when: `docs/SPEC.md` and its split exist with a matching checksum; `AGENTS.md` is at most 150 lines; `cargo check --workspace` and `cargo xtask verify` are green; `hddctl preflight --profile-only` reports honestly (including real failures); the egress guard tests pass; the capability matrix is generated; the first response of section 9 has been delivered and the operator's answers are recorded or marked open.

### T-0001 · Save the specification verbatim, split it, and index every task
`P00` `[DOC][OPS]` · deps: none · size: S · owner: docs
**Objective.** Make the specification durable and cheaply loadable: one verbatim copy, one split copy, one index from task ID to file and line.
**Steps.**
1. Create the repository skeleton directories from section 7 (empty directories get a `.gitkeep`); do not create code yet. The skeleton is `.gitkeep` files only; the first real code arrives with T-0004.
2. Copy this entire document byte-for-byte to `docs/SPEC.md`; compute SHA-256 and write it to `docs/SPEC.sha256` with the date.
3. Write the one-off bootstrap splitter as a short POSIX `awk` command recorded in `docs/DEVIATIONS.md` as `DEV-V5-000` (the sole permitted non-Rust script; it is deleted by T-0005).
4. Split at every `<!-- PART:<id> -->` and `<!-- PHASE:<id> -->` marker into `docs/spec/<id>.md`, keeping the marker as the first line of each file; the preamble before the first marker goes to `docs/spec/00-preamble.md`.

6. Verify losslessness: concatenating `docs/spec/*.md` in order must reproduce `docs/SPEC.md` exactly (compare SHA-256).
7. Add a README section "Reading the spec" explaining the loading strategy of section 0.1.
8. Commit with message `docs: add verbatim spec v5 and split index` and trailer `Task: T-0001`.
**Deliverables.**
- `docs/SPEC.md`, `docs/SPEC.sha256`
- `docs/spec/*.md` (about 50 files) and `docs/spec/INDEX.md`
- `docs/DEVIATIONS.md` containing `DEV-V5-000`

**Acceptance.**

- A3: every phase P00 to P34 has a split file whose first line is its marker.
- A4: no file in `docs/spec/` exceeds 3,000 lines (splitting at phase markers keeps phases manageable; if a phase exceeds it, the splitter adds sub-splits at task boundaries and the index records them).

**Tests.**

### T-0004 · Cargo workspace, lints, toolchain and dependency policy
`P00` `[OPS][SEC]` · deps: T-0002 · size: M · owner: infra
**Objective.** Create the workspace so that unsafe code, unwraps and panics are build failures from the first commit.
**Steps.**
1. Create `Cargo.toml` with `[workspace]` listing every crate from section 7 (each with a minimal `lib.rs` or `main.rs` that compiles), `resolver = "2"`, shared `[workspace.package]` and `[workspace.dependencies]` (no versions asserted from memory; read them from the registry at the time).
2. Add `[workspace.lints]`: deny `unsafe_code`, `clippy::unwrap_used`, `expect_used`, `panic`, `indexing_slicing`, `todo`, `unimplemented`, `dbg_macro`, `print_stdout` (allowed in CLI crates via crate-level override), `missing_docs` for public items; `warnings` denied in CI.

4. Pin the toolchain in `rust-toolchain.toml` (stable) with `rustfmt` and `clippy` components; record MSRV.
5. Write `deny.toml`: licenses allowlist (permissive plus MPL-2.0/OpenSSL-style exceptions decided in the ADR), bans for yanked crates, advisories from RustSec, duplicate-version warnings, sources restricted to crates.io.
6. Add `rustfmt.toml`, `clippy.toml`, `.cargo/config.toml` (no network flags that weaken TLS), and a `lab/vulnlab` workspace member that is excluded from `default-members` and has its own lint override only for the intentional-vulnerability modules, still with `forbid(unsafe_code)`.
7. Run `cargo check --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --check`.
8. Commit the lockfile (`Cargo.lock`).
**Deliverables.**
- `Cargo.toml`, `rust-toolchain.toml`, `deny.toml`, `rustfmt.toml`, `clippy.toml`, `.cargo/config.toml`

- `Cargo.lock`
**Acceptance.**

- A3: `cargo deny check` runs (exceptions documented with expiry).
- A4: `hdd-vulnlab` does not appear in `cargo tree -p hdd-proxy -e normal` or any shipped binary's graph.

### T-0009 · Egress client, SSRF guard, target allowlist and kill switch
`P00` `[SEC][DP]` · deps: T-0004, T-0006 · size: L · owner: sec
**Objective.** Build the single outbound path that makes the safety envelope enforceable in code.
**Steps.**
1. Implement `hdd-common::egress::Client` over `hyper` + `rustls`: allowlist matching by scheme, host (exact or suffix), port and optional path prefix; connect/total timeouts; maximum response size; redirects disabled by default (opt-in per call with re-validation of each hop); TLS verification always on.
2. Implement DNS pinning: resolve, validate, connect to the validated address, never re-resolve silently; the resolver is a trait so unit tests can drive rebinding sequences.
3. Implement the **SSRF-guarded variant** `UserUrlClient` enforcing section 2.9: public unicast only, rejected ranges (loopback, RFC 1918, CGNAT, link-local incl. metadata, multicast, unspecified, documentation, IPv6 ULA, IPv4-mapped forms, platform addresses), port allowlist, no redirects, re-validation on every connect.
4. Implement `TargetGuard` for acceptance and scanning tools: derives the allowed target set from the profile (`test_hostname`, `sandbox_hostname`, and lab addresses in lab mode) and aborts on any other target.
5. Implement the kill switch: a file path watched by a cheap poller; all long-running tools check it and abort within one second.
6. Log every denied egress attempt as a structured event (destination, reason, caller) with rate limiting of the logs themselves.
7. Add an xtask grep rule that fails if `reqwest::Client::new`, `hyper::Client` construction, or `std::net::TcpStream::connect` appears outside `egress`, tests, and listed exceptions (R-22).
8. Write the module documentation and an `OPERATIONS.md` section describing allowlist entries and how to request additions.
**Deliverables.**
- `crates/hdd-common/src/egress/{client,ssrf,target,killswitch}.rs`
- xtask grep rule; docs
- test suite with real local HTTP/TLS servers and a real local DNS responder
**Acceptance.**
- A1: a request to a host not on the allowlist is denied before any socket is opened (proved by an unused-listener test).
- A2: a hostname that first resolves to a public address and then to `127.0.0.1` is rejected at connect time.
- A3: a redirect from an allowed host to `http://169.254.169.254/` is not followed.
- A4: `TargetGuard` rejects any target outside the derived set, including via CNAME to another host.
- A5: touching the kill-switch file aborts a running sample tool within 1 s.
**Tests.**
- Unit: range classification table for IPv4/IPv6 including mapped and compressed forms (property test: classification invariant under textual representation).
- Integration: local servers prove timeouts, size caps, TLS verification failure, redirect policy.
- Fuzz target: URL/host parsing never panics.
**Notes.** This module is the foundation of R-22; later tasks must not create other outbound paths.
