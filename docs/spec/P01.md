## PHASE P01: UX research, personas, information architecture, journeys (T-0011 to T-0028) · milestone M1 · gate G01

Requirement prefix `UXR`. Goal: turn the product definition of Part B into reviewed repository documents and decisions before any pixel is designed, so that design and build start from agreed principles, flows and constraints. Deliverables live in `docs/UX/` and are written for the operator to review. No shipped UI exists yet; these are design inputs, not prototypes.

Constraints: no scraping or browsing outside the egress allowlist; "pattern review" uses only operator-supplied screenshots, public documentation fetched through the egress client if the operator allowlists it, or first principles (and is labeled accordingly). All text follows the voice rules of B11.12.

Gate G01 passes when: the UX charter, personas, information architecture, journeys, states, accessibility and i18n plans, security-UX review and the review pack exist in `docs/UX/` and link to each other; `xtask ux check` reports zero orphan screens or journeys; the open operator decisions each have a default and an owner; and `docs/gates/G01.md` exists in the E5.1 format with the pasted command output. G01 is a light gate: the operator is shown the pack, but design sign-off is the heavier gate G03.

### T-0011 · Product principles, success measures and UX charter
`P01` `[DOC]` · deps: T-0010 · size: S · owner: ux
**Objective.** Fix the principles every design decision is judged against, and the measures that tell us whether the UX works.
**Steps.**
1. Write `docs/UX/CHARTER.md` containing the seven design principles of B11.1 with one concrete "we will" and "we will not" example each.
2. Define the experience measures: time to first domain in monitor mode, completion rate of the add-domain wizard, number of support-worthy errors per 100 sessions, false-positive appeal rate, time to unban, accessibility defects open, and how each is measured honestly in a self-hosted product (local counters, no third-party analytics).
3. Define the "honesty tests": five questions every screen must pass (Does it show real data? Does it state limits? Is anything claimed untested? Is the safe option default? Can the user undo?).
4. Write a decision log format for UX decisions (`docs/UX/decisions/UXD-nnn.md`) and record the first three: dark-first theming, server-rendered UI, no third-party analytics.
5. Map every principle to enforcement mechanisms (a lint, a checklist, or a test) so principles are not decorative.
6. Add the charter to `AGENTS.md` pointers.
7. Review the charter against the claims policy (section 4) and fix any drift.
8. Commit.
**Deliverables.**
- `docs/UX/CHARTER.md`, `docs/UX/MEASURES.md`
- `docs/UX/decisions/UXD-001..003.md`
**Acceptance.**
- A1: each principle has an enforcement mechanism listed.
- A2: each measure names its data source and its privacy treatment.
- A3: the honesty tests are phrased as yes/no questions.
- A4: claims-lint passes on the new documents.
- A5: the charter fits on four printed pages.
**Tests.**
- `cargo xtask verify` (claims-lint, link check for relative links).
**Notes.** The measures feed T-0139 (overview KPIs for operators) only where they are legitimately collectable.
