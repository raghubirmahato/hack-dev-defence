## E3. Acceptance matrix (AC-00 to AC-62)

### E3.1 Rules common to every check

1. **Status taxonomy:** `PASS`, `FAIL(reason)`, `UNVERIFIED(reason_code)` with the closed reason set `capability_not_supplied`, `human_step_pending`, `environment_unsupported`, `oracle_unavailable`, `tool_unavailable`, `stage_not_reached`, `stage_forbids`, `skipped_by_operator`. No other status exists. A PASS needs at least one evidence artifact with SHA-256.
2. **Real-IP handling:** no `X-Forwarded-For` spoofing and no trusted test subnet; the runner uses its real IP. Tests needing several sources use `vantage_points` from the profile; otherwise they run sequentially with an unban between each, and the report states the vantage count used.
3. **Block assertions verify two things:** the 403 (or branded block page) with a Ray ID **and** a matching event record (category, client IP key, `ray_id`) via the events API, so jail blocks are never mistaken for detections.
4. **Inspect-first gate** (section 2.2) precedes every live attack-shaped payload; payload classes A/B/C are enforced by the connector; lab-mode checks target only Vuln-Lab addresses.
5. **Rate profiles** (section 2.3) and the kill switch apply to every check; checks can choose a lower profile but never a higher one.
6. **Stages:** `pilot` allows destructive checks with warning; `production` refuses them without the operator's approval of that specific run; after cutover only the non-destructive regression subset runs by default (AC-00, AC-03, AC-05, AC-20, AC-22, AC-35 login-only, sandbox-only checks).
7. **Failure budget:** three attempts per check (R-14); a check that passes only on retry is `Pass (flaky)` and is not release evidence until diagnosed.
8. **Catalog parity:** the typed catalog in `hdd-acceptance` and this appendix are compared by a CI test; adding a check means editing both in one change.

### E3.5 The checks

#### AC-00 · Preflight and safety-envelope self-tests

- **Area / first live:** Foundation · P11 (T-0217); self-tests T-0492 (P28)
- **Implemented and run by:** T-0010, T-0217, T-0492
- **Tier / mode / safety class:** smoke · live + lab · read-only (self-tests send refused traffic only)
- **Procedure:** `hddctl preflight` validates the profile and environment; the self-test suite proves the guard rails (allowlists, class gating, rate ceilings, kill switch, runner-IP guard, stage refusals, oracle launcher refusal).
- **PASS when:**
  - Profile validates against schema_version 5; required fields present; `min_resources` met; kernel features and XDP mode recorded
  - Required ports reachable and no conflicts on 53/80/443; pilot NS and A records resolve to the VPS from the runner's resolver and two named public resolvers
  - Runner IP is not in `admin_cidrs` and is in the never-ban list; provider AUP confirmation recorded
  - Canary reachable directly while `lockdown_state=pending` and via HDD afterwards; DB/Redis authenticated; secret files 0600; clocks sane; `egress_allowlist` covers feeds and CA
  - Every refusal test shows zero packets sent to the forbidden destination (socket recorder)
- **Evidence:** preflight report, self-test report, socket-recorder logs
- **UNVERIFIED allowed only for:** `human_step_pending` (provider AUP, delegation not yet done), `capability_not_supplied` (lab for oracle refusal tests)

#### AC-01 · Authentication and admin isolation

- **Area / first live:** Security · P06 gate (T-0136); admin T-0439; full T-0503
- **Implemented and run by:** T-0125, T-0128, T-0134, T-0136, T-0417, T-0439, T-0503
- **Tier / mode / safety class:** nondestructive (login checks); pilot-full · live + lab · read-only plus authenticated requests
- **Procedure:** Verify unauthenticated and wrong-role access paths for every surface and API route; verify admin exposure mode and that data stores and SSH are not reachable from forbidden sources.
- **PASS when:**
  - Unauthenticated and bad-key requests receive 401; viewer cannot mutate; platform roles require MFA with enrollment forced at first login
  - Admin surface unreachable from non-allowlisted IPs (`routed_with_cidr`) or absent on the public interface (`tunnel_only`); cross-surface cookie replay fails
  - Port 22 reachable only from `ssh_allow_cidrs`; Postgres/Redis/metrics ports absent in a capped self-scan of the operator's own VPS
  - HDD's own login and signup block and ban the six mandated payloads (runner protected via second source)
  - Generated privilege matrix passes with zero unexpected statuses across all routes and roles
- **Evidence:** route-permission matrix output, scan output, event records
- **UNVERIFIED allowed only for:** `human_step_pending` (tunnel not set up), `capability_not_supplied` (second source for ban test)

#### AC-02 · Zone import and parity

#### AC-03 · Authoritative DNS (real path)

- **Area / first live:** DNS · P11 basic (T-0218); full T-0402

- **Procedure:** Per topology: query the VPS directly (or, in `hidden_primary`, the secondary and observe refusals from other sources) over UDP and TCP, then via at least two public recursive resolvers once delegated.
- **PASS when:**

- **Evidence:** query transcripts (hex), tool versions, propagation timeline
- **UNVERIFIED allowed only for:** `human_step_pending` (delegation), `oracle_unavailable`
