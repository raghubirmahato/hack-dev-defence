## PHASE P25: Host defenses: kernel firewall, XDP and kernel tuning (T-0463 to T-0472) · milestone M10 · gate G25

Requirement prefix `HST`. Goal: implement the layers below the application: the kernel firewall abstraction and agent that enforce bans on the proxied ports, the XDP early-drop program with its pure decision logic, loader and dead-man timer, the full L2 stack tuning with exact undo, the host hardening baseline, a closed-lab flood harness, and the acceptance runs for XDP, tuning and kernel-level ban enforcement.

Non-negotiables: nothing in this phase can lock the operator out (every host-changing command uses the timed auto-revert pattern from section 2.5); the only `unsafe` code in the workspace lives in `hdd-xdp-ebpf` and is justified by an ADR; XDP drops only categories that cannot hit legitimate return traffic; kernel enforcement applies to destination ports 80/443 (and UDP 443 when HTTP/3 is enabled) and never to 22 or 53; volumetric tests run only in the operator's closed lab (section 2.6); capacity claims follow R-10 (three separate numbers, verified-live empty unless measured).

Gate G25 passes when: AC-26 (XDP) and AC-29 (tuning) pass in the lab or are `UNVERIFIED(environment_unsupported)` with the fallback proven; kernel ban/unban propagation meets ≤ 2 s; the dead-man timer detaches XDP when unconfirmed; the nftables baseline and tuning apply and undo cleanly on a disposable VM; the hardening report passes; and no lab flood traffic left the closed lab.

### T-0463 · `hdd-firewall`: Enforcer trait and nftables, ipset/iptables and no-op backends
`P25` `[DP][OPS][SEC]` · deps: T-0322, T-0212 · size: L · owner: infra
**Objective.** Implement kernel-level IP bans behind one trait with a primary and a fallback backend.
**Steps.**
1. Define `trait Enforcer { fn probe() -> Capability; fn ban(&self, key: BanKey, ttl: Duration, meta: BanMeta) -> Result<Applied>; fn unban(&self, key: BanKey) -> Result<()>; fn list(&self) -> Result<Vec<Entry>>; fn reconcile(&self, desired: &[Entry]) -> Result<ReconcileReport>; fn stats(&self) -> Stats; }` with `BanKey` = IPv4 /32 or IPv6 /64 (never anything wider by default; CIDR bans of up to /24 and /48 allowed only from the platform jail with a flag).
2. Implement the **`Nftables` backend** (primary): a dedicated table `inet hdd` with sets `banned4` (`ipv4_addr`, flags `timeout`) and `banned6` (`ipv6_addr`, prefix-aware via `interval` set for /64), element timeouts natively handled by the kernel, rules in a base chain with priority before conntrack (`raw` hook prerouting at `-300`) that `drop` packets from banned addresses to the destination ports in a `proxied_ports` set (80, 443, and UDP 443 when enabled); application via `nft -f -` with a generated script passed on stdin (argument arrays only, never a shell string) or via the netlink crate if the ADR prefers it; atomic updates with `nft -c` validation before commit.
3. Implement the **`IpsetIptables` backend** (legacy fallback): `ipset` hash:ip / hash:net with timeouts, idempotent `iptables -C`/`-I` (and `ip6tables`) rules in a dedicated `HDD_BAN` chain jumped from `PREROUTING` raw; the backend is used only when `nft` is unavailable; both backends are never active simultaneously (probe order documented, mutual exclusion enforced).
4. Implement the **`Noop` backend** for hosts without capabilities: records requested bans, reports `unsupported` acknowledgments, and surfaces a WARN in preflight and the admin console (S-128).
5. Implement the **capability probe**: root/`CAP_NET_ADMIN` check, kernel module availability (`nf_tables`, `nft_set_hash`, `nft_set_rbtree`), nft version, IPv6 support, container detection (refuse to run inside an unprivileged container with a clear message), and interplay with Docker chains (the agent never touches Docker's chains and detects Docker's `FORWARD` policy to warn about published ports bypassing input rules).
6. Implement the **safety rules in code**: refuse to ban loopback, link-local, the host's own addresses, `admin_cidrs`, `ssh_allow_cidrs`, provider health-probe ranges and the DNS secondary's addresses (checked against the never-ban list on every call); refuse sets over the configured cap (default 100,000 elements) and report overflow; ban TTL bounds (60 s to 30 d).
7. Implement set-size and memory accounting, element-count metrics, and the reconcile algorithm (diff desired vs actual; add missing, remove expired/extra, bounded batch sizes of 500 per `nft` transaction).
8. Write tests: unit tests for script generation (golden files, including IPv6 /64 handling and timeout formatting); integration tests inside a network namespace with real `nft` (requires privileged lab, marked `#[ignore]` outside it) verifying drop behavior using `hdd-loadgen` TCP connects before/after ban and after TTL expiry; the shared contract suite from T-0322 run against each backend; negative tests for refused keys.
**Deliverables.**
- `hdd-firewall` crate, backends, probes, tests, docs `docs/FIREWALL.md`
**Acceptance.**
- A1: a banned IPv4 address cannot complete a TCP handshake to :443 within 2 s of `ban` and can again after `unban` (netns test).
- A2: element timeouts expire bans in the kernel without agent action (timing test).
- A3: bans for never-ban keys and for non-proxied ports are refused by code.
- A4: the contract suite passes for `Nftables`, `IpsetIptables` (where available) and `Noop`.
- A5: no shell invocation exists in the crate (static grep gate).
**Tests.**
- Unit (golden), privileged integration in netns, contract, static gate.
**Notes.** The proxy's L7 jail remains authoritative; the kernel layer is an accelerator that sheds attackers cheaply (C11.3 L1).

### T-0464 · `hdd-fw-agent`: signed ban stream consumer, reconcile loop, control socket and acknowledgments
`P25` `[DP][OPS][SEC]` · deps: T-0463, T-0322 · size: L · owner: infra
**Objective.** Run enforcement as a small, privilege-limited host service that can be trusted and observed.
**Steps.**
1. Build the `hdd-fw-agent` binary: subscribes to the Redis ban stream (T-0322), verifies the HMAC on every message with the internal key (loaded from a root-owned file or systemd credential, never from the environment), rejects stale/duplicate/regressed revisions, applies bans through the selected `Enforcer`, and writes acknowledgments (`pending → applied | failed | unsupported`) with timings.
2. Implement the **reconcile loop** (every 30 s and on `reconcile_request`): obtains the authoritative active set from the Redis snapshot (or Postgres via a read-only role), diffs with the kernel set, applies fixes, records divergence metrics and raises alerts when the divergence persists across two cycles.
3. Implement startup behavior: probe → report capabilities → load the full active set (`snapshot_begin/end` protocol) → start the stream; if Redis is unreachable at startup the agent keeps whatever is already in the kernel (no flush), retries with backoff and reports `degraded`.
4. Implement the **control socket** at `/run/hdd/fw-agent.sock` (mode 0600, root only): commands `status`, `list`, `ban`, `unban`, `flush --confirm`, `reconcile`, `backend`; used by `hddctl ban|unban` when the API is down; every command is logged to the audit stream (file-based queue when the API is unreachable) with the caller's UID from `SO_PEERCRED`.
5. Implement least privilege: the systemd unit runs as a dedicated user with `AmbientCapabilities=CAP_NET_ADMIN` only, `CapabilityBoundingSet=CAP_NET_ADMIN`, `NoNewPrivileges`, `ProtectSystem=strict`, `ReadWritePaths` for its state directory, `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK`, `SystemCallFilter` allowlist, and `MemoryMax`; the compose profile `kernel-fw` alternative uses `network_mode: host` with `cap_add: [NET_ADMIN]`.
6. Implement flood protections for the agent itself: message rate caps (max 5,000 ban messages/s processed with batching), max batch sizes, bounded queues, and a "storm" state where individual acks are coalesced.
7. Implement metrics (applied/failed counts, ack latency histogram, set size, divergence, backend, reconcile duration) and `/healthz` on a Unix socket scraped by the metrics collector.
8. Write tests: forged-message rejection, replay and reorder property tests, restart behavior (kernel state preserved), Redis outage behavior, control-socket authorization (non-root UID rejected), `flush` safety (refuses without `--confirm` and refuses when it would remove never-ban protections), storm coalescing, and an end-to-end test with the real proxy: SQLi payload → ban → kernel set contains the IP ≤ 2 s → unban removes ≤ 2 s.
**Deliverables.**
- `hdd-fw-agent`, systemd unit, compose profile, tests, runbook
**Acceptance.**
- A1: unsigned or regressed-revision messages never change kernel state.
- A2: end-to-end ban-to-kernel propagation p95 ≤ 2 s and unban ≤ 2 s (measured on the pilot).
- A3: restarting the agent never flushes active bans.
- A4: the control socket refuses non-root callers.
- A5: acknowledgments appear in S-068 and S-128 with per-layer timing.
**Tests.**
- Integration (netns + Redis), property/chaos, security, e2e with proxy.
**Notes.** Kernel enforcement acknowledgments feed the propagation histograms (MET-hdd_ban_propagation_seconds).

### T-0465 · `hdd-xdp-logic`: pure packet-verdict logic (no_std) with exhaustive tests
`P25` `[DP][SEC][QA]` · deps: T-0463 · size: L · owner: infra
**Objective.** Put every XDP decision in safe, natively testable Rust so the kernel program is a thin shell.
**Steps.**
1. Create `hdd-xdp-logic` as `#![no_std]` (with `alloc` disabled) and `#![forbid(unsafe_code)]`: parse Ethernet (optionally VLAN tags), IPv4, IPv6 (extension headers bounded to a fixed number), TCP, UDP, ICMP/ICMPv6 from a `&[u8]` with explicit bounds checks, returning a typed `PacketView`.
2. Define the verdict function `decide(view: &PacketView, maps: &dyn MapView, cfg: &Config, now_ns: u64) -> (Verdict, Reason)` with verdicts `Pass`, `Drop`; reasons: `Banned`, `SynNoAckUnpublished`, `InvalidTcpFlags`, `Bogon`, `OwnAddressSource`, `Fragment`, `ReflectionSource`, `RateSyn`, `RatePps`, `RateBps`, `RateIcmp`, `Malformed`.
3. Implement the **rules per C11.4**: banned-IP check via the LPM views (v4 /32, v6 /64) for destination ports 80/443 and UDP 443 only; TCP SYN without ACK to ports not in the published set; invalid flag combinations (NULL, FIN+URG+PSH "Xmas", SYN+FIN, SYN+RST, FIN without ACK as policy, URG without PSH not dropped); bogon/martian sources (RFC 1918, 100.64/10, 169.254/16, 127/8, 224/4, 240/4, 0/8, documentation ranges, IPv6 equivalents) unless the interface is private-routed per config; own-address source; fragments (configurable: drop first/non-first fragments to published ports); unsolicited UDP from reflection source ports in the configurable list (53, 123, 389, 1900, 11211, 19, 161, 5353, 3702 by default) unless allowlisted peers; and **per-source token buckets** for pps, bps, SYN/s and ICMP/s on published ports (keys = /32 or /64; table size bounded; eviction by LRU approximation).
4. Implement the **never-drop list** logic: loopback, `admin_cidrs`, SSH source CIDRs for port 22, provider probe ranges and DNS secondary addresses are `Pass` before any other rule (the order is part of the contract and tested).
5. Make time and map access abstract (`MapView` trait) so the same logic runs in the kernel (maps) and in tests (in-memory maps with deterministic time).
6. Write **exhaustive tests**: table tests for each reason (≥ 200 packet fixtures built with `etherparse`-style builders in the test crate), property tests (random packets never panic and never read out of bounds; the verdict is deterministic; never-drop beats every drop reason), differential test against a naive reference implementation written in the test crate for random packet streams, and fuzz targets (`xdp_decide` with arbitrary bytes).
7. Add **legitimate-traffic regression corpus**: captured shapes of normal TCP handshakes, TLS flows, QUIC initial packets, DNS responses from the host's resolvers (source port 53 to ephemeral ports must not drop when it is return traffic for the host's own queries because the source port rule applies only to unsolicited UDP to published ports), NTP responses to the host, ACME/HTTPS return traffic; the policy ensures these `Pass`.
8. Add benchmarks (`criterion`) for decisions per second to guide the in-kernel instruction budget.
**Deliverables.**
- `hdd-xdp-logic`, fixtures, fuzz targets, benches, `docs/XDP.md` (verdict table)
**Acceptance.**
- A1: all fixtures produce the documented verdict and reason.
- A2: property tests find no panics or out-of-bounds in 10,000,000 generated packets.
- A3: legitimate-traffic corpus never drops.
- A4: never-drop precedence holds in all property cases.
- A5: the crate builds for the BPF target configuration without `std`.
**Tests.**
- Unit/property/differential/fuzz.
**Notes.** Keeping the logic pure also lets the userspace fallback (nftables) mirror the same rule table for parity checks.

### T-0466 · `hdd-xdp-ebpf`: the kernel program, `aya` and nightly toolchain ADR, and the single `unsafe` crate
`P25` `[DP][SEC][DOC]` · deps: T-0465 · size: XL · owner: infra
**Objective.** Compile the verdict logic into a verifier-friendly XDP program with minimal unsafe surface and a reproducible build.
**Steps.**
1. Write the **ADR** (`aya` and the nightly requirement): why `aya`/`aya-ebpf` (pure Rust, no libbpf C dependency), the pinned nightly toolchain date and `bpf-linker` version, the build-std requirement, risks (nightly drift), mitigation (pinned in `rust-toolchain` for the eBPF crate only, cached in CI, `xtask ebpf build` is the only entry), and the fallback path (nftables raw table) if the toolchain cannot be built.
2. Create `hdd-xdp-ebpf` (`#![no_std]`, `#![no_main]`) containing the XDP entry point, map declarations (`LpmTrie` for v4/v6 bans, `HashMap` for token buckets with `LRU` semantics, `Array` for config, `PerCpuArray` for counters per reason, `HashMap` for allowlists) and the glue translating `XdpContext` to the pure logic's `PacketView` with verifier-friendly bounded loops and explicit pointer-range checks.
3. Enforce the **unsafe policy**: `unsafe` allowed only in this crate, only in a small `ctx` module for pointer reads, each block commented with the invariants and covered by tests of the pure parser equivalents; CI runs `cargo geiger` (or the substitute selected in T-0517) asserting no unsafe in other workspace crates and reporting counts here; the ADR lists every unsafe block category.
4. Implement the build: `xtask ebpf build` produces the object file with `bpf-linker`, strips debug info for release, records SHA-256, embeds the object into the loader crate via `include_bytes!` with a build-time check that the hash matches the expected manifest; `xtask ebpf verify` loads the program into a test kernel (privileged lab) and checks it passes the verifier on the supported kernel versions (5.15, 6.1, 6.6, 6.8 in the matrix; others UNVERIFIED).
5. Implement size and complexity budgets: program instruction count < 4,096 verified instructions for the main path, stack usage < 512 bytes, map memory budget documented (token bucket map default 262,144 entries), tail calls avoided.
6. Add **differential testing** between the kernel program and the pure logic using `BPF_PROG_TEST_RUN` (via aya's test-run API) with the packet fixtures from T-0465: for every fixture the kernel verdict must equal the logic verdict (this is the key correctness gate for the shell).
7. Handle IPv6 extension header limits and VLAN parsing identically in both; reject over-long chains as `Malformed`.
8. Write documentation of the supported kernel/driver matrix, native vs generic mode behavior, and known limitations (for example virtio_net native XDP requirements, multi-queue and `xdp_frags`).
**Deliverables.**
- ADR, `hdd-xdp-ebpf`, `xtask ebpf`, manifest, differential tests, docs
**Acceptance.**
- A1: the program loads on all kernels in the lab matrix (or UNVERIFIED for kernels not available, with the list).
- A2: kernel/logic differential tests agree on 100% of the fixtures and 100,000 random packets.
- A3: unsafe appears only in the `ctx` module of this crate (geiger/grep gate).
- A4: instruction and stack budgets are met.
- A5: the build is reproducible (two builds produce the same object hash).
**Tests.**
- Privileged lab tests (`BPF_PROG_TEST_RUN`), reproducibility check, static gates.
**Notes.** If the verifier rejects constructs on some kernels, simplify the logic rather than weakening checks; record in the ADR.

### T-0467 · `hdd-xdp` loader: maps, atomic updates, counters, native/generic probe and the dead-man timer
`P25` `[DP][OPS][SEC]` · deps: T-0466, T-0464 · size: L · owner: infra
**Objective.** Operate the XDP program safely in production: attach, update, observe and always be able to get out.
**Steps.**
1. Implement the loader inside the host agent (separate service `hdd-xdp` or a module of `hdd-fw-agent` selected by ADR; default separate unit so a crash in one does not disable the other): attach to the configured interface(s) using the best mode (`native` → `generic` fallback) with a **probe**: attempt native, verify with a loopback packet test, record the mode used, warn on fallback, and publish the mode, interface, driver and measured pps in the status.
2. Implement map management: **atomic updates** (build new map contents off-line and swap via map-in-map or double-buffered generation counter), ban stream applied to the LPM tries with TTL bookkeeping in userspace (the kernel entries are removed by the loader when the TTL expires and by reconcile), config updates (published ports, reflection port list, thresholds) with versioning, and a bounded operations queue.
3. Implement the **dead-man detach timer**: after every load, reload or policy change that tightens drops, start a countdown (default 120 s) that detaches the program unless a confirmation arrives from a second session (`hddctl xdp confirm` or the admin console button); detach is clean (`XDP_FLAGS` unset) and recorded; the timer cannot be disabled in `pilot` stage and requires an explicit documented flag in `production` once the operator has run 30 days without incident.
4. Implement commands: `hddctl xdp status|attach|detach|reload|confirm|counters|dump-bans`, all idempotent, with `--dry-run` for reload (shows the diff of config and ban set), and a preflight that refuses to attach if the interface has an unsupported configuration (for example XDP already attached by another program, bonded interface without native support, MTU > supported for generic mode).
5. Export **per-reason drop counters** and per-CPU totals, map occupancy, update latency, and mode as Prometheus metrics; a periodic self-test sends a loopback probe packet to a controlled port to verify the program still passes legitimate traffic (a failing self-test auto-detaches and alerts).
6. Implement graceful failure handling: on loader crash the program stays attached by default (so protection persists) unless the dead-man timer is running; on host reboot the unit re-attaches with the timer armed; the status shows `attached`, `unconfirmed`, `detached`.
7. Implement `Noop` behavior: if neither XDP nor nftables raw is available, the service runs in `Noop` mode with a WARN and AC-26 marked `UNVERIFIED(environment_unsupported)`.
8. Write tests: attach/detach cycles in a namespace (veth with native-capable driver or generic), timer expiry detaching the program (time-accelerated), confirm resetting the timer, map update atomicity under traffic (no dropped legitimate flow during a swap), self-test failure auto-detach, and crash/restart persistence.
**Deliverables.**
- `hdd-xdp` loader, systemd unit, `hddctl xdp`, metrics, tests, runbook
**Acceptance.**
- A1: without confirmation the program detaches at the timer expiry (±5 s) in the lab.
- A2: a map swap during a traffic flow drops no legitimate packets (zero loss in a 60 s test at 100k pps).
- A3: the status reports the actual mode (native/generic) and warns on fallback.
- A4: the self-test detaches the program if it starts dropping the probe.
- A5: all commands are idempotent and `--dry-run` shows changes without applying.
**Tests.**
- Privileged lab tests, time-accelerated unit tests, chaos.
**Notes.** The detach timer is the XDP equivalent of the SSH-lockout revert (section 2.5).

### T-0468 · Full L2 tuning and the nftables baseline: NOTRACK, conntrack sizing, ICMP limits and exact undo
`P25` `[OPS][SEC]` · deps: T-0213, T-0463 · size: L · owner: ops
**Objective.** Complete the stack tuning and the host firewall baseline so state exhaustion and trivial floods fail cheaply.
**Steps.**
1. Extend `hddctl tune` to the full L2 set from C11.5: `tcp_syncookies=1`, tuned `tcp_max_syn_backlog`, `somaxconn`, `netdev_max_backlog`, `rp_filter` strict (with the asymmetric-route guard), `tcp_rfc1337`, ICMP rate limits (`icmp_ratelimit`, `icmp_ratemask`), socket buffer sizes, `tcp_fin_timeout`, `tcp_tw_reuse` (documented), `nf_conntrack_max` and hash sizes computed from RAM, and file-descriptor limits.
2. Implement the **baseline nftables ruleset** (`hddctl firewall apply`): `inet filter` with default-drop input; allow loopback, established/related, TCP 80/443 (and UDP 443 if HTTP/3 enabled), TCP+UDP 53, TCP 22 from `ssh_allow_cidrs`, ICMP/ICMPv6 essentials (PMTUD, ND) rate limited, and the monitoring ports from allowlisted collectors; output chain allows what the platform needs (DNS to resolvers, ACME CA, feeds, SMTP, NTP, package mirrors) as a documented allowlist (egress filtering is optional but recommended and off by default to avoid breaking installs).
3. Implement the **raw-table NOTRACK** rules **per direction** (valid only because the proxy and DNS use the host network without NAT): `prerouting` for inbound `tcp dport {80, 443}`, `tcp dport 53`, `udp dport {53, 443}`; `output` for the replies (`tcp sport {80, 443}`, `tcp sport 53`, `udp sport {53, 443}`); never a rule that matches an outbound client flow by remote port; add explicit accept rules in input/output for untracked packets; prove with tests that established return traffic of the host's own outbound connections still works (ACME, feeds, SMTP) and that Docker NAT scenarios are detected and refused (the command warns and skips NOTRACK when NAT/masquerade rules exist).
4. Implement conntrack sizing from available RAM (`nf_conntrack_max = RAM_MB * 64` bounded, `hashsize = max/4`) and expose usage and drops as metrics; document the memory implications.
5. Wrap every apply in the **timed auto-revert** (section 2.5), requiring a second-session confirmation `hddctl confirm <id>`; previous rules are saved for exact rollback; `hddctl firewall undo` restores them.
6. Implement **IPv6 parity**: identical policy for v6, with correct ICMPv6 allowances, and tests proving ND/RA/PMTUD still work.
7. Implement mirroring guidance: generate the equivalent cloud-firewall rule list (provider-agnostic table) to apply at the provider's firewall; HDD does not call provider APIs here.
8. Write tests on disposable VMs/containers with systemd and nftables: apply, rerun (idempotent), lockout simulation (deliberately drop SSH → auto-revert within the timer), undo equality (before/after ruleset hash), NOTRACK return-traffic tests, IPv6 tests, and a documentation test that every sysctl and rule has a documented undo.
**Deliverables.**
- extended `hddctl tune|firewall`, rulesets, docs, VM tests
**Acceptance.**
- A1: `undo` returns the sysctl values and the ruleset to the exact prior state (hash comparison).
- A2: the lockout simulation auto-reverts within the timer without operator action.
- A3: with NOTRACK active, outbound ACME, SMTP and resolver traffic (client flows to remote ports 53 and 443) still succeeds and stays tracked (VM test reads `conntrack -L`).
- A4: NOTRACK is skipped with a WARN when NAT is detected.
- A5: IPv6 ND/RA/PMTUD work under the baseline.
**Tests.**
- VM integration, golden rulesets, unit (formulae).
**Notes.** Closes T-0213's pointer (L2 full set); AC-29 verifies in T-0471.

### T-0469 · Host hardening baseline and verification (SSH, services, systemd sandboxing, integrity, updates)

**Deliverables.**
- `hddctl harden`, baselines, report generator, VM tests, docs
**Acceptance.**
- A1: every injected drift is detected by `verify` (≥ 10 cases).
- A2: SSH changes auto-revert if the second session does not confirm.
- A3: `systemd-analyze security` scores meet targets for exposed units.
- A4: the external capped scan finds only the intended ports open (pilot VPS).
- A5: no secret appears in any service environment.
**Tests.**
- VM tests, scan tests, drift injection.
**Notes.** Claims are limited to "checks performed"; HDD does not claim the host is unhackable.
