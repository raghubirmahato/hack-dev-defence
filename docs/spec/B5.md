## B11. Design system specification

The design system is the source of truth for every pixel. Tokens live in `design/tokens/*.toml`; `cargo xtask ui build` generates `hdd-ui/assets/tokens.css` (custom properties), the Rust constants used by SVG charts, and the contrast report. Components are askama macros in `hdd-ui` with CSS in cascade layers. Nothing in templates uses a literal color, size, font or shadow.

### B11.1 Principles

1. **Calm, honest, expert.** Security tools shout. HDD informs: plain words, exact numbers, clear next action. Never alarmist, never decorative fear.
2. **Show state, not decoration.** Every colored element encodes meaning; every meaning has a second non-color signal (icon, text, shape).
3. **Progressive disclosure.** Maya sees a plain summary; Sara can open the evidence; Dan can copy the API call. Same screen, three depths.
4. **Safe by design.** Dangerous actions look and behave differently: confirmation, preview, undo, scoped time boxes. Safe options are the defaults and the primary buttons.
5. **Fast and light.** Server-rendered, small CSS and JS, no layout shift, works on a 4G phone.
6. **Accessible by construction.** Components encode keyboard behavior, ARIA, focus management, and target size; a screen cannot be assembled from inaccessible parts.
7. **Dark first, light equal.** Both themes are fully designed and tested; `prefers-color-scheme` is honored; user choice persists.

### B11.7 Layout

- **App frame:** fixed top bar 56 px; left sidebar 240 px expanded / 64 px collapsed; content area scrolls; skip link "Skip to main content" is the first focusable element; landmarks `banner`, `navigation` (labeled), `main`, `complementary`, `contentinfo`.
- **Responsive behavior:** below 1024 px the sidebar becomes a drawer opened by a labeled menu button; tables become cards (stacked key-value) below 640 px only where horizontal scrolling would hide primary data; otherwise tables scroll horizontally inside a focusable region with a visible scroll hint.
- **Page header:** breadcrumbs, title (h1, exactly one per page), status pills, primary action on the right; secondary actions in a menu.
- **Grid:** 12 columns above 1024 px, 4 below; cards use CSS grid `auto-fit` with minimum 280 px.
- **Reading pages (public, docs):** single column 65ch with sticky table of contents above 1024 px.

### B11.9 Interaction patterns

1. **Forms.** Single column; labels above; required fields marked in text ("required") not asterisk-only; validate on blur and submit; server is the source of truth; errors preserve input; never clear password fields except on success or explicit failure; disable the submit only while in flight; prevent double submit (idempotency key).
2. **Destructive actions.** Use ConfirmDialog with consequences list; type-to-confirm for domain removal, org deletion, global changes; offer undo toast where technically reversible (ban, rule delete within 30 s), otherwise explain irreversibility.
3. **Self-lockout guard.** Any action whose effect would match the current session's IP (ban, deny, geo-block, rule match, access list) shows a blocking warning with the exact rule and a "Run as dry-run first" link.
4. **Empty/loading/error/offline.** Every data region defines all four; the offline state is a banner with retry; list views never show a spinner longer than 300 ms without a skeleton.
5. **Time.** Show relative time with absolute time in `<time datetime>` and `title`; always UTC offset visible in tooltips; user time zone from profile.
6. **Numbers.** Locale formatting; large numbers abbreviated only in cards, exact in tables; units explicit (req/s, MB).
7. **Wizards.** Resumable; each step has "Why we ask"; never lose input on back; show what changes where (HDD vs the user's DNS provider) with distinct visual treatment ("Do this at your DNS provider" boxes).
8. **Live data.** Pause control; "N new" indicator; no scroll hijack; rate-limited announcements.
9. **Search and filters.** Filters reflect in URL; saved views; clear-all; empty-result state suggests loosening filters.
10. **Notifications.** Toasts for transient; Notification center for durable; email for out-of-band; severity maps to channels in alert rules.
11. **Help.** Contextual "Learn more" links to docs pages; consistent help placement (WCAG 3.2.6).
12. **Honest data.** Unknown values display "Unknown" with the reason, never zero.

### B11.10 Data visualization rules

1. Choose the simplest form that answers the question: line for time series, bar for category comparison, stacked bar for composition over time, ranked horizontal bar for top-N, heatmap for hour-by-day, choropleth only with a ranked table alongside.
2. Axes labeled with units; zero baseline for bars; time axis in user time zone; gaps shown as gaps, not interpolated zeros.
3. Direct labels over legends where feasible; legend order matches visual order; limit to 8 series (then "Other").
4. Color-blind-safe palette (B11.2) plus patterns for fills; severity uses icon + label.
5. Every chart has a text summary ("Blocked requests peaked at 14:10 with 412") and a "View as table" toggle.
6. Interaction is progressive: tooltips and crosshair enhance; all information is available without them.
7. Charts are server-rendered SVG so they render without JavaScript and print cleanly; no animation by default.
8. Never chart fabricated or interpolated data; sparse data shows the sparse state.

### B11.12 Voice and tone

- Plain words; short sentences; active voice; second person. "Your domain is protected in monitor mode. Nothing is blocked yet." not "WAF is operating in non-blocking observation state."
- Say what happened, why it matters, what to do. Errors blame the situation, not the user.
- Numbers over adjectives. "412 requests blocked in the last hour" not "many attacks".
- Security terms get a one-line explanation on first use with a docs link.
- No fear language, no emojis in product UI, no humor in errors, no exclamation marks except success confirmations used sparingly.
- Every string is an i18n key in `i18n/en/*.ftl`; keys are semantic (`domain-add-step2-title`), never sentences.
