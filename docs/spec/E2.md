## E2. Benign corpus specification

### E2.1 Principles

1. A false positive is a defect in a rule, never in the corpus (R-23). The corpus is **append-only**; entries are removed only with a written reason in `tests/fixtures/CHANGELOG.md`.
2. Every benign file carries the header of E1.0 with `# class: A`, `# hardness: none`, `# expect: allow` (or `# expect: soft_only(max=N)` for documented ambiguous entries; the gate fails on any hard match or block regardless).
3. Entries are original material written for this project or taken from public-domain/permissively licensed sources with provenance recorded. Real traffic captured for baselines (HAR, access logs) is scrubbed by the redaction library (cookies, tokens, emails, IPs) before it touches a file.
4. Each entry is exercised in **every vector** its metadata allows (query, form, JSON, XML, multipart, cookie, headers, path), in **every field kind** it is plausible for, under presets Balanced, Strict and Shield Balanced at paranoia levels 1 and 2 (Shield Paranoid and paranoia 3 report soft hits but still must not produce hard hits except in the documented password-field exception list).
5. Soft scores are measured and reported (near-miss report); tuning may adjust soft weights but never the hard families, and never to hide a benign hit.

### E2.2 Files, minimum sizes and gate usage

| File | Minimum entries | Content | Gate |
| --- | --- | --- | --- |
| `benign-general.txt` | 500 | Everyday web input: names, addresses, comments, search terms, product titles, URLs, emails, phone numbers, dates, markdown | AC-06, every detector change |
| `benign-sql-prose.txt` | 600 | Natural language about databases and SQL keywords used innocently, tutorial sentences, forum questions, error messages quoted by users | AC-06, T-0279 |
| `benign-apostrophes.txt` | 200 | Names and phrases with `'`, `"`, backticks, smart quotes and elisions in many languages | AC-06, AC-39 |
| `benign-code.txt` | 150 | Code samples pasted into comments/forums (SQL in fenced code, JSON, shell, HTML) that are not injection (no quote breakout, no tautology, no comment truncation) | T-0279 (soft_only allowed) |
| `benign-structured.txt` | 200 | JSON/XML/form/multipart bodies with SQL-ish keys (`order`, `group`, `select`, `limit`, `where`) | T-0279, T-0302 |
| `benign-passwords.txt` | 150 | Passphrases and symbol-heavy passwords (including `P@ss'word#1`), ambiguous cases listed with expected soft outcomes | C4.6, T-0272 |
| `benign-i18n.txt` | 150 | Multilingual text (Latin, Cyrillic, Greek, Arabic, Hebrew, CJK, Devanagari, Thai, emoji), RTL marks, combining characters | T-0241, T-0242 |
| `benign-urls-headers.txt` | 200 | URLs, query strings, cookies, `User-Agent`, `Accept-*`, `Referer`, `Content-Disposition`, JWT-looking tokens, base64 blobs | T-0240, T-0298 |
| `benign-html.txt` | 120 | Rich text from editors (allowed tags, entities, inline styles) for sites that accept HTML by policy; sites that do not accept HTML expect soft only | T-0285 |
| `benign-api.txt` | 150 | REST/GraphQL requests of well-behaved clients (pagination, filters, mutations) | T-0302, T-0304 |
| `benign-outbound.txt` | 500 pages | Documentation, tutorials and security blog pages discussing SQL errors, stack traces and secrets; must not be blocked by the outbound filter | T-0408, T-0409, T-0415 |
| `benign-dns-names.txt` | 200 | Hostnames and records for DNS protocol tests (IDN, underscores, long labels) | T-0389 |
| `har-scrubbed/*.har` | operator supplied | Scrubbed real traffic (GET/HEAD replay unless allowlisted) | AC-06 baseline |

The total committed benign line count must be at least **2,500** across the text files (excluding HAR and outbound pages); `xtask fixtures benign --check` enforces the minimums and the header format.

### E2.5 Near-miss report and corpus governance

1. Every gate run writes `reports/near-miss-<ts>.md`: entries with soft score ≥ 1, grouped by rule and field kind, with the rule's contribution, to guide weight tuning.
2. Real-world false-positive reports (S-060, S-066) can be exported as scrubbed corpus candidates (`xtask fixtures benign --add-from-report`), which require a reviewer note and provenance; accepted entries are added to the corpus and become permanent regression tests.
3. The **meta-test** adds a deliberately over-broad rule (for example any single quote) and requires the gate to fail; a gate that cannot fail is broken.
4. The corpus and the attack fixtures share **no** generator code paths, and a test ensures no line appears in both (set intersection must be empty); ambiguous lines are listed in `ambiguous.txt` with expected behavior per preset.
