# UXD-001: Dark theme first, light theme equal

Status: accepted
Date: 2026-10-19

Part of the [UX charter](../CHARTER.md), principle 7. Source: spec B11.1 and B11.2.

## Context

Security tools are read for long stretches, often at night and next to terminals. A dark default suits that use, but a
light theme that is only an inversion is hard to read in daylight and fails people who need it. Two themes also double
the contrast and screenshot testing.

## Decision

The default theme is dark. The light theme is designed and tested to the same standard: the same tokens, the same
contrast targets (4.5 to 1 for body text, 3 to 1 for large text and component boundaries) and the same visual tests.
The product honors `prefers-color-scheme` on first visit and stores the user's explicit choice. Every color token is
defined for both themes, and meaning is never carried by color alone.

## Consequences

- The color token set has two columns, and `cargo xtask contrast-check` (stub until T-0030) must check both.
- Every UI task needs a dark and a light screenshot in its tests; a screen that only works in one theme is not done.
- Marketing and documentation pages follow the same two themes.
- Revisit if usage data from pilots (measured locally, see [MEASURES.md](../MEASURES.md)) shows the default is wrong; any
  change is a new decision record that supersedes this one.
