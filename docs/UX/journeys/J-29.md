# J-29 Platform admin onboards and manages tenants

Personas: [Omar](../personas/omar.md). Emotional state is a design aid, not a measured value.

Trigger: a new organisation appears and the platform admin must check it, set its plan and act on it.

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 1 | A support lookup becomes silent surveillance. | Every lookup needs a reason and writes a platform audit event. | ATK-295 |

| 6 | Deletion removes tenant data without recovery. | The deletion waits out a grace period and the export remains available. | ATK-173 |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 2 | The wrong tenant is opened. | The header repeats the organisation name and the detail shows the slug and the id. |
| 4 | The suspension notice is not sent. | The tenant status shows the notice state and the retry action. |
| 6 | The grace period expires by mistake. | The deletion is scheduled, not immediate, and the cancel action stays visible until it runs. |

## Admin controls

| Action | Permission | Audit event | Reason required | Step-up |
| --- | --- | --- | --- | --- |
| View a tenant summary | PERM-platform.tenant.read | No B8 event records a tenant read | no | no |
| Change a tenant plan | PERM-platform.tenant.write | AUD-platform.tenant_plan_changed | yes | yes |
| Suspend a tenant | PERM-platform.tenant.suspend | AUD-platform.tenant_plan_changed, and B8 lists the suspension in the same row | yes | yes |
| Delete a tenant | PERM-platform.tenant.suspend | AUD-platform.tenant_plan_changed, and B8 lists the deletion in the same row | yes | yes |

B8 groups the tenant actions in the row `AUD-platform.tenant_plan_changed / suspended / unsuspended / deleted`.
The suspend and delete cells keep the first id of that row and name the grouping instead of inventing a second id;
T-0419 and T-0423 resolve the exact event names when those events are implemented.

## Stress cases

| Case | What changes | What stays usable |
| --- | --- | --- |
| low bandwidth | The usage charts load after the plan and status text. | The search, the detail and the actions stay usable. |
| small screen | The detail tabs scroll horizontally and the tables stack. | Every action stays reachable by Tab. |
| keyboard only | The search field and the tab list work without a pointer. | Arrow keys move between tabs; Enter opens the selected tenant. |

## Instrumentation

- `AUD-platform.tenant_plan_changed` records a plan change with its reason.
- `AUD-platform.support_lookup` records each support lookup with its reason.
- `AUD-platform.impersonation_started` records an impersonation session with its reason and duration.

## Success and checks

Success: the tenant is reviewed with a recorded reason, the plan or suspension is applied with step-up and the customer is notified. Checks: AC-42.
