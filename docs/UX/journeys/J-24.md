# J-24 Owner locks down the origin

Personas: [Maya](../personas/maya.md), [Dan](../personas/dan.md), [Omar](../personas/omar.md). Emotional state is a design aid, not a measured value.

Trigger: the owner wants block mode to be meaningful, so the origin must stop answering direct requests.

## Stacks

These are conceptual steps for each stack, never a real command line.

| Stack | Concept | What the page shows |
| --- | --- | --- |
| ufw | Allow the HDD edge addresses to the origin ports and deny the rest. | The address list and the current status. |
| iptables | Restrict the origin ports to the HDD edge addresses. | The rule summary and the revert text. |
| nftables | Restrict the origin ports with a named table. | The table summary and the revert text. |
| cloud security group | Allow the HDD edge addresses and deny the rest. | The group difference and the revert text. |
| nginx or apache | Reject requests without the secret header. | The snippet and the verification result. |

## Verification probes

| Probe | What it proves | What it cannot prove |
| --- | --- | --- |
| A direct request to the origin address | The origin still answers without the proxy. | Whether the owner's own network is allowed. |
| A request with a wrong secret header | The origin verifier rejects a wrong secret. | The strength of the secret itself. |
| A request through the proxy path | The configured path still reaches the origin. | Every edge address in every region. |
| A repeat probe after the change | The state stays applied over time. | A later manual change at the provider. |

## Instrumentation

- `AUD-origin.lockdown_applied` supplies the counter for the applied lockdown.
- `AUD-bypass.probe_run` records each probe with its result class.

## Success and checks

Success: the origin answers only through HDD and the lockdown state is verified before it is marked applied. Checks: AC-18.
