# J-03 New user enrolls MFA

Personas: [Maya](../personas/maya.md), [Dan](../personas/dan.md), [Sara](../personas/sara.md), [Omar](../personas/omar.md), [Alex](../personas/alex.md). Emotional state is a design aid, not a measured value.

Trigger: the platform requires MFA for the role, or the organisation requires it, or the user chooses to add it.

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Opens the MFA enrolment page. | The page shows a QR code as SVG and a manual key for a weaker camera. | S-030 | none | ERR-AUTH-006: The page explains that enrolment is required by the organisation and links to the QR code. | unsure | mfa-enroll-title | - |
| 2 | Scans the QR code with an authenticator. | The form accepts a six-digit code and shows the drift tolerance in words. | S-030 | TOTP code | ERR-AUTH-003: The form says the verification code is incorrect or expired and shows the retry window for the authenticator. | unsure | mfa-code-label | - |
| 3 | Enters the six-digit code. | The chosen factor is confirmed and the code is never shown again. | S-030 | TOTP code | ERR-AUTH-004: The page shows a retry time after too many code attempts and keeps the chosen factor and the drift tolerance visible. | anxious | mfa-code-verify | - |
| 4 | Reaches the recovery-codes page. | Ten recovery codes are shown once, with download, print and copy. | S-031 | none | ERR-SYS-001: The system keeps the recovery codes visible and says the code service is temporarily unavailable. | anxious | recovery-codes-title | - |
| 5 | Saves the codes and ticks the "I saved these" confirmation. | The page records the confirmation and keeps the codes until the page is left. | S-031 | none | ERR-SYS-001: The system keeps the recovery codes visible, so the saved codes can be downloaded after the unavailable service returns. | calm | recovery-codes-saved | - |
| 6 | Optionally enrols a passkey. | The page offers a passkey next to the authenticator code. | S-031 | passkey registration | ERR-AUTH-017: The page says the passkey is already registered and offers the existing device. | unsure | passkey-enroll-action | - |
| 7 | Returns to the security summary. | The page states that MFA is active for the account. | S-030 | none | ERR-SYS-001: The system shows the security summary but marks the MFA state as temporarily unavailable. | calm | mfa-active-title | - |
| 8 | Checks the recovery codes later. | The codes are hashed at rest and the page says they cannot be shown again. | S-031 | none | ERR-SYS-001: The system shows that the hashed recovery codes cannot be displayed and the section stays temporarily unavailable. | calm | recovery-codes-hashed | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 1 | The secret is shown to me alone. | The QR code and the manual key are rendered on one page with no other session data. |
| 4 | I can still sign in if the phone is lost. | Ten recovery codes with download, print and copy actions. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 2 | Brute force against the six-digit code. | The drift window is capped and the attempt rate limit applies. | ATK-163 |
| 4 | Recovery codes are guessed or copied from a shared screen. | Codes are single-use, shown once, and hashed at rest. | ATK-162 |
| 6 | A passkey is registered by someone else. | Step-up authentication is required before a new passkey is added. | ATK-164 |

## Instrumentation

- `AUD-auth.stepup` counts a completed step-up, which covers the first sign-in after enrolment.
- `AUD-auth.login_success` counts the sign-ins that follow, so the two together show MFA use without a new event.
- No dedicated enrolment audit event exists in B8; this gap is recorded here rather than invented, and the counters above are the honest substitute.

## Success and checks

Success: MFA is active and the recovery codes are hashed at rest. Checks: AC-35.
