# J-30 Platform admin investigates abuse and global bans

Personas: [Omar](../personas/omar.md). Emotional state is a design aid, not a measured value.

Trigger: an abuse report names a customer domain and the same addresses attack several tenants.

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Opens the abuse report queue. | The queue asks for a reason for the platform access. | S-114 | none | ERR-PLAT-001: The abuse queue is refused until a reason is given for the platform access. | calm | abuse-queue | Abuse reports triaged per shift |
| 2 | Reads one report and its evidence. | The report evidence names the tenant and the redacted requests. | S-114 | none | ERR-PERM-002: The report is not found for this tenant and no resource existence leaks. | unsure | abuse-report | - |
| 3 | Triages the report and marks it resolved. | The triage reloads the report after it changed. | S-114 | outcome, note | ERR-CONC-001: The report changed, so reload and retry with the current state. | unsure | abuse-triage | - |
| 4 | Adds a global ban for the campaign address. | The global ban operation is checked against the never-ban list. | S-106 | address, reason | ERR-PLAT-002: The global ban operation is blocked by the never-ban list and the entry is named. | anxious | jail-add | Global bans created per week |
| 5 | Extends the global ban TTL. | The ban list limit is checked before the TTL extends. | S-106 | TTL | ERR-BAN-004: The ban list limit is reached and the oldest expiry is explained. | anxious | jail-extend | - |
| 6 | Removes a never-ban entry that collides with the ban. | The entry removal is refused while the ban would affect it. | S-109 | none | ERR-PLAT-001: The removal is refused until a reason is recorded for removing the never-ban entry. | anxious | never-ban-remove | - |
| 7 | Checks the never-ban guard for the runner address. | The guard page checks the never-ban permission before it lists entries. | S-109 | none | ERR-PERM-001: The never-ban check is refused and the missing permission is named. | calm | never-ban-guard | - |
| 8 | Exports the abuse and ban evidence. | The evidence export is rate limited per operator. | S-106 | none | ERR-RATE-001: The export rate limit is reached and the reset time is shown. | calm | abuse-export | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 4 | A global ban cannot hit the runner or a protected address. | The never-ban list is checked first and the collision is named. |
| 6 | The never-ban list is not edited casually. | The removal shows the entry, the reason and the audit event before it saves. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 4 | A global ban is used to silence a customer. | The reason is mandatory, the ban has a short TTL and the release action is audited. | ATK-291 |
| 5 | A ban is extended forever. | The TTL ladder is bounded and the extension is recorded with its reason. | ATK-295 |
| 6 | The runner address is added to the jail by mistake. | The never-ban guard blocks the ban and names the colliding entry. | ATK-295 |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 2 | The report is shared with the wrong tenant. | The evidence names the tenant and the support lookup requires a reason. |
| 4 | A ban hits a shared address used by many visitors. | The ban form shows the collateral hint and the never-ban result before the ban saves. |
| 6 | The runner address loses its never-ban entry. | The guard warns before the removal and the audit row keeps the previous value. |

## Admin controls

| Action | Permission | Audit event | Reason required | Step-up |
| --- | --- | --- | --- | --- |
| Triage an abuse report | PERM-platform.abuse.write | No B8 event records abuse triage | yes | no |
| Add a global ban | PERM-platform.jail.write | AUD-ban.global_created | yes | yes |
| Release a global ban | PERM-platform.jail.write | AUD-ban.global_released | yes | yes |
| Change the never-ban list | PERM-platform.jail.write | AUD-platform.never_ban_changed | yes | yes |

## Stress cases

| Case | What changes | What stays usable |
| --- | --- | --- |
| low bandwidth | The evidence excerpts load after the address and reason text. | The ban and release actions stay usable. |
| small screen | The jail table becomes one column per address card. | Every action stays in the tab order. |
| keyboard only | The ban form and the menu actions work without a pointer. | Tab reaches the evidence, the ban and the release actions. |

## Instrumentation

- `AUD-ban.global_created` records a platform-wide ban with its reason and TTL step.
- `AUD-ban.global_released` records the release and the actor.
- `AUD-platform.never_ban_changed` records a never-ban list change with the CIDR.

## Success and checks

Success: the abuse report is triaged with a reason, the campaign address is banned with a short TTL and the runner address stays protected by the never-ban list. Checks: AC-51.
