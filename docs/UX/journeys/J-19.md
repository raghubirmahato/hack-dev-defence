# J-19 Owner builds a custom rule

Personas: [Dan](../personas/dan.md), [Sara](../personas/sara.md). Emotional state is a design aid, not a measured value.

Trigger: the owner needs a request condition that the built-in rules do not cover.

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 4 | The test is the same engine that will inspect live traffic. | The test names the inspect API and the configuration revision. |
| 5 | The dry run does not change production. | The page labels the run as a replay and never forwards a sample. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 2 | A condition is written to match more traffic than intended. | The test and the dry run show the matched samples before the rule is enabled. | ATK-001 |
| 4 | A crafted sample is used to probe the inspect API. | The inspect API is rate-limited and returns the decision only. | ATK-002 |
| 8 | A rule with the ban action bans an innocent address. | The self-ban guard and the short TTL limit the collateral effect. | ATK-003 |

## Safeguards

| Step | Risky action | Safeguard | Kind | Copy key | Exact copy |
| --- | --- | --- | --- | --- | --- |
| 3 | Setting the ban action. | The consequence text states the collateral risk and the TTL before the action is saved. | confirmation | rule-ban-confirm | Read the ban consequence and the TTL before you save; the self-ban guard refuses your own address. |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 3 | The ban action catches an address that shares a network. | The collateral hint and the short TTL keep the effect small. |
| 5 | The dry run names a benign request as a candidate. | The candidate opens in the event detail with the matched condition. |
| 8 | The rule blocks real traffic after it is enabled. | The rule list shows the hit count and the pause control next to the rule. |

## Rule builder error taxonomy

| Class | Example | Message copy key | Exact copy |
| --- | --- | --- | --- |
| syntax | `action =` with no value | rule-syntax-missing-value | Add a value after the operator; the marker shows the empty position. |
| syntax | `path = "/admin` with the quote open | rule-syntax-quote | Close the quoted value before you save; the marker shows the open quote. |
| semantic | a country condition without a GeoIP database | rule-semantic-geoip | Add the GeoIP database first, or remove the country condition before you save. |
| semantic | a ban action without a scope | rule-semantic-ban-scope | Give the ban a path or method scope; a global ban needs the platform jail. |
| performance | a catch-all condition on every request | rule-performance-catch-all | Narrow the path before you save; a catch-all condition is replayed against all traffic. |
| performance | a regular expression over long query values | rule-performance-regex | Bound the query length in the condition; an unbounded expression is too expensive. |

## Instrumentation

- `AUD-waf.rule_created` supplies the counter for the created rule.
- `AUD-waf.inspect_run` records each test and dry run without storing a sample body.

## Success and checks

Success: the rule is saved as a revision and can be tested against samples and recent traffic. Checks: AC-12, AC-13.
