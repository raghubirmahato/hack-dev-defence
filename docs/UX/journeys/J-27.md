## API key lifecycle

| Stage | What happens | Control |
| --- | --- | --- |
| create | The owner names the key and picks its scopes and expiry. | The scopes are the intersection with the creator's current role. |
| secret reveal once | The secret appears on the page exactly one time after the save. | The page warns before hiding it and the list shows only the prefix. |
| rotation | A new key is created and the old key is revoked; B6.3 has no in-place rotation endpoint. | The list shows both keys until the old one is revoked. |
| expiry | The key stops working at the chosen date. | The list shows the expiry date and warns before it passes. |
| restrict by IP | The key is refused from any address outside the listed ranges. | The key page lists the allowed address ranges. |
| revoke | The key is deleted and its secret stops working immediately. | The audit row records who revoked the key and when. |

## Stress cases

| Case | What changes | What stays usable |
| --- | --- | --- |
| low bandwidth | The code examples render before the usage chart. | The secret, the copy button and the revoke action stay usable. |
| small screen | The scope list becomes a set of stacked checkboxes. | Every scope and the create button stay in the tab order. |
| keyboard only | The copy button and the reveal-once warning work without a pointer. | Tab reaches the secret, the copy button and the revoke action. |

## Instrumentation

- `AUD-apikey.created` records a key with its prefix and scopes, never the secret.
- `AUD-apikey.revoked` records the actor and the key prefix.
- `AUD-apikey.used_denied` records a refused call without the key value.
