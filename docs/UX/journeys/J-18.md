# J-18 Analyst investigates an attack

Personas: [Sara](../personas/sara.md). Emotional state is a design aid, not a measured value.

Trigger: an alert shows unusual traffic and the analyst opens the live monitor

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Filters the live monitor by the attack category. | The feed keeps only the matching events and shows the count. | S-065 | none | ERR-RATE-001: The page shows the filter rate limit exceeded and gives the reset time. | calm | monitor-filter-title | - |
| 2 | Reads the would-block and blocked counts. | The page shows both counts and the time window. | S-065 | none | System error ERR-SYS-001: The counts service is temporarily unavailable; the last window stays shown. | unsure | monitor-counts-title | - |
| 3 | Opens an event for the policy branch. | The detail shows the redacted evidence, the rule and the branch. | S-066 | none | ERR-PERM-002: The not-found page keeps the event link from leaking another tenant's data. | unsure | event-detail-title | - |
| 4 | Bans the address after the confirmation. | The confirmation shows the TTL and the affected scope. | S-067 | none | ERR-BAN-002: The page refuses the ban because it would affect your own address or a never-ban entry, and says which. | anxious | event-ban-action | - |
| 5 | Reads the ban list with the expiry. | The list names each ban, its rule and its expiry. | S-067 | none | System error ERR-SYS-001: The ban list service is temporarily unavailable; the last expiry stays shown. | calm | ban-list-title | - |
| 6 | Creates an exception for the false positive. | The preview shows the scope and the expiry before it saves. | S-064 | none | ERR-WAF-005: The expiry is required; the exception cannot be saved without one. | calm | event-exception-create | - |
| 7 | Links the event to the Ray ID. | The page keeps the Ray ID visible with a copy button. | S-067 | none | ERR-APPEAL-001: The Ray ID is not found or expired, so the page keeps a generic message. | calm | event-ray-link | - |
| 8 | Unbans the address. | The page shows the release time and the audit record. | S-067 | none | ERR-BAN-001: The page says the address is not banned any more and offers a refresh of the jail list. | calm | event-unban-action | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 1 | The filter counts are real. | The time window and the filter are shown with the count. |
| 4 | A ban is explainable. | The confirmation names the rule, the subtype and the TTL. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 1 | A cross-tenant event is exposed. | The event query is scoped to the organisation and answers 404 otherwise. | ATK-225 |
| 3 | The event detail exposes another tenant's event. | The cross-tenant lookup answers the generic not-found page. | ATK-223 |
| 4 | A ban is placed on the owner address. | The self-ban guard refuses it and shows the preview. | ATK-161 |

## Safeguards

| Step | Risky action | Safeguard | Kind | Copy key | Exact copy |
| --- | --- | --- | --- | --- | --- |
| 3 | Opening an event from another tenant. | The link is scoped and answers 404 for a foreign event. | confirmation | event-open-confirm | This event belongs to your organisation; a foreign link shows the not-found page. |
| 4 | Banning the address. | The confirmation shows the TTL and the scope before the ban applies. | confirmation | ban-confirm | Confirm the address and the TTL before the ban applies; the ban list lets you release it. |
| 6 | Creating a scoped exception. | The preview shows the scope and the expiry before the exception saves. | preview | event-exception-preview | Review the scope and the expiry; the exception can be removed from the list. |
| 8 | Unbanning an address. | The page shows the audit record and the release time before the unban. | undo | event-unban-confirm | Release this address now; the ban history keeps the decision and the actor. |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 1 | The filter hides the real cause. | The filter is shown and the count is visible before any conclusion. |
| 4 | A ban hits a shared address. | The collateral hint is shown before the ban and the TTL is short. |
| 8 | The unban is wrong. | The audit record and the release time are shown before the unban. |

## Instrumentation

- `AUD-ban.created` supplies the counter for the ban decision.

## Success and checks

Success: the event is explained, the address is banned or released, and the Ray ID links the evidence. Checks: AC-07, AC-08.
