# J-22 Blocked visitor files an appeal

Personas: [Vi](../personas/vi.md), [Maya](../personas/maya.md). Emotional state is a design aid, not a measured value.

Trigger: a visitor is blocked, opens the block page and believes the block is a mistake.

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Reads the block page with the Ray ID. | The page states the reason class and shows the Ray ID with a copy button. | S-140 | none | ERR-VISITOR-403: The block page says access is denied and shows the Ray ID. | anxious | appeal-block-page | - |
| 2 | Opens the appeal form from the block page. | The form shows the prefilled Ray ID and the optional contact field. | S-145 | none | ERR-APPEAL-001: The form says the Ray ID is not found or expired and asks for the block page value. | unsure | appeal-form-title | - |
| 3 | Enters an optional contact and a note. | The fields state the length limits and keep the note as plain text. | S-145 | contact, note | ERR-VAL-003: The note payload is too large and the plain text limit is shown. | unsure | appeal-note | - |
| 4 | Passes the light proof-of-work check. | The form states the check is running and then enables the submit button. | S-145 | none | ERR-GATE-003: The check makes too many attempts and the visitor sees the retry time. | anxious | appeal-pow | - |
| 5 | Submits the appeal. | The page shows the pending receipt with a reference and the next step. | S-146 | none | ERR-APPEAL-002: The receipt is refused after too many appeals and the retry time is shown. | calm | appeal-submit | - |
| 6 | Reads the receipt and keeps the reference. | The page repeats the reference and explains what happens next. | S-146 | none | System error ERR-SYS-001: The receipt service is temporarily unavailable; the reference stays on screen. | calm | appeal-receipt | - |
| 7 | Waits for the owner's decision. | The page states the appeal state and the estimated window. | S-146 | none | ERR-RATE-001: The appeal state check limit is reached and the next check time is shown. | anxious | appeal-status | - |
| 8 | Opens the appeal form again after the window. | The form keeps the reference and states the previous decision. | S-145 | none | ERR-APPEAL-001: The form keeps the generic not-found message for an expired reference. | unsure | appeal-return | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 1 | The block names a mistake without exposing a rule. | The page shows the Ray ID and a plain reason class, never the matched rule. |
| 5 | The appeal was received even if the reply is neutral. | The receipt shows a reference and the same wording for every Ray ID. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 1 | The block page leaks the matched rule to an attacker. | The visitor page shows a reason class and the Ray ID only. | ATK-161 |
| 3 | The note carries a payload that is rendered later. | The note is stored as text, length-capped and never rendered as markup. | ATK-061 |
| 8 | An expired reference is used to confirm whether an address is banned. | The form answers with the same generic receipt for a known and an unknown Ray ID. | ATK-170 |

## Safeguards

| Step | Risky action | Safeguard | Kind | Copy key | Exact copy |
| --- | --- | --- | --- | --- | --- |
| 4 | Passing the proof-of-work check. | The check is time boxed and a retry is offered after the window. | time box | appeal-pow-window | The check runs for a short window; if it fails, wait for the retry time shown on the page. |
| 5 | Submitting the appeal. | The receipt states the reference and the decision window before the appeal leaves the page. | confirmation | appeal-submit-confirm | Submit the appeal and keep the reference; the receipt shows the decision window. |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 2 | The Ray ID has expired before the appeal is opened. | The form shows the generic message and the block page value can be copied again. |
| 4 | The proof-of-work check fails on a slow device. | The page offers the retry time without discarding the note. |
| 7 | The visitor checks the status too often. | The page gives the next check time and keeps the receipt reachable. |

## Abuse cases

| Abuse case | Defense | ATK |
| --- | --- | --- |
| A bot files appeals for many Ray IDs. | A per-address rate limit, a light proof-of-work and a neutral receipt. | ATK-170 |
| A note carries a script payload. | The note is stored as plain text and never rendered as markup. | ATK-061 |
| The form is used to learn whether an address is banned. | The receipt is identical for a known and an unknown Ray ID. | ATK-161 |
| An oversized note is submitted to exhaust the queue. | The note is length-capped and the submit button enforces the cap. | ATK-132 |
| A third-party page submits the form for a visitor. | The form carries a CSRF token and an origin check on submit. | ATK-172 |

## Instrumentation

- `AUD-appeal.submitted` records the appeal without the note text or the contact address.

## Success and checks

Success: the appeal is received with a reference and the visitor sees the same receipt for every Ray ID. Checks: AC-43.
