## Cutover safety

| Step | What could break the live site | Guard | Undo |
| --- | --- | --- | --- |
| 2 | A scan that runs against the wrong zone could hide records. | The preview and the zone scan run before any change is offered. | Undo by reverting the provider values through the R-19 path. |
| 3 | The CNAME replaces an existing `www` record. | The preview shows the current `www` value before the CNAME choice. | Undo with the R-19 return path and the previous `www` record. |
| 4 | A proxied mail record stops mail delivery. | The preview marks mail records grey before the proxy toggle is saved. | Undo with rollback to the previous zone snapshot. |
| 5 | A wrong TXT record blocks ownership without touching traffic. | The verification TXT preview shows the exact record before the change. | Undo by deleting the TXT record; no traffic moves. |
| 7 | A DNS challenge record leaks the pre-issuance plan to the wrong zone. | The TLS plan preview lists the challenge records before any DNS change. | Undo by removing the challenge records; no traffic moves. |
| 10 | The CNAME change is saved before the checklist is complete. | The go-live checklist and the CNAME preview precede the change. | Undo with the R-19 return path and the previous `www` value. |
| 9 | The CNAME is switched before the target resolves. | The checklist and the resolution preview precede the cutover. | Undo with the instant return path of R-19 and the previous `www` record. |
| 11 | Propagation is assumed before every resolver agrees. | The propagation check uses the resolver matrix before go-live. | Undo with the previous CNAME value and the TTL-based rollback. |
