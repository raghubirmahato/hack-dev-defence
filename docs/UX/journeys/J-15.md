# J-15 Owner issues TLS and enables HSTS

Personas: [Maya](../personas/maya.md), [Dan](../personas/dan.md). Emotional state is a design aid, not a measured value.

Trigger: the owner enables HTTPS and later raises HSTS after the certificate is active

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |

## Safeguards

| Step | Risky action | Safeguard | Kind | Copy key | Exact copy |
| --- | --- | --- | --- | --- | --- |
| 2 | Choosing the certificate plan. | The plan lists each authority and challenge before the order. | preview | tls-plan-preview | Review the authority and challenge before you order; staging stays available until approval. |
| 3 | Requesting a certificate. | The plan and the CAA check run before the order is created. | confirmation | tls-issue-confirm | The order waits for your confirmation; staging stays until you approve production issuance. |
| 5 | Enabling HSTS. | The warning shows the staged max-age ramp before it applies. | time box | tls-hsts-confirm | Enable HSTS in stages; the previous value returns automatically if the site fails the check. |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 1 | The status is stale. | The refresh time is shown and the page can be reloaded. |
| 3 | Validation fails. | The challenge type and a plain-language cause are shown, with a retry. |
| 5 | HSTS breaks a site that is not ready. | The staged ramp and the automatic revert apply before the full value. |
