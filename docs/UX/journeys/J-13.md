# J-13 Owner imports existing DNS and resolves parity warnings

Personas: [Maya](../personas/maya.md), [Dan](../personas/dan.md). Emotional state is a design aid, not a measured value.

Trigger: the owner brings an existing zone to HDD and must resolve the parity warnings before any cutover.

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Reads the source and target diff per record. | The diff shows each record's source value, target value and difference. | S-047 | none | ERR-PERM-002: The not-found page keeps the import diff reachable from the zone page. | unsure | dns-parity-title | - |
| 2 | Reviews the unsupported record types. | The list names each unsupported type with an explanation and a suggested manual record. | S-047 | none | ERR-DNS-006: The list names the unsupported record types and what to do instead. | unsure | dns-unsupported-title | - |
| 3 | Acknowledges each unsupported type. | The acknowledgement is recorded and the remaining parity count drops. | S-047 | acknowledgement | ERR-DNS-001: The acknowledgement is not valid because the record type is unsupported. | calm | dns-ack-type | - |
| 4 | Resolves a conflicting record. | The page names the conflict and the value HDD expects. | S-047 | none | ERR-DNS-002: The conflict report names the CNAME value and the record it blocks. | anxious | dns-conflict-note | - |
| 5 | Confirms the parity is clean. | The page states that no warning remains before the nameserver step. | S-047 | none | ERR-DOM-005: The page says the domain is not in a state that allows the parity confirmation. | calm | dns-parity-clean | - |
| 6 | Checks the imported records against the live zone. | The parity report refreshes with a server timestamp. | S-099 | none | System error ERR-SYS-001: The parity service is temporarily unavailable; the last count stays shown. | unsure | dns-parity-refresh | - |
| 7 | Reads the cutover prerequisite list. | The list names the parity acknowledgement and the rollback path. | S-042 | none | System error ERR-SYS-001: The prerequisite service is temporarily unavailable; the checklist stays visible. | calm | dns-cutover-list | - |
| 8 | Hands the zone to the add-domain wizard. | The wizard opens with the imported records already selected. | S-042 | none | ERR-DOM-004: The wizard says ownership has not been verified for the imported domain. | calm | dns-handover | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 1 | The diff is complete and server-side. | The report names its timestamp and the zone it read. |
| 5 | No warning is hidden to speed the flow. | The page stays on the parity step until every warning is acknowledged. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 1 | Zone enumeration during the scan. | The scan is rate-limited and reads only records the zone serves publicly. | ATK-225 |
| 4 | A conflicting record is used to hijack a name. | The conflict is reported and the import cannot overwrite it without acknowledgement. | ATK-223 |

## Safeguards

| Step | Risky action | Safeguard | Kind | Copy key | Exact copy |
| --- | --- | --- | --- | --- | --- |
| 3 | Acknowledging an unsupported record type. | The acknowledgement is per type and can be undone before the cutover. | confirmation | dns-ack-confirm | Acknowledge this type only if you keep the manual record; you can undo the acknowledgement before cutover. |
| 5 | Confirming parity is clean. | The page requires every warning to be acknowledged before it continues. | preview | dns-parity-preview | Review every remaining warning before you confirm; the cutover stays blocked until the list is empty. |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 1 | The diff is read against the wrong zone. | The report names the zone and the timestamp, and the import can be restarted. |
| 4 | A conflict is overwritten by mistake. | The conflict record is kept and the previous value is restored from the change history. |
| 5 | Parity is confirmed with a warning left. | The cutover step checks the parity count again and refuses to continue. |

## Instrumentation

- `AUD-dns.parity_acknowledged` supplies the counter for the parity acknowledgement.
- The parity count is stored on the domain record; no browser script is needed.

## Success and checks

Success: the parity report is clean before the nameserver step. Checks: AC-02.
