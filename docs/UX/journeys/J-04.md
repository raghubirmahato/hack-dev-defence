# J-04 Returning user logs in

Personas: [Maya](../personas/maya.md), [Dan](../personas/dan.md), [Sara](../personas/sara.md), [Omar](../personas/omar.md), [Alex](../personas/alex.md). Emotional state is a design aid, not a measured value.

Trigger: a returning user opens the app to start the day's work.

## Steps

| Step | User action | System response | Screen | Data collected | Error path | Emotional state | Copy key | Metric |

| 1 | Types the email and the password. | The form never says which of the two is wrong. | S-023 | email, password | ERR-AUTH-002: The form says the email or password is incorrect, with the same text for both fields. | calm | login-title | - |
| 2 | Submits the form. | The next step depends on the factors the account has. | S-023 | email | ERR-AUTH-004: The account form shows a retry time after too many attempts, without naming the lock cause. | unsure | login-submit-action | Support-worthy errors per 100 sessions |
| 3 | Enters the six-digit code. | The code field focuses itself and accepts paste. | S-024 | TOTP code | ERR-AUTH-003: The code field says the verification code is incorrect or expired and keeps paste enabled in the field. | unsure | mfa-prompt-title | - |
| 4 | Retries a wrong code. | The page keeps the field and says how long to wait. | S-024 | TOTP code | ERR-AUTH-004: The page keeps the code field and gives a retry time after too many wrong-code attempts. | anxious | mfa-prompt-retry | - |

## Trust moments

| Step | What the user must believe | Evidence we show |
| --- | --- | --- |
| 1 | A typo in one field does not tell anyone my email exists. | Both fields produce the same error text and the same timing. |
| 8 | I can see this session and the device next time. | Settings S-089 lists the session and its last use. |

## Security considerations

| Step | Risk | Control | ATK |
| --- | --- | --- | --- |
| 1 | Credential stuffing across many accounts. | The login rate limit and the progressive backoff apply per address. | ATK-158 |
| 2 | Brute force against one account. | Lockout and backoff do not reveal the account state (ERR-AUTH-004). | ATK-157 |
| 5 | A stolen session is fixed on the attacker's session id. | The session id is rotated at login and never placed in a URL. | ATK-164 |
| 7 | Account enumeration through the lockout message. | The lockout page is identical for a real and an unknown address. | ATK-161 |

## Instrumentation

- `AUD-auth.login_success`, `AUD-auth.login_failure`, `AUD-auth.lockout` and `AUD-auth.new_device` are the audit sources.
- The support-worthy error counter reads `ERR-AUTH-004` and `ERR-AUTH-007` from the error log.
- The session list on S-089 reads the same session records and stores no additional data.

## Success and checks

Success: the user is signed in and lands on the last organisation overview. Checks: AC-35.
