# J-16 Owner enables protection in monitor mode, reviews, switches to block

Personas: [Maya](../personas/maya.md), [Sara](../personas/sara.md). Emotional state is a design aid, not a measured value.

Trigger: the owner starts from monitor mode and later decides whether to block

## Trust moments

| Step | What the user must believe | Evidence we show |

## What could go wrong

| Step | What goes wrong | Recovery action |
| --- | --- | --- |
| 1 | Monitor mode is mistaken for protection. | The page repeats that nothing is blocked yet and the counts are would-block. |
| 5 | The exception is too broad. | The preview shows the scope and the expiry before it saves. |
| 8 | The switch blocks the owner. | The self-lockout preview and the consequences dialog block the change. |

## Decision support

- The would-block count for the last 24 hours.
- Three example events with the matched rule.
- The would-block share of all requests.
- The false-positive review from the last week.
- The honest warning about shared IPs and collateral risk.

## Instrumentation

- `AUD-waf.mode_changed` supplies the counter for the mode switch.

## Success and checks

Success: the mode is monitor or block as chosen, with the readiness hint and the undo path. Checks: AC-06, AC-13.

Question: Should the monitor-to-block switch use a scheduled switch with typed confirmation? See OPERATOR-QUESTIONS.md.
