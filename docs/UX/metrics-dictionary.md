# Metrics dictionary

Every number an analytics screen shows has one row here: what it means, its unit, how it is aggregated, the time window
it covers, where it comes from, the RFC 3339 type or value class, the B9 labels that apply, how fresh it is, and what the
widget shows when the value is unavailable (A1 and A5). The companion document, [DATAVIZ.md](DATAVIZ.md), says which
screen shows which KPI and why each chart form was chosen.

The source of a value is one of four things, and the row says which:

- a Prometheus metric of the B9 catalog, cited by its real `MET-` id with the same type and labels as B9;
- an aggregate of the rollup tables of B5.8 (`rollup_minute`, `rollup_hour`, `rollup_day`);
- a live row or stream of the event store or a configuration table of B5 (`waf_events`, `ip_bans`, `campaign_clusters`,
  `shield_incidents`, and so on);
- a value computed by the application from other values (a ratio, a delta, a readiness score, a health probe), marked
  `derived` or `state` with its formula or its origin in the definition.

Where a displayed number has no B9 metric, the row says so instead of citing a metric that does not exist: bandwidth
exists only in the rollup column `bytes_out`, and the three capacity numbers of S-127 have no metric id at all. Those
are honest gaps in the instrumentation, not licences to invent a `MET-` id.

## Source legend

| Source | What it is | Notes |
| --- | --- | --- |
| `rollup_minute`, `rollup_hour`, `rollup_day` | The aggregates of B5.8, written by the `hdd-worker` rollup job from proxy counters and events | Minute buckets are kept for 48 hours; hour and day are yearly partitions (T-0140, T-0441) |
| `waf_events` | The partitioned event store of B5.7, holding notable requests only | Counts differ from request counts because ordinary allowed requests are not stored as events (T-0441 notes) |
| `ip_bans` | The durable ban table of B5.7; Redis is the fast path | Used for active bans, ban reasons and ban times |
| `audit_log` | The hash-chained audit table of B5.10 | Used for annotations and for release events |
| `campaign_clusters`, `challenge_stats`, `event_aggregates` | The remaining B5.7 tables | Campaign grouping, challenge pass rate and jail-hit aggregates |
| `shield_events` | The B5.11 shield event table (states, signals, actions) | `shield_incidents` is named by T-0474 but has no B5 table row yet, so it is cited with that task rather than as a modelled table |
| `MET-` ids | The Prometheus metrics of B9 | The type and the labels in a row are the B9 entries, not a paraphrase |
| `GET` and `POST` routes | The B6.3 API surface | Named with the route the screen calls |
| `docs/CAPACITY.md` | The published capacity model | Lab-derived, explicitly not a guarantee (T-0476) |

## Reading a row

`Window` is the time range the value covers: a preset from the picker, "Current state" for a gauge read at request
time, "Last 24 hours" for a fixed card window, or a bounded retention. `Refresh` is how often the value can change on
screen; "rollup watermark" means the widget updates when the rollup job advances the watermark, and the widget cache
may serve a value up to 30 seconds old (T-0139 step 7). A Prometheus gauge or counter is read at each scrape; the scrape
interval is deployment configuration and the specification sets no default, so no number is claimed here. `Type` is the
Prometheus type when the row cites a metric, and `derived`, `rollup`, `event` or `state` when the displayed value is
computed or read from a table. `Labels` lists the B9 labels the value can be split by; `-` means the metric has none or
the row is not a Prometheus metric. `Aggregation` says how the points in the window become one number. `Unknown` is the
exact fallback: a missing source is always `Unknown ({reason})` and never zero, a gap is a gap, and "None in the window"
is a known zero, which the row says where it applies.

Two rules apply to every row. A rate or a ratio is computed from two sums of the same window and the same scope, never
from one sum and a different window. A percentile is merged from the fixed histograms of T-0441 step 6 and never
averaged, and it carries the approximate label with the 2 percent bound.
