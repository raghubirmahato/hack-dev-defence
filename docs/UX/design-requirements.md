# Design requirements from the pattern review

These requirements turn the patterns in [PATTERNS.md](PATTERNS.md) into testable expectations for the screens of spec
B12.1 and the components of spec B11.8. DR-01 to DR-20 are the contract for design review and the gates in P02 to P04;
a requirement without a screen or component cannot be tested, so each row names its target.

| DR | Requirement | Rationale | Pattern topic | Screens and components |
| --- | --- | --- | --- | --- |
| DR-01 | Before the owner confirms a change, the wizard lists every affected record and the provider that changes it. | The owner edits DNS at a registrar they barely use, so a change must be visible before it is saved. | [Onboarding](PATTERNS.md#topic-onboarding) | S-042, Stepper |
| DR-02 | The onboarding checklist keeps one next action and resumes from the last completed step on any device. | A session can end in the middle; a saved position keeps the first task recoverable. | [Onboarding](PATTERNS.md#topic-onboarding) | S-035, S-040 |
| DR-03 | The DNS import shows a source and target diff and requires an acknowledgement for each unsupported record type. | One dropped mail record costs more than the security setup is worth. | [DNS import](PATTERNS.md#topic-dns-import) | S-047, DataTable |
| DR-04 | Every DNS change shows the records that will resolve before save and offers a rollback to the previous version. | An edit with no visible result or way back is a trial by outage. | [DNS import](PATTERNS.md#topic-dns-import) | S-045, S-046 |
| DR-05 | The per-record proxy control states "Proxied" or "DNS only" in text and prints the consequence beside it. | A toggle that only changes colour cannot be read and hides the switch between a proxy and a direct record. | [Proxy toggles](PATTERNS.md#topic-proxy-toggles) | S-045, CloudToggle |
| DR-06 | Switching a protection mode shows each consequence and offers one undo action for the previous mode. | A mode change is the most consequential click in the product, so it must be reversible. | [WAF modes](PATTERNS.md#topic-waf-modes) | S-055, ConfirmDialog |
| DR-07 | A new domain starts in a mode that blocks nothing until the owner has reviewed the preview. | The preview is the evidence that turning protection up will not break the site. | [WAF modes](PATTERNS.md#topic-waf-modes) | S-054, S-055 |
| DR-08 | An event row opens a detail view with the rule, vector, policy branch and a redacted evidence span for its Ray ID. | An analyst needs the decision behind a row, and the evidence must never leak the payload. | [Event logs](PATTERNS.md#topic-event-logs) | S-065, S-066, PayloadViewer |
| DR-09 | The live feed pauses on a keyboard command, reports "N new" while paused and never scrolls while focus is inside it. | Reading a live list requires stopping it without losing the position or the keyboard focus. | [Event logs](PATTERNS.md#topic-event-logs) | S-065, LiveFeed |
| DR-10 | The rule builder prints the rule as one sentence and blocks save until server validation passes. | A row of dropdowns can express a condition the author did not intend; the sentence is the check. | [Rule builders](PATTERNS.md#topic-rule-builders) | S-059, RuleBuilder |
| DR-11 | Saving a rule requires a dry run against recent traffic that reports the number of matched requests. | The dry run is the only way to see a rule's effect before it reaches visitors. | [Rule builders](PATTERNS.md#topic-rule-builders) | S-060, S-059 |
| DR-12 | Each ban shows its reason, rule, TTL step and a text countdown, and offers an unban action on the same view. | The reader must be able to explain and reverse a ban without leaving the page. | [Bans](PATTERNS.md#topic-bans) | S-067, S-068, CountdownBadge |
| DR-13 | The block page shows the Ray ID and links to an appeal form that works without an account. | A blocked visitor needs a reference and a route back, on a phone, without signing up. | [Appeals](PATTERNS.md#topic-appeals) | S-140, S-145 |
| DR-14 | Charts state their units and the time zone and offer a table view of the same values. | A chart without units or a text alternative implies precision the reader cannot check. | [Analytics](PATTERNS.md#topic-analytics) | S-070, ChartKit |
| DR-15 | A period with no data shows an honest empty state that names the missing source instead of printing zero. | Zero and missing are different facts, and showing zero would be a false statement. | [Analytics](PATTERNS.md#topic-analytics) | S-070, EmptyState |
| DR-16 | An API key is shown once in a copy field with its scopes and expiry, and can be revoked from the same list. | A secret that stays visible or that never expires is a standing risk. | [API keys](PATTERNS.md#topic-api-keys) | S-080, CopyField |
| DR-17 | A role change dialog shows the role's plain description and blocks removing or demoting the last owner. | A confident click on a role control is the shortest route to a locked-out organisation. | [Team management](PATTERNS.md#topic-team-management) | S-081, S-083 |
| DR-18 | An alert rule names its channels and shows the retry outcome of each delivery attempt. | An alert that silently fails to arrive is worse than no alert, because the owner believes it is covered. | [Notifications](PATTERNS.md#topic-notifications) | S-076, S-079 |
| DR-19 | The readiness score lists every check with its reason and a link to the screen that fixes it. | The score is useful only when the reader can act on the failing item. | [Protection readiness](PATTERNS.md#topic-protection-readiness) | S-044, ReadinessRing |
| DR-20 | The origin lockdown wizard shows the current lockdown state and reruns verification probes before it reports success. | A bypass path that remains open makes the rest of the setup optional for an attacker. | [Origin lockdown](PATTERNS.md#topic-origin-lockdown) | S-098, S-138 |
