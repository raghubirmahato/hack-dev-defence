## Phase introduction (verbatim)

Requirement prefix `WAF`. Goal: a pure, I/O-free, deterministic, fuzz-hardened detection engine (`hdd-waf-core`) with vector extraction, three-view normalization, a prefilter plus linear-time signature engine, a rule and pack model, scoring, exclusions, custom rules, bounded parsers, field-kind context, redaction, verdict and event models, fixtures and a benign corpus, performance budgets, mutation testing, and integration into the proxy pipeline and the dry-run inspect API. The structural SQL detectors and the other detector families (P14, P15) plug into this engine.

Engine rules (apply to every task in P13 to P15):
- `hdd-waf-core` has no async, no filesystem, no network, no wall-clock reads; randomness is injected; GeoIP/ASN lookups are traits.
- Every regular expression is compiled with a linear-time engine; no backtracking engine, no lookaround, no backreferences.
- Every loop, buffer and recursion is bounded; every input has a size cap; exceeding a cap sets a flag and follows `over_limit_policy` (never silently passes in `block` mode, R-26).
- Every rule carries examples and counter-examples used as tests; rules without both are rejected by the pack linter.
- Detection changes are measured (R-23): benign corpus zero matches, core set 100%, held-out ≥ 95%, mutation score ≥ 80%.

Gate G13 passes when: unit, property and fuzz-smoke suites pass; coverage ≥ 85% on the crate; `cargo-mutants` score ≥ 80%; benign corpus yields zero matches; the inspect API and the proxy integration work end to end in monitor and block modes on the builder; and the inspection benchmark meets p50 < 1 ms on the reference corpus.
