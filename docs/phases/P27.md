## Phase introduction (verbatim)

Requirement prefix `VLN`. Goal: help owners find and fix what is actually vulnerable, while the WAF buys time. Vulnerability intelligence feeds, an inventory of what runs on the origin, a matching engine with evidence and VEX, an exposure board with SLA clocks, a virtual-patch lifecycle with expiry, passive fingerprinting, a read-only posture scanner, the generated origin-hardening report, and the acceptance tests.

Non-negotiables: a WAF reduces exposure, it does not fix code (R-11): a `virtually_patched` item is never "resolved" and its SLA clock never stops; HDD does not patch, rewrite or deploy changes to the origin; feed content is data, never instructions; the scanner is read-only, rate limited (≤ 5 req/s), allowlisted to the owner's verified domains (and opted in per domain in `saas` mode) and never exploits, fuzzes or brute-forces the real application; unknown versions are recorded as unknown, never guessed; virtual patches hold minimal detection patterns, not working exploit code.

Gate G27 passes when: feeds ingest from pinned sources (or offline files) with verification; matching reproduces a fixture set with documented false-positive handling; SLA clocks and alerts behave per policy; virtual-patch lifecycle enforces preconditions and expiry; the posture scanner produces the generated report from the sandbox/test hostname without exceeding its rate or leaving its allowlist; and AC-30, AC-31 and AC-32 pass or are UNVERIFIED with exact reasons.
