## Phase introduction (verbatim)

Requirement prefix `RTM`. Goal: one product that runs in two ways. **Local:** on an operator's computer (Windows, macOS or Linux, no Docker required), live only while it runs. **Hosted:** on a server, running 24/7 under a supervisor with backups, upgrades and runbooks. Plus the controls that make coverage as complete as can honestly be shown: an access gate for sensitive paths, API discovery with positive security, business-flow protection, and a coverage map with a "does not cover" list. Read Part C, C18 and C19 and rules R-31 and R-32 first.

Design rules for this phase:
- One code path (R-31). Profile-dependent code lives only in `hdd-local`, `hdd-common::kv`, `hdd-common::profile` and the `Enforcer` factory; `xtask profile-lint` enforces it. Wherever another task says "Redis" for runtime state it means the `KvStore`, `Bus` and `Limiter` traits, and only `hdd-common::kv` talks to Redis (`xtask kv-lint`). Tests that say "real Redis" or "testcontainers" run against both backends, and on a builder without Docker (Track L) against the embedded PostgreSQL and in-process stores.
- Nothing weakens security to be convenient locally. There is no `DEV_MODE`.
- Honest availability: local protection exists only while HDD runs; hosted availability is measured, not promised (section 4).

**Execution order within P33 (the numbering is not the order).** T-0561 to T-0563 run immediately after gate G00 (delivery slice R0, section 0.8) because later phases build on the profile model, the store traits and the embedded database. T-0564 to T-0570 run as soon as their dependencies exist (slice R1, the local walking skeleton, and R2). T-0571 to T-0574 run with the deployment phases (slice R3). T-0575 to T-0577 run after P15 and P17 (slice R4). T-0578 and gate G33 close the phase.

Gate G33 passes when: AC-55 (local runtime, including `profile-parity` with zero verdict differences), AC-56 (24/7 hosting readiness), AC-57 (access gate, API discovery and business flows) and AC-58 (coverage map integrity and absolute-wording lint) pass; the local suite is green on Windows, macOS and Linux CI runners; the hosting check passes on the pilot server with a successful reboot test and a restore drill; and the coverage map lists every mapped category with a status and the "does not cover" section.
