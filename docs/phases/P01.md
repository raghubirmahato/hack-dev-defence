## Phase introduction (verbatim)

Requirement prefix `UXR`. Goal: turn the product definition of Part B into reviewed repository documents and decisions before any pixel is designed, so that design and build start from agreed principles, flows and constraints. Deliverables live in `docs/UX/` and are written for the operator to review. No shipped UI exists yet; these are design inputs, not prototypes.

Constraints: no scraping or browsing outside the egress allowlist; "pattern review" uses only operator-supplied screenshots, public documentation fetched through the egress client if the operator allowlists it, or first principles (and is labeled accordingly). All text follows the voice rules of B11.12.

Gate G01 passes when: the UX charter, personas, information architecture, journeys, states, accessibility and i18n plans, security-UX review and the review pack exist in `docs/UX/` and link to each other; `xtask ux check` reports zero orphan screens or journeys; the open operator decisions each have a default and an owner; and `docs/gates/G01.md` exists in the E5.1 format with the pasted command output. G01 is a light gate: the operator is shown the pack, but design sign-off is the heavier gate G03.
