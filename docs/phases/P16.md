## Phase introduction (verbatim)

Requirement prefix `BAN`. Goal: turn detection into containment. Every hard detection in `block` mode (outside cross-site subresource context) bans the attacker's IP key; the ban is enforced in the proxy within 100 ms on the creating node and within 2 s everywhere, mirrored to the kernel for proxied ports, visible and reversible in the UI and API, resistant to poisoning and self-lockout, appealable by legitimate visitors, and explainable. This phase also adds platform-wide promotion, evasion defenses, collateral-damage controls and a builder-local end-to-end proof that an exploitable test origin is protected: exploit succeeds directly, fails through HDD, and the source is banned.

Design invariants (C6): bans are by IP key (IPv4 /32, IPv6 /64 by default); the hot path never awaits the database; Postgres is the durable source of truth, Redis the fast shared store, local memory the enforcement copy; unban effect ≤ 2 s; the runner IP is bannable; bans apply to proxied ports only (80/443, UDP 443) so SSH and DNS remain available; every ban stores its reason and evidence (R-24).

Gate G16 passes when: AC-08 (ban persistence and unban), AC-34 (ban-poisoning resistance), AC-22 (IP resolution) subsets, the builder-local vulnerable-origin proof, loom/shuttle concurrency tests and all P16 UI checks pass; AC-38/AC-39 full lab proofs remain scheduled for P28 with the minimal local equivalent passing now.
