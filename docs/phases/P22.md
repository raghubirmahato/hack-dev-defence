## Phase introduction (verbatim)

Requirement prefix `ADM`. Goal: a complete, safe operator console on the `admin` surface for running the platform: overview, tenants, users, domains, impersonation, tenant lifecycle, global jail and never-ban, rule packs, threat-intel feeds, infrastructure, abuse and signup policy, plans, audit, settings, email templates, announcements and flags, emergency controls, releases and backups, exposure board, shield and firewall views, and support lookup. Screens S-100 to S-130 are built here; screens whose data comes from later phases (S-125 to S-128) ship with the full contract, honest empty states and real wiring completed in P25 to P27.

Non-negotiables: the admin surface is isolated (own host, own session cookie scope, forced MFA, short timeouts, step-up for sensitive mutations, never reachable from the app host); every mutation writes an audit event with actor, reason and before/after; platform staff cannot read tenants' request bodies or secrets (R-22); impersonation is read-only, time-boxed, banner-marked and audited; no screen shows a number without a real source (R-16: "Unknown (reason)" otherwise); typed confirmation protects irreversible actions; the permission catalog (B4.2) is the only authority and is enforced server-side per route.

Gate G22 passes when: every S-1xx admin screen in scope renders from real data or an honest empty state; the platform-role privilege matrix passes in full (AC-01 admin isolation, AC-42 admin operations); all mutations are audited and chain-verified; accessibility, visual and performance checks pass for all admin screens; and no admin API can be reached with an org-role session or from the app host.
