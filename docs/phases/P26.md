## Phase introduction (verbatim)

Requirement prefix `SHD`. Goal: implement `hdd-shield`, the host service that watches the machine, decides when an attack is large enough to need stronger measures, and carries out documented escalation steps: tightening XDP and challenges, calling provider mitigation (when contracted), failing DNS over to standby edges, and alerting the operator even when the VPS is saturated. Capacity statements remain honest.

Non-negotiables: the shield never claims volumetric protection beyond contracted and measured upstream capacity (R-10); it never bans provider ranges, `admin_cidrs` or the origin; every transition and action is audited with an undo; actions whose features are absent are recorded as `skipped(feature_absent)`, never silently ignored; de-escalation is one step at a time after a quiet period; all state machine tests use recorded counter traces through the real binary's telemetry input.

Gate G26 passes when: the state machine passes the recorded-trace test suite (including flapping, slow-ramp and saturation traces); live low-rate checks confirm alerts, heartbeat and audit events; provider activation dry-run documentation exists; manual standby-edge failover is rehearsed in the pilot with measured TTL-bound timing; AC-25 and AC-27 are PASS or UNVERIFIED with exact reasons.
