## Phase introduction (verbatim)

Requirement prefix `DSN`. Goal: a complete, tokenized, accessible component library (`hdd-ui`) plus design documentation, built before any product screen. Components are Rust structs (typed props) that render askama partials with scoped CSS classes prefixed `hdd-`; no component accepts raw HTML except through a `SafeHtml` newtype produced only by the template engine or the sanitizer. All tokens come from `design/tokens/*.toml`.

Conventions for every component task in this phase:
- Props struct in `crates/hdd-ui/src/components/<name>.rs`, partial in `crates/hdd-ui/templates/components/<name>.html`, CSS in `crates/hdd-ui/css/components/<name>.css` (cascade layer `components`), snapshot tests with `insta`, unit tests for prop validation (for example icon-only buttons without a label do not compile or return an error).
- Class naming: `hdd-<component>`, modifiers `hdd-<component>--<variant>`, state via ARIA or data attributes (`aria-busy`, `aria-invalid`, `data-state`).
- Every component documents its keyboard map and ARIA contract in `docs/UX/components/<name>.md` (generated from doc comments).
- Visual states shown in the gallery: default, hover, focus-visible, active, disabled, loading, error, read-only where relevant, in dark and light.

Gate G02 passes when: the contrast check, token build and CSS budget checks pass; every component renders in the static gallery in both themes; the axe oracle reports no serious or critical findings on the gallery; keyboard maps are documented; the operator has seen screenshots of the gallery.
